# sm24：只给四向立面的受控缺信息输入

这是从既有 `sm24_anchor` 派生的**部分推理建模输入**。生成侧只得到四张立面与少量用户提供事实：深圳、办公、一层、建筑面积约 200 m²。唯一平面图、房间/热区数量、GT、历史识读、修订和旧 BIM 均不在本目录。

## 模型实际能知道什么

- 四向立面中的外轮廓、高度、门窗与标注线索；图中能否判清仍由模型说明。
- 用户提供的用途、楼层数和近似总面积。
- 输出目标是后端共用的轻量 BIM；本轮无需选择模拟插件。

## 明确省略的资料

| 省略项 | 对生成的影响 |
|---|---|
| `case_tests/e2e_tests/sm24_anchor/case_data/1f_view.png` | 不可直接读取真实平面轮廓、隔墙、房间语义、内部门和连通关系 |
| 原 `testdata_prompt.json` 中的 `thermal_zones: 8` | 不给空间数量答案；输出不以凑固定块数为目标 |
| `case_tests/test_baseline/gt*/sm24_anchor/` | 不给参照几何或分区答案 |
| 原案例全部 run、reading、correction、building geometry 与报告 | 不给历史观察、旧候选或修复线索 |

因此需要推断的内容包括：平面进深与未被立面完全约束的轮廓、内部实际隔墙/空间组织、入口对应、内部门和空间连通。模型可直接给出有说明的简化表达；不能只因朝向或达到某个房间数而添加物理隔墙。无法从立面判断的事实应写为假设或未知，不能写成读准。

## 隔离与运行

`input.json` 是给实验编排者看的输入契约；当前 runner 会扫描图片目录，因此四张 PNG 直接作为 `--images`。不要把原案例根目录或本 README 当作图片目录，也不要使用 `--resume-candidate`。

```bash
python scripts/tool_scripts/run_bim_agent.py run \
  --images case_tests/partial_inference/sm24_exterior_only \
  --out AI_agent/logs/experiments/<new_run> \
  --scope "部分推理建模独立冷启动。用户只提供：深圳普通办公建筑、一层、建筑面积约 200 平方米，以及南北东西四张立面。内部平面、房间数、隔墙、内部门与连通均未知。请利用立面中可见的外轮廓、尺寸和门窗证据，生成一个对现有信息有用、合理简化的通用轻量 BIM；逐项区分观察、估计、类型假设和未知。内部空间分隔必须有办公用途或实际隔墙假设依据，不要按朝向切源空间，不要为了凑数量造房间；允许直接表达合并后的空间，并说明合并和省略范围。不得假装恢复了真实内部布局。"
```

这是熟悉案例的受控对照，不是未见样本泛化成绩。生成后可由评测侧读取完整参照，检查外部已知信息、几何自洽和推断边界；内部参照差异应作为信息不足条件下的诊断，不能直接判成还原失败。
