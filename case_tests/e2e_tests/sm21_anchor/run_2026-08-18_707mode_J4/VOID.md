# ⛔ J4 作废 —— 但它的诊断是本日最硬的一条

**作废原因 = orchestrator 的操作错误**：为「原模原样复现 707」把图恢复成 07-07 的原尺寸
（`vision_resize_tier: high_res` ⇒ 2133×1345），**以为那是忠实复原，实际是把 F-51 专门修掉的
帧错位又打开了**。

## 证据（决定性，0.3% 吻合）

| | |
|---|---|
| 读图器标定锚点跨距（`px_a=275, px_b=1175`，15.0 m） | **900 px** ⇒ 60.0 px/m |
| 07-07 在**同一个文件**上的锚点（`425.4 / 1815.9`） | **1390.5 px** ⇒ 92.69 px/m |
| 两者帧比 | **1.545** |
| `2133 / 1377`（standard 档尺寸） | **1.549** |
| `60.0 × 1.549` | **92.94** vs 真值 92.69 ⇒ **误差 0.3%** |

⇒ **读图器的像素坐标在它「看到」的 ~1377 宽的帧里，工具读的文件是 2133 宽。**
同族 [[vlm-pixel-frame-differs-from-file-pixel-frame]]（1.544× 因子，本仓早有记录）。

## ⭐⭐⭐ 那 07-07 为什么没被坑

**07-07 的帧错位一模一样存在**，但它的锚点是 `425.4` / `1815.9` —— **亚像素、明显是从
`crop_zoom` 读回来的文件帧数字**，不是眼估的。
⇒ **07-07 靠的不是「复核把它纠正过来」，是它根本没用眼估像素。**
⇒ 正是 `cv_toolbox.md` §Source-Frame Anchor 那句：
「prefer numbers read back from a tool over eyeballed ones」，也正是 directive 里
measure-before-draw 的实义。

⇒ **⛔ orchestrator 上一条向用户说的「原模原样该保留这个错帧、交给 pilot 复核处理」是错的**，已更正。
