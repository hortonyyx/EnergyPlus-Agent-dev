# ⛔ J1 作废（VOID）—— 污染源 = orchestrator 在本臂引入的新缺陷（F-61）

**跑测**：`run_2026-08-18_guard_control_J1`（宽松 guard 对照臂 · sm21 · haiku-4-5 · 冷启无 pilot 审）
**作废理由**：**F-61** —— 放松档解锁管道后，CV 工具的参数校验器把管道尾巴当成探针参数，
**读图器唯一一次真正去跑测量的调用被误判拒绝**。
⇒ 本抽的「零 CV 调用」**不承载任何关于 guard 假说的信息**。

## 一、发生了什么

读图器**主动去测量了**：写了 **7 个 CV 请求文件**（标定 ×4、裁剪、墙检测），
然后执行：

```
python tools/run_cv_probe.py --batch requests/1f_wall_detection.json 2>&1 | tail -300
→ DENY: unknown probe parameter --batch; allowed: --tool --image --out-dir ...
```

**而 `kickoff_prompt.md` 明确教它用 `--batch`。**

## 二、判别（决定性，只改一个变量）

| 命令 | 结果 |
|---|---|
| `--batch requests/t.json` | **ALLOW** |
| `--batch requests/t.json 2>&1 \| tail -300` | **DENY「不认识 --batch」** |
| `--batch requests/t.json \| tail -5` | **DENY「不认识 --batch」** |
| `--tool crop_zoom --image … --out-dir …` | **ALLOW** |
| `--tool crop_zoom --image … --out-dir … \| tail -5` | **DENY「意外的裸参数 \|」** |

⇒ **根因 = 放松档解锁 `|` 之后，`_check_bash` 仍把整条命令（含管道尾巴）交给探针参数校验器**，
`|` / `tail` / `-300` 被当成探针参数 ⇒ 落进「未知参数」分支。
⇒ **摩擦不是被移除了，是被搬到了另一处**，且搬到的位置恰好在测量路上。

**⚠️ 最该记的**：F-61 出现在**专门为消除这类摩擦而设计的对照臂里**。
我在解锁一处摩擦的同时，在下游造了一处新的，而且**没有在跑之前验证「解锁后测量路仍然通」**——
本仓 memory 白纸黑字写着「判『模型不肯做 X』前先确认做 X 的路是通的」，
本次我验证了**边界没松**（11/11），却**没验证摩擦解锁后主路径仍可用**。
⇒ **验证清单缺了一格：不仅要验「该拦的还拦着」，还要验「该通的真的通」。**
