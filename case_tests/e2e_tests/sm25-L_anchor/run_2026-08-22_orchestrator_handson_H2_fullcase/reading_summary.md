## 一、基准声明（R-2 / R-3）

- **全图唯一基准 = 墙中线**，墙与洞口都落在它上面。⛔ 不存在「墙落实测中心线、窗落标称链位」这种混用。
- 平面局部原点 (0,0) = 本图自身总长链的西南端见证刻度（1f: px 281.5 / 1234.5；2f: px 241.0 / 1258.5）。
- 每一笔洞口都记了它的坐标来源：`chain_exact`（两端都吸附到已转录刻度）或 `pixel_fit`（无刻度可依，取像素×尺度）。
  **实测：31/31 扇窗全部 `chain_exact`，零 `pixel_fit`。**

| 图 | 链数 | 最差 rmse | 最差单点残差 | 链闭合（Σ段 − 总长） | 跨轴尺度偏差 |

## 三、洞口极性：由代码判定，不由读图器选

⭐ **本轮最重要的发现**：这些图纸按图层配色，**门窗画在一个单独的青色图层上**
（1f 占全图墨迹 12.3%，2f 12.9%）。而现行 `clean_vector_v1` 掩膜只认 `R≈G≈B` 的灰墨
（`rgb_tol=8`）⇒ **它看得见的青色像素数 = 0**。

⇒ F-69（东墙 7 扇窗被读成 7 个墙垛）**不是判断力失误，是观测能力缺失**：
读图器手里唯一的尺子看不见窗，只能从灰色墙面线的断口反推——北墙那次反推对了，东墙那次反推反了。

现在的判据是一行确定性规则：**墙带内部有青色墨迹 = 洞口；只有灰墨或空白 = 墙垛。**
东墙实测 7 段青色（行 344–924，每段 43–44 px），段间为墙垛，与读图器上一轮报的 7 个区间正好互补。

**门与窗的区分**同样是测量：门的青色墨迹**延伸到墙带之外**（开启弧），窗的墨迹在墙面线处收住。

**降级是显式的**：sm20 是 100% 灰度扫描图，无青色图层 ⇒ 工具返回 `mode="monochrome"`
并把每一段标 `polarity_ambiguous`，⛔ 不会给出一个自信的错答案。

## 四、A×B 对账（作业设计 §一 要求的形态）

| 路线 | 它能回答 | 它答不了 |
|---|---|---|
| A 像素（青色图层） | **哪一段是洞口** —— 无歧义 | 边界偏胖 1–2 px（青线含窗樘） |
| B 尺寸链算术 | **边界精确在哪** | 哪个区间是窗、哪个是墙垛（07-08 丢窗、F-69 反极性都栽在这里） |

**代码对账 = 把 A 的每个洞口两端吸附到最近的见证刻度**（容差 3 px），
吸附距离逐条记账，超容差则保留像素值并标 `snapped: false`。
实测东墙 7 扇窗吸附后宽度 = 41–42 px = **900 mm 整**，与右侧细链逐段吻合。

## 五、自证指标（⛔ 不含 gt）

- 窗宽全为整模数：**0.6 / 0.9 / 1.2 / 1.8 / 2.4 / 4.0 / 4.32 / 8.0 m**（极性或吸附若错，宽度必然参差）
- **零笔无证据**（每一笔都带 note + 像素锚点或链引用）—— 07-07 那两份的指纹
- 离线过程指标（`reading_process_metrics.py`）：**零硬告警**；证据密度 2.28（好夹具区间 2.37–3.23）

## 六、已知弱点（本轮没解，已登记）

1. **墙厚仍是像素量的，没吸附到图纸声明值**：1f 量出 0.237–0.249（应为 0.240）、0.110–0.125（应为 0.120）；
   2f 更差，出现 **0.131 / 0.146** 两个不存在的厚度 ⇒ 那两条八成是错配的墙带。
   修法与洞口同形：厚度也吸附到 callout 声明值，残差记账，超容差报红。
2. **`stroke_dimension_consistency` / `partition_on_window_jamb` 各 4 条 flag**：
   走廊墙的门洞 y 坐标与办公室窗的 y 坐标同源（都出自同一条 900/720 模数链）⇒ 重合是真的，不是描重了。
3. **房间类型未读**：本图没有印任何房间名标注（R-5 已登记，下一个 case 起由用户填）。
