# 项目协作约定

本文件是所有开发助手共同的项目级执行入口。用户在当前会话的新指令优先。
2026-09-08 起由 Codex 接手；旧 Claude 角色矩阵、批次硬门和本地 memory 不再覆盖本文。

## 开始工作

1. 读 [项目说明](AI_agent/README.md) 和 [当前计划](AI_agent/plan.md)。
2. 查看 `git status --short --branch`、`git worktree list` 和近期提交，确认实际代码位置。
3. 按本次任务读相关源码、技术参考和实验产物，不要求通读历史日志或清空旧债。

## 目标与范围

- 多模态输入生成可检查、可继续加工的轻量 BIM（用户称“丐版 BIM”），随后复用 IntakeOutput / IDF / EnergyPlus 链路。
- 两个近期输入方向：现有图纸及 case 输入；带表皮的外部体量。最终接入 CAD 等混合输入。
- 输入多少决定可支持的精度。缺信息时允许显式假设、默认值和简化分区，不能把推断写成实测。
- 先跑出一个能查看的真实 case，再按问题迭代。现有框架按需复用，也允许替换或删除不合目标的部分。
- 不以完善 harness、全覆盖测试、清空审阅台账或毫米级复刻为开工前置。
- 完整目标与协作边界见 [产品范围](AI_agent/project_scope.md)：通用轻量 BIM 为核心、EnergyPlus 为首个下游；我方主线是几何，物性由协作者负责。产品多 agent 的模型可配置，目标档模型从首批实验参与，运行上限为 Sonnet 级；开发模型另按 [使用约定](AI_agent/guides/model_usage.md)。

## 开发方式

- 当前助手可直接设计、修改、验证和提交，包括核心代码；不再强制派工、跨模型复审或模型家族阶梯。
- 默认单助手。需要并行时按用户授权开短期任务，明确文件边界；没有常驻施工/复核工作树。
- 单一主干 `main`。输入适配可以分模块、短分支，共享模型、几何内核和输出契约不各自复制一套。
- 常规改动只运行相关检查。改跨阶段接口时增加一个真实产物贯通检查；大范围内核/依赖变更再选全量。
- 同一份代码、同一验证范围已有通过结果就复用；不因交付、复核、收工等角色切换重复全量。
- 新测试只保护关键契约、几何有效性和实际出现过的缺陷；不为文档、可逆小改或实现细节加测试锁。
- 优先使用已建好的 CLI 和函数。脚手架若挡住真实用例，修最短路径，不再叠一层治理系统。
- 使用当前环境的 `python -m ...`；避免在短期树内用自动同步命令改共享环境。导入串树时查模块 `__file__`，不把哈希哨兵当日常工序。

## 保留的边界

- 不丢文件、不覆盖原始输入；每次实验独立 run 目录，记录输入、代码版本、运行命令和输出位置。
- 评测用 GT 不输入被评测的生成链。用 GT 喂内核的调试明确标作诊断，不宣传为识图或端到端成绩。
- 几何计算、坐标变换和装配优先用确定性代码；模型负责感知、语义和不完整信息下的判断。
- 统一单位、坐标系、方向和来源。容差/简化策略按任务用途显式配置，避免硬编码现有 case 答案。
- 不能为了跑通静默吞掉房间、窗或失败。输出模型同时呈现缺失、假设和未解决问题；仿真成功也不等于建筑正确。
- 不擅自改 GT 或人为签字记录来抬分；机器规整与修改设计事实分别记清来源。
- 凭据、`.env` 和含凭据的本地备份不提交或推送。普通测试保持离线，不意外调用计费模型。

## 项目记忆同步（所有助手适用）

- Codex、Claude 及其他助手的所有项目记忆都必须同步到仓库管理文档，不能只存在本地 memory、工具记忆或会话中，避免切模型后上下文不一致。
- 形成或更新项目记忆时，同次先更新对应文档：事实/进度/待办归 `AI_agent/plan.md`，约束与用户反馈归本文或指南，架构归 `AI_agent/architecture/`，历史决策与经验归 `AI_agent/decision_log.md` 或 `AI_agent/logs/`。
- 本地记忆只保留仓库文档索引；不维护另一份独立口径，也不等到收工才同步。发现旧记忆中有仓库缺失的项目内容时，补档并标明过期或未验证状态。
- 收工和切换模型前核对本轮是否仍有仅存于记忆/会话的项目内容；有则先补齐文档。凭据等敏感内容仍不写入管理文档。

## Git 授权与收工

用户已将本项目 Git 日常操作全权授权给助手：建/并/整理分支与 worktree、commit、正常 push、tag 和备份无需逐次确认。
正常开发以可回退的小提交推进。已共享历史不强推改写；不为清理直接丢弃未知改动。
本次存档和恢复方法见 [接手记录](AI_agent/logs/worklog/2026-09-08_takeover.md)。

用户说“收工”即执行，不再询问是否提交/推送：

1. 更新当前计划的完成项、实际卡点和下一步；口径/架构有变化则同步对应文档，移走过期状态，并按项目记忆同步规则补齐仅存于记忆/会话的内容。
2. 核对本轮验证结果与未验证范围。收工本身不触发全量测试。
3. 检查完整 diff/status，只提交属于本轮的改动；commit 并正常 push 当前交付分支，里程碑增加可回退 tag。
4. 收回已完成临时树。未完成工作先存档并写清去向，不把它伪装成完成成果。
5. 汇报提交、远端同步、测试、遗留问题和下次入口。失败就如实报告，不能声称已收工。

遇到有丢失风险的冲突、互相矛盾且无法判定的产品要求或新的外部权限障碍，停下用中文说明具体问题再确认。
技术细节可附链接，面向用户先讲影响与建议。详见 [开发与收工手册](AI_agent/guides/development.md)。
