**2026-08-21 落地**：`case_tests/test_baseline/reading_fixtures.json`（5 份好 + 9 份坏历史 reading）
+ `scripts/tool_scripts/reading_process_metrics.py`（过程指标 + 硬门，**不需要 gt / LLM / 跑抽**）。

**Why**：此前 `reading_regression.py` 比的是**分数**，而分数**要先花钱跑一抽才存在**
⇒「我加了一道门 / 改了一行脚手架，会不会伤到 reading」这个问题**只能用钱回答**。
这正是六周里 146 个文件的改动零信号累积、最后以一坨无法归因的失败呈现的机制。

**How to apply**：
- **新门的收录判据（唯一）**：**5 份好夹具必须全绿，且至少 1 份坏夹具必须变红。**
  全绿 = 没有分辨力（同族 [[neuter-proves-wiring-not-discriminating-power]]）；
  红了好夹具 = 对一份已知正确的 reading 的回归。
- ⭐ **这条判据第一个拦下的是 orchestrator 自己写的门**：我因误读 A2 产物写了个「窗被写成图像比例」
  检测器，实测在整个夹具集上一次不响 ⇒ 当场删掉。**没在真实夹具上响过的检查不许留。**
- **坏夹具也要写明「它是拿来标记哪个缺口的」**：B1/E1/G1 现在没有任何硬门抓得住，
  这不是缺陷是**已登记的覆盖缺口**，⛔ 不靠猜去补。
- 同一形状可复制到别的环节：任何「只能靠跑一次真链路才知道好坏」的地方，
  都该问「历史产物能不能冻成离线夹具」。相关 [[real-chain-run-exposes-what-tests-cannot]]。
