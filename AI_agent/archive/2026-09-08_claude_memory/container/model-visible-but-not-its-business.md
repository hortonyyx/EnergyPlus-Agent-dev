**2026-08-05 → 08-07 两天内，同一形状的缺陷现形六次**，全在「生产者接口」这条缝上：

| # | 缺陷 | 模型看见了什么它不该管的 |
|---|---|---|
| F-5 | 窗源字段名错拼（契约 `x_range_m` / 代码 `x_range`） | 消费侧字段名，四个测试的夹具照抄了实现的错拼写 |
| F-7 | `source_ids` 要 locator，而结构上没人产得出 | 要求一个它拿不到的标识 |
| F-9 | 立面笔画配对要模型心算镜像 | 未归一的裸局部坐标 |
| F-12 | prompt 命 LLM 重算墙顶点（`surface_specs` 明明给了） | 让它"重新推导"已经算好的几何 |
| F-15①| 内核专属字段 `facade_segments`/`facade_segment_id` 在 schema 里 | 模型照填，连 `source_footprint_fingerprint` 都编了 64 个 a 的假哈希 |
| F-15②| 门里**另外硬编码**一份禁止清单，与 schema 标记集**已经漂了** | 两份"该禁什么"的清单各自维护（F-5 形状升了一层）|

## ⭐ 固定形状（可当预测器用）

> **凡是「模型看得见但不该它管」的东西，最终都会被它填，然后靠事后拒绝纠正。
> 有效修法只有一种形态 —— 让它看不见，而不是告诉它别碰。**

**推论（已被实证）**：
- **prompt 不是防线** —— F-12 的正则锁被 GLM 用「换个说法但语义相同」的注入**实测绕过**（5 条全绿）。
- **盲重抽治不了系统性错** —— F-15 三次抽签同一个错；F-9 的错因是策略性的不是噪声。
- **事后拒绝 = 每次都要先错一次**，且若那道门抛的是**裸异常**（不带 `model_draw_error` 类别），
  连重试引导都拿不到 ⇒ F-15 实测**白烧 3 次里的 2 次**。

## 有效修法的两种形态

1. **结构上让它看不见**：给字段打标记 → **从给模型的 JSON Schema 里机械剥除**（F-15 修法）。
   ⛔ **不是**手维护一张禁止名单 —— 那正是 F-5 的成因。
2. **代码把它该算的算好、喂给它可比的数**：F-9 的 advisory 世界区间
   （⚠️ 但**必须标 advisory、绝不进强制路径**，否则交叉校验退化成同义反复 —— 见 [[lock-must-exercise-real-entry-point]]）。

## ⭐ 二阶纪律

**任何"该禁什么/该有什么"的清单，只要存在两份，就一定会漂。** 必须合成单一来源
（F-15 的做法：门遍历 schema 标记，而不是自己再抄一遍字段名），并配一条**双向属性锁**：
**取消标记则门必须停止拒绝 · 新加标记则门必须开始拒绝** —— 锁的是「门跟着标记走」这个性质，
不是某个字段名，将来任谁加门都漂不了。

## How to apply

**下轮建议（待用户拍板）**：不要再一堵堵推，**把整个生产者接口盘一遍** ——
一次性找出所有「模型看得见但不该管」的字段/语义。依据 = 六次全在同一条缝上。
