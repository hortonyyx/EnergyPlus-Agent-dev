2026-08-29 用户当面校准：我交了一份「gt 链 + pipeline 链」的梳理，把**现状**写成主体、
目标态压成一张小表。用户回：**「咱主要是关注目标态，现状本身就是施工中。」**

**Why**：现状每天都在变，写多了下一轮就过期（我那份里就有两处已过期的措辞是从别的文档抄来的）；
而**目标态是跨会话唯一稳定的东西**，也是用户真正要花时间检查的对象——他要核的是
「这个形态对不对」，不是「今天做到哪了」（后者他知道是施工中）。

**⭐ 关键：这条与 [[design-doc-described-what-code-never-implemented]] 不冲突，两条必须合起来用。**
那条的病根是**叙述比产物更合规**（写了没实现的形态还拿旧实现的数去证明它）。
解不是「少写目标态」，而是：

> **目标态当主体详写 · 每一格标状态（✅有代码+有接线+有产物 / 🟡有代码没接线 / ❌没有）·
> 每个状态都能指到 file:line 或实测目录 · 现状压成每部分末尾一张表。**

**How to apply**：
1. 梳理/说明类文档一律**目标态开篇**，现状**不单独成章**，只作状态列。
2. ⛔ 别把「现状差距」当文档的高潮章 —— 用户更要的是
   **「目标态里还悬着、需要你拍板的」**（阈值签字 / 没名字的参数 / 排期时点）。我改成这个之后才对味。
3. 状态标记只有三档，⛔ 不发明第四档；🟡 那档要写清**缺的是接线还是产物**
   （本项目实测：as-drawn 的产/门/判三件早就在 `src/` 了，缺的从来是**编排接线**，
   而两份权威文档还在写「`src/` 一行未动」）。
4. 引用别的文档里的现状描述前**先实测**——过期措辞会一路抄下去。
