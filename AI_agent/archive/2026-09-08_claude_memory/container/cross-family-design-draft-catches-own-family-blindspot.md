**跨家族出设计稿的价值，不在「换个人可能更聪明」，在于它不继承派工单里的错误前提。**

2026-08-10 F-20：orchestrator 写派工单时把岔口描成 **「有账本 / 无账本」二分**，
调查席（Claude 侧 Sonnet）**照题作答**，orchestrator 自己做轻门时**也没看出问题** ——
**同家族两道工序，同一个盲区。** 设计稿交 sol（GPT 侧）出，**第一轮就躲开两发雷**：

1. **「账本存在」不是二值事实** —— 有 V1/V2 两种 wire，V1 是 grandfathered legacy。
   实测盘上 **V1 账本 11 份 / V2 22 份**，而那个加载器第一件事就是对 V1 抛
   `v1 runs are legacy-only` ⇒ **按二分法施工会把 11 个今天还能被审的目录当场废掉**。
2. **新检查放哪一层是必须、不是整洁** —— approval digest **直接哈希整份 kernel report**
   ⇒ 往那份报告里加**任何**一行（哪怕 legacy 上一条无害的 `NOT_APPLICABLE`）
   ⇒ **盘上每个既有 run 的 digest 全变、所有历史批准一次性失效**。
   而调查报告建议的 check_id 正是放在那一层的。

**Why**：调查席拿到的是派工单，**派工单的错误前提会被原样继承**；
轻门方是派工单作者本人，**同一个盲区照不出自己**。跨家族出稿方**从产物读起、不继承那句话**。

**How to apply**：
- **设计稿一律跨家族出、原作者不写 v2**（08-09 第一例 = sol 判 orchestrator 亲手写的 F-9 稿 REWORK；
  本条是第二例、方向相反 = **我的题被出稿方纠正**）。见 [[whoever-writes-cannot-review-blind-spot]]。
- ⭐ **派工单里凡是描述「岔口 / 选项 / 分类」的句子，都要当成【可能错的前提】写**，
  并**明确邀请执行席证伪**（本单写了「§2 四条已核实事实**允许并欢迎证伪**」，
  但岔口那句没这么写 ⇒ 下次连岔口描述一起挂上证伪邀请）。
- ⭐ **判别问法**：**「我这句分类是二值的吗？盘上真的只有两种吗？」** ——
  本次两发雷都是「我以为是二值 / 我以为放哪都行」。
  与 [[stop-and-report-catches-dispatcher-errors]] 的「凡『一律/全部/共 N 处』发单前必须逐处列值对账」同族，
  只是这次错在**类别的个数**而不是**成员的值**。
- **orchestrator 该做的是机械测量**：本轮我关掉了出稿方自陈的一条未确定项
  （全仓 22 份 V2 账本逐个比 sha256 ⇒ DIFF=0），**但必须说准口径** ——
  测的是**今天的盘上语料**，不是「代码保证恒等」的不变量证明。见 [[neuter-proves-wiring-not-discriminating-power]]。

**派工方错误率 14/14**（本条漏检记 orchestrator 的账，施工席是照题作答）。

## ⭐⭐ 同日第三次兑现：跨家族**审施工**又抓出一条 MAJOR（这次是「遮蔽」）

同一批（F-20）里，sol 审 Claude 侧施工时抓出：**resolver 级 fail-open 无锁** ——
把 V2 加载器侧的「拒绝 ⇒ FAIL」改成「回退不受信的 stage-root 副本」
⇒ **69 项定向测试全绿、零锁捕获**（orchestrator 已独立复现）。
这正是设计稿最强调、派工单禁令第 2 条的那条规则。

**⛔ 根因不是「忘了写锁」，是【遮蔽】**：L2/L3 用 **v3 夹具** ⇒ fail-open 退回 stage-root 后，
那份 v3 几何**又被第二条防线**（`_resolve_legacy_stage_root` 自己的「v3 必须 FAIL」）拦住
⇒ 最终仍 FAIL ⇒ **锁照样绿**。

**⛔⛔ 最刺的一点**：**施工席自己在同批的另一处（NIT-1）发现过这个遮蔽模式**
（其 neuter 记录逐字写着「v3 夹具下被另一条独立防线掩盖、红不了 ⇒ 补 legacy-schema 变体才精确捕获」），
**却没有把它推广到 L2/L3/L8**；而**施工席与 orchestrator 共同签字**判过
「L2/L3/L8 已独立覆盖该防线、不需重复」——**两方都错。**

⇒ ⭐ **新判别问法（加进 neuter 清单）**：
**「我这个夹具里，有没有第二条防线会先于目标门把这个变异拦下？」**
若有 ⇒ **这把锁测的是那条防线，不是目标门**。
⇒ **凡在某一处发现了遮蔽，必须立刻横扫同批所有锁问同一遍** ——
局部修掉不够，遮蔽是**夹具形态**带来的，同形夹具处处都有。
与 [[neuter-proves-wiring-not-discriminating-power]]「变红 ≠ 有分辨力」同族，
但这条更狠：**红的是别人，你以为红的是自己。**

⛔ **同轮 orchestrator 自己也栽在 neuter 上两次**：① `/tmp` 副本漏拷 `data/` ⇒ 环境错被当成「10 条红」；
② 用正则匹配 `except ValueError` 块**打错了位点**（命中 NIT-1 那个而非 V2 加载器那个）⇒ 差点误判。
⇒ **neuter 必须先确认改动落到【目标那一处】，行号精确定位优于正则形状匹配。**
