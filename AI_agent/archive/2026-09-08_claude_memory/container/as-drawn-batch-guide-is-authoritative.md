## 指南里已经定死、⛔ 不要再问的

- **四刀分工**：量=代码 · **认=模型（在 reading）** · 对账=代码门 · 装配=correction
- ⭐⭐ **只判答案，不判过程** —— 「过程怎么提升可以产出更好的答案，这就是优化 harness 的工作」。
  ⛔ orchestrator 提的「判裁决对不对」已被否。
- **两个判分器都对着 gt**：出模方式一旦确定 gt 就派生确定答案。
  ⭐ **现有 6817 行判分器不扔，它就是 correction 判分器**；新写的是 reading 判分器。
- **correction 三拍循环**：代码算+列待裁决清单 → 模型逐条裁决+**总体把控** → 代码执行+复查。
  ⭐ 铁律 **模型出决定、代码出坐标**（保住不变量 #1）。
- **配对（哪两条线是一堵墙）= 模型认**，代码给候选 + 事后对账。
- **墙厚**：reading 观测层⛔无厚度字段；声明层只比字面；假设层带 `spacing_m` 观测量；吸附归 correction。
  ⚠️ **内墙厚度在 gt 里不存在**（R-6）⇒ 判分器判不了它，归出模专项。
- **验收**：先 sm25 完整跑一遍 → 历史校验尺度 = **新工具跑得通 + 降级显式**，⛔ 不要求历史 case 出分；本批⛔不降智力。

## ⭐⭐⭐ 2026-08-28 用户新定：**两把尺子各对着【一层】gt**

**reading 按【修正前】gt 判 · correction 按【修正后】gt 判 —— 两道工序各判各的**（判的仍然都是**结果**）。

- **「修正前」= 没有修改答案事实之前**（用户原话）⇒ 拿**未经手改的原始图**跑转换器的结果；
  ⭐ **转换器自己的量化/吸附/扩张【不算】改事实**，被排除的只有**人在管线之外动的那一刀**。
- **因果链**：我们自己画 CAD ⇒ DXF 与截屏图完整对应；但有肉眼看不出、标注也体现不了的微小画图误差
  ⇒ gt 侧主动修正成标准答案；而 pipeline 侧本来就有 correction 在吸附 ⇒ 能力够强就该产出与修正后一致的结果。
- ⭐ 它**取代**了跨家族对抗审给的「改名 / 建修订台账」二选一：
  修正前那层一旦是**活的判分参照**，就丢不掉，两层之差也随时算得出 ⇒ **白送一道「手改幅度上界」**。

⛔ **三条硬提醒**（全在指南里）：
① ⭐ **这两层的差本来就量不出来，而这是它的【性质】不是问题**（用户 08-28 纠偏：目的是**数据逻辑干净**，「本身就不太能遇到」；实测手改 0.2773 px vs 尺子噪声 0.85 px）⇒ ⛔ **别把「在某个 case 上验证有没有效」当准入条件**，也 ⛔ **别反过来拿「分数没变」当「没用」的证据**；碰到量得出来的那天再说；
② **修正前那层现在产不出来，卡点是【源图哈希门】不是几何**（`tarch_normalize.py:705` 直接 return 全空几何）
⇒ 它需要**自己的一份签字请求书**；且**原图跑不跑得通仍然未知**（从没走到 S0）；
③ 空分母是**静默**返回的（F-126），不管怎么拍都得先修。
