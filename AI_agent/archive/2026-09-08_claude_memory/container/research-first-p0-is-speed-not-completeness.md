**用户原话（2026-08-18 开工）**：
> 「P0 是快速迭代快速开发快速跑通，是作为一个**科研项目**推进的，
> 而不是一个产品每一步都要敬小慎微打很多补丁做很多围栏……
> **产品化和工程化的问题最后再来做，不需要每一步都考虑得特别完善周全。**」

**同日重申的唯一第一目标**：「**恢复 707 的水平，不要再大量做一些无关紧要的东西了。**」

**Why**：清点出来的数字自己会说话 —— 07-08 → 08-18 共 **41 天 / 35 次跑**，
08-13 起的 **25 次全部标注「诊断 / 非成绩 / 作废」**；同期 `guard.py` 长到 **1490 行**、
全仓 **2255 把锁**、测试 60845 行 : 源码 70601 行。**围栏在长，科研问题一步没动。**

**How to apply**：

1. **唯一判断法则**（要加防御 / 补边界 / 写锁 / 补审前必问）：
   > 「**不做这件事，下一次跑测能不能跑起来、结果能不能读？**」
   **能 ⇒ 登记进 plan.md，不做。** 不能 ⇒ 才做，**且只做到「能跑能读」为止**。
2. **三档口径，默认探索档**：探索（只记录不阻断 / 免审 / 免锁）· 工程（gate①+全量绿 / 同族自审 /
   只锁契约与几何不变量）· 成绩（全门+强隔离 / 跨家族 / 全）。**升档必须显式写进 run 的 README。**
   ⛔ **反向铁律 = 分档成立的唯一前提：探索档产物永远不得记成成绩。**
   放松防线之所以无害，正因为它产出的东西本来就不进成绩账。
3. **锁跟着契约走，不跟着脚手架走**：只锁交接契约 / 几何不变量 / 已经真咬过人的坑；
   围栏、隔离壳、诊断工具**不配锁**（天天改，配锁 = 每改一次重做一遍锁）。
   例外：锁**治理决定本身**（如「默认档 = observe」）值一把——静默回退会让下一抽重付摩擦且归因出错。
4. **主控可直接改**探索档脚手架 / 诊断工具 / `AI_agent/` 文档；
   **仍须派工换人审**：`src/agent/pipeline` 内核 / 交接契约 / `src/validator/`。
   ⇒ CLAUDE.md §5#8「凡实质改动一律走角色矩阵」按此收窄，[[whoever-writes-cannot-review-blind-spot]]
   只在后一类上仍成立。
5. **积压的审阅债先重分类再补**：13 笔按此法则降到 3 笔。
   **销账 ≠ 审过了，是「按新档位本来就不需要审」。**

**⛔ 不降档的四条**（便宜、且是根）：gt 铁律 · 收工 ritual · 用户拍板必须白话 · 几何/契约不变量。

**⛔ 我在这次拍板里犯的错**（值得单记）：用户给上位口径时，我第一反应是把它翻译成
「哪道护栏坏了」这种更窄的技术问题（见 [[lexical-guard-cannot-be-completed]]），
**而用户问的是「护栏该不该按产品标准建」**。⇒ **用户给的是口径时，别降维成技术诊断。**
