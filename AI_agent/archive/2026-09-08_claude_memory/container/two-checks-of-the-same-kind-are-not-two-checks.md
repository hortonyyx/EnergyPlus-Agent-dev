2026-09-07（第九程 · G-c 返工复核）。对照表要回答「还有哪些锁的存货被这次修复消灭了」。
施工方（Astra）用 token + AST **扫 `tests/` 源码字面**划外延；主控（我）不放心，
**独立**扫了一遍——**也是 token 扫源码字面**，得零缺口，判为「外延已被独立核实」。

⭐⭐⭐ **复核方（GLM）把这层拆穿了，而且是在自己的「最薄弱一处」里主动写的**：
两次扫描**是同一类方法**，因此**盲区完全重合**——本项目夹具普遍直接喂真实 facts，
一个 helper 若从真实产物取数，源码里只有 `view.face_lines` 这类字段访问、
**不会出现 `13AD`/`rev-`/`axis_snapped` 任何字样** ⇒ 静态扫描对这类锁**结构性失明**。
⇒ **一份含空转锁的对照表，会在「两个静态扫描一致」下双绿通过。**

**Why**：我把「换了个人做」当成了「换了一种验证」。独立性的载体是**方法族**，不是**执行者**。
两个人用同一把有盲区的尺子量同一个东西，得到一致读数，**只证明尺子一致，不证明量对了**
——这和 [[citing-someone-elses-fact-does-not-transfer-responsibility]] 是一体两面。

**How to apply**：
- 看到「A 独立核过、B 也独立核过、结论一致」，先问 **「这两次用的是同一类方法吗？」**
  同类 ⇒ 一致**不增加**置信度，只增加**盲区的一致性**。
- ⭐ 派工/复核单里写「请独立核实 X」时，**指定一个与已有方法【不同族】的走法**，
  ⛔ 不要只写「独立」二字——对方多半会挑最顺手的那条，而那常常就是你走过的那条。
- ⭐⭐ **本例给出的换族办法值得复用：静态扫描 → 运行时扰动探针。**
  把真实产物里**这次修复消灭掉的那个存货**临时改成哨兵值/删掉，跑一次全量，
  拿**变红集合**与对照表对账：**表外却变红 ⇒ 表漏了它**（间接读的直接证据）·
  **表内声称依赖却不变红 ⇒ 该锁的存货描述是错的**。它测的是**运行时真依赖**，
  恰好补上源码字面扫描的盲区。
  ⚠️ 局限要一起写：探针只暴露「对被扰动字段敏感」的读；**「读了但恒绿」的空转锁仍需逐锁变异**。
  ⇒ **完整解 = 扰动探针（管外延）+ 逐锁变异（管牙）**，两者缺一不可。
- ⛔ 反向也要防：别因为「换了族」就以为覆盖全了——换族解决的是**盲区不重合**，不是**覆盖完整**。
