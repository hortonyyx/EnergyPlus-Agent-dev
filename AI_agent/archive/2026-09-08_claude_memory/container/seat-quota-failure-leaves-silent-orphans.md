⛔⛔ **席位撞额度上限会留下【未提交的半成品】，而它的会话日志只字不提。**

**2026-09-02 一天两次实证**：GLM 撞 5 小时上限留下 **1035 行**（5 个文件）、
Claude 施工席撞月度上限留下 **1273 行**（3 个文件）——
**两次的日志都只有 2–3 行**，全是启动 warning 加那条额度错误。按日志读，"它什么都没做"。

**Why**：日志是**它自己写的叙述**，而工作树是**它留下的产物**——
[[self-report-more-compliant-than-artifact]] 的同族：**只看日志 = 只读自述**。
而这些半成品**未提交、未跑测、未过审**，留在树上会污染下一轮（被误当"已经做过了"）。

**How to apply**：
- ⛔⛔ **收到任何席位失败通知，第一件事永远是 `git status`（含它的 worktree）**，
  ⛔ 不许只看日志就下"它什么都没做"的结论。
- **处置三步**：① 移出工作树存进 `logs/experiments/` ② README 写死「**线索非证据**」
  ③ 主控点名可疑处但**不代判**；重派时写明「**重新实现**，复用任何一段须自己重新论证 + 补锁」。
- ⭐⭐ **配套解法（当天立、当天三次兑现）**：**派工单一律要求分段提交** ——
  每完成一个能独立成立的小步就 commit 一次，⛔ 不许攒到最后。
  立此条后的三次中断（会话结束 ×2 + 额度 ×1）**零丢失**，其中一次连复核裁决草案都保住了。
- ⚠️ 配套坑：我当时写 `... && echo "(空=没留下任何东西)"` —— 那是**无条件标签不是断言**，
  同族 [[stop-and-report-catches-dispatcher-errors]] 里记的那条。**要打印计数，别打印结论。**

## ⭐⭐ 附条（2026-09-03 用户当场纠正）：**席位报的「额度重置时间」不是容器的 UTC**

GLM 席位 429 原文写「限额将在 **2026-09-03 20:22:30** 重置」。
容器跑 **UTC**，我直接拿它减当前 UTC 时间，算出**要等 11.2 小时** ⇒ 判「今天没了，得改派」。
**用户当场纠正：等 3h10min 就行。** 差**整 8 小时** = **UTC+8**
—— 智谱是国内厂商，**那个时间戳是北京时间**。

**Why 这条贵**：8 小时的误差**直接翻转决策** —— 「等 3 小时后续上」 vs
「改派另一家族 / 今天这条线作废」是两种完全不同的排工。
而且它长得**完全像一个可信读数**（有年月日时分秒），⛔ 不会自己报错。

**How to apply**：
- 席位报的任何**绝对时间戳**，⛔ 别直接与容器 UTC 相减。**先问它是哪个时区的**：
  国内厂商（GLM/智谱、DeepSeek）默认按 **UTC+8** 读。
- ⭐ **判别签名 = 整 8 小时的差**。算出来的等待时间若比预期长得离谱，先试减 8h 看合不合理。
- 挂自动续跑时，**把换算写进命令里并打印出来核对**（`date -u -d "<北京时间> -8 hours"`），
  ⛔ 别只在脑子里换算。
