2026-08-23 → 08-30 的 gt 事实层线上，跨家族审**连续六轮各击穿一次**。
复盘后发现**六次是同一个病族**，而且**没有一次是「门算错了」**：

| 轮 | 被击穿的形态 | 门被骗了吗 |
|---|---|---|
| 一 | 一条线**两头读到、中间没读到**（挖掉中间 20%，分数逐位不动）| 没有 |
| 二 | **一个像素**把整段墙桥回满分 | 没有 |
| 五 | `band_collapse`：两线墙塌成一条带，**产物里没有一个假数**，却优于诚实产物、八门全绿 | 没有 |
| ②-1b-R | 换 `axis` / 换 `layer` **伪装成 `translate`**（数值巧合即可）| 没有 |
| ②-1b-T | **`case` 参数路径穿越** —— 一次完全合法的调用把未签字候选种进**答案根** | 没有 |
| **②-1b-T-R** | ⭐⭐⭐ **「公开面没有 Path」这个判断本身** —— 查的是 `import *` 面，而 Path 是从**返回类型**出去的 | 没有 |

**共同形状**：**门完好地量了它声称要量的那个量，而【载体】被移形了。**

⭐⭐⭐ **第六轮最值得记，因为被换掉的载体是【一个概念的定义】**：
docstring 声称「两个公开函数都不把 `Path` 交给调用方」⇒ 据此判定「拷目录这条路在 API 层不存在」。
实测 `write_facts_candidate` 的签名就是 `-> Path` 且 `return out_dir`
⇒ **全公开面、两行**就能把三件套拷进答案根，比它自己承认的「私有 helper 三行」还短。
上一轮复核方查「公开面」时只查了 `import *` / `__all__` 那一面，**没查返回类型**
——⭐ 复核方主动认账：「施工方照单施工，**处方本身有盲区，这是我方责任**」。

**Why**：判据的正确性一直被当成「算得对不对」来验，而**六次全部逃在「算什么」之外** ——
锚点、坐标系、分组键、目标目录、比较字段集、**以及「公开面」这类词各自的外延**。
这些都**不在**门自己的计算里，所以再怎么加严阈值、再怎么加重算，都碰不到它们
（[[threshold-hardening-is-not-recomputation]] 只解了一半）。

**How to apply（立任何一道门时，三问缺一不可）**：
1. **它量得准不准？**（老问题：能不能重算、公式有没有复刻生产者的定义）
2. ⭐ **它量的那个东西，能不能被换掉？** —— 逐条过：
   **锚在谁给的坐标/孔径上**（[[self-consistent-gates-anchor-on-product-chosen-apertures]]）·
   **比较的字段集漏没漏语义字段**（换轴/换图层那两次）·
   **目标路径/根目录能不能被参数改写**（路径穿越那次）· **分组键是谁定的** ·
   ⭐⭐ **判据里出现的每个名词，我用的外延和它的真实外延一样吗**（第六轮：「公开面」=`__all__` 还是 `__all__`+返回类型+抛出的对象？）
3. ⭐⭐⭐ **反过来查：哪个方向【没有】锁？然后问「为什么没有」。**
   第六轮的配套实测：读侧有锁（`…returns_typed_documents_never_a_path`），
   **写侧返回值零锁 —— 理由是「一写就会红」**。
   ⇒ **「加了就会红所以没加」不是缺锁，是缺陷本身在挡着锁**；
   这个空白比任何一条红都更能定位病灶（同族 [[gate-teeth-direction-follows-fixture-inventory]]、
   [[gate-with-only-negative-assertions-is-unobservable]]、[[absence-conflates-causes-in-observables]]）。
4. 写复核请求书时**明确要求对方「再找一种能骗过它的真实错误形态」** ——
   六次全是这么问出来的；⛔ 送审方自己挑的破坏方式挑不出自己的盲区。
   ⭐ 且**复核方自己的上一轮处方也要当【可能有盲区】重查** —— 第六轮就是这么找出来的。
5. ⛔ **别用词法锁去堵**（「源码里不许出现某个名字」）——
   [[lexical-guard-cannot-be-completed]]；有效解是**让那条路在类型/API 层不存在**，
   或**在出口全检**（复核方原话：出口全检，⛔ 不是入口收窄）。

⭐⭐⭐ **2026-09-02 又两例，且两例都是「跑通了」之后才现形的**：
① **模型不是配置点名的那个** —— 新加的 llm 配置节名叫 `correction_decision`，
而加载函数拼的是 `intake_<stage>` ⇒ 找不到 ⇒ **静默回落到别的节**。
「模型真的跑通了 186 秒」是真的，**但跑的不是那节配的模型**。
⭐ 更细一层：`route` 记的是**请求名的回显** ⇒ **它证明不了实际拿到谁**（代理量）；
修法 = 记**从加载后的 section 字典里读出来的** model_name。
② **坐标从正则认不出的通道进来** —— 无坐标 guard 是词法正则，成对形式**要求带小数点**
⇒ `(12, 34)` / `X = 12, Y = 34` / `[12, 34]` **五种写法漏三种**。
⭐ 有效解**不是补正则**（[[lexical-guard-cannot-be-completed]]），
而是**收窄成 `^[A-Z][A-Z_]*$` 的 code token —— 字符集里没有数字** ⇒ 任何进制的数都进不来，
即**让它在类型层装不进去**。

⭐⭐⭐ **同日第三例（判分侧）**：门把**两种性质不同的证据数进同一个数** ——
「独立可证的按阈值排除」与「producer 自写的台账」⇒ 加一个比例阈值既**误判诚实数据**、
又**放过正好相等的灌证**。解法同样是**类型层分离**（豁免凭据字段收成 `Literal` 单值
⇒ producer 自写的那种**结构上表达不成凭据**）。

⇒ ⭐ **三例共享一个正解形状：能让它在【类型层】装不进去，就别在【运行时】把它认出来。**

⚠️ **量这类东西时极易量错面** —— 我用**裸 dict** 喂那个运行时函数，三种写法**仍然放行**，
差点判「没搬、只是补了正则」；**从类型入口量才是全拦住**（那个正则已被显式降级为诊断）。
⇒ **「量错面」与「真漏掉」在读数上长得一模一样。**
