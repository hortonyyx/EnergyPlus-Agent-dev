**判据**：把一道门的**判断依据**从 A 换到 B（例：从「命令长什么样」换成「要跑的字节里有什么」），
**真正的工作量不在放开那一步，在搬家那一步**。
⇒ **逐一列出旧判据覆盖过的每一种形态，对每一种问：「新判据看得见它吗？」**

**2026-08-16 实例（EnergyPlus-Agent，撤 reading 沙箱的能力封口）**：判据从「命令行文本」搬到
「即将执行的代码文本」。我**搬了两次才搬对**，两次都是同一种漏：

1. 第一版只扫 `.py` ⇒ 跨家族审（sol）端到端复现
   `exec(Path('out/payload.txt').read_text())` —— **普通动态加载，不是混淆**。
   ⇒ **carrier 可以不是代码文件**。
2. 我补修时自己发现**连 `exec` 都不需要**：`.txt` 里放路径、干净脚本 `open` 两次。
   ⇒ **必须动「文件集合」，只加机制黑名单不够；两条要互相独立。**
3. 再复核时又证伪了自己写进复审请求书的一句主张（「纯斜杠豁免没放过任何真实路径」）：
   `os.walk('/')` **零禁词遍历整个文件系统**。
   ⇒ 共同形状 = **路径不是写出来的、是取出来的**（`os.sep` / `Path.home()` / `expanduser` /
   `os.environ`），而**词法扫描只能判断以文本出现的路径**。

**⇒ 可迁移的三个提问**：
- **carrier 问题**：新判据只看某一类文件/字段吗？**能承载同样东西的其他载体呢？**
- **机制 vs 载体**：我堵的是**机制**（`exec`）还是**载体**（那个文件）？**两者要各自成立、不互相依赖。**
- **写出来 vs 取出来**：判据靠「文本里出现」来认目标吗？那**不写出来、在运行时取到**的路子呢？

**⚠️ 连带纪律**：三条里**两条是审阅方/自己复核时才现形的，作者第一遍全没看见** ——
[[whoever-writes-cannot-review-blind-spot]] 又验证一次；
且请求书里主动写「派工方错误率 N/N，请证伪我」**当天兑现**（第一条 BLOCKER 就打在被点名处）。
同族 [[neuter-must-cover-wiring-not-just-mechanism]] · [[free-correctness-evaporates-when-representation-changes]]
（「加规范化时问『谁在拿变换前的形态跟它比』」——这条是它的反向：**换判据时问『旧判据看得见的，新判据还看得见吗』**）。

## ⛔⛔ 2026-08-16 晚：同一条缝**第三次**现形 ⇒ 结论从「补漏」升级为「词法扫描有结构性上限」

三次：① `os.walk('/')`（F-47）② 用 `.txt` 携带路径（F-46）
③ **`Path.cwd()` / `__file__` / `parents` 锚点族**（GLM 补审 BLOCKER-2，
**实测定位到本仓 gt.json 真实路径**）。

**⇒ 判据升级：这不是「再补一族词」能解决的。**
读图器的脚本**跑在 staging 里**，`Path.cwd()` 天然就是一个锚点 ——
只要允许它执行任意代码，**运行时可推导的路径集合就不可能被文本扫描穷举**。
**修法要么把判据搬到进程能力/文件系统那一层**（`setpriv` 降权 / 非 root 用户 / 只读挂载），
**要么明确承认边界只到某一档并写进威胁模型**。⛔ 别再加词表。

**⚠️ 环境会让「搬到 OS 层」也落空**：同日实测 —— 容器**全程 root**，
`chmod` 成 `r-xr-xr-x` 后 root **照样 append 成功**（root 绕过自己拥有文件的 DAC 检查）；
`chattr +i` 在 overlayfs 不可用。⇒ **搬判据之前先验新测量点在本环境真的有分辨力**，
否则只是把「带变量名的注释」从代码层挪到了权限位上。

**⚠️ 修法之间会互相封顶**：同日的 F-55 把审计日志挪到 staging 的兄弟目录，
防的正是「**写出来**的路径」⇒ **它的强度上限直接取决于这条锚点族关没关**。
判一个防线的强度，要连着看它依赖的那条判据。
