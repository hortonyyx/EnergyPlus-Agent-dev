**2026-08-06 orchestrator 实犯（本轮第二次框架性出错）**：把 `_sort_vertices_clockwise` 的「挪起笔点」写进派工单，断言它是「多余的那半」，让施工席砍掉。

**它不多余。** IDF 头部写着 `GlobalGeometryRules = UpperLeftCorner, Counterclockwise`，**EnergyPlus 信任这句声明**去推每面的 `~Width`/`~Height`（再喂外表面对流）。那段代码正是在让声明成为真的。

**砍掉后的观测**（全部为真，全部掩盖不了错误）：全仓 **2243 绿 / 0 红** · 漂移门 104→**0** · 端到端首次跑到 **`EnergyPlus Completed Successfully, 0 severe`**。
**而实测**（本地 EP，对账脚本自带「逐面面积与 EP 一致」自校验，三次均 115/115）：

| IDF | 声明 | 垂直面 判对/判错 |
|---|---|---|
| 老件（规范化还在） | `UpperLeftCorner` | **79 / 0** |
| 砍掉之后 | 同上 | **3 / 76** |

同一 IDF **只改这一个词**重跑 ⇒ csv **36% 数据格不同、最大相对差 100%**。

## ⭐ 新自检（硬规矩）

**删除一段「看起来多余」的规范化之前，先找出它在为哪一份对外契约服务。**
本例那份契约**就写在产物自己的头部，查一眼就能看到 —— 我没查。**
问法：**这段代码消失后，谁会因为「以为它还在」而算错？**（消费方常常在产物外部：仿真引擎、下游解析器、另一个团队的工具。）

## ⛔⛔ 2026-08-10 原样重犯一次（F-9 设计稿被判 REWORK 的 BLOCKER-3）⇒ 本条扩写两点

我在 F-9 治本设计稿里写：「确定性换算已存在，**源码逐字写着 `never authoritative`，
缺的只是让它当权威**」—— 把一个**警告标记**读成了「当初没人敢用」，并据此写进设计。

**它有明确原因，而且理由就在引入它的那次提交说明里，一句话。**
`99d9521` 写着「**B3 的同义反复风险已避开**：该区间标注为 advisory，**绝不进任何强制路径**」，
并当场登记了 `lo == 0` 只是假设。实证代价：advisory 给 `[11.36,13.76]`，权威给 `[11.24,13.64]` ⇒ **0.12 m**。

⇒ **扩写①：契约的承载物可以是【一个标记 / 一个 flag / 一句注释】，不限于代码。**
凡「这东西看起来多余／保守／可以放开」都适用本条，不只是「删代码」。
⇒ **扩写②：首选证据是【引入它的那次提交说明】，不是当前源码。**
`git log -S "<那句话>"` + `git blame` 是最便宜的一步，我这次跳过了。

**同型累计 2 次（08-06 砍规范化 · 08-10 提权 advisory 标记），两次都是交叉审／实测抓的
⇒ 这是我的系统性盲区，见 [[whoever-writes-cannot-review-blind-spot]]。**

## ⭐ 第二条：对账脚本本身必须先有自校验

用来判决的对账脚本**首版有解析 bug**（`FenestrationSurface:Detailed` 的 `Multiplier`/`Number of Vertices` 被「取末尾连续数字」的启发式吞进顶点，窗被算成 7.30m 宽）。
⇒ **对账脚本不先自校验，它只是另一个没被验证的断言。** 本例的自校验 = 用 EnergyPlus 自己报的逐面面积核对解析结果（115/115 才采信）。
⇒ 同族：[[lock-must-exercise-real-entry-point]]、[[neuter-must-cover-wiring-not-just-mechanism]]。

## ⭐ 第三条：判「是新引入还是老缺陷」，去跑历史产物

中途曾假设「EnergyPlus 会自己找那个角 ⇒ 属声明配对的老缺陷」。**拿 07-02 老 IDF 跑同一份对账（79/0）当场证伪。**
⇒ 与 [[two-kinds-of-latency-no-ruler-vs-never-reached]] 同一手法：**历史跑通产物 = 免费的回溯尺子。**

**How to apply**：门绿 + 引擎绿 + 全仓绿，**三绿齐了也不等于对**。问一句「我有没有量过这次产出的**物理量**本身」——本例只要量一面墙的宽高就穿了。
