**2026-08-11 orchestrator 实犯，自查照出。**

既有纪律（08-09 立）：**权威门的输出直接重定向到文件、退出码单独落一个只属于该命令的文件、
中间不接任何管道**（`| head` / `| tee` 会 SIGPIPE 连带打断 pytest，通知里的「退出码 0」是管道尾巴的）。

**本轮发现这条还不够**：

1. 第一次后台全量跑**根本没启起来**（我用 `nohup` 绕开了工具自带的后台通道，进程没起，
   却照样打印了「launched」）；
2. 第二次跑**复用了同一组文件名** ⇒ `.rc` 里躺着第一次残留的 `0`；
3. 我去读 `.rc` ⇒ 看到 `0` ⇒ **差一点把陈旧的退出码当成本轮权威门通过**。

**⭐ 照出它的判据（两条同时用）**：
- **`.rc` 的时间戳早于日志文件** ⇒ 它不属于这次跑；
- **日志里根本没有 `N passed` 汇总行** ⇒ 这次跑还没结束。

**How to apply**：
- **「只属于该命令」必须包含「不与上一次跑复用文件名」** —— 每次跑用带时间戳/序号的新文件名，
  或**跑之前先 `rm` 掉旧的 `.rc`**。
- ⭐ **判「跑完没有」看日志汇总行，不看 `.rc` 存不存在** ——
  与 08-10 那条互为反面：那次是「**`.rc` 缺失只说明没跑完**（判活要 `pgrep`）」，
  这次是「**`.rc` 存在也不说明是这一次跑的**」。
- ⛔ **不要用 `nohup` 绕开工具自带的后台通道** —— 进程可能根本没起，而你还收到一句「launched」。
  一律走工具的后台参数（它会在结束时真的通知你）。
- 同族：[[stop-and-report-catches-dispatcher-errors]] 里那条「**验收路径根本不经过被改的代码**」——
  都属于**观测通道本身不可信**，而不是被观测对象有问题。

## ⚠️ 2026-08-27 第 N 次现形（同一条，管道那半）

派 GLM 时写 `bash scripts/glm_code.sh ... 2>&1 | tail -120`，而启动器**没有可执行位**
（本项目已登记「登记不改」项）⇒ `Permission denied`；**退出码是 `tail` 的**
⇒ 系统报回 `exit 0`，看着像跑成功了。

⭐ **抓住它的不是退出码，是「裁决文件写出来了吗」这一问**（答：没有）。
⇒ **判跑完看【产物】或【汇总行】，⛔ 永远不看退出码**——这条上面早就写了，我又犯了一次。
修法：不经管道，`cmd > file 2>&1; echo "REAL_EXIT=$?"`。
