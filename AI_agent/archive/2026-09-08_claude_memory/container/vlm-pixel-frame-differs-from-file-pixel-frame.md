**2026-08-16 G2 跑测撞出（F-51），四条独立证据全部吻合。**

## 事实

读图器（Claude Haiku，看 `1f_view.png` = 2133×1345 ≈ 2.87 MP）自报的像素坐标，
系统性地是真实文件坐标的 **1/1.544**。而 `cv_probe` / `run_cv_probe.py` 读的是**原分辨率文件**。

| 证据 | 读图器 | 实测真值 | 比 |
|---|---|---|---|
| x 锚点 900px/15m | 60.00 px/m | 92.67 px/m | 1.544 |
| y 锚点 480px/8m | 60.00 px/m | 92.38 px/m | 1.540 |
| 自报「西墙 275–315px」 | ×1.544 = 425–486 | 西墙实测 426–431 | ✓ |
| 自报「东墙 1160–1200px」 | ×1.544 = 1791–1853 | 东墙实测 1811–1816 | ✓ |

2133/1.544 ≈ 1381、1345/1.544 ≈ 871 ⇒ **1381×871 ≈ 1.20 MP**，与「图片按总像素上限降采样」吻合。

## ⭐ 三个后果（每一个都单独具有欺骗性）

1. **标定自洽但整体错 54%** —— 结果长得完全正常，没有任何 warning。
2. **跨轴一致性门（C1）抓不到它** —— 两轴同比例偏移 ⇒ 相对偏差 0.000% ⇒ **门放行**。
   ⇒ **一致 ≠ 正确。门校的是内部一致性，不是与外部真值的一致性。**
3. **crop 落在错误区域 ⇒ 诚实的假阴性** —— 它按流程去 crop「东外墙」，
   切到的其实是建筑内部（实测该 crop 里是家具、没有外墙），于是如实写下
   「checked with detector, no openings found」。**流程对、坐标错、结论错、态度诚实。**

## ⛔ 它推翻了什么

「给了工具也不去量 / 量了也没用 ⇒ 是模型肯不肯的问题」——**不成立**。
本仓另有 [[verify-the-path-works-before-blaming-the-model]] 记的 F-49（工具直接调不通），
F-51 是它的下一层：**调通了，但两端不在同一个坐标系里。**

## ✅ 单变量实验已跑（同日，haiku，A×3 目测 / B×2 先调一次工具再答）

问同样四个数（四面外墙外皮的源图像素）。真值 west 426 / east 1816；降采样帧宽 ≈1381。

- **A（目测）**：12 个数字**全部落在降采样帧内**（最大 1259），跨度系统性偏小，
  且 **`west_x` 三抽 = 107 / 294 / 104（近 3 倍散布）**。
- **B（先调一次 `wall_line_profiler`）**：报出 **1888** —— **该值在降采样帧里不存在**
  ⇒ 只能来自源图帧；两抽**逐字节相同**。

⇒ **① 一次工具调用就把坐标系锚定回源图。② 但它只锚定坐标系、不锚定语义**
（B 取的是绿色尺寸引出线、不是墙面，反方向错 0.86×）。
**③ 计划外发现：目测坐标不仅错、而且不稳定；工具回读的坐标是确定性的。**

⚠️ **自我修正**：1.544 这个恒定倍数是**某一跑的性质**（两锚点用了同一套视觉缩放），
**不是普适常数** —— A 臂 x/y 比在 1.20–1.46 之间且逐抽不同。
普适说法只到：**目测像素被困在降采样帧内、系统性偏小、不稳定。**

## How to apply

- **凡是「模型报坐标 → 代码按坐标取像素」的接口，先问：这两端是同一个帧吗？**
  多模态模型看到的图几乎一定被缩放过，而文件没有。
- 修法方向（未施工）：工具在每份 sidecar 里回报**源图真实尺寸**；
  kickoff 明确告知「你目测的像素可能在缩放帧里，先用工具回报的尺寸校准自己」；
  或让接口收**归一化坐标**而不是绝对像素。
- 排查同类问题时，**用「比值是否在多个独立测量上恒定」来识别帧错位** ——
  单点偏差像是读错，**多点同比例偏差就是坐标系问题**。
