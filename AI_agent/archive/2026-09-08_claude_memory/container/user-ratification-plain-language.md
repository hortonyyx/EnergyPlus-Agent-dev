2026-07-10 用户明确反馈:"之后需要我拍的技术决策都需要用大白话说明,因为我人类没有代码上下文,你拿什么 E4(RW啥的)以及具体的代码变量名,我不知道啥意思。"

**Why**:用户是项目 owner 但不持有代码上下文;拍板请求里塞内部代号(E4/B-O)、变量名(north_axis)、缩写选项(R/W)等于让用户盲签,拍板质量和信任都受损。

**How to apply**:凡面向用户的拍板请求,必须按四段讲:① 背景(我们在干什么)② 问题(撞上了什么)③ 每个选项的**后果**(选了会发生什么、代价是什么)④ 推荐+理由。代号/技术细节放链接或括号供查,不作叙述主体。审阅产物/判卷等技术层文档照旧。已落 CLAUDE.md §5#13。同族先例=[[c2-full-unlock-sprint]] 里的"C2 白话对齐"(用户要建底图)。
