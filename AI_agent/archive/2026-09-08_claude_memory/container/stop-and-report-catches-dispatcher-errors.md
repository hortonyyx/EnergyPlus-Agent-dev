**How to apply**：
1. **派工前的核实义务扩到工作基点本身**：worktree 从哪个 commit 切的 · 派工单文件在不在那个树里 ·
   施工席的 cwd 会落在哪 · 并行席位是否共享同一棵树。派工单里把这些写成可自检的三条，让它开工前先对。
2. **⛔ 不要用 `isolation: "worktree"` 的默认基点**（会从 `origin/<default>` 切）。
   手工 `git worktree add <path> -b <branch> <sha>` 并把未提交的派工单 `cp` 进去。
   基点不对时用 `git merge --ff-only`，**⛔ 不用 `reset --hard`**（CLAUDE.md §5#7 明令禁止）。
3. **⭐ 在派工单里如实登记自己的错误率是有防御价值的，不只是记账**：Sonnet 拒绝自行 `reset --hard` 凑基点，
   引用的理由正是派工单自陈的「派工方本轮已出错四次」—— 而 `reset --hard` 恰好是本项目禁令。
   **写下自己的错误率，会让施工席在该停的地方停住。**
4. 「停下上报」在本项目**记功不记过**，这条要写进每份派工单。
5. **⭐ 写「行为锁」类验收条件前，必须先读那段策略/判定代码，确认要求的行为差异真的存在。**
   ⛔ 不许从「这个参数没传进去 ⇒ 一定有行为差异」反推 —— 参数可能压根不参与该类 check 的判定。
   自检问法：**这个差异，我在代码里指得出是哪一行产生的吗？**
6. **⭐ 发单前把验收条件并排读一遍，问「它们能同时成立吗」** —— 08-06 第 10 次就栽在
   「0 红」与「会有 3 条已知红」写在同一份单子里。**这条我写下过一次却没执行，所以要机械化：
   发单前最后一步 = 把所有数字型验收条件抄到一起对账。**
7. **⭐ 区分「现象」与「归因」**：把自己的复现结果写进派工单时，标明**哪些是实测数字、
   哪些是我对成因的推断**。08-06 第 9 次就是把「干净 worktree 红 5 条」（现象，含环境假象）
   当成「5 条都因 gitignore 而红」（归因）发了出去。
   ⇒ 与 [[real-chain-run-exposes-what-tests-cannot]] 的 F-8 同源：**「红/绿」是这台机器的属性，
   归因必须另外证明。**
8. **⭐⭐ 写验收路径前先问「这条路径真的会经过我改的那段代码吗」**。
   **冻结产物 + 跳段入口（`--intake-from` 一类）= 天然的假验证温床。**
   机械做法：在派工单**第一步**写一条**防假验证自检**（例：新产物里某个可判定的规范特征必须成立，
   不成立就停下上报），⛔ 不要等跑完再回头怀疑。与 [[dont-delete-normalization-without-finding-its-contract]] 并列。

9. **⭐⭐ 说「这 N 处同形、一律照同一种改法」之前，必须逐处把值读出来**。
   名字同形（`_*_BLOCK_PROFILES`）**不等于**语义同形：`{"golden","regression"}` 是按档位分级，
   `frozenset()` 是永久 advisory，**同一个"翻转"动作对两者的后果相反**。
   自检问法（与第 5 条同源，但作用在**批量指令**上）：
   **我说的「同形」，是形状同还是那一行约束的东西同？我把每一处的值都读过了吗？**
   ⇒ 凡是「一律 / 全部 / 共 N 处」这类批量措辞，**发单前必须逐处列值对账**。

10. **⭐⭐⭐ 2026-08-12 第 14、15 次（都是 sol 抓、都是 orchestrator 的题错）⇒ 两条新纪律**：
   - **第 14 次**：判卷拿 `schema_version=="3"` 当「坐标在外皮框」的证据，我的请求书把 fail-closed 路径
     分成「缺失/None/解析失败/未知版本」四类 —— **穷举的全是「身份不合法」的形态，漏掉「身份合法但过时」**。
     详 [[version-number-is-not-behavior-attestation]]。
   - **⭐ 第 15 次 = 新类别「否定式结构断言未经实测」**：我在请求书里写
     「某错误码**没有 mutual-nearest 就结构上不可能触发**」并拿它当论据。**sol 实测出两条真实触发路径。**
     **我的结论对（该功能确属本步），但三条论据里有一条是假的。**
     ⇒ **判别问法：「我说『X 不可能发生』，我去触发过 X 吗？」**
     ⛔ 否定式的结构断言**只能靠实测**，不能靠读代码推断 —— 这正是我整天在要求施工席做的事。
     ⇒ 与 [[absence-conflates-causes-in-observables]] 同源：**「不可能」和「没看见」都不是证据。**

11. **⛔⛔ 2026-08-12 发现的【规矩本身的缺陷】：「发现前提错就停」连续两轮把整批主体挡在审阅之外。**
   sol 两轮都在**外围论据**上停下，裁决书自己写着「这项前提错误**不改变**范围裁定」——
   它知道那条错是外围的，**但我的硬规矩逼它停**。代价 = BLOCKER 修法 + 三摊 + 上轮 7 条 finding
   **两轮下来一次都没被真正审过**。
   ⇒ **规矩必须分层写进派工单**：
   **① 承重前提错（错了则整个任务方向作废）⇒ 停下上报；
   ② 外围论据/支撑证据错（错了不改变任务方向）⇒ 【报告并继续审其余】。**
   ⛔ 不许再写成无差别的「发现前提错就停」。

## ⭐⭐⭐ 2026-08-29 一天内又三次（13/14/15），并由此得到**唯一一条机械自查法**

三次都在同一条线（gt 事实层三截）上，**施工席三次都如实报差异而不是凑数通过**：

- **⑬ 验收项与本单【自己的任务项】互斥**：②-1b 验收 1 要求「`as_measured` 的 `content_sha256` 与 ②-1a **逐位相同**」，
  而同一份单子的 **R3 要求给 `AsMeasuredV1` 加一个必填的指纹字段** ⇒ **schema 变了哈希必然变**。
- **⑭ 验收项要求做一件本单【自己禁止】的事**：②-1b-S 验收 6 要求
  `verify_raw_layer_reproduction("sm25-L_anchor")` 变成 `implementation_drift`，
  而同一份单子明令 **⛔ 不许动豁免逻辑** —— 而那份恰恰是豁免让它 `recorded == recorded` **恒真**的一份

## ⭐ 同程另一条：**我写了标签，没写断言**

还原孤儿 worktree 时我跑
`git checkout -- <file> && git reset -q && git status --porcelain && echo "(空 = 已还原)"`
—— `git status` **打印了 ` M <file>`**，而我的 `echo` **无条件**跟在后面打印「(空 = 已还原)」。
两个错叠在一起：① `git checkout -- <file>` 是**从 index 恢复**，而 index 里正是要丢弃的那版
（正解 `git checkout HEAD -- <file>`）；② **我给输出贴了一个标签，而不是断言它**。
⇒ 同族 [[absent-file-read-as-passing-check]]（`grep … || echo 通过`）。
**纪律：验收行要写成 `[ -z "$st" ] && echo ✅ || { echo ⛔; exit 1; }`，⛔ 不写无条件的结论 echo。**
