2026-09-07（第九程）。我向用户汇报「一体改本体一行没动、卡在 sol 那 6 条阻断」，
依据是 **plan.md 的 `⏭ / 🔶 / ⛔ 未做` 标记**。用户顶了一句「**一体改还没动吗？跑不了吗？你查一下呢**」。

**一查，盘面全错**（逐条证据 → `AI_agent/logs/experiments/2026-09-07f_plan_reality_audit/`）：
- sol 六条阻断**只剩 1 条真没做**（②③④⑤⑥ 全已落地；② 是**换了名字**落在 `AsMeasured*V1` 家族，
  所以 `grep ReferenceFactsV1` 零命中 ⇒ **按旧名字搜会得出「没做」的错误结论**）；
- **②-1 整个包完整落地**，而活表写着「⛔⛔ 现在不能开工」；
- 两个标「⛔ 未过审」的提交，`git merge-base --is-ancestor` 一验**早在主线祖先里**；
- 「as-drawn 产物喂不进 correction、零接线」是 **08-25 的旧状态**，早已接线；
- ⭐ 而且它**用真模型端到端跑通过一次**（09-02，185.8s/2 轮/success）。

**Why**：文档滞后是**单向**的 —— 代码往前跑、没人回来销账，所以**产物总比叙述更完备**。
这与 [[design-doc-described-what-code-never-implemented]] 的方向**正好相反**（那条是叙述比产物更合规），
而后果更贵：**拿旧题面去派工 = 让席位去修早就修好的东西**，还会把「真缺口」挡在视线外。
本例的真缺口根本不在实现，在**生产入口没接线**（`flow` CLI 与 `run_pipeline` 仍走 legacy 腿）。

**How to apply**：
- ⭐⭐⭐ **换会话 / 换主控后的第一件事，是【抽查活表】，⛔ 不是照着活表派工。**
- ⭐ 判别问法：文档里每条 `⏭ / 🔶 / ⛔ 未做`，问
  **「这条我最后一次【拿代码】验它是什么时候？」** 答不上来 ⇒ 它是**印象**不是**状态**。
- ⭐⭐ **按名字搜会漏**：概念常以另一个名字落地（`ReferenceFactsV1` → `AsMeasured*V1`）。
  验一条「有没有做」要搜**它承担的职责**（字段/函数/枚举值），⛔ 不只搜设计稿里那个名字。
  同族 [[grep-zero-hits-conflates-unused-with-nonexistent]]。
- ⭐ 「已交件·未过审」这类状态，**一条 `git merge-base --is-ancestor <sha> HEAD` 就能验**，⛔ 别凭记忆。
- ⭐ 汇报状态给用户前，先分清哪几条是**我刚验过的**、哪几条是**读文档得来的**，并把后者标出来。
