**2026-07-26 用户提议 + 主控修订后确立**（用户原话「每次收工跑一次全仓就行，过程中只跑受影响的」）：

| 时机 | 跑什么 |
|---|---|
| 施工方中间轮 | 只跑受影响子集（**由 `scripts/tool_scripts/affected_tests.py` 算，不许自由裁量**） |
| **施工方交付前** | **全仓一次，原始输出进执行日志** |
| **主控轻门** | **独立全量复跑** |

**Why**：用户提的「每天/收工一次」被主控改为「**每个交付边界一次**」——省掉施工方交付前那次全仓，回归要等主控轻门才暴露，等于多一次跨家族返工往返，比跑测试贵得多；而主控轻门的独立全量是项目里的**唯一权威门**（B5 Phase C 靠它抓出 6 个施工方自查全绿的越界回归），不可削。所以是**一批活跑两次全仓**，不是每轮都跑。

**How to apply**：派工单里写明这三档；施工方在执行日志贴工具输出的「跑测声明」行。主控轻门永远跑默认 `pytest -q`（**不加 `-m` 过滤**，否则漏掉变异矩阵那类 marker 测试）。

**✅ 提速批已落地（2026-07-26，terra 施工 / GLM 验证性审 / 主控轻门）**：
- 全仓**默认并行**（`addopts = -n auto --dist load`，pytest-xdist）：**1135s → 256s（16 核，4.4x）**；串行留 `-n0`（单文件调试更快：3s vs 9s，worker 启动约 6 秒固定开销）。
- **`--dist loadfile` 禁用**（25 格变异矩阵会压到同一 worker、提速报废）；**嵌套子 pytest 必须显式 `-n0`**（否则继承 `-n auto` → 25×16 压死机器）。
- **验收方式硬口径**：串行 1 次 + 并行 2 次的 `-q -rA` 输出各抽节点行排序去重、两两 `diff` 必空。**只对计数不算过**。
- **并行暴露两处既有隔离缺陷（都是真 bug，不是 xdist 的错）**：① E4 e2e 把仓库内固定 idf 直接喂 EnergyPlus，而 EP 会在**输入文件旁**建临时 `in.idf` → 多 worker 撞同一路径（修法=输入拷进 tmp）；② `test_mcp_stdio` 用 10 秒硬超时当断言，满载机器启动就超（主控授权放宽到 120 秒，两条语义断言未动）。**教训写进 [[artifacts-into-repo-not-tmp]] 邻域：测试不许往仓库固定路径写、也不许把仓库固定文件喂给会在其目录旁建临时文件的外部程序；紧超时不能当断言。**
- 受影响子集工具 = 静态 AST import 边（含相对导入）+ **字符串路径边**（捕获 subprocess 调脚本的无 import 耦合）传递闭包；一等公民含**仓库根 top-level `*.py`**（漏了它就漏选 `test_mcp_stdio`↔`src/mcp/server.py`，主控轻门抓到过）；fail-closed 五条一律回落全仓；`uncovered_allowlist` 被双向门卡死（实算未覆盖集合必须与清单严格相等）。

**✅ 全批 CLOSED 收口（`bb6d509`·1656→1671 绿 + 10 xfail·主控轻门 r2 实测 4:34）**：
- **GLM 审 = APPROVE-WITH-CHANGES**（19 命题 18 成立）；唯一 MAJOR = **施工方越界改 `AI_agent/guides/`** ⇒ 主控收回文件主权、亲自复核并把两处过乐观耗时改成实测区间（全仓 **4.5–8 分钟**〔空机 4:21〕/ 串行 **15–26 分钟**）。**派工单写「不改 `AI_agent/**`」时要顺带提醒执行档：成果文档化也归主控。**
- **主控轻门 r1 抓 3 条（GLM 与施工方均未报）**，最值钱那条 = **环境依赖弱锁**：`changed_since("HEAD") == []` 只因工作树恰好脏才承重，一 commit 即退化为永真断言（`git diff --name-only HEAD`=6 / `HEAD...HEAD`=0）⇒ **审锁时要问「换个环境它还红不红」**；修法=锁自造证据（tmp 里 `git init` + 一个已提交 + 一个未提交改动）。另两条：子集命令吐非测试 helper（且它同时是全仓触发器＝口径矛盾）、死码噪音。
- **字符串边加方向约束**（目标在 `tests/` 下的边仅当来源也在 `tests/` 下才传递）⇒ 掐掉「生产模块文档字符串里提到测试文件」形成的伪桥：`cv_probe` 子集 **87→3**、`judge/gt.py` **87→29**。
- **⚠️ 但 `src/agent/**` 枢纽子集仍≈全仓**（`pipeline.py` 85/93）：根因 = **`src/agent/__init__.py` 首行 `from src.agent.graph import build_graph`**，import 任何 `src.agent.*` 都拉进整张下游图 ⇒ **依赖团是真的、工具没保守过头**；改惰性＝唯一杠杆（顺带压 import 开销），**登记跟进债、生产码改动需独立立项**。函数体内 import 也算边（AST 不区分）＝宁多跑不漏跑。
- **纪律新增（已进 §7.5）**：**验锁的临时 neuter 只在 `/tmp` 副本做**，不许在工作树改了再还原——本批 GLM 在工作树 neuter 与主控轻门撞时间窗（主控快照到被改状态、md5 与其裁决书声称不符；两分钟后复核已还原、md5 逐字符一致 ⇒ **别急着定性别人造假，先复核一次**）。

## ⭐ 2026-08-05 新增第四档：**真链路（端到端）跑测** —— 用户拍板制

**缘起（硬证据）**：最后一次跑通 EP 是 **`run_2026-07-02_sonnet_flow_e2e`**；此后 **114 个提交动过 `src/`**
（`run_stage.py` 35 次 · `isolation.py` 16 次 · `window_sources.py` 4 次），**一次真实端到端都没跑过**。
2026-08-05 拿一份已知满分的历史 reading 产物跑「下游烟测」，**一次撞出 6 条工程缺陷**，
而当时全仓 **2177 绿零红** —— **单测一条都没抓到**。详 [[real-chain-run-exposes-what-tests-cannot]]。

**病根不是「某一批没做干净」**：六条分布在至少三批里（B5/C2 · 硬隔离批 · 更早的 pipeline）。
每一批**内部**都有锁 / neuter / 跨家族对抗审，**坏的是批与批之间的接缝** ——
**每批的夹具都在「模拟邻居」，而不是用邻居的真实产物**（F-5 就是夹具把邻居的字段名抄错了，实现与夹具一起错、永远绿）。

**⭐ 用户 2026-08-05 定的口径（原话）**：
> 「**不用每一次提交都跑全链路，你觉得需要跑全链路的时候跟我提一嘴，我拍板跑。**
>  平时改动比如只动某一个环节的，可以就只跑影响的这一个环节测试一下，**大节点再全链路跑**。」

⇒ **四档表**：

| 时机 | 跑什么 |
|---|---|
| 施工方中间轮 | 受影响子集（脚本算） |
| 施工方交付前 | 全仓一次 |
| 主控轻门 | 独立全量（唯一权威**单测**门） |
| **大节点 / 主控提议 + 用户拍板** | **真链路**（冻结好 reading → `flow --judge off --with-ep`） |

**主控该在什么时候「提一嘴」**（建议触发面，供拍板参考）：
1. 动了**跨段接缝**：产物契约/字段名、产物落盘位置或形状、accept/记录契约、段间读写点
   （`isolation.merge` · `window_sources` · `run_stage` 的 draw/accept 路径 · `output_coordinates` 的 loader）；
2. 动了 **LLM 段的 prompt / schema / 校验**（1_correction · 4_mep）——今晚证明这类最容易「模型产出不合规 ⇒ 整链死」；
3. **批次收官前**（大节点）；
4. **距上次真链路已积压很多提交**（今晚是 114 个）。

**不需要提**：单段内部算法、判卷层、文档、测试本身、gate① 检查项内部逻辑（除非改的是它的**阻断档位语义**）。
