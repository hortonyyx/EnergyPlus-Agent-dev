**关键事实/约束（非显然，动手前必读）**：
- **天正活对象普通另存 DXF 后 ezdxf 仍读不了几何（2026-06-20 sm21 实测定论）**：TCH_WALL/TCH_OPENING 等专有对象→`DXFTagStorage`,ezdxf **能读层(WALL/WINDOW)、读不了几何**,**proxy-graphics 解码实测返回空**→"直接吸收"行不通。**既定前置=一次「图形导出」**(命令 TXDC/文件布图→图形导出),把 TCH 变纯 LINE/INSERT、保留语义层+图名。实测导出版 `SM_21_t3.dxf`: proxy=0/WALL 216 线/WINDOW 29 块/E_WINDOW 18/**PUB_DIM 165 DIMENSION(精确尺寸)**/6 图名/6 视图区全聚出/块名带语义(`$TCHSYS$WIN2D`×15=正好 15 窗、`$DorLib2D$`×14=门)。inspector 已能安全读 TCH 层(`_layer` 回退扫 code 8)+报 custom_objects+给图形导出建议。SAVEAS 直读仅非天正/已炸开文件成立。
- 用户的 CAD 是**一份合并文件**（平面+立面同一文件，2 平面在上+4 立面在下），**图层按构件类型分**（天正图层标准），**不按平面/立面分** → 不能靠图层分视图，必须**先空间聚类切视图区再按层认构件**。**真文件无图名**(用户 2026-06-20 截图确认)→视图命名三档:①图名文字(若有,最稳) ②per-case 布局 manifest(零改图) ③几何启发式;sm21 几何可识别(平面在上有内墙+家具+门、立面在下;N-S 宽=footprint W·E-W=窄 8m;南·西带入口门、北·东无门;F1 平面有外门洞 F2 无;窗数对 gt)→②/③可定。建议用户写**纯文字**图名(别用天正"图名标注"专有对象)或给布局确认。
- **逐 case bundle（用户 2026-06-20 定）+ 纪律**：一个 case 的 gt 内容放一起 `gt/<case>/`={`gt.json`(答案)+`source.dxf`(图形导出后的 CAD)+`renders/`}。已迁移:`gt/sm21_anchor/{gt.json,source.dxf,renders/gt_plan.png,gt_elev.png}`;loader `gt_path` 改 `gt_dir/case/gt.json`、render_gt 输出改 `<case>/renders/gt_{plan,elev}.png`(260 测绿)。**与 Codex H1 调和**(他要源 DXF 放 gt 根外防 rglob,用户要逐 case 聚拢):靠①`load_gt` 只读 `gt/<case>/gt.json` 单文件不 rglob ②真边界=source.dxf 绝不进 case_data(执行器读到=作弊),由文件系统隔离测试守——非靠分目录。绑定靠机械指纹(cad/png sha256)。

**归一化（用户 2026-06-20 问）**：分两个消费者——**gt(内部评测)源格式我们说了算→不需归一化层,一个天正适配器够**;**CAD 输入模态(产品,真实用户任意 CAD)才需要**。模态架构=各方言适配器→一个 canonical 几何 IR(=0_reading 图片识别产出的同一目标),下游对来源无感。语义富(天正/ACA 对象自带类型)=确定性适配器;语义贫(纯线条/手画)=类型靠几何推断,**退化成"识别"、与图片管线同构→复用识别栈不另造**。现在不全建:只建天正适配器,但把 canonical IR 边界先定死(避免被天正锁死),真实 case 出一个加一个。详见方案 §10。
