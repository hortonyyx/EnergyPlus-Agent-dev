2026-08-26 用户当场纠偏：「整个 reading 和 correction 流程都变了……**一体化改造完之后都用新的就行了**，
为什么要执着用旧的 sm25 跑通？」
⇒ 我把返工包的验收判据锚在**即将作废的旧产物**上，逼得施工方花三轮去试「在输入侧中和那个偏差」，
三次都被真实 validator 拒绝，**全废**。

**Why:** 缺陷登记表把两类东西混在一起了——**代码的属性**与**某一份产物的读数**。
后者会随产物形态一起消失，给它排期 = 给废弃物修 bug。而两者在登记表里长得一模一样。

**How to apply:** 每条缺陷登记问一句 —— **「换一份产物，这条结论还在吗？」**
- **在** ⇒ 代码侧，照常排期（例：顶点规范化毁凹多边形、跨层碎片无守卫、判分对浮点末位敏感）。
- **不在** ⇒ 产物侧观察，**挂起，⛔ 不占工期**（例：某份产物 `facade_segments=0`、`polygon` 全 null、
  立面段与 gt 差 0.12 m）。
- ⚠️ **能力 ≠ 读数**：「cell 多边形全 null」是产物读数（挂起），但「correction 得能产多边形 cell」
  是能力目标（在范围内）。我把这两个混成一条，被用户当场分开。
