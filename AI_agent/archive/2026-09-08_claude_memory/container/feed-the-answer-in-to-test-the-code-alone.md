2026-08-25 用户提：「能不能直接捏一份答案出来从 correction 之后走？我还是想看看几何内核那部分有没有问题，反正这个不计入跑测。」
⇒ **这是一把独立的第三把尺子**，与 [[two-rulers-answer-side-and-source-side]] 的两把互补：
那两把都在问「产物对不对」，这一把问「**给正确输入，代码自己会不会出错**」。

**为什么它能撞出别的方式撞不到的东西**（实测）：真实产物往往**没有行使**下游的某些能力
—— sm25 现有产物 38 个房间的 `polygon` 全是 `null`（全矩形 bbox），
而答案里有 14 个真多边形、含一条 14 顶点凹形走廊
⇒ **多边形这条代码路径从落地起一个月没被真正走过一次**，缺陷就一直躺着。
一喂答案就撞出两条（顶点规范化毁凹多边形 · 跨层切分碎片无守卫）。

**How to apply**：
1. **⛔ 铁律：产物永不作成绩** —— 答案在输入里，任何"对答案"的分数都是同义反复。挂牌写死。
2. ⭐ **走真实生产路径，⛔ 不伪造信任根**。撞到证据链门（如"每扇窗必须引用识图观测"）时，
   正解是**骨架取答案、证据引用取真实产物**，⛔ 不是伪造那套互绑 sha256 的证书 —— 伪造了整个探针就没意义了。
3. **先做零成本侦察**：先拿真实产物喂一遍下游，确认"卡点不在这儿"，顺便量出**它没行使哪些能力**
   —— 那个空白正是答案输入要去撞的地方。
4. **配判别实验**：撞到现象后只改一个量做三四点对照（我做了 0.0604 / 0.0600 / 0.20 / 0），
   把触发条件夹死，⛔ 别拿单点现象下结论。
5. **诚实分离主因与加重因子**：我最初想写"吸附挪错方向造成碎片"，但 0.06 本来就低于下限、不挪也出碎片
   ⇒ 主因是"跨层碎片无守卫"，挪错方向只是加重。

**Why**：用户当时的原话点破了本质 ——「反正这个不计入跑测」。**放弃计分，换来的是把变量隔离干净。**
