**2026-08-16 晚，一次跑测把两轮已写进管理文档的结论推翻了一半。**

## 事实

隔离沙箱里 `px_m_calibrator`（**像素→米的唯一出厂工具**）的两种**被文档写出来的**调用形态
**全都跑不通**：`anchors_json` 被放进 wrapper 的 `PATH_KEYS`
⇒ 内联 JSON 字符串被 `_resolve()` 拼上 staging 根路径（argparse 拒）、
JSON 数组撞 `must be a path string`。**唯一可用的「先写成文件再传路径」没有任何文档写过。**
（F-49；wrapper 自 `df6f249` / 07-08 落地，⇒ **隔离形态下这把尺子从没被成功调用过**；
三份好 reading 全在 wrapper 之前、走 `cv_probe.py` 直调。）

## 被推翻的两条归因（都是我写的）

- 08-16 上半场 E1：「能力给了、用了、**零次用于测量** ⇒ 剩下的解释不在能不能，在**肯不肯 / 知不知道该量**」。
  回查 access_log：它**先试了出厂工具 4 次**，试不通**才**改写硬编码坐标的自制脚本。
  ⇒ 它**知道该量、也去量了**。
- 更早的整条「模型不去量图」叙事，至少在隔离抽这一侧，都站在一把坏尺子上。

## ⭐ 判据

**判一个「模型不肯 / 不会 / 不想做 X」的结论之前，先自己把做 X 的那条路走一遍。**
特别是当 X 依赖一个**我们自己提供的工具**时 —— 工具坏掉的表现和「模型不用它」的表现
**在产物上完全一样**（都是「没有测量证据」），只有**过程日志**能把两者分开。
⇒ 同族：[[absence-conflates-causes-in-observables]] · [[removing-a-restriction-needs-the-allow-side-logged-first]]。

## ⚠️ 同一天差点犯的第二个版本（记下来）

我先用「各 run 目录里 `px_m_calibrator` sidecar 的数量」做证据，得到一张极漂亮的表
（有 wrapper 的 8 抽全 0、没 wrapper 的全 >0），**差点当因果写出去**。
**那张表是假的**：隔离抽的 CV 证据**根本不进 attempt（F-35）**，run 目录里的 0 是
「没留存」不是「没调用」。真数据只有 staging 的 `access_log.jsonl` 里有。
⇒ **用一个观测量做因果论证前，先问「这个量为 0，有几种可能的原因」。**

## ⛔⛔ 第二次现形：**F-60（2026-08-18 首次开抽），而且我差点原样重犯**

`guard.py` 用裸子串 `".." in text` / `"~" in text` 扫**整份脚本正文** ⇒
`print("…walls...")` 的**英文省略号**判「上级目录穿越」·`# gray = ~180` 的**波浪号**判「家目录」；
且扫描面是 `out/` 下**全部** `.py` ⇒ **一个文件毒死整个执行面**。
⇒ 读图器**两次尝试真实像素测量、两次被英文标点拦掉**，然后才退回去写整数坐标。

**⚠️ 我起草的 pilot 审阅意见里已经写好了「你的脚本算完 intensity profile 又把结果扔了」
——发出前查 access_log 才发现是冤枉。** 那句话如果发出去，就会把工具缺陷记成模型缺陷，
并且**读图器会照着这条错误反馈去改**，污染整条线。
⇒ **规矩升级：写任何「模型没做 X」的反馈之前，先在 access_log 里确认它没试过 X。**

⚠️ 排查时我**第一次 neuter 还判错了**：移走可疑文件后仍 DENY，一度要判「毒死全场」不成立；
真因是**我自己的探针文件带同一个毛病**。靠**打印真实拒绝理由**（而不是看 ALLOW/DENY 这个形状）
才分开 ⇒ 同族「形状匹配 ≠ 行为验证」。

## How to apply

- 排查「模型行为退化」时，**第一步不是读 prompt，是把它该走的工具链自己跑一遍**。
- 工具的**文档形态**要当成产品的一部分实跑验证：本项目连续撞了两条同族
  （F-45 路径/参数形态错、F-49 参数语义错），**都是文档里的示例本身跑不通**。
- 验证要在**真 staging + 真 guard** 里做，不是在主树里调函数（形态不同，结论不迁移）。
