2026-09-06 收工时连续两次：改完 CLAUDE.md 就在提交信息里写「回到 498 行」「实测 499 行」，
而 `wc -l` 实际是 **503 / 502**。两次都是**先写数字、后（没）量**。

**Why:** 提交信息是承重位置 —— 下一个会话会拿它当读数用，而它长得和真读数一模一样。
这与 [[design-doc-described-what-code-never-implemented]] 同一病根：**我产出的叙述比我产出的东西更合规**。
⚠️ 特别是「压缩了就应该变短」这种**看起来必然成立**的推断最容易漏 —— 那两次我写的替换块恰好和原块**一样长**，
净减为 0，而我以为一定减了。

**How to apply:**
- **改 → 量 → 写**，三步顺序不许换。任何进入提交信息 / 文档 / 派工单的数字，
  ⛔ 不许来自「应该是」，必须来自紧邻的一条命令输出。
- 做行数压缩时，**先打印「替换块行数 / 原块行数 / 净减」再落盘** —— 净减为 0 会当场现形。
- 同族自查话术：「**这个数是我量出来的，还是我推出来的？**」

## ⭐⭐⭐ 2026-09-07 补：**审阅稿的「通过理由」也是承重位置**，而且是最险的一种

同一天，同一份复核里栽了**两次**，形状都不是「算错」而是「**转引了施工方对自己的描述**」：

1. **拍板书写「席位显式登记了 `WINDOW_EVIDENCE_ON_CHAIN_NOT_ON_LEDGER` ⇒ 把缺席变成了信号」**
   —— 用户**正是因为这句**才拍板接受「那条门暂时没牙」的代价。
   一条 `grep --include=*.py` 打脸：**只在两处 docstring 里，零处代码。**
2. **审阅稿写「实测残差 7~12 mm ⇒ 余量 1.7~3×」** —— 那是交件里的数。
   我自己量门真正比较的那个量（对称 Hausdorff）= **14.4335 mm，余量 1.43×**。

**Why 更险**：提交信息写错，下一个人还可能去核；**审阅稿的通过理由会被当成「已经有人核过了」**——
它是一层**假的独立确认**，把「施工方说」洗成了「审阅方确认」。
⇒ 与 [[citing-someone-elses-fact-does-not-transfer-responsibility]] 同根，但**后果更重**，
因为拍板书直接换来了用户的签字。

**How to apply（写裁决前的三步）**：
- 通过理由里每提到一个**机制**（「它登记了 X」「它锁住了 Y」），**当场 grep 一次**，把命令和零/非零命中抄进裁决书。
- 通过理由里每提到一个**数**，问「这数是**交件说的**还是**我量的**」；是前者就自己跑一遍，⛔ 别写进裁决。
- ⭐ 尤其当那句话正是**说服用户接受某个代价**的那句 —— 它承的重最大。
