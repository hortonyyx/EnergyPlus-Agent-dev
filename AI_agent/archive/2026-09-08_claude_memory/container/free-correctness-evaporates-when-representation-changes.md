**2026-08-09 F-17 实证。** 同一个 envelope 变换有两条实现：

| | 表示 | 「改哪个坐标」怎么定 | 跨轴独立性 |
|---|---|---|---|
| legacy | cell 的 **bbox**（`cell.x`/`cell.y`） | **索引** `values[edge_idx] = new_value` | ✅ **免费** |
| v3 重写 | cell 的**顶点环** | **坐标匹配谓词** `_on_component(point, …)` | ❌ 谓词在第一次移动后失效 |

v3 顺序就地改写几何，但各组件的区间锚在**变换前**的坐标系 ⇒ 第二个正交组件判定公共角点时，
它的坐标已被前一个组件改过 ⇒ 判为「不在组件上」漏移 ⇒ 直角裂成两点、连成 45° 斜边。

**Why 这条值钱**：legacy 的跨轴独立性**不是任何人写的防护，是表示本身送的**。
没人给它写过测试（因为它「不可能错」）⇒ 换表示时它**静默蒸发，且没有锁会红**。
而且 legacy 那侧**恰好用真实数字测过**（`_three_bay_inset` 就是 `[0.12,14.88]×[0.12,7.88]`
且同时声明 x/y 两轴）——**证据一直在仓库里，只是没人把两条实现对照着看**。

## ⭐ 2026-08-10 F-19：**镜像形态 —— 加一层规范化也是「换表示」**

F-13 的修法（08-06 `a3458cc`）给 `build_geometry` 的输出**加了顶点规范化**（起笔点挪到
IDF `UpperLeftCorner`）。**它没删任何东西、全仓当时全绿**，但它**静默打坏了一道
07-18 就存在、一直正确的门**：`kernel.window_parent_binding` 的复算侧
（`window_verts_on_line` 原始输出）**没跟着规范化** ⇒ 两侧起笔点差 3 位
⇒ 浮点逐位相等**恒假** ⇒ 真实产物 15/15 恒红（**几何其实是对的**：15/15 循环旋转、
法向全保持、零绕向反）。决定性验证：两边过同一规范化后 **15/15 逐位相等**，直接比 **0/15**。

| | F-17 | F-19 |
|---|---|---|
| 动作 | **重写**换表示 | **新增**一层规范化 |
| 后果 | 丢掉旧表示**免费送的**正确性 | 打破既有比较的**相等前提** |

### ⭐ 2026-08-11 增补：**同一个过时假设在同一个文件里有【两处】实现，登记时只点了一处**

开工发单前做机械核实，当场把范围改宽：除 `_boundary_centerline_to_outer`（外包边界，`:252`）外，
**`_expand_boundary_span`（`:125`）把内墙线段碰到边界的端点也各外扩半墙厚** —— 同一个假设、同一个病。
真实产物实测：外包 8 条边 `delta ±0.12`（**不可见**），**内墙 9 段** `extent_drift=true`、
状态从 `complete` **降级成 `within_tol`**（**可见但会被误读成「模型画得差一点」**，
且 `wall_hits` 仍报 4/4、5/5 ⇒ **headline 数字不受影响**，更难发现）。
⇒ **「谁在按改动前的形态理解这份产物」要问到【实现】粒度，不是【文件】或【函数名】粒度**：
一个假设可以有 N 处实现，只修点名的那处 ⇒ 剩下的继续冤枉产物，且可能以「模型质量差」的面目出现。
配套见 [[stop-and-report-catches-dispatcher-errors]] 的「凡『一律/全部/共 N 处』发单前必须逐处列值对账」。

**How to apply**：
- **重写/换表示时的必答题**：⭐**「旧表示里有哪些正确性是免费的？」** 逐条列出来，
  新表示里每一条要么继续免费、要么补一把锁。
- ⭐**加规范化/归一化/排序/去重时的必答题**：**「谁在拿【未规范化】的形态跟它比？」**
  机械做法 = 列出该产物的**全部消费点**，逐个问「这一侧过没过同一个规范化、比较用的是不是 `==`/`!=`」。
  （F-19 修完做同族排查：`window_verts_on_line` 的 4 个消费点逐个对账 ⇒ 0 新命中。）
- ⭐⭐ **「全部消费点」必须包含判卷 / 渲染 / 报表侧，不只生产侧**（F-22 实犯）。
  **判卷侧尤其危险**：它的错不会让流水线变红，只会让成绩**悄悄变宽**。
  判别问法加一句：**「这次改动之后，还有谁在按【改动之前】的形态理解这份产物？」**
- ⭐ **改的是「修好一个 bug」也算换表示** —— F-22 的上游动作是**修复**（F-17），不是重写、不是新增规范化，
  **产物形态照样变了**。⇒ 三种动作（重写 / 加规范化 / **修好原本坏掉的变换**）都要过这道必答题。
- ⛔ **修法只能是「两侧共用同一份规范化」，不是给门加等价类豁免** ——
  F-19 若加「循环旋转视为等价」，就会同时放过**绕向反转**（法向翻转 ⇒ 内外面反转 ⇒ 窗挂错房间）。
- **调查一个新实现的 bug 时，先找旧实现有没有测过同一个场景** —— 若测过且是对的，
  **两条实现的对照就是根因定位器**（本次直接给出了架构级表述，比读代码快得多）。
- 与 [[dont-delete-normalization-without-finding-its-contract]] 互补：那条问「这段没了谁会算错」，
  这条问「这段本来就不用写、现在还免费吗」。
- 配套坑：**新实现的夹具形态分布常与旧实现不同**（v3 夹具 footprint 全以 `[0,0]` 起
  ⇒ lo 侧不产生 intent ⇒ **结构上凑不出正交组件对**，2323 绿照样漏）——
  见 [[real-chain-run-exposes-what-tests-cannot]]。
