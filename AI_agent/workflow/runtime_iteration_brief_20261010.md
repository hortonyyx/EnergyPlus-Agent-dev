# runtime 可控续跑与效率迭代

用户 10-10 授权“先迭代runtime”，需要测试时优先 GLM 订阅。基线 `83cf373b`，runtime v2 / domain v57；依据 [独立审阅](../logs/reviews/2026-10-10_runtime_independent_review/summary.md)。本轮进入实施，覆盖审阅中的有界能力包及所需验证。

## 范围与责任

- 项目经理：任务控制（定向消息、安全边界暂停/继续）、工具恢复分类、计时/上下文估计一致性、集成、版本登记与验收。
- 预算恢复：追加式未发送预留释放、有来源缺 usage 补账、根/子账和停止原因。GPT-6.1 Sol/high，因涉及账本与事件协议跨模块一致性。
- 日志热路径：增量事件/预算验证、任务事件索引、完整重放保留、计时和性能对比。GPT-6.1 Sol/high，因必须保持全部事件不变量及失败追加的原子性。
- 配置贯通：共用公开连接身份、各角色实际上下文配置。GPT-5.6 Sol/high，普通有界实现包。

三包在独立短期工作树开发，项目经理集成回 main。任务控制和恢复利用既有 task ID、追加日志、检查点与产物，不增加通用消息平台、provider平台、角色或自由摘要。建筑规整和识读方法不在本包；入口接线涉及已登记 domain 文件，发布时如实更新其版本。

## 语义边界

1. 缺 usage 默认保持未知和完整预留；仅有绑定原请求/原结算的后到证据才补账。确定没有 durable request 的预留可以幂等释放；请求已记录而无响应仍不能假定未计费。
2. 任务指令有 ID、目标、来源、顺序和处理回执。暂停在请求/完整工具交互的安全边界生效，不强杀 HTTP，不冻结或重置既有墙钟预算。进程可继续等待定向 resume；重启仍按检查点与原截止恢复。
3. 工具权限与恢复策略分开：明确纯读取可重取；委派按原 task ID 恢复；未知非幂等写不重放。历史 unknown 与后续重取记录同时保留。
4. 运行时增量校验与离线全量校验接受/拒绝应一致；不删 fsync、哈希、单写者锁或费用保护。
5. endpoint、上下文限额及压缩策略的实际生效值与记录一致；密钥不进入版本、日志或报告。

## 验证

- 按改动运行相关 runtime/contracts/role 接线离线检查；核心场景包括六子任务混合中断/暂停/成功、消息不重放、已完成写不重复、未知费用不填零、root/child余额正确、坏事件不能污染索引。
- 读取冻结 10-10 日志做增量/全量一致性和同机微基准。旧 run 与失败建模声明保持冻结，不用新实现原地续跑。
- 需要实测时使用现有 GLM 订阅 `glm-5.3-flash`，先做单独 runtime 协议小测（计划一个 run、至多四次模型请求、确定性临时工具、无建筑建模、无自动线路回退）。用于验证真实请求与定向纠正/暂停续跑，不外推为 sm25 质量或30分钟达标；完整记录请求、耗时、usage与终态。
- 不调用 DeepSeek；不以 GLM 不可用为由自动切换付费 API。普通相关离线检查与该有界订阅小测由本次授权覆盖；不顺带做重复整案抽样。
