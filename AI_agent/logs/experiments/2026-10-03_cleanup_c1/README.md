### 上下文与图片的具体规则

- 状态消息是历史末尾的独立可变尾项，不写回对话历史；前缀检查排除这一项。任务原文保留在最初的用户消息，不在状态中复制。
- 压缩按完整的工具调用／回包／图片交互组移出旧历史，目标为阈值的 60%。初始指引、当前交互、显式固定的依据和主动取回的图片受保护。压缩说明用一句话说明移出的交互组与取回原图／保存依据的方法，不列哈希。
- 图片体量默认 **32,000,000 解码字节**，是压缩发生时的保留目标；同一图片在多个保留消息中重复出现，分别计量。阈值以下不因图片数量或体量改写已发送前缀。固定内容或最新完整交互不可分割时允许超过这个保留目标，实际模型上下文与预算上限仍由发送前检查执行。
- 检查点保留完整历史、来源引用、原图、当前 BIM、维度／对象／几何审计状态。压缩缓存必须与已落盘事件对应；篡改归档历史列表会被拒绝。
- 显式设置 `active_window_messages` 的兼容路径仍在，供旧回放和已有局部委派调用使用。本包改的是公共默认值与默认单模型整案入口；`runtime_delegation.py` 中既有显式 16 消息配置不在本包文件范围内，未迁移。
- 局部委派的计算所得剩余预算仍会作为操作约束展示，保留原有子任务预算和 revision 检查。普通 BIM 状态不带这项；没有借清理状态之名移除子任务限额提示。

### 故障与恢复的具体规则

每一次真实尝试都先独立预留预算，成功或失败均结算；拿不到用量时继续保守占用，不退款、不伪记零消耗。HTTP 失败若带用量，最终汇总和逐请求账目均计入一次。等待时间受原始截止时间约束，不能为补试延长任务。达到调用／token／时间上限即停。

零用量空回复不进入模型历史，崩溃后恢复也一样；重试链按当前请求计数，不让前一个已经恢复的故障消耗以后所有请求的次数。未知写入仍先检查已保存状态，不自动补写。R2 截断补救仍是独立路径，使用原来的连续／总次数上限，不和 HTTP 补试合并。
