# sm24 东侧 profile Sonnet 观察离线复核

日期：2026-09-14
结论：对象识别优于 Haiku，但完整端接、开放走廊和外墙开口仍有实质误读，暂不可接入 source 一致性检查

## 复核边界

本项逐条判断只以本目录保存的 `1f_view.png`、三份 `pixel_profiles` 原图/色罩、`observation.md` 和 `execution_audit.json` 为依据，没有用 source 或 GT 为各项定真。这是了解项目历史的开发侧事后复核，不是盲评；观察模型运行时未获候选 source、GT、旧答案或其他模型观察。本复核没有调用模型/API。

审计显示原图与隔离副本像素一致；8 次工具调用包括 5 次 `view_image` 和 3 次 `view_pixel_profile`，没有 source 查看或修改工具。第三次 profile 与第一次是同参数复查。运输、量测和调用范围通过只证明模型看到了真实原图和真实候选，不证明其语义判断正确。

本次能正确引用 profile 候选，并将 y=305/327 的主要灰线认作家具，且正确识别两道纵墙。相较 Haiku 候选观察已有明显改善。剩余错误集中在墙如何端接、灰线缺口究竟是门窗还是开放空间，这些仍会直接改变源分区或开口。

## x 轴候选

### W-vertical-402：profile_001 / C01，`x=402`

**判定：墙身份和 `separates_spaces` 正确，两侧空间说明不准确。**

原图清楚显示约 `x=402` 的纵向实体隔墙，从北侧横墙向南延续，多个间断处有门扇和圆弧。它分开的是西侧一列房间与中间狭长空间；观察称其为“含餐桌房间的左边界”，把墙东侧再跨过另一道墙后的家具房误当成直接邻区。

这不推翻墙与分隔关系本身，但说明目前文字还不能可靠提供“墙两侧分别是什么空间”。原图也足以确认主要缺口确有门洞，无需把它们保留成“门扇可能只是贴在连续墙旁”的歧义。

### W-vertical-457：profile_001 / C02，`x=457`

**判定：核心判断正确，缺口复核不完整。**

原图支持它是中间狭长空间与东侧房间之间的实体隔墙。`y=323–356` 和 `y=383–414` 附近均可见门扇/圆弧及墙线中断；带门洞的墙仍分隔两侧空间。因此 `physical_wall + separates_spaces` 正确。

观察只明确讨论了第一处缺口，对第二处缺口及其门的归属没有完成同样核对。作为墙候选可以采用，作为完整开口/两侧空间观察仍不够。

### W-right-exterior：profile_003 / C03，`x=603–611`

**判定：外墙身份正确，把两段窗误称标注覆盖是错误。**

约 `x=603–611` 确为东外墙。profile 中灰墙支持分成 `y=260–310`、`356–381`、`558–609`，中间缺失处在原图上不是“灰墙连续但被旁边青绿标注干扰”：沿外墙本体可见青色窗线，尤其 `y≈382–557` 是一段明显长窗，`y≈311–355` 还有另一段窗。外侧绿色线和 `240` 数字才是尺寸标注。

外墙作为空间边界仍成立，但“没有可见开口、无门框、青线只是标注”的解释会漏掉外窗，不能进入开口核对。这里再次说明 profile 灰色缺口必须回看缺口本体，不能因整列位于外围就推定实体灰墙连续。

## y 轴候选

### W-top-with-door：profile_002 / C01，`y=296`

**判定：正确。**

原图支持该横墙分隔北侧房间与下方空间，`x=408–451` 的间断对应可见双扇门。两段 profile 支持属于同一带门物理墙，`physical_wall + separates_spaces` 合理。

### W-mid-horizontal-top-of-dining：profile_002 / C04、C05，`y=367/371`

**判定：物理墙识别正确，`wall_fragment` 错误；它在可见范围内有完整端接并分隔两个东侧空间。**

两条相距 4 像素的灰线是同一墙的两条画线，观察已正确合并。它们从约 `x=457/462` 接到东外墙 `x=603–611`。profile 在 x=457 只显示单像素交点、实质横向支持从 x=462 起，正是横墙面接到纵墙厚度边缘的正常表现，并不表示它没有接上 x=457 纵墙。

因此“未延到 x=402/457，可能自由端”的判断与原图 T/端点结点不符。该墙无需穿过中间狭长空间；它完整连接走廊东墙与外墙，分隔东侧上、下两个房间。将其降成 `wall_fragment` 会再次合并真实空间。

### W-bottom-with-door：profile_002 / C06、C07，`y=583/587`

**判定：两侧各有建筑墙线，但把它们合成一条带门横墙是实质错误。**

profile 保留了两个主要支持段：西段约 `x=360–397`，东段约 `x=462–611`；`x=402`、`x=457` 的单像素支持是纵墙交点。原图显示西、东两段分别接到两道走廊纵墙，中间 `x≈402–457` 是中间狭长空间本身，并没有横墙跨过，也没有一樘门横跨整个间距。

观察所称“底部左侧青色门弧”位于西段与 x=402 纵墙附近的另一处门口，并不占据 `x=397–462` 整个中央间隔，更不能把左右墙段桥成一个对象。此处应将西段和东段分成两个墙对象，再各自合并 C06/C07 两条画线。当前 `W-bottom-with-door` 会错误封闭连续空间。

### furniture-cabinet-outline：profile_002 / C02[2]、C03[1]

**判定：正确。**

`y=305–307` 的 `x=508–595` 与 `y=327` 的 `x=509–594` 是北端东侧房间内矩形家具的上下边，不与建筑墙形成端接。`not_wall + not_applicable` 正确，修复了 Haiku 将其中一条误配成墙面的错误。

### single-pixel-crossings

**判定：正确。**

y profile 内的 `[402,402]`、`[457,457]` 等单像素区间只表示该扫描行撞到已识别纵线，不能证明沿 y 候选方向另有横墙。把它们单列为交点、不给分隔关系符合题目约束。

## 尚不能提供的空间关系

本观察没有输出墙两侧清晰室内点，也没有输出不穿实体墙的连续空间路线。其文字两侧解释仍出现 x=402 邻区错认；y=583/587 又把开放走廊当作门洞。因此即使部分 `physical_wall` 对象已经识别正确，也不能据此生成可靠的 `physical_wall / continuous_space` 对照输入。

三种缺口仍需明确分开：

- x=402、x=457 的局部缺口有门扇/圆弧，是隔墙上的门洞；
- 东外墙的长青色段是窗，不是覆盖灰墙的尺寸标注；
- y=583/587 两段横墙之间是一个空间的完整宽度，不是单墙门洞。

## 采用建议

不原样采用整份观察，也不接 source checker。可保留为实验依据的局部结论是：x=402、x=457 为两道纵向实体分隔；y=296 为带双门横墙；y=367/371 为接在 x=457 与东外墙之间的完整横墙；y=305/327 主体是家具。东外墙开窗解释和 y=583/587 的左右对象关系必须先纠正。

下一步正在进行的端点/缺口返工可只复核两项：y=367/371 与 x=457 的可见接头，及 y=583/587 中央间隔两端实际墙面和附近门弧归属。返工仍应引用既有 profile 端点/间隔计算出的裁图，不向观察模型提供 source、GT 或本复核的正确答案；只有它能把“墙端接、门洞、窗、开放空间”分别说清，才值得继续构造只读 source 条件矛盾检查。
