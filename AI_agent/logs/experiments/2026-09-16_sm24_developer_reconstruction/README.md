## 从原图到源模型

1. `measure_plan.py` 根据开发助手指定的候选区域提取尺寸 tick、成对墙带和窗色带。`plan_measurements.json` 保存像素依据；真实墙的完整路径与端接由开发助手判读，不把整图投影峰贯穿成隔墙。
2. 外周选图示外缘，内部选墙中线，明确混合代表面。连续走廊和东南折角保留；墙端仅按可见接头接到所选代表面。`plan_draft.json` 保存物理墙、门窗、房间用途假设。
3. 开发 Sol 独立读取四原立面；`measure_elevations.py`、`elevation_observations.json` 和 `elevation_review.md` 保存标注与像素核对。北1/东3/西5三组大窗采用1.0–3.4m，其余八窗1.0–2.8m；三个外门0.2–2.6m，亮子视为门组件。
4. `build_source.py` 结合上述记录生成 `plan_final.json`，复用 `compile_plan_partition` 和源导出，保存方案、源、显示数据、平面、回叠与四立面。8个空间由墙网围合，去掉用途种子仍为8个；不是根据预设房间数量切块。

生成脚本不加载GT、旧reading或旧BIM；开发助手有本案历史上下文，不能叫盲测。平面选择由开发 Astra 完成、四立面由开发 Sol 核验；这些显式选择仍需转换成工作模型能执行的方法，而非宣称脚本已自动理解图纸。

## 验证和限制

源自洽、方案与显示数据精确重放通过；总面积200m²，无实质重叠，21开口均保留原声明的投影和高度，8空间均可经已声明门连通室外。离线浏览器源散列一致，旋转有效，无脚本错误或外部请求。详见 `verify_source.py` 和 `verification.json`。

生成结束后的独立分区评价匹配8/8空间，没有漏墙、多墙或拓扑差异；整体标为minor，约1–2cm位置差处于既有2cm容差内。未用评价结果精修生成坐标。既有诊断对typed-v3门窗只给数量、不计算匹配；本次另有 `opening_evaluation.py` 逐项评价，结论见其报告，不能把11/11计数冒充位置全对。

未证实的部分：七个内门2.1m高为假设；图纸没有完成面标高，外门0.2m底差保留但不凭空生成台阶；4.5m是立面包络高，不代表已知室内净高；房间用途按家具推断；外墙厚度、板构造和物性未建。平面开口位置有约一个原像素（约0.028m）的量测不确定性。用户尚未验收，工作模型迁移与换例稳定性未做，未跑EnergyPlus。

## 可迁移的做法与未完成项

- 先识别尺寸链tick，不把绿色标注全范围当建筑尺寸；裁图坐标必须明确逆变换到原像素，检查是否越界。
- 量测成对墙带、连续支持范围、接头与门弧，再判断物理墙的有界路径；单个投影峰不代表贯穿隔墙。
- 单独保存真实开放段、折角和完整门窗清单；几何报错时回查证据，不移动真实墙来迁就旧错门。
- 按平面身份匹配立面高度族，缺失高度保留假设；用实际保存源反投影，分别验解释、写入和显示。

这些方法来自本例开发探路，尚未包装或验证为通用自主kit。用户09-20安排本程结束后先接手Claude的15个部分推理素材案例；方法迁移待后续继续，旧工作模型采用基点sm24/run12、sm21/run22保留。
