## 判定口径（开跑前写定）

1. **底座与新线路**：正常交付或到点交出最近完整稿；记录完整；没有底座引起的失败；协议往返（工具、图片、思考块）整案无协议错误。临时故障被重试救回的次数单列。
2. **速度与模型每轮看到的量**（本次主要问题）：每次请求平均输入、缓存命中占比、每轮输出、每轮用时。与同期 Claude Code 比，缓存命中差 20 个百分点以内、每轮用时 1.5 倍以内记为“接近”；同时与上次新底座（缓存 66%、每轮 2.7k／61 秒）比，说明新线路带来多少变化。
3. **质量**：sm24 看房间一一对应、挂墙、门连通、门窗位置、外部高度，对照上次新底座（8/8、21/21、10/10、19/21、14/14）、同期 Claude Code 与 10-02 基线（20/21、12/14）；sm25 先看是否按米建出两层（尺度检查若拦下毫米输入，看模型是否据返回改用米），质量对照 T1 sm25（Claude Code：一层 14/14，二层多拆一间，位置 41/61，高度 25/34）。每次单次样本，只判有没有明显变差，变差的按行为记录找原因。
4. **时间**：6000 秒内交出完整全楼稿。
5. **存储**：记录运行目录体积，对照 A1-R 的估算（sm24 145 → 77 MB）。

## 结论

1. **底座与新线路：通过。** 三次都正常结束，两次模型自选交付（sm24、sm25），记录完整；新线路整案 101 次请求无协议错误，0 次重试（这次没遇到服务故障，重试路径仍未经真实触发）。
2. **速度：** 按改正后的口径，新底座每次请求用时是 Claude Code 的 1.48 倍，在 1.5 倍以内；缓存命中 46% 对 89%，差 42 个百分点，**仍未达到“接近”，差在缓存**。思考量已不是主要差别。A2-R 的会话标识小测（两组各六次、3,360 token 同正文）两组都很快命中，测不出跨服务器分流，**结论是“这种测法测不出来”，不是“无效”**；缓存差距转入提速线，待查方向：接近真实的长前缀序列下的会话标识、流式与非流式、长间隔下的服务端缓存保留。
3. **质量：** sm24 与 Claude Code 同档（18/21 对 21/21，高度都 14/14）；sm25 按米建出两层，位置、高度比 T1 sm25 好，一处走廊错拆。没有明显变差。
4. **存储：** 新底座 sm24 64 MB、sm25 231 MB，约为上次的一半；A2-R 再减一半（目录 63.4 → 32.2 MB，按本次 sm24 重放）。
5. **下一步：** A2-T（依据一次办完、高度一张表）与 A2-R 合入后，在 27B 上抽测 sm24，看依据手续合并后能否在预算内自己交付；走廊错拆归入下一批吸收（全楼检查与错拆）。
