# 总 Agent 设计第二轮：约束核对与首个切片（Opus 5.5 审阅）

**总判断：** 主助手的六点异议，我大部分接受。第一轮有几处写得过硬，还有一处事实错误（revise_bim）。仍坚持的只有三条结构约束，列在 D 节末尾。

## A 修订后的最小架构

我撤回“PlanClaims 是唯一事实载体”“空间只能由墙声明编译”这两个主张。修订后分三层，每层只存一次，不复制数据：

1. **原件层（不新建）**
   - 【事实】原图散列、profile/candidate、region、裁图和比较结果都已经各自落盘，并有 ID。
   - 【建议】声明只引用这些 ID，不复制它们的内容。
   - 以后接入网格、文本或推理来源时，同样只登记引用。

2. **声明层（模型写）**
   - 在草稿账本上最少增加三处：
     - `claim_id`；
     - `evidence_refs`：指向原件 ID，或原图框；
     - `basis`：取值为 annotation+pixels / pixels / visual_estimate / inference / other_input。
   - 另加 `mode`，取值为 blind 或 review，review 时记录显示给观察者的旧声明 ID。
   - 采纳、搁置、撤回仍用草稿里的 `decide` 事件，由模型决定。
   - `statement` 可以保留自由文本。但声明若要被几何操作引用，必须带可解析的 `object_refs`，只有需要编译的主题才要求结构化 `value`。
   - 厚度只是 attribute 主题下的一类声明，不单列。

3. **应用层（代码推导，模型不写）**
   - 每个候选保存一份 `applications.json`，格式为：claim_id → {候选, 触及的对象, applied / failed / partial, 错误}。
   - 它由 build/revise 的真实结果生成。
   - 采纳后构建失败时，记为 `failed`，同时保留父候选；声明仍为 adopted。
   - 交付时列出“已采纳未应用”“应用失败”“应用了但未显式采纳”三类情况。

plan_partition 只是众多编译器之一，不限制声明的形态。

## B 接口（3 个）

1. **`record_claim` / `decide_claim`**（合并为一个工具，用 action 区分）
   - 校验引用的原件存在，且原图散列一致。
   - 纯数值自动标为 visual_estimate，不拒收。

2. **现有 build/revise 的 `source_refs` 扩为 `claim_refs`**
   - 允许与旧的字符串并存。
   - 代码校验声明存在，其 `object_refs` 能在父候选中解析，或属于本次新增的对象 ID。
   - 【事实】move_shared_wall 和 replace_space_region 已返回 before/after 与 moved_openings，可以直接当影响闭包使用，不另造几何内核。

3. **`claim_status(candidate)`**
   - 按候选输出应用状态。
   - 输出闭包外的源几何/语义差异。比较对象是空间多边形、开口的 p1/p2/z/kind/宿主、ID 集合，不比较备注和派生面。
   - 输出一个“几何语义摘要”，与整体来源摘要分开计算。

**概念例子（占位符，不含案例坐标）：**
- 输入：声明 C12，主题 opening，`object_refs=[A_x]`，value 为 kind=window，端点引用 profile P 的 start/end，basis=pixels，mode=blind；随后 `decide(C12, adopted)`；再调用 revise：update_opening A_x，`claim_refs=[C12]`。
- 输出（成功）：新候选；C12 状态为 applied，触及 A_x；闭包外差异为空。
- 输出（宿主失败）：不产生候选；C12 状态为 adopted 加 failed(OpeningHostError)；交付中可见。
- 若同一次修订还改动了另一扇门、但没有引用任何声明，`claim_status` 会把它列为“未引用的开口变化”。它只提示，不自动判定为作弊。

## C 首个有界工作包

**输入：**
- 已保存的真实产物：run01 为消除报错而删墙、裁开口的构建链；09-13 那次缩门修订；run03/run04 的合法修订链。
- run04/candidate_02。
- sm24 平面与 East 原图。
- 通用连通范围方法说明。
- 不提供 GT、正确坐标或候选名单。

**验证顺序：**

1. **离线测试**
   - 声明校验；
   - `claim_refs` 解析；
   - 成功、失败两种应用记录；
   - 厚度写入后，几何语义摘要不变（只需一条测试）。

2. **接口回放（不调用模型）**
   - 正例：run01 的裁开口和 09-13 的缩门，应被列为“无声明支撑的变化”或“闭包外变化”。
   - 反例对照：run03 的新增墙门、run04 的高度修改，是合法的连带改动，不应误报。
   - 如果反例被误报，说明接口太窄，应先修接口，而不是归咎于模型。

3. **有界模型试验（一次）**
   - 从 candidate_02 恢复。开发指定东侧区域，由 Sonnet 调度，一次 blind 局部观察，产出声明，模型自行决定是否采纳和应用。
   - 该区域的开口已经过开发限定修复，所以本试验只检验两件事：
     - 不做误改：已正确的对象保持不变，或任何改动都能追溯到具体声明；
     - 为 H1 增加一个类型判读数据点：开发事后对照原图判断声明类型是否正确。
   - 报告标注为“指定区域、开发限定”，不等同于自主发现，也不等同于冷启动。

**成功条件：**
- 回放中正例、反例都判对；
- 试验中所有几何差异都能追溯到声明，无闭包外误改；
- 若出现失败，能在交付中看到。

**失败信号及解读：**
- 类型判错但端点引用正确：为语义瓶颈假设增加一例，不据此宣称 H1 成立。
- 被局部性检查拒绝：先分类为合法连带改动、接口太窄或无依据改动，再下结论。

**不做：**
- 三个历史问题的捆绑复现；
- 旧 reading 全量对照；
- sm21 pilot（排除示例和旧答案后，只作为已知换例回归，不称新图泛化）；
- sm25、冷启动、自主选题；
- 通用事件平台、停点编辑器、EP；
- 放宽 plan_partition 的外形限制。

## D 撤回与保留

**撤回：**
- 唯一事实载体；空间只能由墙声明编译。
- “采纳由代码推导”：改为采纳由模型决定，应用状态由代码推导。
- 坐标必须来自工具量测；第二来源作为准入条件（改为提升置信度的可选方法之一）。
- 问题中禁止出现候选数值；按散列禁止重复调用。改为：由运行代码按“连续无新引用、无声明变化、无候选变化”判定空转。
- “revise_bim 没有墙级局部修订”：这是事实错误。
- 未触及对象“逐字节不变”。
- “局部性检查拒绝即模型作弊”；“单次失败即 H1 成立”。
- “冷启动回答默认墨线 = 墙”：改为“冷启动回答未说明语义判别机制”。
- “像素只作交叉验证”：改为有标注时标注加像素最强，无标注时像素是主依据，其次才是推断。

**保留（本轮仍有分歧）：**

1. **review 模式的结论不算对所示声明的独立佐证。**
   - 【事实】run09 中 Haiku 看到了未验证的旧声明，结果沿用了错误的判读。
   - 【推断】如果把这类“同意”计入佐证，日志就会为错误背书。只加文字提示无法防止代码层面的计数，所以这一条需要结构约束。

2. **修改开口的跨度或位置，必须引用一条指名该开口的声明。**
   - 依据可以是视觉估计，但不能不留痕地修改。
   - 这针对的是 run01 与 09-13 的真实失败。

3. **“已采纳未应用”和“应用失败”必须在交付中可见。**
   - 立面比较残差超过容差时，交付中显示未解决项；模型可以给出解释，但解释不能把这一项隐去。

以上都是基于冻结摘录的推理，没有运行代码，也没有做实验。
