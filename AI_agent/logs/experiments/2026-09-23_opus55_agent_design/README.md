## 收敛结论与主助手取舍

1. **首个工作包从独立通用账本调整为观察到几何应用的贯通。** 历史量测引用已经改善数值采用，但墙/窗类型、范围及尺寸归属仍错；结构化记录本身不能解决语义。厚度作为小型属性接线处理，不作为还原质量突破。
2. **原始观察、模型解释/采纳、实际应用分别记录。** 复用现有图像、profile/region、标定和候选产物，通过引用关联，避免复制三套建筑。模型可以采纳一个判断，而构建仍失败；代码只根据实际结果记录应用状态。
3. **应用关系必须具体到参数。** 主助手进一步收紧：在 revise 操作旁挂 claim_refs 不足以说明参数来自该观察。可计算的端点/尺寸引用应由代码解析、换算到动作参数，记录所用字段/变换/前后值；模型仍裁定构件类型和对应。视觉估计、建筑声明和推断也可使用，按实际来源标注，不把全部纯数字自动降为视觉估计。
4. **复用现有修订内核。** move_shared_wall、replace_space_region、reshape_spaces 与开口更新已存在；检查涉及的源空间/开口、宿主和连带变化，比较源几何/语义，不要求元数据或派生面的字节不变。失败沿用现有候选留档/父候选保留机制，不按审阅例子改成“失败无候选”。
5. **中间表示不限制共同底座。** 像素墙网是图纸能力之一，不能强制所有空间从它生成。尺寸标注加像素优先；无标注时像素仍可作主依据，明确估计/推断允许出模。后续网格/文本复用引用、判断和应用关系，本轮不同时施工。
6. **子任务分盲观察与带候选复核。** 后者可以接收明确未验证的旧判断，但其同意不自动计为独立佐证；不要求每项信息必有第二来源，不按问题文字是否含数字或文本散列一刀切禁止调用。
7. **接口验证与识读质量分开。** 建议先选少量真实修订链核应用记录、失败留存和合法连带变化，再做有界原图观察及修订试验。历史链需先逐个核实际内容，不按“旧修改无新schema引用”就判无证据，更不能把有引用的错误修改判正确。恢复基点已修好的区域可验证不误改，不能当新修复成功。

## 修正与未采纳事项

第一轮提出的“唯一像素声明图”“只能墙网出空间”“全部坐标必须工具量测”“必须第二来源”“采纳等于已编译”“无墙级局部修订”等，在主助手给出具体反例/源码后已由 Opus 第二轮撤回。单次失败仅支持瓶颈假设，不证明因果；历史示例影响的是当次输入独立性，不能据此永久排除 sm21 的干净输入回归。

第二轮仍有需要主助手收紧的表述：纯数值不必然为视觉估计；引用完整不等于参数真正采用；“任何修改有引用”不够证明不误改；合法历史修改也可能没有新schema引用，回放须如实标为开发侧适配；失败不一定没有候选。第一轮的局部残差也不能直接作为全楼保真门槛。

下一节点不能停在“记录完善”。先验证有界观察的类型/范围与参数采用，再在仍有实质错误的候选上检验实际修复；随后再验证自主选题、冷启动与换例。指定区域、已有候选辅助、开发历史回放各自明确标注，GT只作事后评价。

本次没有新生产实现、新BIM、原图模型调用或新测试成绩。以上为主助手综合后的实施建议，不能视为用户已经逐项批准新接口设计。
