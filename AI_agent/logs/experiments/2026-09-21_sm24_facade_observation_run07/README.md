## 失败定位

**正确候选已经返回，但没有被采用。** 首份平面青色扫描真实给出170/225、311/355、382/556等窗端点，模型提交却为165/225、306/340，并把大窗写成367/388和407/508两段。它的文字把这些值称为实际量测，±1—2px的不确定度也不能覆盖这些偏差。量测图及数值确实送达；不能归因于图像丢失或扫描不出。

East原图20m尺寸端点为x373/2261；模型用了250/2381，把图外竖向尺寸相关位置误当墙角。平面用了外墙角147/879而非它自己扫出的尺寸端点151/878。两图标定基准和开口区间都没有被可靠绑定，导致比较米数偏差远大于真实图纸的小误差。

初版算法在数量不等时按排序前缀临时配对，把P5门列为未配对；模型识别了该配对不合理，并在文字中提出P5↔E1、P3+P4↔E2。这是有价值的冲突识别，但区间仍错，不能算自行修好。原方向反向均值2.22m小于同向7.33m，只是基于错误观测的部分配对，不能作为可信方向/几何误差。

模型看见1900/2400/200链并在原答复述，却仍称东门高度未知；右侧高度链把1800写成800，中央大窗只记录屋顶到窗顶的1100。大多数高度未观察完整，没有建立开口与链的可靠对应。

主助手在模型结束后重看两原图，并用前一程开发原图探针作为**评测侧**位置对照。该探针坐标未进入本轮模型输入，不是GT，也不计为模型量测结果；详见semantic_review.json。
