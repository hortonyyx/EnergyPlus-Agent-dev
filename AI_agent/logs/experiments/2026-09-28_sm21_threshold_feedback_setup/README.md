## 实际过程与实现

run75首份平面只声明两道走廊横墙、三个空间；四道房间纵隔墙从初稿就遗漏，不是装配或用途修改删墙。后续F1关系检查的`same_space`期望本身错误，与候选一致不能作为独立原图验证。

第24次工具调用的`profile_010`在实际MCP消息中完整可解析。原请求在`1f_view.png`的`[1330,250,1350,800]`框沿y扫描，支持门槛2像素；y=370..617各有1个匹配像素，被主轴过滤。主列表剩墙端等局部高支持区，且因列表不为空，没有空过滤诊断。但**同一旧回执的另一轴已报告x=1346上y=370..618的长线支持**，没有运输丢失。run75最终以“只有短凸头”支持错并，与已返回信息矛盾。

确证的是阈值摘要隐藏细线，以及模型未正确采用既有另一轴证据。不能说旧工具完全没给证据，也不能把一个反馈缺口当作已隔离的回归根因。它不直接解决漏窗、标定、尺寸段顺序或窗型高度对应。[实际回执/初稿/关系检查](failure_trace.json)及[73次重放](historical_replay.json)仅在开发侧，不输入生成。

现有`view_pixel_profile`双轴返回增加`threshold_excluded_support`，列出有正像素但低于同一门槛的原图闭区间及最少/最多匹配数。明确这些区段不等于空白，也不证明同一笔画连续或某对象存在。候选编号、阈值、原量测、图像、工具清单/说明、GUIDE与按需参考保持；无新工具、自动识墙/补墙、调阈值或几何改写。
