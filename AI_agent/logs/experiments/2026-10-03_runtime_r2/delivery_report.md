**A：截断能够有界补救。** 底座先按接口实报全额结算，单独记录请求、回复、思考与可见文字长度、有无工具调用，再丢弃整条截断输出。即使其中有一个完整调用，也不执行这一批中的任何调用。下一轮只加短提示，不回灌被截断的思考。默认允许每任务连续补救 2 次，整个根运行累计 3 次；参数可调，超出仍停为 `incomplete_response`。子角色、摘要和崩溃恢复共用相同规则，预算与时间继续累计。真实迁移失败的 63,420-token 回复已用于离线反例，验证完整结算、继续执行、超限停止、半截调用不执行和恢复不重复收费。

**B：输出上限有依据且能拦住误配。** GLM-5.3-Flash 建议最小 32,000，依据是首试 16,384 耗尽、旧基线约 19,600 思考 token 及其 32,000 上限；Qwen 两档建议 16,384，档案记录各自历史样本。配置和入口都会拒绝过小上限，只有写明非空理由才放行，理由进入配置与回执。R1 历史配置字节未改，可用命令参数明确填写例外。

**C：图片进入预算与费用估算，全部 Qwen 图片账单完成校准。** 每次按实际发送图片尺寸、模型网格及像素范围缩放，计算 `图片 token=(缩放宽/f)×(缩放高/f)+2`。Qwen 的 `f=32`，像素范围 65,536–16,777,216；GLM 的 `f=28`，范围 12,544–6,272,000。回执分别列接口实报、图片估算、预算扣除和人民币估算，缺失 usage 时保留原预留。
