# 下一轮 domain 改进建议

依据本轮 `probe_summary.json`、`live_behavior_notes.md` 与
`AI_agent/archive/local_backup/role_runtime_repair/f1_evaluation/summary.json` / `role_evaluation.json`
交叉核对。这里只评价已分配的 sm25 F1；不外推整案、其他模型或 Claude Code。

本文件是独立审查建议，不是已采纳的实现规格。项目经理下一轮需先核查现有能力、反馈和可实现性，优先复用并替换失效方法，不把以下建议直接变成层层新增的硬关口。正式推进顺序见 [本轮报告](README.md#下一轮安排)。

## 结论与口径

本轮 runner、路由和证据保存通过，但 F1 质量失败。下一轮首先应补上原图外轮廓和开口完整性的
独立验收，再优化首稿节奏与提交接口。当前 compiler/self-consistency 会接受一个内部闭合、但与原图
明显不符的模型；继续只改接头容差或提示措辞不能解决这个主因。

| 口径 | 核对结果 | 限制 |
|---|---:|---|
| 虚构东北区域 | 140 m² | 候选 `hall` 为 10 m × 14 m；原图/overlay 中该区域没有建筑外边界，却被六点 footprint 包入。它是一个具体错误房间的面积，不应写成所有 footprint 误差的总面积。 |
| 房间 | 参考 14、候选 17、匹配 14 | 匹配是评分器的一对一几何对应，不代表 14 个都合格；2 cm 边界阈值下 14 个匹配均标为 severe，其中一个匹配的对称差约 44.90 m²、Hausdorff 14 m。另有三个候选空间，不能把“匹配 14”写成语义完整。 |
| 门窗/开口 | 参考 31、匹配 21、位置通过 18、参考漏 10 | 另有候选额外开口 `O_stub_passage`。`15/3/1/2` 的端点误差分档只覆盖 21 个已匹配项，并未计入垂直偏移或 10 个缺失项。 |
| 缓存 | 62.1147% | 计算为 `1,374,272 / (838,202 + 1,374,272)`，即供应商实报 cache-read 输入占实报输入的比例；不含输出和图片估算，也不是总 token 比例。 |

## 优先修复

1. **P0：给 footprint 增加原图外轮廓证据门。** 方法层应在 interior drawing differences 之外，
   单独检查每条 footprint 边是否有外墙墨线、可定位的尺寸边或明确的 void/courtyard 决策。工具反馈应
   返回缺少支撑的边段、原图 `look_box` 和由这些边围出的异常大空间；出现本轮这种大面积无支撑区域时，
   不应仅凭 source self-consistency 进入可提交状态。guidance 要求先沿真实外墙逐段闭合轮廓，并明确
   区分 overall dimension rectangle 与实际建筑边界。面积异常只能作为找错线索，不能单独自动拒绝正常大厅。

2. **P0：在提交前建立开口完整性清单。** 当前 drawing-difference 范围排除了 exterior/windows，
   `facade_counts` 又没有观察记录，因此 10 个参考开口缺失仍可通过 trial。方法层应按立面边/内部宿主墙
   汇总原图中观察到的开口带，并与声明逐项核销；工具输出应明确 `observed / built / unresolved` 及未核销
   的局部区域。guidance 要求首次可提交稿前完成这个清单，不能以“编译有宿主”代替“原图门窗完整”。

3. **P1：把删 seed 和空间合并变成显式、可审计的拓扑决策。** 本轮修复确实增加了七条有用隔墙，
   但也通过删除 `corrV`、`strip`、`corrStub` 将 20 个初始 seed 收缩到 17。trial/revision 反馈应单列
   新增/删除 seed、生成空间数变化和受影响连接，并要求引用原图中的“无分隔连续区域”证据；同空间冲突
   不应默认引导删 seed。该门只约束发生变化的对象，不需要引入 GT 房间数。

4. **P1：让首个完整 trial 更早且格式必然完整。** 首次 trial 在 35.7 分钟后才出现，且只因缺少
   `unresolved` 被格式拒绝；此前已有 28 个互不重复的 profile，其中多数有局部价值，所以不能简单认定
   测量无用。更合适的是由工具提供可直接填充的完整 plan skeleton，默认带空 `assumptions/unresolved`，
   并在第一次全图和分块观察后先提交结构稿；profile 主要用于 footprint 转折、开口端点和 compiler 指出的
   高风险位置。暂时没有证据支持固定 profile 次数上限。

5. **P1：收窄提交接口的重复手抄。** 十次 `submit_plan_reading` 中九次被拒，主要是 note 对象引用和
   `wall_reference.dimension_basis` 语法；最终通过删除 `wall_reference` 才接受。提交工具应直接复用已通过
   trial 的 wall reference、unresolved 和对象身份，只让 reader 添加必要决策；若仍允许覆盖，应返回可选
   对象的规范引用和字段级最小修正，而不是让模型多轮猜字符串格式。这是明确的请求浪费来源，但尚未测得
   改接口后的实际节省量。

6. **P2：批量暴露同阶段问题。** 在不改变严格 compiler 的前提下，反馈可一次列出同一阶段所有可独立
   发现的无宿主开口、未支撑 footprint 边和重复 seed。依赖上一项修复后才出现的问题仍应顺序处理，避免
   把不可同时发现的错误数量当作反馈缺陷。

## 仍属猜测，不能据此下结论

- 62.1% 高于旧 v53 全案的 39.94%，但任务范围、上下文、请求序列和运行阶段不同；不能归因于 30%
  压缩保留比例，也不能据此声称缓存或速度已经改善。
- 单次 F1、不同任务文本且无同任务对照，不能证明分工模式相对单模型更快、更省，也不能证明
  自有 runtime 相对 Claude Code 更优或更差。
- 四次 compaction 与后续请求并存，只能报告行为；没有反事实运行，不能判断 compaction 导致或避免了
  重读，也不能把本轮 57.8 分钟归因到某一项 runtime/domain 修改。
- 14 个参考房间都有几何匹配不代表空间语义和连接正确；反过来，严格 2 cm 阈值造成的小偏差 severe
  也不应与 140 m² 虚构空间混为同等严重。下一轮验收应分别报告重大拓扑/完整性错误和微小位置偏差。
- 当前只证明已提交 F1 为 severe；没有整案运行，也没有自动重跑或 provider fallback，不能外推整案通过率。

下一轮在再次调用 work model 前，可先用现有原图和已保存声明离线验证两条门：凹形/void footprint 不被
整体尺寸矩形填满，观察到的门窗清单在提交前全部核销。真实对照若获授权，应固定同一任务、原图、模型、
reasoning effort、入口与评分范围，并分别报告质量、墙钟、请求、实报输入/cache-read/输出，避免由本次
单样本推导因果提速。
