## 范围与验证

主要研发方向为 runtime + domain 的分工模式，单模型模式保留参照。当前没有证据证明分工能稳定更快，也没有达到 runtime 轻量且在速度、消耗、缓存方面优于 Claude Code 的目标。

1. domain/kernel：修复上一轮尺寸对齐异常、接头误差放大、有效台阶退化；用原始声明和最小反例验证连接、正交与有效几何保持，不把编译通过当作质量恢复。
2. runtime：修复并发预算在途预留引发的永久停止，保留真实异常诊断和不确定写入保护；用已有请求记录检查压缩与缓存复用，控制输入量、运行开销、依赖和维护复杂度。
3. domain/tools、roles、guidance：统一首稿字段与示例，缩减不必要的声明负担，提供具体可执行的返工反馈；保持原图空间、墙、门窗和连接的验收。
4. 先做离线重放与模拟并发；通过后做一次 GLM 订阅 `glm-5.3-flash` / medium、sm25 一层平面读图员小测，从原图冷启动，使用分工模式相同入口并保留全部行为与原始回执。单层未通过不追加整案；单层通过后再判断整案的具体条件与范围。不自动重复抽样。

GT 只在评价侧；不将开发纠错注入 work model。保留严格门窗位置分歧裁决、截断工具不执行与不确定写入阻断。DeepSeek、Claude、Paratera 和付费回退不在本次调用范围内。

## 已集成改动

- **domain/kernel**：同时移动共线轮廓边；近接头随垂直方向的宿主墙移动；拒绝把平行小间隙拖成斜墙、把有效短台阶压为退化边。三份原始失败声明的纯函数重放确认这些缺陷消失，但原声明的其他错误仍严格失败。见 [kernel 报告](kernel_report.md)。
- **runtime**：根预算的秒数暂被在途请求占满时等待结算；等待前释放调度位置，重试也使用相同逻辑。真实耗尽、墙钟到期和历史未结算请求仍停止。持久记录等待起止和安全异常诊断。见 [runtime 报告](runtime_budget_report.md)。
- **domain/tools、roles、guidance**：统一首稿字段，反馈给出对象与可执行修改；已知失败声明带哈希核验的原稿进入返工。未知执行、缺少执行结果和孤儿回执不作为可编辑基线。完整回执保留，模型所见反馈去重。见 [首稿与返工报告](draft_report.md)。
- **domain 的 runtime 配置与行为观察工具**：读图员压缩后保留比例改为 30%，离线同历史输出重放的输入估算减少 8.95%；这不等于实际缓存提升。观察器区分请求/响应、工具失败/未知、成功试建/提交，并记录预算等待。见 [缓存与观察报告](cache_observer_report.md)。

以上 kernel 为两种模式共用；首稿、返工和压缩策略主要影响分工模式。未新增依赖，未增加角色或自动模型回退。

### 质量与行为结论

- **外形有实质错误。** 六点外轮廓把东北侧建筑外空白包入室内，生成约 140 m² 的虚构空间；左侧外形也存在错误。原图与最终叠加图均能直接确认。
- **空间与门窗未保真。** F1 参照 14 个空间，结果 17 个；匹配算法找到 14 组对应，不表示 14 个房间都正确。31 个参照门窗只匹配到 21 个，另 10 个未匹配；结果中额外未匹配的 `O_stub_passage` 是通道表达，不能简单称作“多一扇门”。21 组匹配门窗的沿墙端点误差中，15 组 ≤5 cm、3 组 5–10 cm、1 组 10–30 cm、2 组 >30 cm；此统计不含垂直方向偏移和漏项。
- **评价边界。** 固定参照使用 2 cm 房间边界阈值，会把微小偏差也标为 severe；本次拒收依据是原图确认的错误外形、虚构空间、错误拆分和门窗漏项，不靠微小尺寸偏差或连通代理分数下结论。只评价已分配的 F1，不扣未分配楼层或立面分数。
- **前期测量投入大，整体错误未被发现。** 首次试建前用了 28 次像素剖面查看，21 次找到候选、7 次为空；不是简单重复同一请求。模型后续补看局部图、增加有效隔墙并返工，但外轮廓理解一直错。成功试建只说明几何能编译，内部差异检查也不覆盖整个外轮廓。
- **接口仍有负担。** 首次声明缺 `unresolved`，格式失败后没有可编辑草稿，模型仍尝试 operations；提交阶段又在 `notes`、`wall_reference` 等字段上反复被拒。此次改进没有消除这些真实摩擦，需要结合原始参数继续简化接口与反馈。
- **没有证据支持的解释不写成结论。** 四次压缩未发现导致重复取同一证据；也未证明慢主要由 runtime 本地计算或缓存造成。本次仍是单样本，不能据此断言模型能力上限。

## 下一轮安排

继续以 **runtime + domain 的分工模式** 为主要研发方向，单模型模式保留参照；不增加角色或框架层。

1. **domain/methods、guidance：先改善整体判断。** 用本次首稿与最终稿定位外轮廓、走廊和房间关系的误读，调整为在细部测量前形成可检查的整体草稿，并对原图检查边界与空白区域；替换失效说明，不累加一层层提醒。不要把单一成功顺序写死成唯一流程。
2. **domain/tools：降低首稿与提交的格式负担。** 对照真实 9 次提交拒绝统一字段、示例与报错；研究让已成功试建的结果直接承接提交所需信息，减少重复重述。保留图纸证据、未决项、对象完整性与未知执行保护。
3. **runtime：继续做有证据的效率优化。** 先离线比较真实请求中的稳定前缀、图片和压缩变化，区分本地准备时间、服务时间与真实命中；不把本次 62.1% 视作任务完成，也不先堆缓存或调度框架。
4. **验证顺序。** 先复用本次完整记录和失败参数做离线检查，固定版本及改动范围后，再提出下一次有界小测。以正确整体外形、空间关系和门窗覆盖为前提看时间与消耗；小测未过不推进整案。每次仍保留全流程行为、原始回执与独立看图复核。

这份安排是下一轮建议；本轮实际 work model 请求止于上述 40 次，没有自动补跑。
