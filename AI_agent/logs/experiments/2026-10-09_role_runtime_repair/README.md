# 分工模式可靠性与 runtime 效率修复

状态：2026-10-09 修复已集成，离线检查完成，准备启动已批准的单层小测。用户在确认下一轮方案后说“好的，开干吧”。

## 范围与验证

主要研发方向为 runtime + domain 的分工模式，单模型模式保留参照。当前没有证据证明分工能稳定更快，也没有达到 runtime 轻量且在速度、消耗、缓存方面优于 Claude Code 的目标。

1. domain/kernel：修复上一轮尺寸对齐异常、接头误差放大、有效台阶退化；用原始声明和最小反例验证连接、正交与有效几何保持，不把编译通过当作质量恢复。
2. runtime：修复并发预算在途预留引发的永久停止，保留真实异常诊断和不确定写入保护；用已有请求记录检查压缩与缓存复用，控制输入量、运行开销、依赖和维护复杂度。
3. domain/tools、roles、guidance：统一首稿字段与示例，缩减不必要的声明负担，提供具体可执行的返工反馈；保持原图空间、墙、门窗和连接的验收。
4. 先做离线重放与模拟并发；通过后做一次 GLM 订阅 `glm-5.3-flash` / medium、sm25 一层平面读图员小测，从原图冷启动，使用分工模式相同入口并保留全部行为与原始回执。单层未通过不追加整案；单层通过后再判断整案的具体条件与范围。不自动重复抽样。

GT 只在评价侧；不将开发纠错注入 work model。保留严格门窗位置分歧裁决、截断工具不执行与不确定写入阻断。DeepSeek、Claude、Paratera 和付费回退不在本次调用范围内。

## 已集成改动

- **domain/kernel**：同时移动共线轮廓边；近接头随垂直方向的宿主墙移动；拒绝把平行小间隙拖成斜墙、把有效短台阶压为退化边。三份原始失败声明的纯函数重放确认这些缺陷消失，但原声明的其他错误仍严格失败。见 [kernel 报告](kernel_report.md)。
- **runtime**：根预算的秒数暂被在途请求占满时等待结算；等待前释放调度位置，重试也使用相同逻辑。真实耗尽、墙钟到期和历史未结算请求仍停止。持久记录等待起止和安全异常诊断。见 [runtime 报告](runtime_budget_report.md)。
- **domain/tools、roles、guidance**：统一首稿字段，反馈给出对象与可执行修改；已知失败声明带哈希核验的原稿进入返工。未知执行、缺少执行结果和孤儿回执不作为可编辑基线。完整回执保留，模型所见反馈去重。见 [首稿与返工报告](draft_report.md)。
- **domain 的 runtime 配置与行为观察工具**：读图员压缩后保留比例改为 30%，离线同历史输出重放的输入估算减少 8.95%；这不等于实际缓存提升。观察器区分请求/响应、工具失败/未知、成功试建/提交，并记录预算等待。见 [缓存与观察报告](cache_observer_report.md)。

以上 kernel 为两种模式共用；首稿、返工和压缩策略主要影响分工模式。未新增依赖，未增加角色或自动模型回退。
