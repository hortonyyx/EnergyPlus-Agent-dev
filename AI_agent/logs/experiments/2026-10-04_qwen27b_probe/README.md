# 27B 摸底：Qwen3.8-27B 在新底座上单跑 sm24（10-04）

**目的：** 主力转向开源本地级之前，先摸清 27B 跑整案能做到什么程度，见[开发计划](../../../project/unified_agent_harness_plan.md)第七之二节 ③ 与 10-03 决定第②点。这不是节点回归，不和 GLM 比优劣；要看的是它能不能走完整案、错在哪一环、花多少钱和时间，为吸收包在 27B 上抽测、为转主力做准备提供依据。

**批准依据：** Paratera 开发期额度 50 元内由 Opus 安排（10-03 用户：“我先批准50块吧，这部分你可以自由调度测试”），10-04 开跑前已告知用户。批准以来估算已用约 5.7 元（按文字单价估算，没算图片重复计费，以账单为准）。

## 条件

- 配置 [`configs/sm24_qwen27b.json`](configs/sm24_qwen27b.json)。与同日节点回归的 GLM 两条线同原图、同任务正文（`task_sha256` `381c6092…`）、6000 秒、24 个候选、无委派；Agent 版本 `t1-20261004-a1t.1`。开跑前 `runtime_r1_preparation check` 通过，0 次模型请求。
- Paratera 不提供 medium 思考档，改用 `enable_thinking`。温度 0.7、输出上限 16,384 沿用 10-02 Paratera 小测的设置（那次 27B 两张立面都读对了；16,384 也是登记的最低推荐值）。运行底座默认温度 0.0 是贪心解码，Qwen 官方不建议在思考模式下这样用。上下文上限取模型原生的 262,144，估算 15 万 token 压缩，与 GLM 相同。
- **预计：** 约 45 次请求、400 万 token，10–20 元（按 10-03 账单反推的单价：文字 3、缓存 0.6、输出 12 元／百万，图片收两次）。**硬停 600 万 token**，最坏约 25 元。
- **时间：** GLM sm24 两条线结束、核过回执后，与新线路 sm25 同时开跑。

## 看什么

1. 能否在 100 分钟内走完整案并交付；报错、格式错误、截断补救的次数。
2. 质量：用同一套 sm24 评分（房间、挂墙、连通、位置、外部高度），只作摸底，不判合格。
3. 行为：首稿时刻、平面建模次数、高度依据从哪来，失败出在哪一环（看错、对象对应错、执行错、发现了没改）。
4. 用量与花费：请求数、token（含缓存）、底座估算金额；账单出来后对账。
