# runtime 可控续跑与日志开销迭代

用户授权：先迭代 runtime，需要测试时优先使用 GLM 订阅。基线 `83cf373b`（runtime v2 / domain v57），实施依据为 [独立审阅](../../reviews/2026-10-10_runtime_independent_review/summary.md)及[执行范围](../../../workflow/runtime_iteration_brief_20261010.md)。最终实现登记为 runtime v5 / domain v60，生产提交 `f54dd9f3`，登记提交 `b27405fa`；domain 变动为恢复接线、配置与 Windows JSON 编码修复，建筑规整和读图方法留到 domain 下一轮讨论。中途登记的 v3/v58、v4/v59 及全部旧版本保留不变，工具/指引模式指纹未改变。

## 实现

| 改动 | 现在的行为 | 保留的边界 |
|---|---|---|
| 定向控制 | 持久化 message / pause / resume；同 ID 幂等，任务日志有接收回执，重启不重复注入 | 在完整交互边界暂停；不强杀 HTTP，不重置墙钟；接收不等于模型已执行纠正 |
| 预算恢复 | 可证明未发送的预留追加释放；缺 usage 可绑定原请求、结算和证据补账 | 未知费用不填零；保留原未知记录、原费率、原额度 |
| 工具恢复 | 明确允许的纯读取可有界重取；委派保存完整展开批次，按原 task ID 续跑并复用已完成结果 | read_only 权限不自动等于可重放；未知非幂等写仍拒绝盲重试 |
| 日志与账本 | 增量验证、按任务/预算投影索引；预算缓存按请求、响应和预算变化失效 | fsync、哈希、单写者锁、打开和独立审计的完整校验保留 |
| 配置和计时 | 实际 endpoint 与公开路由身份同源；角色上下文设置贯通；拆出请求准备、发送、解析、检查点等计时 | 密钥不入日志；阶段可重叠，HTTP往返不冒充纯模型生成时间 |

使用方式见[控制与恢复说明](../../../workflow/runtime_controls.md)。无需增加新的角色或通用消息平台。

## 独立复核后的补齐

复核发现：释放记录已存在时，主循环仍把保留的原预留视为孤立预留；补账后的恢复仍可能读取原 response 中的未知 usage；自动补齐的读图任务在部分子任务启动后重启会从委派批次丢失。本轮将这些问题纳入恢复接线和回归检查。

初轮 824 项相关集成检查得到 793 通过、30 失败、1 跳过，耗时 824.53 秒，保留原始 [JUnit](integration.xml) 与失败清单。失败分为：新增诊断计时误用测试注入的业务时钟、早停路径尚未初始化计时状态、Windows 默认 GBK 读取 UTF-8 BIM JSON，以及两项需要更新的测试约束（1 ms 的实际磁盘操作期限、锁定整个传输模块源码）。生产修复明确分离计时钟、在构造时初始化诊断状态、显式读写 UTF-8；测试仍检查实际请求超时上限、首请求准备逻辑和 prompt/tool/input 一致性。新增两项强制 GBK 的回归验证实际建模源文件、图像复读、候选判定、工具日志和 continuation receipt。

v4/v59复验51项仍有24失败：诊断计时还有两处响应解析调用未隔离；`ClaimStore.candidate`仍按GBK读proposal/source，导致高度与立面反馈不可用、声明修订失败，且在写交付选择文件之前抛错。三个分工流程的runtime receipt虽为completed，却缺实际交付选择文件，不能算E2E通过。75步回放首个新增非预期错误在第59步修订，后续候选缺失是其连锁结果；失败现场保留在本地 `archive/local_backup/2026-10-10_runtime_control_iteration_frozen75`。v5/v60补齐四处实现行，保留原断言并针对真实报告/source哈希和无诊断钟的注入时钟增加回归。最终E2E以交付文件、写入去重、原75步的错误序列及状态覆盖共同判定，不只读取completed。

最终只读独立复核再次检查控制 ack/checkpoint 崩溃边界、原 task ID 委派恢复、有效补账的使用及增量索引的落盘顺序，未发现新的高影响集成缺口。`applied` 只表示指令已进入任务，纠正是否有效仍要观察模型后续行为。

## 质量与后续边界

本轮没有新开真实模型的 sm25 BIM 整案，没有新的几何精度、空间划分或门窗质量分数。离线夹具会生成工具产物，但不能作为模型建模质量证据。协议通过只证明可介入和可恢复的运行机制；sm25 减负建模目标仍待 domain 迭代后的整案验证，也尚未证明 30 分钟达标或优于 Claude Code。10-10 原失败实测及其未知用量保持冻结。
