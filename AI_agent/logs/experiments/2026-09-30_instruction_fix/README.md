## 自动检查的离线验证

[验证脚本](drawing_differences_validation.py)：用三个案例事先由开发侧从原图整理的参照（门窗像素位置、房间内部点）冻结标注，标注不调用检查本身；再对 108 份历史编译草稿（sm21 64、sm24 21、sm25 23；GLM 与 Sonnet，09-20 至 09-29）运行检查并逐对象对照。报告分两级：逐对象条目，与“完全未声明隔墙”的整层提醒（单列，不计入逐对象检出）。门洞报告须与门标注在同一面墙（垂直墙向位置差 ≤0.3 m、沿墙重叠过半）才算匹配；“墙线不足”只匹配位置相关的标注。[标注](drawing_differences_labels.json)、[结果](drawing_differences_results.json)（含每稿检查状态与逐对的下一稿结果）、[人工判定](drawing_differences_adjudication.json)。

| 项目（105 份实际检查的草稿；3 份比例错误被跳过） | 结果 |
| --- | --- |
| 没有任何标注差异的 43 份草稿 | 0 条报告 |
| 缺分隔关系（参照房间点落进同一声明空间，由参照点合并构造，不等于同数独立墙） | 逐对象 15/31：sm21 12/12、sm24 3/6（漏的是同一种东南折角并房）、sm25 0/13（13 处全在 run50 一份未声明任何隔墙的草稿里，由整层提醒覆盖：报 15 条接到外墙的双线） |
| 明显错位门（与参照重叠不足一半） | 5/5 |

| 门端偏差 >0.10 m | 123/141（报告阈值 0.15 m） |

| 下一稿修好后报告是否消失 | 逐对象口径下被下一稿修好的 4 处，报告全部消失；未修的 41 处报告仍在；run50 的整层提醒在下一稿声明隔墙后消失 |

局限：参数是在这批草稿上调出来的（起初 12 份小试，全量后暴露 sm24 家具双线、sm25 双开门等问题才改），没有独立留出集，run98 才是第一份新数据。“本数据集上零误报”不能推广：Astra 构造的“开敞房间加三张双线桌子”反例曾让整层提醒误报，已把整层提醒限定为“接到外墙且长于 2 m 的双线”并写成测试。只覆盖三个 CAD 风格案例；外墙窗、立面高度、单线墙、斜墙不检查；“用通道代替假墙”（sm25 GLM）与折角墙并房未能报出。报告只陈述墨线事实，不认定墙或门。

## 回归（仅 run98 获准执行）

条件：sm21，`claude-sonnet-5` / medium，3000 秒，24 候选，0 续查，禁委派，原图冷启动；`python AI_agent/logs/experiments/2026-09-30_instruction_fix/batch.py run --run run98`，读真实回执后再做任何后续步骤，429 即停、不重试。评价：[evaluate.py](evaluate.py)，在原有 sm21 审计之外加两项严格判据——房间与参照一一对应（审计须完成、两层都在、参照点与候选房间双向恰好一一对应）、外墙门窗高度逐个 0.05 m 以内且两边都无未配对项（run57/58 均达标：一一对应、17/17；run93 为一一对应、15/17；run94 为三间合一、9/13 且各有 4 个未配对）。

约束如实说明：本脚本只启动一次、不重试，但不能控制 Claude CLI 内部的请求重试；“禁委派”只写在任务提示里，`review_detail` 工具仍对模型可见（审计会检查它没被调用）。
