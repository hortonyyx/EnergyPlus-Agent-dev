本节点由Astra独立开发、执行和事后复核，按用户要求继续还原建模。用户同时澄清：房间类型尽量选择合理类别，允许推断及后续修改，不追求用途细类唯一真值；源几何和连接要求保持。

## 冻结任务

run66生产实现提交：`2e15c2aa`；run67使用`eb16d19a`，只追加通用整图依据入口及指引。`run_recovery.py`冻结任务、五张原始PNG、run65/candidate_01 proposal及旧3份模型声明的摘要。旧声明原文进入任务，须先作为未采纳记录查看，再由模型自行决定保留、改正或撤回；不导入旧采纳/确认文件，不提供原图评测、GT、修正框或开发助手的房间/高度答案。

这是**明确限定任务的保存稿和未核验声明恢复**，不是冷启动，也不是工具与提示因果对照。产品模型通过现有Claude订阅调用Sonnet、medium，1800秒总时限，可选至多2轮同档续查；禁止产品委派。实际模型、时长、用量和结束状态以各run回执为准。

新增MCP反馈直接显示所记录区域的实际裁图，最多自动返回3张；其余区域及放大可用`view_claim_evidence`查看。旧记录不可变，新解释须另记并撤回旧解释。代码既不读懂标注，也不自动把看到的图转成正确判定。

run66确实撤回旧框，但新框仍有截链、错用门链为窗链的问题。因此第二步允许`sources`只填写图片名，由代码绑定原图完整范围；既不自动修复旧框，也不提供正确坐标。两次任务/输入相同，但生产实现不同，不称冻结重复或因果证明。run66的40份生产文件已保存到自己的`runtime_snapshot`，原始模型流无损gzip归档。

## 验证方法

- 离线104项不同检查最终通过：初步裁图/用途实现覆盖45+58=103项；整图入口新增1项，并重跑claims/state/height/shape/continuation合计50项通过（其中49项是重复，不加到不同测试数）。新图像试件最初忘同步输入摘要、错误消息断言过窄，修正两处测试后通过；未因此放宽原图校验。
- `audit_run.py`只在生成完成后调用已有独立原图/GT诊断，维持原容差；检查实际源/显示重导出、输入与实现摘要、几何保持、实际调用及图像传输，并明确补记旧声明也是生成输入。
- `claim_crops.py`导出所有实际引用区域，并将模型流中真正收到的图逐像素与保存原图的相应裁图比较。裁图符合引用框仍不等于引用了正确标注，语义结论另由实际看图记录。
- 实际Claude CLI保留图片、用structuredContent合并文本；首次审计解析器只识别逐图文本，断言失败后已支持实际的`evidence_previews`数组，并逐像素通过。此为离线审计适配，不改变生成产物或生产实现。
- 复用房间类型节点的离线浏览器检查：实际WebGL、旋转、楼层/空间/表面选择、功能颜色、来源与推断文字。
