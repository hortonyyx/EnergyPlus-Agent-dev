# run99 长记录夹具

本夹具只用于离线验证长任务、压缩和恢复。它不是一次新的模型运行，也不重新判定 run99 的建筑质量。历史源保持只读，模拟写入只发生在 pytest 临时目录里的源 BIM 副本。

## 取材与数据形态

来源是 `AI_agent/logs/experiments/2026-09-30_sm21_instruction_fix_run99/`。其中 `agent_stream.jsonl.gz` 有 829 条运输记录，能一一配对出 75 个模型工具调用和 75 个工具返回；`tools.jsonl` 有 79 条服务端审计记录，两者数量不同，是因为服务内部的派生动作没有逐一成为 Claude CLI 的直接工具调用。长任务夹具采用可从模型侧真实观察和恢复的 75 对，不拿 79 条审计记录补造模型轮次。

75 步包括 56 次只读动作、19 次不可安全重复的写动作和 7 个历史原样保留的报错。动作覆盖看原图、区域总览、像素剖面、两层构建、多层装配、声明、修订、开口检查、候选检查和最终交付。脚本模型在每一步只发一个工具调用，最后追加一条固定结束回答，因此离线运行共有 76 个脚本模型响应。

图片共有 67 个返回块、56 个唯一哈希，按历史返回顺序合计 2,259,103 字节。21 个图片块可直接命中历史目录里的独立 PNG；其余 46 个带坐标网格或局部裁切的返回图只存在于无损压缩流中。清单对前者记录文件路径，对后者记录 gzip 文件、JSONL 行号和块路径；两类都记录 SHA-256、媒体类型和字节数。测试取回时先从历史源读取，再按清单验哈希，不在新夹具中复制 base64。

## 文件

- `build_long_fixture.py`：只读提取器；核对调用/返回配对、图片字节和源文件，生成下面两份清单。
- `run99_long_fixture.json`：75 步的紧凑脚本清单。大参数、文本返回和图片不复制，只记历史流定位及哈希。
- `source_manifest.json`：三个直接源的路径、大小与 SHA-256，动作和图片统计，以及所有改编说明。
- `tests/test_runtime_long_task.py`：清单加载器、严格历史字节恢复、脚本模型响应工厂、隔离写模拟后端及长任务故障检查。

生成命令：

```bash
PYTHONPATH=$PWD PYTHONDONTWRITEBYTECODE=1 \
  TMPDIR=$PWD/.stage2_tmp/long_fixture_tmp \
  python AI_agent/logs/experiments/2026-10-02_harness_stage2/build_long_fixture.py
```

## 改编边界

历史并发工具调用被依原顺序拆成一轮一个工具调用，以便在明确的轮次边界注入故障。工具名前缀 `mcp__bim__` 被机械去掉，以匹配冻结运行器目录。Claude CLI 的返回块仅作协议字段转换：文字、图片块顺序、媒体类型和图片字节不改。自然语言、私有思考、限流事件、时间戳和最终 CLI 回执不进入脚本行为断言，仍留在历史源中。

脚本里的 token 用量（每次 10 输入、10 输出、20 合计）是明确标注的离线测试数，不是服务用量；金额未知。六层版本统一使用 `run99-fixture-v1` 合成戳，也只是测试身份；实际六层版本证据由真实冻结入口归档保存，不在本夹具中补造。模拟后端会把历史保存的 `candidate_05/source_model.json` 复制到测试临时目录，并用独立操作账记录每次成功写。它用于证明恢复后没有重复执行写，不代表历史工具被真实重放，也不证明源 BIM 再次通过质量验收。

未知写结果遵循保守边界：返回路径丢失后只查状态并安全停止，保留已写的隔离 BIM；文件变化不能证明远端操作已成功，也不能据此自动继续或重试。
