## 接口结论

如果模型判断需要恢复一个被合并的实际空间，现有 `revise_bim` 局部操作无法完整表达：

- `reshape_spaces` 只能替换已有空间 ID 的多边形，不能新增空间；
- `replace_space_region` 只在两个既有相邻空间的并集中重新分配面积，空间数保持不变；
- `move_shared_wall` 只支持两个矩形空间共享一条完整边，不能处理新增分隔或折角走廊；
- `update_opening`、`update_window` 只能修改既有对象，不能增加或拆分对象。

因此需要增加空间、拆分跨新分隔的窗，或补充新开口时，应提交完整 `build_bim` proposal；`build_plan_bim` 也能从完整像素墙网重建，但本次没有把旧 plan 放进冻结输入，不能要求运行中补入。

run18 seed proposal 没有 `enclosure_declaration`、`wall_references` 或 `wall_dimensions`，相关特殊拒绝条件不是本次障碍。真正约束是：所有空间仍须无缝覆盖矩形 footprint、没有重叠或洞；非矩形空间须是单一无洞正交环；门必须完整落在一个外墙宿主或两个内墙宿主上，不能跨墙结点。

## 局部恢复会牵动的对象

恢复中段实体分隔或南端连续走廊时，不能只改空间多边形：

- 东侧空间若被拆开，现有 D4、D5 的两侧空间需重新核对；
- O7 当前由一个空间独占，若新分隔切开其外墙宿主，可能需要拆成多个窗，局部更新接口做不到；
- 走廊延伸或折转会改变 D3、东外门 O8、南门 O11 的可能宿主；
- O9 位于同一受影响东侧/南侧范围，也需检查是否仍完整落在一个实际外墙段；
- D1、D2 以及未受影响的北、西、南立面对象应逐对象保持，不能只比较总数。

## 本次最短运行路线

1. 先读取 seed proposal，并把完整未改观察当作待核 claims，不直接抄成几何；
2. 只围绕中段墙端接、门洞和连续走廊回看原图；

4. 查看实际返回的 source plan 和原图回叠，重点检查墙端接、走廊连续性及受影响门窗宿主；
