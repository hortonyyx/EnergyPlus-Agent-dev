# run05 门洞、分区与来源文字复核（开发助手）

本记录复核最终 `candidate_01/proposal.json` 与 F1/F2 原平面、南立面及 F1 候选平面。它只检查此前发现的分区方向、假门、重复/错连门和小窗位置；**不是 GT 自动验收、人工批准、完整图纸保真结论或生成模型输入**。

这版没有发现此前四类严重问题：F1 的 `D_F1_N2_Cb`、`D_F1_S2_Cb` 已删除；第二条隔墙上下各只保留 N3/S3 一扇门。F2 只保留 O1--O4 各一扇通向走廊的门，端部重复的 `D_F2_O1_C`、`D_F2_O4_C` 已删除，也没有办公室互通门。房间南北行与立面模式一致。入口旁的小南窗已移至正确的粗略位置，但尺寸和窗台仍是明确标注的推断。

F1 第二隔墙的放大原图证据是：上方 N2 左侧墙在 `[1200,542,1384,624]` 连续，只有 N3 侧 `[1385,542,1469,624]` 有门扇/弧线；下方 S2 左侧 `[1200,809,1384,891]` 连续，只有 S3 侧 `[1385,809,1469,891]` 有门扇/弧线。此前快速检查误把左侧当成门，本记录已按放大原图纠正。

F2 的四个真实办公室门均在相邻办公室分界的走廊侧：O1/O2 为 `[657,793,740,875]`、`[807,793,890,874]`，O3/O4 为 `[1350,793,1433,875]`、`[1500,793,1583,874]`。候选的 `other_space_id` 都是 `F2_Corridor`。本轮没有保存 F2 候选平面 PNG，因此这是最终 proposal 关系结合原图的核查；门宽仍不作为精确验收。

仍有细微或未核实项：西侧外门建模宽度 1.2 m，图上约 1.5 m；F2 M1/M2 门宽沿用近似；所有门状态未知。这些没有构成新的漏门、多门或错连证据。

来源记录也有边界。run05 新删门的旧对象完整保存在 `geometry.corrections.before`，留下的 `D_F1_N3_C`、`D_F1_S3_C` 已把单弧证据回写到活动 `source_refs`。但 F2 的 `D_F2_O1_O2`、`D_F2_O3_O4` 在来源传播功能加入前已修订，活动 ID 和 `source_refs` 仍写成“office1/2”“office3/4”的旧措辞；实际连接已是走廊，审计记录也有更正说明。这是遗留的命名/证据文字歧义，不是现有室间错连。小南窗的活动来源仍写“assumed size”，审计又有像素/尺寸链依据，且对象假设保留了尺寸未完全定尺的限制。新 helper 只会传播后续更新来源，不能据此称 run03/run04 的所有旧文字已自动清理。
