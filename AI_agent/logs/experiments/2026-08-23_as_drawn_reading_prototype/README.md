## 一、⭐ 认与量彻底分开了：perception 是一份**独立文件**

`perception/<case>.json` 由**做识别的那一方**产出（今天是主控亲手，将来是 reading 模型），
配置只写一句 `"perception": "<path>"`。它承载**两件都属于「认」的事**：

| 字段 | 内容 |
|---|---|
| `family_roles` | 哪个**被发现的**墨迹族是墙 / 标注 / 家具 / 门窗 |
| `wall_pairs` | 哪两条面线是**一堵墙**（从代码穷举的候选里选） |
| `solid_band_walls` | 哪条面线**自己就是一堵墙**（实心带方言，两条边即两个面）|
| `unpaired_wall_faces` | 是墙面、但另一面没进观测（⛔ 不许硬配） |
| `non_wall_face_lines` | 不是墙，**并说明是什么** |
| `ambiguous_face_lines` | ⭐ **「我认不出来」** —— 模型必须被允许这么答 |

**⛔ 代码不再按声明厚度筛配对。** 候选 = 同轴 + 支撑列不相交 + 沿墙有重叠，**不设间距阈值**；
声明的 callout 只当**标签**贴上去。旧的「按声明筛」正是 sm24 整批 120 mm 隔墙被静默丢掉的机制。

**没有 perception 就响亮降级**（`pairs_status = ABSENT_NO_MODEL_SELECTION`），
⛔ 绝不拿一条代码规则冒充模型的答案。

### 本轮认出来的三件事（⭐ 都是代码分不出的）

1. **sm25 的 `240` 厚度标注文字是用「和墙一样的无彩色」画的** ⇒ 它的笔画进了结构族，
   被读成 5 条 0.30 m 长的「面线」（1f 的 L003/L018/L035/L036/L049，2f 的 L001/L004/L005）。
   ⭐ **代码排不掉它们**：笔直、无彩色、最近邻居的间距还恰好合法（L035↔L033 = 0.119 m）。
   8× 放大后一眼是数字笔画。
2. **族编号跨图不稳定**：1f 的墙是 F0，**2f 的墙是 F1**（F0 在 2f 是标注）。
   ⇒ 结构上没人能写死「F0 = 墙」。
3. **sm24 没有家具图层**（家具族实测 0.00% 墨）⇒ 98 条面线里绝大多数是桌椅沙发，
   而它们和墙同色。本轮**只对 20 条下判断**（4 条实心带外墙 + 8 对内墙），
   **其余 78 条显式记为「认不出来」** ⇒ 对账门**降级**而不是给一个自信的绿。

## 三之二、⭐⭐⭐ 可评分分母 + reading 判分器（2026-08-24 晚，三审最小前置组第 ① 条）

三审把这条列为动 gt 的**第一道门**：「哪些 primitive / run 是 reading 必须画出来的，没给机器规则」。

### 分母 = 五条机械规则（`tools/denominator.py`，`denominator_v1`）

| | 规则 | ⛔ 为什么 |
|---|---|---|
| **D1 来源** | 该平面视图墙层上的每条 LINE（用转换器自己的采集，⛔ 不另写一遍「什么算墙线」）| 重算必须复刻生产者的定义 |
| **D2 排除** | **门垛短线**（洞口/墙端的横断笔）—— **只审计、不计分** | 它是厚度证据，不是面 |
| **D3 分组** | 剩下的按（方向, 常坐标）成组 = 一条画出来的面线 | |
| **D4 合并** | 组内间隔 ≤ `merge_m` 的碎片并成一个 run | 碎片是 CAD 的，不是图纸的 |
| **D5 目标** | 每个存活的 run = 一个可评分目标 `(axis, const, lo, hi)` | |

**不计分且写明的**：门垛（D2，审计）· 非墙层的一切（文字/家具/尺寸/洞口块）——
⚠️ **必须写明的不对称**：在 DXF 里这些是**按图层**分开的（免费），
在栅格里读图器得**认**出来（sm25 的 `240` 标注文字就是用墙的颜色画的）
⇒ **分母干净不等于任务容易**，这是答案源的性质，不是对难度的判断。

**参数扫描**：⚠️ **初版这里写的「0.40–0.80 干净平台」是假的**（那次扫描在 D2 改之前跑的，改完没重扫；
四审证伪，见 §三之三）。**加了「不许跨洞口合并」之后**才真的不承重：
`merge_m` 0.30–1.20 恒 **110 个目标 / 282.28 m**。

### ⛔ D2 第一版是错的，而且错得很典型

初版把门垛判定**完全委托给转换器自己的集合**（理由：「复刻生产者，别自己重写」）。
**实测证伪**：转换器判门垛**只看长度**（落在墙厚区间 [0.06, 0.50] m 即算），
而 sm25 走廊墙上**连着 7 樘门**，门与门之间的**真墙面片段只有 0.36 m** ⇒
**59 条真墙面被从答案里删掉**，reading 反被判了 **21 m「多画」**。

⇒ D2 改为**按几何**判：一条笔画是门垛，当且仅当它**横跨在两条对向长面线之间**且不长于最厚的墙。
**实测**：sm25 1F 几何规则排除 **65** 条，转换器的长度规则会排除 **124** 条。

⭐ **教训的边界**：「复刻生产者」适用于**生产者拥有的那个量**；

## 五、⛔ 本轮查出的新缺陷 **F-86**（未修）

**症状**：sm25 2f 的一堵隔墙**只有一个面进了产物**（`L012`，x=9.15，y 0.2–3.89 m），
它在候选表里**最近的伙伴在 3.795 m 外**。

**实测根因**：`_ink_groups` 里一句
`along = keep[:, g].mean(1) >= FILL_RATIO` —— 一个列组的某段墨迹只要**不是组内多数列**都有，
就被整段丢掉。实测列 655 在第 1080–1249 行有 **170 px** 墨迹，而它所在的组是 653–656（4 列）⇒ 0.25 < 0.5 ⇒ 丢。

**候选修法已实测，⛔ 但不采纳**：改成 `keep[:, g].max(1)`（任一列有就留）后
sm25 gt 侧 93.3 → **94.7**、sm24 仍 100.0，**但 sm24 有 5 个洞口断口被整个填平**
（实心带方言里一列门垛就把断口补上了）⇒ **会静默 heal 洞口**，代价比收益大。
⇒ 正解应是**按 run 兼容性拆分列组**，归下一轮。

**本轮的处置**：`L012` 如实记进 `unpaired_wall_faces`，⛔ 不与任何线硬配。
