## 〇、一句话形态

```
observations   尺子在像素上量到的        ← 唯一可评分层
declarations   图纸/配置声称的，逐字转录   ← 只比字面
hypotheses     认出来的，带证据引用        ← ⛔ 不直接计分、可整层丢弃
```

**代码穷举候选 · 模型做判断 · 代码事后对账。** 三件事分别落在：
`tools/as_drawn_v2.py`（量 + 穷举）· `perception/<case>.json`（认）· `tools/checks_as_drawn_v2.py`（对账）。

## 一、⭐ 认与量彻底分开了：perception 是一份**独立文件**

`perception/<case>.json` 由**做识别的那一方**产出（今天是主控亲手，将来是 reading 模型），
配置只写一句 `"perception": "<path>"`。它承载**两件都属于「认」的事**：

| 字段 | 内容 |
|---|---|
| `family_roles` | 哪个**被发现的**墨迹族是墙 / 标注 / 家具 / 门窗 |
| `wall_pairs` | 哪两条面线是**一堵墙**（从代码穷举的候选里选） |
| `solid_band_walls` | 哪条面线**自己就是一堵墙**（实心带方言，两条边即两个面）|
| `unpaired_wall_faces` | 是墙面、但另一面没进观测（⛔ 不许硬配） |
| `non_wall_face_lines` | 不是墙，**并说明是什么** |
| `ambiguous_face_lines` | ⭐ **「我认不出来」** —— 模型必须被允许这么答 |

**⛔ 代码不再按声明厚度筛配对。** 候选 = 同轴 + 支撑列不相交 + 沿墙有重叠，**不设间距阈值**；
声明的 callout 只当**标签**贴上去。旧的「按声明筛」正是 sm24 整批 120 mm 隔墙被静默丢掉的机制。

**没有 perception 就响亮降级**（`pairs_status = ABSENT_NO_MODEL_SELECTION`），
⛔ 绝不拿一条代码规则冒充模型的答案。

### 本轮认出来的三件事（⭐ 都是代码分不出的）

1. **sm25 的 `240` 厚度标注文字是用「和墙一样的无彩色」画的** ⇒ 它的笔画进了结构族，
   被读成 5 条 0.30 m 长的「面线」（1f 的 L003/L018/L035/L036/L049，2f 的 L001/L004/L005）。
   ⭐ **代码排不掉它们**：笔直、无彩色、最近邻居的间距还恰好合法（L035↔L033 = 0.119 m）。
   8× 放大后一眼是数字笔画。
2. **族编号跨图不稳定**：1f 的墙是 F0，**2f 的墙是 F1**（F0 在 2f 是标注）。
   ⇒ 结构上没人能写死「F0 = 墙」。
3. **sm24 没有家具图层**（家具族实测 0.00% 墨）⇒ 98 条面线里绝大多数是桌椅沙发，
   而它们和墙同色。本轮**只对 20 条下判断**（4 条实心带外墙 + 8 对内墙），
   **其余 78 条显式记为「认不出来」** ⇒ 对账门**降级**而不是给一个自信的绿。

| `opening_role_matches_where_the_ink_sits` | ⭐ 叫「门窗」的族，墨迹真长在墙的断口里吗 | 🟢 | 🟢 | 🟢 |
| `pair_hypothesis_reconciles_with_observations` | 引用在不在 · 有没有一线两卖 · 支撑是否重叠 · **有没有面线没人认领** | 🟢 | 🟢 | ⚪ **降级**（78 条未认领）|
| `pair_spacing_explicable_by_callouts` | 量到的间距，图纸自己的 callout 解释得了吗 | 🟢 | 🟢 | 🔴 **8 条**（见下）|
| `forward_ledger_structural_ink_claimed` | 有没有结构墨迹没人认领 | 🟢 2.77% | 🟢 1.74% | ⚪ **降级**（无家具图层）|

### ⭐ sm24 那 8 条红是**对的红**

8 堵内墙实测间距 **0.1238–0.1262 m**，而图纸 callout **只声明了 240**。
⇒ 判据说的是「**图纸的标注解释不了这个测量值**」，⛔ 不是「这个测量值错了」。
**模型照样把它们选成了墙，它们就活下来了** —— 这正是新分刀的整个论点：
**声明不全时，代码会静默丢墙，模型看图不会丢。**

### 两条判据是被自己的假绿逼出来的（都记在代码注释里）

- **`edges_m` 从来没有消费者** ⇒ 它是个藏东西的地方。变异 `widen_all`（谎称每条线都是 0.24 m 宽带）
  在其余四条判据下**全绿**；加上「必须能从自己的像素重算」后**变红**。
- ⚠️ **这道新门第一版差点误伤诚实产物**：sm24 偏 **1.480 px**，门是 1.5 px。
  真因是**我的重算公式偷设了「墨迹质心 = 支撑列中点」这个生产者从没做过的假设**。
  按生产者自己的仿射映射逐边重算后，三份诚实产物最大偏差 **0.004 px** ⇒ 门与它差 **400 倍**。

## 四、立面结构线反证 v2（`tools/reconstruct_elev_lines_check_v2.py`）

二审实测 v1 的假绿：**把 `runs_m` 全清空，仍然 24/24**。v2 补了三件：

1. **比完整绘制范围**，不只比坐标 —— 目标的「另一根轴该画多长」同样由现有 gt 字段推出
   （楼层线 → 该立面各段 `world_along_interval` 的并集；轮廓线/台阶线 → 相关楼层的 z 区间）。
2. **一对一 assignment**（`linear_sum_assignment`）—— 一条线最多满足一个目标。
3. **按 view 取该立面真正有的楼层**，⛔ 不再对每个立面都取全部楼层。

| | 结果 |
|---|---|
| 诚实产物 | **24/24**（进深台阶 4/4 · 楼层 12/12 · 轮廓 8/8）· 最大误差 **0.0065 m** · 最低跨度覆盖 **0.9655** · 未预测线 **0** |
| `clear_runs`（**v1 的假绿**）| **0/24** |
| `shrink_runs`（只留中间 30%）| 0/24 |
| `shift_lines`（整体平移 0.10 m）| 0/24 |
| `drop_vertical`（删掉全部竖线）| 12/24 |
| `spray_lines`（每条旁边撒 3 条假的）| ⚠️ **24/24 免疫**，只有 `unpredicted_lines` 0 → **72** |
| `duplicate_line`（0.2 mm 孪生）| ⚠️ **24/24 免疫**，`unpredicted_lines` 0 → **24** |

⚠️ **如实记**：后两种**分数分辨不了**，只有旗标能分辨。
「gt 能预测每一条画出来的线」这个更强的主张本轮**没挣到**，所以多画的线报 `unpredicted` 而不计分。

**参数扫描**：`min_span_cover` 在 **0.50–0.96** 是干净平台（诚实 100 / `clear_runs` 与 `shrink_runs` 全 0），
0.97 起开始误伤诚实产物（西立面楼层线实测 0.9655）⇒ 取 **0.80** 不承重。

⚠️ **一对一 assignment 没有真实夹具**：手上的图纸不存在「两个目标落在同一条线的容差内」
（sm25 楼层线相距 3.6 m）。⇒ 用 `--selftest` 的合成对照证明这条属性承重：
v1 的 `min()` 匹配判 **2 个目标都满足**，v2 判 **1 个**。**这件事必须写进裁决书。**

**第二栋楼**：sm24 的目标推导实测 **每个立面 4 个 · 零个进深台阶**（单层矩形），
与产物侧探针数到的 4 条结构线一致。⚠️ **但 sm24 立面坐标仍未验**（缺四组尺寸链转录）
⇒ 「进深台阶线」这条**仍然只有 sm25 一栋楼的正例**。

## 五、⛔ 本轮查出的新缺陷 **F-86**（未修）

**症状**：sm25 2f 的一堵隔墙**只有一个面进了产物**（`L012`，x=9.15，y 0.2–3.89 m），
它在候选表里**最近的伙伴在 3.795 m 外**。

**实测根因**：`_ink_groups` 里一句
`along = keep[:, g].mean(1) >= FILL_RATIO` —— 一个列组的某段墨迹只要**不是组内多数列**都有，
就被整段丢掉。实测列 655 在第 1080–1249 行有 **170 px** 墨迹，而它所在的组是 653–656（4 列）⇒ 0.25 < 0.5 ⇒ 丢。

**候选修法已实测，⛔ 但不采纳**：改成 `keep[:, g].max(1)`（任一列有就留）后
sm25 gt 侧 93.3 → **94.7**、sm24 仍 100.0，**但 sm24 有 5 个洞口断口被整个填平**
（实心带方言里一列门垛就把断口补上了）⇒ **会静默 heal 洞口**，代价比收益大。
⇒ 正解应是**按 run 兼容性拆分列组**，归下一轮。

**本轮的处置**：`L012` 如实记进 `unpaired_wall_faces`，⛔ 不与任何线硬配。
