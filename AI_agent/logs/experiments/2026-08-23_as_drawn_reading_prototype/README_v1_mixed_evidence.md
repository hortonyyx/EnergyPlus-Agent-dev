## 一、形态：一堵墙 = 成对的两条面线，**不写厚度、不写中线、不判内外**

```jsonc
{
  "id": "B19",
  "axis": "row",                       // 沿墙方向
  "constant_world_axis": "y",
  "representation": "two_face_lines",  // | "solid_fill"（方言 2）
  "faces": [
    { "role": "a",
      "pos_px": 772.5, "pos_m": 10.058,       // 面【在哪】
      "cols_px": [771, 774],                  // 支撑它的【墨迹范围】（两者不是一回事）
      "runs_px": [[527, 695], [796, 966]],    // ⭐ 真实连续区间，不是 [min,max]
      "runs_m":  [[5.311, 8.924], [11.109, 14.809]],
      "gaps": [ {"len_px": 101, "class": "break"} ]   // 断口逐个记账
    },
    { "role": "b", "...": "..." }
  ],
  "spacing_px": 5.7, "spacing_m": 0.1246,      // ⭐ 观测量，**不叫 thickness**
  "declared_thickness_candidates_mm": [240, 120],
  "opening_runs": [ {"run_m": [...], "fen_px_in_band": 737, "beyond_ratio": 0.31} ]
}
```

**四条设计决定**

| 决定 | 为什么 |
|---|---|
| 不写 `thickness_m` | 它是 `face_a`↔`face_b` 的距离，派生量。**一堵墙的内外两面长度可以不同**（Z 形凹口就是），塌成"中心+宽"这个差异就没了 |
| 不做模数吸附 | 声明值（240/120）来自图上 callout，是 OCR 产物；吸附是换算 ⇒ 归 correction。reading 只交**实测间距 + 见证刻度** |
| 不判内外 | 需要闭合外轮廓才知道哪边是室内 ⇒ correction 的活 |
| 门洞不 heal | 图上面线本来就在门洞处断开，忠实记断口；接不接是 correction 的换算选项 |

**唯一的阈值，而且不是新造的**：`OPENING_MIN_M = 0.60`（项目已签字的洞口下限，F-73）。
实测 sm25 1f 断口长度分布有干净的谷：≤15 px 有 5 处、16–30 px 只有 2 处、31–60 px 有 34 处。
小于此值的空白记为 `hairline` 并入账，**不静默合并**。

**方言容纳（声明化，不是加分支猜）**
- `two_face_lines`（sm25）：两条细面线 + 中空
- `solid_fill`（sm24）：一条实心带 ⇒ 两个面 = 带的两条边；`pos_px` 是位置、`cols_px` 是整条带

### ⭐⭐ 顺带推翻 F-78

## 五、⭐⭐ 反证判据本身的分辨力（**本节被跨家族审推翻过一次**）

   一条**没有门窗证据**的空档不是墙的证据；未配对面线根本没算过洞口 ⇒ 它的空档一律不桥。

### 反证之一：洞口（`tools/reconstruct_elev_check.py`）

### ⭐⭐ 反证之二：结构线（`tools/reconstruct_elev_lines_check.py`，⛔ 未改 gt 一个字节）

跨家族审指出：洞口那份反证只遍历 `gt.openings`，**新升为一等元素的结构线在 gt 里没有对应目标**
⇒ 「一面输出一面说不用管」不成立。**补上了，而且结论仍是「不用动 gt」——但理由换了，这次有实证**：
