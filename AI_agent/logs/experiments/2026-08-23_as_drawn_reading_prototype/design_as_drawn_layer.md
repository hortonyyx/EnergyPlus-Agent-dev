## 一、为什么改（依据是实测，不是推理）

2026-08-23 对 sm25 全案逐条对答案，我的真错**只有三条**：

| 错 | 量/层 |
|---|---|
| 画了一堵穿过走廊的不存在的墙（W18）| 2.1 m |
| Z 形凹口两条外墙边没单独成段 | 15.0 m |
| 内墙一笔画穿多段 | 19.7 m |

**三条同源**：把一堵墙的两条面线塌成一条中线时，沿墙范围取了面线出现过的**首尾**
（`[rows.min(), rows.max()+1]`），而不是**墨迹实际连续的区间**。

而**测量那一层几乎零错**：31 扇平面窗 30 满分 · 31 扇立面窗手工对账全对 ≤0.02 m · 12 条链闭合 0.0 mm。

⇒ **错全在判断层，不在描摹层。** 把判断搬走，这三条一起消失
（[[representation-collapse-manufactures-unrelated-errors]]：换表示 > 加容差 > 加分支）。

**顺带自动消失的两条已登记缺陷**：
- **F-78**（「2f 出现两个不存在的墙厚 0.131 / 0.146」）—— 实测那是 **0.49 px** 噪声。
  病根不是量错，是把观测量命名成 `thickness` 这个**事实性名字**，它就以事实身份往下游走。
  as-drawn 里它叫 `spacing_m`，吸附归 correction。
- **三樘门全部丢失** —— 旧形态因为 reading schema 没有 `door` 笔，把三樘**坐标全对**的门写进了
  `uncaptured`。as-drawn 里它们就是普通 `opening`，门窗之分下放。

## 二、形态

### 2.1 平面：一堵墙 = 成对的两条面线

```jsonc
{ "id": "B19", "axis": "row", "constant_world_axis": "y",
  "representation": "two_face_lines",          // | "solid_fill"
  "faces": [
    { "role": "a", "pos_px": 772.5, "pos_m": 10.058,
      "cols_px": [771, 774],                    // 支撑它的墨迹范围（≠ 它在哪）
      "runs_px": [[527,695],[796,966]],         // ⭐ 真实连续区间，不是 [min,max]
      "runs_m":  [[5.311,8.924],[11.109,14.809]],
      "gaps": [{"len_px":101,"class":"break"}] },
    { "role": "b", "…": "…" } ],
  "spacing_px": 5.7, "spacing_m": 0.1246,       // ⭐ 观测量，⛔ 不叫 thickness
  "declared_thickness_candidates_mm": [240,120],
  "opening_runs": [{"run_m":[…], "fen_px_in_band":737, "beyond_ratio":0.31}] }
```

### 2.2 立面：结构线 + 裸洞口

```jsonc
{ "structure_lines": [
    { "id":"S02", "axis":"col", "constant_quantity":"x",
      "pos_m": 5.997, "runs_m": [[…]], "gaps":[…],
      "covered_px": 533, "span_ratio": 1.00 }      // ⛔ 不命名是哪条线
  ],
  "openings": [
    { "id":"O01", "bbox_px":[…], "x_range_m":[…], "z_range_m":[…],   // ⭐ 未吸附
      "edge_witnesses": { "x0": {"nearest_tick_px":…, "distance_mm":…,
                                 "dimension_refs":["C_bot_fine_s3"]}, … },
      "line_below_px":"S06", "gap_to_line_below_m": 0.183 } ] }      // 门窗证据，非判定
```

### 2.3 两侧共用的设计决定

| 决定 | 为什么 |
|---|---|
| 不写 `thickness_m` / 不写中线 | 派生量。**一堵墙的两面长度可以不同**（Z 形凹口就是），塌成「中心+宽」这个差异就没了 |
| 不做模数吸附 | 声明值 240/120 来自图上 callout（OCR 产物），吸附是换算 ⇒ 归 correction。交**实测值 + 见证刻度** |
| 不判内外 | 需要闭合外轮廓才知道哪边是室内 |
| 门洞不 heal | 面线本来就在门洞处断开，忠实记断口 |
| 不判门/窗 | 交**离所站结构线的高度**等测量量，判定下放 |
| 不命名结构线 | 「哪条是地坪线」是识别 |
| **原点从尺寸链拟合导出** | ⭐ 本轮实测：手填原点在我细看过的两张图上准到 0.31 px，在没细看的那张偏 **1.73 px = 47.6 mm**，直接造成一条外墙判不上（P-2）。手填值降级为**声明的交叉核对**，差值逐轴记台账 |

**唯一的阈值，而且不是新造的**：`OPENING_MIN_M = 0.60`（项目已签字的洞口下限，F-73）。
⛔ 立面侧**一个新阈值都没引入**（旧的 `DOOR_MAX_SILL_M = 0.50` 被搬走，不是搬到别处，是**删掉**）。

## 五、B 步细则（**动 gt，本设计稿要审的就是这一节**）

> ⚠️ **本节已按实测修正过一次**。初稿照 plan.md 写「`_WallFacePair` 已经在算，序列化即可」，
> 我在送审前按 §八#4 自己列的存疑项去核了源码与 DXF，**结论变了**。以下是核后的版本。

### 5.1 gt 侧已有什么（[`tarch_normalize.py:1208`](../../../../src/agent/judge/tarch_normalize.py#L1208)）

`_WallFacePair` 确实携带成对面线的证据：
`handle_a/handle_b` · `coord_a/coord_b` · **`span_a/span_b`** · `overlap_native` · `thickness_native`。

### 5.2 ⛔ 但它**不是**「序列化就完事」——三处实测

| # | 实情 | 后果 |
|---|---|---|
| 1 | **`span_a` 是单个 DXF LINE 实体的端点**（[`_wall_line_geometry`](../../../../src/agent/judge/tarch_normalize.py#L1240) 直接取 `min/max` 于一条线），⛔ 不是这条面线的完整绘制范围 | B 步**必须加一个碎片归组 + 合并 pass** |
| 2 | sm25 的 `WALL` 层实测 **448 条 LINE，归组后只有 151 条面线**；碎片数中位 1、**最多 15**（含 1 条零长度线、0 条非正交）。对最碎的几条按 600 mm 规则合并：15 段 → **9 个 run**（⛔ **不会塌成 1 个** —— 那些断口是真洞口）| 合并规则**必须与读图侧同一条**，否则两侧 run 数不一致、判分满屏假红 |
| 3 | `_build_wall_face_pairs` 带**两道过滤**：厚度容许范围（`request.wall_thickness_range_m`）+ 墙体区域覆盖 ⇒ **配不上对的面线在 gt 侧根本不出现** | 而**读图侧的 as-drawn 携带未配对面线**（sm24 实测 69 条）⇒ **两侧集合不对称，本设计稿必须裁决** |

**⇒ B 步的工程量应重估为「中」而非「小」**，且它与 §5.3 是**同一件事**，不是两件。

### 5.3 ⭐ 必须在本稿定死：两侧共用一条归一化规则

这是两侧唯一的硬耦合点，**定错了 B/D 两步全部返工**。

**建议**（请审阅方重点裁决）：
1. **合并下限 = `OPENING_MIN_M = 0.60`**，两侧共用（它已经是签字过的领域参数，⛔ 不新造）。
2. **单一实现**：把合并函数放在一个模块里，转换器与读图器**同源引用**，
   ⛔ 不许两侧各写一份（[[free-correctness-evaporates-when-representation-changes]]）。
3. **gt 记录归一化前的原始碎片数与句柄**，使「合并掉了什么」可查而非静默。
4. **未配对面线的裁决**（§5.2#3）：建议 gt 侧也落**未配对面线**（带 `paired:false` 标记），
   理由 = 判分时若 gt 只有成对的，读图侧多转录的真实面线会被计成「多画」而实际上它画对了。
   ⛔ 但这会扩大 gt 的表面积，须审阅方拍。

### 5.4 ⭐ 立面：**不用加**

gt 的立面洞口坐标直接来自 `E_WINDOW` 实体，**本来就是 as-drawn**。
本轮 34/34 反证就是拿**现有 gt** 做的，⛔ 没改一个字节。
（实测 sm25 DXF：`E_WINDOW` 层 21 个 `INSERT` + 14 条 `LWPOLYLINE`。）

### 5.5 重签流程（照 08-23 的教训走）

⛔ **候选包不能直接入库**：08-23 那次强制二次转换红了，因为候选包是**旧版转换器代码**产的。
