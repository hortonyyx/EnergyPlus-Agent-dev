## 一、为什么改（依据是实测）

2026-08-23 对 sm25 全案逐条对答案，真错**只有三条**，且**同源**：把一堵墙的两条面线塌成一条中线时，

内墙画穿 19.7 m。而**测量那一层几乎零错**（平面窗 30/31 · 立面窗手工对账 ≤0.02 m · 12 条链闭合 0.0 mm）。

⇒ **错全在判断层。** 把判断搬走，三条一起消失（[[representation-collapse-manufactures-unrelated-errors]]）。

**顺带消失的两条已登记缺陷**：F-78（「不存在的墙厚 0.131」实为 0.49 px 噪声 —— 病根是把观测量命名成
`thickness` 这个事实性名字）· **三樘门全丢**（schema 无 `door` 笔 ⇒ 坐标全对的门被写进 `uncaptured`）。

## 二、⭐ 核心结构：三层，两侧对称

**v1 最大的毛病 = 观测、声明、推断混在同一层**，于是「这个字段能不能只用尺子量出来」这个自查
逐个字段问是问不出来的。v2 把它变成**结构问题**：

| 层 | 是什么 | 判分地位 | 例 |
|---|---|---|---|
| **`observations`** | 尺子在像素上量到的 | ⭐ **唯一可评分层** | 面线位置 · 原始 run · 每个空档的长度与墨量 · 洞口包围框 · 间距 |
| **`declarations`** | 图纸/配置**声称**的，逐字转录 | 只比对**字面**，不比对含义 | 厚度 callout OCR 原文 · 图层→族映射 · 尺寸链数列 |
| **`hypotheses`** | 由前两层**推**出来的 | ⛔ **不计分、可整层丢弃** | 成对关系 · 方言标签 · 空档分类 · 极性 · 门窗之分 |

**硬性质（这是三层制的全部意义）**：**只拿 `observations` + `declarations`，下游必须能重新推出
`hypotheses` 里的一切。** 任何做不到这一点的字段，说明它偷偷携带了没写下来的判断 ⇒ 设计缺陷。

⭐ **gt 侧用同一个三层**（`source_primitives` / `normalized_runs` / `pair_hypotheses`），
两侧对称正是「比什么」有定义的前提。

## 三、⭐⭐ 阈值：reading 里一个都不留

v1 声称「唯一阈值 = `OPENING_MIN_M=0.60`，且不是新造的」。**这句话是错的**，审阅方点名了两处：

1. **提取器里至少还有九个阈值**：RGB 判族 · `FILL_RATIO=0.5` · `min_run_px=14` · `min_support=10` ·
   配对容差 `max(2px, 30%)` · `MIN_LINE_PX=120` · `min_area_px=40` · 嵌套 2 px · polarity 1%。
2. ⭐ **更重的一条**：同一个 0.60 m 在墙线上做「**补断墨**」（跨过去），在门窗层上做「**吞窗间墙**」
   （并成一个洞口）—— **语义相反**。它绝不能当两侧统一的合并阈值。

### v2 的做法：把空档**当观测量交出去**，不分类

实测（sm25 1f / sm24 1f，原图像素）：

| 空档长度 | 个数 | 其中有门窗墨 | 中位「穿越结构墨」 | 物理上是什么 |
|---|---|---|---|---|
| 1–4 px | 7 | 0 | 0–4 | 抗锯齿掉点 |
| 5–27 px | 6 | 0 | **14–23** | **另一堵墙横穿过来** |
| ≥28 px（≈0.6 m）| 62 | **42** | 7 | 洞口 |

⇒ reading 每个空档只交四个数：**`len_px` · `fenestration_px_on_line` · `fenestration_px_near` ·
`crossing_structure_px`**，⛔ 不写 `class`、不跨接、不合并。分类留给 correction。

**代价实测：几乎没有。** sm25 1f 不跨接时原始 run 段数 **124**，而 <28 px 的空档只有 **13 个**
⇒ 不跨接只多出 13 段。⛔ 不会炸。

### ⚠️ 本条已在实装中被自己咬过一次 —— 测量窗口的定义是承重的

第一版把「这个空档有没有门窗墨」只在**面线自己那几列**上量。sm25 的面线只有 1–2 px 宽，
而**洞口是画在墙上、横跨两条面线的**，不是画在某一条面线上 ⇒ 62 个 break 空档里 **20 个读成 0**
（放宽到 ±0.30 m 后只剩 2 个）。代价 = 信息没丢反证**掉了 26.6 个百分点**。
⇒ 两个数**都交**（`_on_line` 与 `_near`），窗口 **`NEAR_WINDOW_M = 0.30 m`**（≈ 一个最厚声明墙 240 mm
再加余量，gt 的 `wall_thickness_m` 也是 0.24）**写进 calibration 台账**。
⭐ **它是测量量的定义、不是分类阈值** —— 不同意这个窗口的消费者仍拿得到原始的窄窗口数。

### 于是「两侧共用什么」有了确切答案

**只共用无语义的区间算术**：① 坐标量化 ② 同线归组 ③ 区间并集 ④ 碎片句柄可追溯。
⛔ **不共用任何阈值**。「是否跨过某个空档」在两侧都是 `hypotheses` 层的显式假设，各自带证据。

```jsonc
        "ink_coverage": 0.94 } ],               // ⭐ 新：这条线自己压在墨上多少（见 §六）
    "fenestration_components": [ … ] },         // ⛔ 不叫 opening，叫「门窗色连通域」
  "declarations": {
    "thickness_callouts": [ {"text_verbatim":"240", "source":"…", "confidence":"…"} ],
    "layer_family_map": {…}, "dimension_chains": {…} },   // ⛔ 不挂到具体墙上
  "hypotheses": {
    "pairs": [ { "face_a":"L07", "face_b":"L08", "spacing_px":5.7, "spacing_m":0.1246,
                 "admissible_alternatives":["L11"],        // ⭐ 全部枚举，非 first-match
                 "evidence": {…}, "confidence":"…" } ],
    "dialect": {"representation":"two_face_lines", "basis":"…"} } }
```

**四条设计决定**（与 v1 相同，理由不变）：⛔ 不写 `thickness_m` / 不写中线（派生量；一堵墙两面长度可以不同，
Z 形凹口就是）· ⛔ 不做模数吸附（换算）· ⛔ 不判内外（需闭合轮廓）· ⛔ 门洞不 heal。

### 4.2 立面

同样三层。`observations` = `structure_lines`（位置 + 原始 run + 空档，**⛔ 不命名是哪条线**）
+ `fenestration_components`（**裸像素包围框，⛔ 未吸附**）+ 每条边的**最近刻度与距离**（证据）。
`hypotheses` = 门窗之分、线的身份、极性。

## 六、B 步细则（**动 gt，本稿要审的核心**）

### 6.1 gt 侧已有什么

[`_WallFacePair`](../../../../src/agent/judge/tarch_normalize.py#L1208) 携带成对面线证据：
`handle_a/b` · `coord_a/b` · `span_a/b` · `overlap_native` · `thickness_native`。

### 6.2 ⛔ 但**不是**「序列化就完事」——三处实测

| # | 实情 | 后果 |
|---|---|---|
| 1 | **`span_a` 是单个 DXF LINE 实体的端点**（[`_wall_line_geometry`](../../../../src/agent/judge/tarch_normalize.py#L1240)），⛔ 不是面线的完整绘制范围 | 必须加**碎片归组 pass** |
| 2 | sm25 `WALL` 层 **448 条 LINE → 归组后 151 条面线**（碎片中位 1、**最多 15**；含 1 条零长度、0 条非正交）。⚠️ 审阅方按 1e-3 容差归组得 **154** ⇒ **归组容差本身还没定死，须在本稿签字** | 归组必须**可复现、有明确容差与身份定义** |
| 3 | 配对器带**厚度容许范围 + 墙体区域覆盖**两道过滤 ⇒ 配不上对的面线在 gt 里根本不出现 | 两侧集合不对称（读图侧 sm24 有 69 条）|

⇒ **B 步工程量 =「中」**，且它与归一化规则是同一件事。

### 6.3 gt 三层（与 §二 的读图侧三层对称）

1. **`source_primitives`** —— selector 命中的**全部**原始句柄、端点、layer/type。**完全守恒**。
2. **`normalized_runs`** —— 只做**无语义**的区间并集；保留 fragment handles 与**每一个**空档。
3. **`pair_hypotheses`** —— 配对 / 未配对 / jamb-cap / 拒绝原因，明确标为派生。

### 6.4 ⛔ 未配对面线**不得**直接作 `paired:false` 进可评分 gt

v1 曾倾向让它进，理由是否则读图侧多转录的真实面线会被计成「多画」。**审阅方驳回，本稿接受驳回**：
CAD 的「未配对 `WALL LINE`」**不等于**墙面线 —— 转换器明确把厚度范围内的短 `WALL LINE` 识别为
**jamb cap（门垛横截面线）**（[`tarch_normalize.py:404`](../../../../src/agent/judge/tarch_normalize.py#L404)），
而实测 447 条非零线里有 **250 条 < 600 mm、128 条在 240–360 mm**，必然混有这类。

**替代解法（不靠扩大分母）**：产物里一条多出来的线，**若有 `source_primitive` 支撑**，
进 `unscored / uncertain`，⛔ 不进「多画」罚分。哪些未配对项该成为判分目标，**证据不足，本稿不拍**，
须人工抽样核完 sm24/sm25 的未配对集合后单独定。

⛔ 候选包不能直接入库（08-23 教训：候选包由旧版转换器代码产出，强制二次转换必红）

## 七、⭐ 配对器：审阅方的诊断我实测后要修正一处

审阅方判定「配对器是**顺序敏感的贪心**（遇第一个合法伙伴即 `break`），sm24 已实证把家具边配成墙面」。
**贪心确实在，但它不是 sm24 那次错配的原因。** 实测每条面线的**合法伙伴个数**：

| | 面线数 | 0 个伙伴 | 1 个 | **>1 个（真有歧义）** |
|---|---|---|---|---|
| sm25 1f | 49 | 2 | 44 | **3（6.1%）** |
| **sm24 1f** | 98 | **82** | 16 | **0（0.0%）** |

⇒ sm24 **一条歧义都没有**：那个家具框的竖边是**唯一**的合法伙伴。
**真因是合法性判据太弱**（只查「间距落在声明厚度 ±2 px」+「重叠 ≥10 px」），
而 sm24 的**家具与结构同色**（家具图层实测 0.00%）⇒ **这在该方言上靠调阈值根本修不好**：
补 120 声明后墙带 21→56、反向对账红 2→6、间距判据红 0→21，多出来的全是家具框。

**v2 的处置**（不是修阈值，是换层）：
- 配对整体降为 `hypotheses`，**枚举全部合法伙伴**（`admissible_alternatives`），⛔ 不 first-match-break；
- 每条面线交出 **`ink_coverage`**（它自己压在墨上多少）—— 这是**测量量**，与 `spacing_m` 同类。
  ⭐ **sm24 实测分得干干净净**：那条假面线（B08.b）= **0.74**，
  **其余 40 个面全部 = 1.000**（连它自己的真伙伴 B08.a 也是 1.000），⛔ 无一介于两者之间
  ⇒ correction 拿得到丢弃它的依据，且**不需要新阈值**——空档本身就是空的；
- ⭐ 反证在补不补 120 声明两种情形下**都是 100%**（旧规则）⇒ 这是**多画**问题不是**漏画**问题，
  信息没丢，只是多了。

### ⭐⭐ G-1 已修：内墙判据收紧为「夹住目标的两条面线」

一审查出内墙目标可以退化成匹配**单条** face（sm24 当时 16/16 条内墙全走 face、20 个目标里 15 个
匹配到未配对线）⇒ 那个数说明不了「correction 能还原答案」。

**新判据**：内墙必须由**两条夹住目标的面线**满足，且**只在两条都画到的那一段上计覆盖**。
⭐ 搜索范围是**全部转录到的面线**，⛔ 不是产物发出的 band —— 配对是**假设**，
而这条判据问的是**观测本身**支不支持。

**修后**：sm24 **100.0%** · sm25 **93.3%**（内墙 91.5%）。且新增变异 `drop_one_face`
（删掉每堵墙的一面，旧规则下完全不可见）把 sm25 打到 **9.3**。

**这个 100% 站得住的三条证据**：
1. **用到的配对间距全部合理**：sm24 内墙全部 **0.1237–0.1262 m**（≈124 mm）·
   sm25 **0.109–0.24 m**（两种声明厚度）。⛔ 没有靠宽得离谱的「墙」蒙混。
2. ⭐ **我发明的那个域上界不承重**：`MAX_WALL_M` 从 **0.50 收到 0.26，两个 case 的数一格不变**。
3. 五种丢信息变异**全部报红**。

⭐⭐ **顺带成为三层制最好的一份证据**：sm24 那些内墙在**观测层完好存在**（间距 124 mm 量得清清楚楚），
丢掉它们的是**依赖声明的配对假设**（cfg 只声明了 240）。**观测扛得住不完整的声明，假设扛不住。**
