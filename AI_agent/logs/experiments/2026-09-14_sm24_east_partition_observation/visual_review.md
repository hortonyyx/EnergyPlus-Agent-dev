# sm24 东侧分区局部观察离线复核

日期：2026-09-14
结论：本次局部观察不可作为后续 source 一致性检查的输入

## 复核边界

本项逐条判断只以本目录的原始 `1f_view.png`、`observation.md`、`execution_audit.json` 及同一原图的离线 `profile_diagnostic` 为依据，没有用 source 或 GT 为各项定真。这是了解项目历史的开发侧事后复核，不是盲评；观察模型运行时未获候选 source、GT 或旧答案。本复核没有调用模型/API。

`execution_audit.json` 证明观察模型收到的主目录图、隔离目录图和清单图像完全一致，原图大小为 790 × 1111，图像文件 SHA-256 为 `47cf5ee...f34350`；7 次工具调用全部是 `view_image`，包含全图和声明范围 `[360,260,630,610]` 的多个裁图，没有源模型、派生图或量测工具。它证明图像运输和裁图可用，不证明输出中的墙、门或坐标正确。

## 逐项复核

### P1：`P1_horizontal_y310`

**判定：坐标错误；附近确有另一条建筑隔墙，但 P1 不能作为其可重放观察。**

原图在该范围北侧可见一条横向实体隔墙，实际灰色墙线约在 `y=296`，中间有一组双扇门洞。P1 却把整条墙写在 `y=310`，从 `x=375` 延至 `x=620`；沿这条声明线查看时，多数位置已经位于墙下方室内，右端还越过约 `x=603–611` 的东外墙。它所述的门弧位置也没有对应到横墙上的真实门洞。

侧点 `[450,290]` 和 `[450,330]` 大致落在北侧房间与中央走廊一带，但两点邻近并穿过双门范围，不是“不靠门洞的清晰两侧室内点”。因此，即使原图确实支持附近存在一条带门的完整隔墙，也不能用这组错误 path 和侧点认证其位置或两侧关系。

### P2：`P2_horizontal_y350`

**判定：墙身份错误，`separates_spaces` 无图像依据。**

原图在 `y≈350` 没有一条由 `x=375` 横贯到 `x=620` 的建筑墙。该高度实际遇到的是约 `x=402`、`x=457` 的纵向隔墙、东外墙，以及纵墙门洞的门扇/圆弧。观察把纵墙上的门弧和附近家具横线解释成了横向隔墙及其门洞。

侧点 `[450,330]` 与 `[450,370]` 的 x 坐标都位于两道纵墙之间的中央狭长空间内；它们没有分居一条 `y=350` 横墙两侧。P2 同时存在错误线位、错误墙方向和错误空间关系。

### P3：`P3_horizontal_y400`

**判定：墙身份错误，且输出正文承认端点未核清后仍升级为完整分隔。**

原图在 `y≈400–410` 不存在 P3 所称的全宽横墙。东侧可见的实体横墙位于更北的约 `y=367/371`；再往南，下一组横向房间边界约在 `y=583/587`，并且它在中央走廊处不是一条横贯墙。`y≈400` 一带主要是纵向走廊墙、门弧和房间内部家具。

侧点 `[450,380]`、`[450,420]` 仍都在两道纵墙之间或其门口附近，没有跨过所声称的横墙。观察自己的 `unresolved` 又说 P3 向东的完整延伸没有确认，却在主结果中直接标为 `separates_spaces`，证据等级与结论不一致。

### C1：`C1_horizontal_middle_space`

**判定：连续空间声明错误；路径跨实体墙、门洞并越出外墙。**

路径从 `[375,330]` 沿 `y=330` 到 `[630,330]`：

- 先从西侧房间穿过约 `x=402` 的实体纵墙；
- 再穿过约 `x=457` 纵墙上的门洞。门洞表示两个空间之间有连接，不能据此称为一个没有物理分隔的连续空间；
- 最后穿过约 `x=603–611` 的东外墙，终点 `x=630` 已在建筑外。

所以“整条路径是清晰空地、没有穿门”的文字与原图直接矛盾。黑色背景在不同房间和室外都相同，也不能作为空间连续证据。

### C2：`C2_vertical_left_side`

**判定：坐标对象错误；路径不是内墙边，也不是同一连续空间。**

观察称 `x≈375` 是左侧围护墙，但原图西外墙约在 `x=248`，中央走廊西侧纵墙约在 `x=402`；`x=375` 实际位于西侧房间内部。它又说室内在墙东侧 `x≈385`，却把连续路径本身放在声称的“墙”上，定义也自相矛盾。

从 `y=310` 走到 `y=600` 会跨过西侧房间之间的横向实体隔墙，至少在约 `y=583/587` 处有清楚灰墙支持；原图还显示更北一处分隔。该路径没有证明一个连续空间。观察把伸入西侧房间的门扇圆弧误当成门都开在 `x=375` 的墙上，真实门的墙身/门框位于中央走廊边界附近。

## 离线 profile 能证明什么

`AI_agent/logs/experiments/2026-09-14_partition_relations_setup/profile_diagnostic/` 使用同一 SHA-256 原图，对相同 `[360,260,630,610]` 范围保存了 x/y 两轴的原图与灰度色罩。它不识别墙，只给出候选峰和该峰上真实出现的像素支持区间。

这些确定性位置足以发现本观察的坐标叙述不可靠：

- x 轴候选 C01、C02 的峰分别是 `x=402`、`x=457`，且有长的纵向支持；回看左侧原图面板，可辨认为中央空间两侧的建筑纵墙。这直接反驳“范围内没有内部纵墙”。
- y 轴在 `y=296`、`y=367/371`、`y=583/587` 给出长候选；原图分别可核到北侧横墙、东侧房间横墙及南部两段边界。没有与 P1/P2/P3 所称 `y=310/350/400` 相符的贯穿墙候选。
- `y=583/587` 的支持被明确列成西侧与东侧两段，中间保留中央空间间隔。这说明 profile 不会自动把同高的灰线拼成一条全宽墙。
- y 轴 C02/C03 在 `y=305–307`、`y=327` 也抓到横向灰线，但支持主要落在东侧家具范围。它同时说明“长灰线候选”仍可能是家具，必须回到原图核对象身份。

该 profile 使用 `[169,169,169]`、容差 100 的较宽色带，候选会混入家具、门符号和抗锯齿像素。其 `support_intervals_at_peak` 只描述一个峰位上的颜色命中，不能单独证明整段连续，更不能把候选直接命名为物理墙或空间边界。

## 总结

五项观察都不能直接采用：P1 邻近真实横墙但路径和侧点错误；P2、P3 是不存在的横向完整隔墙；C1 穿实体墙、门洞和外墙；C2 错认墙位并跨越房间隔墙。主要失败不是几像素容差，而是墙方向、宿主位置、门洞含义和连续空间判断均发生了变化。

其后实际执行的候选式复测见相邻目录 `2026-09-14_sm24_east_profile_observation/`：它已禁止新写坐标并要求引用 profile 候选，但独立复核仍发现带门纵墙漏认、家具边误配和跨中央空间合并断段，详见该目录的 `visual_review.md`。因此问题不只是不受约束的坐标估计；在局部模型能稳定区分墙、门窗缺口与开放空间前，不应接入 source checker。
