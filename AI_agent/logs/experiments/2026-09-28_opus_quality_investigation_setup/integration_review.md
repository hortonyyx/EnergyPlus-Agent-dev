# Astra 对 Opus 独立调查的复核与采用决定

Opus的[原报告](../2026-09-28_opus_quality_investigation/REPORT.md)和初判原样保留；本页区分我核实的事实、补充/更正及实际采用范围。工作模型回归没有随调查自动启动。

## 核实与更正

- 已直接比较run57/58/81：请求全文sha256、manifest的全部33项生产文件散列、六图信息完全相同。见[root_crosscheck.json](root_crosscheck.json)。补上Opus所列“run57与旧树代码未逐字节核”的缺口，但范围是已记录的33文件；不声称控制了服务端或一切运行环境。旧树仍能出现行为变化，不代表新代码对错误概率没有间接影响。
- 撤回我此前把run83的x≈718确定写成“无关线”的判断。公开请求确有`2f_view.png`裁框[400,300,1820,1090]、display_scale=1；该图中的718对应原图1118，落在北隔墙1114/1125双线之间。原声明同时使用原图坐标，未明确说明718来自哪一个视图；**裁图坐标混用是强支持的解释，不能把模型未外显说明的坐标来源当成直接观测事实**。确定事实是该墙已在返回原图中呈现，声明仍以“无灰填/无墙厚像素支撑”否定它，并保存了错并。
- 初判F5把53–59、61、62计成11次；实际9次，均未读reconstruction，见root_crosscheck。最终报告使用六次较好结果的0/6，分母正确。
- Opus的“4/12对象级错误”包含429中断run82；12次中还有中断run76。正常完成的10次中有72/75/83三项严重对象/尺度错误，且72是指引消融、各次条件不同；只作样本描述，**不能作为同条件失败率**。两项中断仍保留未知完整质量。
- 严格2cm分区评分、对象拓扑、原图端点、窗高是不同维度。10cm/30cm重算说明评分对尺寸偏差敏感，不代表把0.1–0.3m统一判成可接受，也不排除同一run的窗型、完整跨度或高度错误。尤其run81东窗半宽和小窗高度不能被“拓扑正确、几厘米墙位差”掩盖。
- 未出现压缩/清理事件只能排查可见的截断路径；上下文负担对行为的影响没有因此被排除。B仍用量测也不足以证明“必为模型服务端变化”；参考未被读取、组合约束、抽样等仍可能存在。

## 采用决定

保留当前底座和有效开发，先不整体回旧基线逐包加回。接受“看行为与结果、对象错误和尺寸差异分报”的方向；这与项目已有评价约定一致。保留全部原始评分，不改生成容差，也不以更宽阈值重命名旧结果。

本轮量测绑定是可选输入能力，39项相关检查、真实工具链和开发重放已过；它解决选定证据的转录，不解决上游物理解释。原先的立面引用实测已提供“引用使用仍认错对象”的反例，所以不把它宣传为恢复根因修复，也不强制模型增加量测。

Opus的贯通线原型保留为后续候选能力：本次真实错误和71组人工合并可被提示，同时sm21存在固定家具误报，原型使用矩形包围框/当前三例标定约定，泛化与实际纠错尚未验证。此次不接生产，不与下一方法试验混合。锚点绝对米值>1000的硬拦截也不采用：绝对坐标大不必然是单位错，需针对尺度与已知尺寸不一致设计，不能新增任意建筑大小准入条件。

下一步已离线准备[两次sm21方法参考对照](../2026-09-28_dimension_first_comparison/README.md)，待用户决定。保持全局提示、scope、工具与其余代码；只在独立试验树替换reconstruction参考。B优先图形/尺寸、局部未决才量测；A保持现状。每臂一次只检验实际采用和保存质量，不采纳Opus的工具次数/首建速度作为质量门槛，不把B失败自动归因模型侧。比原建议五次缩小范围，复测/换例不自动获批。

旧基线逐包路径继续作为备选。若出现可重放的新旧执行差异，或同期对照持续显示当前版才有严重错误，再定对应能力包的回退/二分；不把0/2对2/2当统计证明，也不再无界叠加修复推迟验证。
