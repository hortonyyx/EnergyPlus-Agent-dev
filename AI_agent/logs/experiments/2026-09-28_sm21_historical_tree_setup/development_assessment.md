# 后续开发的证据分层

这里判断的是实际收益及目前证据边界，不以代码量、工具调用次数或单轮分数判定开发价值。生成对照不更改旧树；当前版生成结果仍指run79/80，不能把本次离线接口修复冒充新整案结果。

| 开发内容 | 已经证明的作用 | 还不能证明的事情 / 处理 |
|---|---|---|
| 房间公开名称、类型目录、房间依据保留 | 同一份旧/新提案经当前代码导出，公开名称存在、原声明中的房间依据保留；物理几何与旧转换一致。run79保存14房间用途依据 | run80仍全部unknown，说明工具/提示可用不保证采用；保留能力，不宣称几何准确率提高 |
| 不改几何的用途编辑 | 已有几何保持检查，本次原始失败操作离线重放定位省略空假设及错误消息问题；修复后与当时成功提案完全一致，30项相关检查通过 | 4次额外失败属于接口返工，发生在几何生成之后，不能解释此前窗高或墙门位置错误 |
| 实际证据裁图返回、已看视图复用 | 既有run79/80实际运输核验通过，能追溯模型到底收到哪张图；替换引用能保持几何与声明值 | 模型可以面对正确原图仍误读尺寸链/窗型；证据绑定不等于识图判断正确 |
| 过程版本额度6→24 | 旧run69/70确实撞到6份保存限制；扩额消除了这类确定性阻碍。run79/80保存8/7份，超过旧额度 | run79最后3份只改用途/备注；不能按保存次数算几何进展，也不能据此说24必然优于6 |
| 有界主模型续查 | 接续入口、共享额度及纯用途编辑后高度确认保持已有离线/历史恢复证据 | run79/80及旧树run81均无续查，所以续查执行不是这三轮首轮错误的来源；其提示存在仍属于版本组合变量 |
| 像素剖面的局部峰值、阈值下支持信息 | 离线证据证明所报数值与像素一致；阈值追加不改已有候选/图片。run80真实收到3次新反馈 | 3次均为绿色尺寸线，未复现灰色细隔墙用例；此前两组没有证明整案因这一改动恢复，不能据反馈送达宣称有效 |
| 平面局部修改、楼层装配、空间关系检查 | run80自主补回3扇漏窗，最终独立房间/宿主/连接完整；确定性重放能复核输入到几何 | 这些主体能力在旧基线已经存在，不能记作基线之后的新增收益；关系检查基于模型声明，不会自动发现声明本身漏墙 |

同声明跨版本重放详见[producer_comparison.json](producer_comparison.json)。物理比较包含楼层、空间形状和标高、边界、门窗、连接及宿主关系；用途、公开名称、来源和备注另计。所有保存的平面草稿亦比较编译结果或错误，没有改输入使之迎合旧代码。

目前可以定位到**读图→选取实体/尺寸段→形成声明→复核时是否修正**这条路径。不能由转换一致进一步推断新提示/反馈没有影响模型行为，也不能把一次旧树复跑概括为全部新开发无效。旧树实跑终态及与成功历史的过程差异在本目录README另记。
