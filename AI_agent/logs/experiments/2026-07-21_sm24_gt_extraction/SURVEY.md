## 1. 结论先行

**天正图形导出的真实建筑墙线，喂不进 GT v3 提取器**（`src/agent/judge/gt_extraction.py`）。
两者对"图"的定义不同：

| | v3 提取器要求 | 天正真实建筑图 |
|---|---|---|
| 墙的表达 | **单线**区划边界（相邻房间共享一条线）| **双线**（240 厚画两条）|
| 洞口 | 边界连续、不断开 | 门窗洞处墙线**断开**，洞里放门窗块 |
| 拓扑 | polygonize 后**每个面正好一个房间**，悬空线头必须为 0 | 双线夹层自成细长面；外轮廓不闭合 |

**用户 2026-07-21 拍板：走转换器，不改变人类正常画图习惯。**
理由（用户原话意）：复杂建筑手画区划线不是十几分钟能解决的，且**容易画错**；
手画方案只对简单建筑成立 = 违反不变量 #6（建筑复杂度可扩展性铁律）。

## 3. 阻塞点实测（转换器要解决的问题）

### 3.1 全部墙线直接 polygonize → 失败

```
faces=23  dangles=1  cuts=0  invalid=0     # v3 契约要求 dangles=cuts=invalid=0
face areas m2 (top 12): [1.49, 1.44, 1.03, 0.95, 0.74, 0.69, 0.6, ...]
```
23 个面**全是双线墙自己的夹层**（0.5–1.5 ㎡），房间面根本没围出来。

### 3.2 仅外皮线 polygonize → 完全不闭合

```
faces=0  dangles=18   # 18 根全是悬空线头
```
每条外边的缺口位置与门窗**精确对应**：

| 外边 | 段数 | 覆盖/总长 | 缺口（=洞口）|
|---|---|---|---|
| x=23057.6 (西) | 6 | 9500/20000 | 5 处，对应 5 扇窗 |
| x=33057.6 (东) | 5 | 10900/20000 | 4 处 = 3 窗 + 1 门 |
| y=26565.2 (南) | 4 | 6100/10000 | 3 处 = 2 窗 + 1 门 |
| y=46565.2 (北) | 3 | 3600/10000 | 2 处 = 1 窗 + 1 门 |

### 3.3 v3 提取器的硬约束（读码确认，非推断）

- `_entity_points` 只吃 `LINE / LWPOLYLINE / POLYLINE`；**INSERT 直接 fail**
  （`dxf_entity_type_unsupported`）⇒ 门窗块不能直接进边界选择器。
- `_polygonize` 对 dangles / cuts / invalid **零容忍**，一律 `dxf_polygonize_residual`。
- `boundary_reference` 只支持 `"outer_skin"`（`centerline` → `dxf_centerline_unsupported_in_phase_b`）。
- zone 判定：每个面必须**恰好含一个 `zone_seed`**，且所有 zone 面并集 == footprint（`dxf_zone_tiling_mismatch`）。

## 4. 为什么 sm21 当时能行（已查证，非猜测）

sm21 走的是**老提取器 v2**（`git show 41558e1:scripts/tool_scripts/gt_from_dxf.py`，B4a 已重写替换），
算法完全不同 —— **矩形网格法，不做拓扑闭合**：

1. 坐标**聚类**（`_cluster`）：240 厚双线坐标只差 240mm，被聚成一个位置 ⇒ 双线问题自动消失；
2. `WALL_MIN = 800mm`：只认长线为结构墙，洞口边短线直接丢弃；
3. `_bands` + `_zones`：**横墙分带 → 带内竖墙切格**，切出矩形房间；
4. footprint = 所有墙线的 **bbox**（洞口断开完全无所谓）。

**硬假设 = 房子是矩形网格**。`_self_check` 还要求所有房间面积和 == 外包矩形面积。

⇒ **sm24 不能退回 v2**：L 形走廊会被"分带切格"切成两块矩形，
而这**正是本 case 要判的缺陷本身** —— 等于把缺陷写进标准答案，判出来永远满分。
（v3 重写为真拓扑 polygonize，正是为了支持 L/U/回字形 = C2 整条路线的前提。）

## 5. 转换器：目标与已观察到的可用线索

**目标**：天正真实建筑图（双线墙 + 洞口断开）→ v3 提取器可消费的**单线区划边界**，
**不要求人改变正常画图习惯**。

**建议架构（待方案确认）**：源 DXF → 转换器 → 规范化几何 → 现有 v3 提取器 → gt。
即**不改 v3 提取器本体**（零风险），转换器产物须留痕可核验。

**已实测的可用线索**（供方案参考，非设计结论）：

1. **洞口可由窗块精确补齐；门块不行**（⚠️ **2026-07-21 更正**：本条初稿标题误把窗的结论推广为"门窗块"，
   由 sol 独立复核指出、主控实测确认）：
   - **窗块** `$TCHSYS$WIN2D` 的 bbox **精确等于洞口**（240 厚 × 洞宽）——实测西墙缺口 (27105, 31905)
     长 4800 == 窗 AE4 y[27105.2, 31905.2]，逐个吻合；北窗 AE1 bbox 高 **240 = 精确墙厚**。
   - **门块** `$DorLib2D$*` 的 bbox **含开启扇（门扇弧线），≠ 洞口**——实测门 AC3 bbox 高 **780 ≫ 墙厚 240**，
     且上边界 47225.2 **越出外墙皮 46565.2**。⇒ 门洞宽度只能取**沿墙方向的投影**，不能拿整个 bbox 补墙。
   - ⇒ 转换器对门、窗必须**分别处理**，不得统一按 bbox 补齐。
2. **门窗类型可由块名判别**：`$TCHSYS$WIN2D`=窗 / `$DorLib2D$*`=门 / `$EWDLib$*`=立面门窗 / `$plan$*`=家具。
3. ⚠️ **双线配对：本图墙厚就已经不统一**（外墙 240 / 内墙 120，见 §2.4 更正）——
   "坐标差恒定"的配对法**在本图就失效**，不是未来才失效。厚度必须逐墙求证（不变量 #6）。
4. **`PUB_HATCH` 只覆盖外墙**（18 个），内墙无 hatch ⇒ 不能作为通用墙体实体源。
5. 家具在 `0` 层且块名前缀独立 ⇒ 易排除，不会污染墙线。

**已知难点**（方案须正面回答）：
- 双线配对（墙厚不一 / 内外墙不同厚）
- 丁字 / 十字 / L 形接头处的延伸与裁剪
- 墙自由端（端头封口）
- 凹角（L 形、U 形、回字形）——**必须能长到 sm25/sm26/sm27**
- 失败诊断：转换失败必须 fail-closed 且给出可定位的诊断，**绝不静默出一份错答案**

## 6. 本轮产出的附带结论

- **视图框 + 框内图名的画图约定：验证成功，保留**（§2.3）。
- **房间用途标注**：用户定 sm24 不作判分项（识图模型自推）；**sm25 起在 CAD 标房间名**。
  天正图形导出**不带房间名**（全图仅 5 个文字 = 5 个图名），sm21 的 role 靠另一份手工对照表补。
- **走廊口径（用户 2026-07-21 拍板）**：L 形走廊算 **1 个热区**，sm24 总 **8 区**。
  ⇒ 本 case 考的是"程序能不能把切碎的碎片合并回一个区"，跑出来大概率当场红 = 真实水平。
