# sm24 东侧 profile 候选观察离线复核

日期：2026-09-14
结论：候选定位明显改善，但墙身份和分隔关系仍有关键误判，暂不可接入 source 一致性检查

## 复核边界

本项逐条判断只以本目录保存的 `1f_view.png`、两份 `pixel_profiles` 原图/色罩、`observation.md` 和 `execution_audit.json` 为依据，没有用 source 或 GT 为各项定真。这是了解项目历史的开发侧事后复核，不是盲评；观察模型运行时未获候选 source、GT、旧答案或其他模型回答。本复核没有调用模型/API。

审计显示原图、清单输入和隔离目录副本像素一致；观察实际调用 15 次 `view_image` 和 2 次 `view_pixel_profile`，没有读取 source 或修改文件。两份 profile 的候选位置与保存图一致。以上只能证明输入、量测和查看轨迹真实，不能作为语义通过。

相比自由坐标探针，本次没有另造墙坐标，能逐项引用 `profile_record + C## + interval_indices`，这项约束有效。但 profile 只显示某个 x/y 峰上的灰色像素支持；对象是否为墙、两条线是否同一墙的两面、间断是否为门，仍必须由原图判断。

## x 轴候选

### X_C01：profile_001 / C01，`x=402`

**判定：基本正确。**

原图清楚显示约 `x=402` 的纵向建筑隔墙，从北侧横墙向南延续；多处间断处可见门扇与圆弧。它将西侧房间与中央狭长空间分开，门洞没有把两侧变成同一物理空间。因此 `physical_wall + separates_spaces` 有原图支持。

观察将 `[301–359]`、`[392–418]`、`[451–598]` 识别为同一墙的实线段，方向是合理的。不过用于说明的 `[395,290,420,330]` 小裁图主要覆盖北端结点，不能独自证明两个更南的缺口；完整原图和其他实际裁图才支持门洞解释。

### X_C02：profile_001 / C02，`x=457`

**判定：关键漏判。它是清楚的物理隔墙，不是家具或仅有局部墙片。**

profile 左侧未改动原图直接显示一条从北侧横墙向南延续的纵墙，位置正是 `x≈457`。它在 `y=367/371` 与横墙形成 T/端点结点，并继续向南；`[324–355]`、`[383–414]` 一带的间断对应纵墙上的门扇圆弧和门洞。右侧两个会议家具组位于墙东，不构成 x=457 的竖线。

因此 `object=uncertain`、`relation=wall_fragment` 低估了证据。输出以“有间断”为由否认完整分隔，混淆了墙体实线与带门洞的物理隔墙。门洞允许通行，但墙仍分隔两侧空间。

### X_C03：profile_001 / C03，`x=603–611`

**判定：外墙身份正确，间断类型错误。**

原图支持该处为东侧外墙，`physical_wall + exterior_boundary` 正确。灰墙实线之间的长青色段是嵌在外墙中的窗表示，尤其 `[382–557]` 不可能解释成一樘带圆弧的门；该位置没有观察所称的“cyan door arcs”。

错误不改变外墙身份，但说明模型仍会把 profile 的灰色缺口统一套成门洞。后续若把 door 标记用于拓扑或开口核对，这一解释不能采用。

## y 轴候选

### Y_C01：profile_002 / C01，`y=296`

**判定：基本正确。**

原图支持 `y≈296` 为北侧房间与下方空间之间的横向实体隔墙；`x=408–451` 的缺口有清楚的双扇门符号，缺口两侧墙线继续。`physical_wall + separates_spaces` 正确。

墙在本裁图左边界之外仍继续，因此“贯穿本裁图的大部分宽度”比“从 x=402 开始”更准确；这不影响本候选的墙身份。

### Y_C02：profile_002 / C02，`y=305–307`

**判定：错误。主体长支持是家具边，不是 Y_C01 的另一墙面。**

该候选的实质横向支持为 `x=508–595`，原图显示它是北端东侧房间内矩形家具的上边；`x=402`、`x=457` 和东墙处的一像素支持只是纵线与这一行相交。它的支持分布与 Y_C01 的 `x=360–407`、`x=452–611` 并不同步。

输出还称 `y=305` 比 `y=296` 低 4 像素，实际峰值相差 9 像素。`physical_wall + separates_spaces` 以及“Y_C01 的对面墙线”均无原图依据。

### Y_C03：profile_002 / C03，`y=327`

**判定：应归为非墙；保留 uncertain 避免了强行分区，但仍未完成对象核对。**

长支持 `x=509–594` 是同一矩形家具的另一条横边，`x=402` 为纵墙的一像素交点。观察引用的 `[360,293,630,315]` 裁图根本不包含 `y=327`，不能用来复核该候选；其实际调用过的 `[360,280,630,340]` 裁图和 profile 左面板已经足以看出家具轮廓。

因此更合适的结果是 `not_wall + not_applicable`。当前 `uncertain + wall_fragment` 不会直接新增分区，但若以后把 wall_fragment 当作物理对象，仍会产生假墙。

### Y_C04 与 Y_C05：profile_002 / C04、C05，`y=367/371`

**判定：墙身份与分隔关系正确，但应合并为同一物理墙的两条画线。**

原图清楚显示这两条相距 4 像素的平行灰线从约 `x=457/462` 接到东外墙，构成东侧上下两个房间之间的实体隔墙。它只需要分隔东侧两空间，不需要继续穿过中央狭长空间；“左侧没有支持”不等于自由端墙片。

两份 assessment 的 evidence 已互称“同一墙的另一面”，却仍分别输出两个 `physical_wall + separates_spaces` 对象，没有按题目要求把它们合并。若下游逐 assessment 计墙，会重复计数；语义上应是一个分隔关系、两条 profile 引用。

### Y_C06 与 Y_C07：profile_002 / C06、C07，`y=583/587`

**判定：灰线属于建筑墙，但把两段合成一条墙、把中央空档解释成门洞是实质错误。**

profile 明确保留了两段主要横向支持：西段约 `x=360–397`，东段约 `x=462–611`。中间 `x=403–456` 是中央狭长空间的完整宽度；原图没有跨越这个宽度的门扇、门框或横墙。`x=402`、`x=457` 的一像素支持是两道纵墙在该 y 行的相交点，不能把两段横墙桥成一个连续对象。

西段和东段各自是建筑隔墙的一部分，且 C06/C07 是其上下两条画线；它们应按左右分成两个对象，再将每个对象的两条平行线合并。观察却把全部 interval 放在一个 assessment 中，并说间隔“可能是内部划分或门洞”。这会把中央连续空间错误封闭，正是 profile 保留 disjoint intervals 本应避免的错误。

## unresolved 与方法问题

- “C01/C02、C04/C05、C06/C07 都相差 4 像素”不成立：y 轴 C01/C02 峰为 296 与 305，相差 9 像素，且对象和支持范围不同。只有 C04/C05、C06/C07 是 4 像素平行线候选。
- 不能仅因灰色支持有缺口就叫门。X_C01、X_C02 的缺口可由原图门扇/圆弧支持；X_C03 的缺口是窗；Y_C06/C07 的中央缺口是空间本身。
- `separates_spaces` 取决于墙的完整端接及两侧空间，不取决于线长。Y_C04/C05 虽只在东侧出现，仍完整连接纵墙与外墙；X_C02 虽有门洞，仍是完整分隔。
- 本题没有要求或提供两侧室内点、连续空间路线。本输出也没有生成这些对象，因此即便墙候选全部分类正确，也尚不能直接驱动“同一 source 房间落在物理墙两侧”或“连续空间被 source 墙切断”的确定性检查。

## 总结与采用建议

候选式约束解决了自由编造全局坐标的问题，并使 Y_C01、Y_C04/C05、X_C01 和东外墙的位置可复核。它仍发生三类会改变分区的错误：漏认 x=457 的带门纵墙；把 y=305/327 家具边误配或保留为墙片；把 y=583/587 的左右独立墙段跨中央空间合成一墙。运输和工具执行通过不改变这一结论。

因此本观察不应传给 source checker，也不能作为冷启动分区证据。若继续同类探针，输出结构还需强制：一像素交点不得作为沿轴墙段；相隔数值由代码给出而非模型心算；每个 disjoint support interval 单独分类；只有原图可见同一实体和端接关系时才允许合并；门、窗、开放空间三种缺口必须分别选择，不能使用笼统“可能是门”。
