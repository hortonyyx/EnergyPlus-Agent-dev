## 0. 一句话结论

**`window_host_claim_issues`（`window_host.py:576-613`）用 `!=` 精确比较两条不同计算路径得到的
同一个世界跨度 —— 存下来的 `clamped_span` vs 用 `line.point_at(t)` 重新投影出来的值。
实测偏差是 1–4 个 ULP（≤ 2e-15 m），门判它「被篡改」并抛
`invariant_no_geometry_commit` 裸异常，直接终止整条 flow。**

**⇒ 这不是几何错，是零容差门在误报。几何精度是 10⁻¹⁵ 米。**

**⭐ 最关键的一句**：项目**早就有**为这个量准备的容差
`window_host_span_epsilon_m = 1.0e-9`（`src/configs/correction.yaml:98`），
它在**同一个文件里被用了 11 次**，其中一处就在失败那道检查**上面 14 行**（`:562`）。
**⇒ 不是缺容差、不是不知道该用多少 —— 是这道门自己没用项目已有的那把尺子。**
实测偏差比该容差低**六个数量级**。

## 1. 现场

flow 崩在 `stage_runner.py:299` → `recompute_window_host_claims` → `WindowHostResolutionError`：

```
conflicts=15 · issues=6 窗 · reason=line_geometry · detail="world span"
fallback_action = invariant_no_geometry_commit   ⇒ 按 F-9 的设计【故意】裸抛、不归档重抽
```

判据原文（`window_host.py:596-600`）：

```python
projected = (q0[0], q1[0]) if dy == 0 else (q0[1], q1[1])
lo = projected[0] if projected[0] < projected[1] else projected[1]
hi = projected[1] if projected[0] < projected[1] else projected[0]
if (lo, hi) != (resolution.clamped_span.lo, resolution.clamped_span.hi):
    raise ValueError("world span")
```

`q0/q1 = line.point_at(t)`，即 `p1 + t*(p2-p1)`；`clamped_span` 由解析器另一条路算出并存下。
**两条路径、精确相等比较。**

## 2. 实测（`tools/f18_detail.py`，逐窗对账）

| window | 重算 (lo, hi) | 声明 clamped_span | 差值 |
|---|---|---|---|
| `W_F1_SE` ⛔ | `11.359999999999998` | `11.36` | **−1.8e-15** |
| `W_F1_NW` ⛔ | `1.2400000000000002`, `3.6400000000000023` | `1.24`, `3.64` | **+2.2e-16 / +2.2e-15** |
| `W_F1_N` ⛔ | `6.300000000000001` | `6.3` | **+8.9e-16** |
| `W_F2_SW` ⛔ | `2.1900000000000004` | `2.19` | **+4.4e-16** |
| `W_F2_NW` ⛔ | `1.9499999999999993`, `5.550000000000001` | `1.95`, `5.55` | **−6.7e-16 / +8.9e-16** |
| `W_F2_W` ⛔ | `3.4000000000000004` | `3.4` | **+4.4e-16** |
| 其余 9 个 | 逐位相同 | — | `0.0` |

**15 个窗里 9 个过、6 个不过。** `11.36`/`1.24`/`2.19` 这类十进制值在二进制浮点里
本就不可精确表示，走不同算式必然差最后一位。

### ⭐ 由此得出的定性：**这道门本质上是逐窗抛硬币**

同一份代码、同类数据，**过不过取决于具体算式的末位舍入**。
A/B 实测印证：抑制 envelope 变换后失败集合变成**另外 8 个窗**（`W_F1_E`/`W_F1_SW`/`W_F2_E` 等）
—— 坐标微动 ⇒ ULP 结果重新洗牌。**门的判定与几何正确性无关。**

## 3. 归因（A/B，决定性）

`tools/f18_ab.py`：

| 试验 | envelope 变换 | 写入侧重算 |
|---|---|---|
| A · 正常（4 个跨轴 intent） | 生效，footprint → `[0,15]×[0,8]` | ⛔ 失败，6 窗 |
| B · 对照（抑制 intent） | 不发生，footprint 保持 `[0.12,14.88]` | ⛔ **照样失败**，8 窗 |

**⇒ F-18 与 F-17 无因果关系**，是既有缺陷第一次被跑到（F-17 修好之后链路才走到这里）。

## 4. ⛔ 与 F-9 的关系：**不是同一条**（已足以定性）

| | F-9 | F-18 |
|---|---|---|
| reason code | `source_geometry_mismatch` | `line_geometry` / `world span` |
| 量级 | **0.12 m** 级真实几何错配（立面换算命中镜像搭档） | **1e-15 m** 末位噪声 |
| 性质 | 换算逻辑错（LLM 心算立面区间） | 门的比较方式错（零容差比浮点） |

**⇒ 同一子系统、不同缺陷，⛔ 不许归并。** F-9 治本仍是独立待决项。

## 5. 修法方向（⛔ 未施工）

把这道自洽门改为**用项目已有的 `window_host_span_epsilon_m`（1e-9 m）比较**，
而不是 `!=`。1e-9 m 仍远小于任何有物理意义的差异（1 纳米），**防篡改能力不受影响**
（实测噪声 ≤ 2e-15，与之相距六个数量级）。

### ⛔ 施工必须注意

1. **同一个 try 块里还有两处同族的精确相等比较**，目前没报但是同一枚地雷：
   - `if declared_endpoints != (q0, q1)`（`:594`）
   - `if fresh_vertices != declared_vertices`（`:609`）
   **应一并处理**，⛔ 否则修完这处，下一份真实产物就在另外两处炸。
2. **⛔ 不要把门删掉或降级为 advisory** —— 它是 anti-tamper（`resolver_output_tampered`），
   要保留其防篡改语义，只把「相等」的定义从「逐位」换成「项目容差内」。
3. **该门的失败走 `invariant_no_geometry_commit` 裸抛**（F-9 的**有意设计**：不变量违反必须硬崩、
   不得静默归档重抽）。修法**不应改这个出口语义** —— 该改的是判据，不是崩的方式。

### 建议的锁形态

- 夹具的窗跨度**必须用二进制不可精确表示的十进制值**（`11.36` / `1.24` / `2.19` 这类），
  ⛔ 不许用 `0/4/10` 这类整齐数字 —— **全仓 2326 绿之所以漏掉它，正是因为夹具都是整齐数字**。
- 断言：这样的产物**能通过**该门；并配一条反向锁：人为把 `clamped_span` 挪 1e-6 m（远大于容差、
  远小于几何意义）**必须仍被拦下** ⇒ 证明防篡改能力没被放水。
  （呼应「恒等锁 ≠ 正确性锁」：只证明「现在能过」不够，必须同时证明「该拦的还拦得住」。）

## 6. 这是同一族缺陷的又一次现形

**「同一事实在同一份输出里被声明两次，然后互相校验」** —— 窗的世界跨度既存在
`clamped_span` 里，又隐含在 `clamped_plan_endpoints_p1_to_p2` + `segment_parameter_interval` 里。
**轴 B 的第四种形态**（前三种：代码 vs 代码〔F-13〕· schema vs 门〔F-15②〕· 模型输出内部〔F-16〕）。

⇒ **更彻底的修法（登记，非本轮）**：让这个量只存一份，另一份按需派生 ——
那样连「用什么容差比」这个问题都不存在。与 F-16 的修法同精神。
