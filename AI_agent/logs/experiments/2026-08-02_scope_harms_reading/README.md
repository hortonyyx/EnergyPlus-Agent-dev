# 2026-08-02 · 「减卷有害」实证 + 高档模型无监督基线 + 六条机制缺陷

- **主控**：Opus 5
- **用户拍板的原则（本轮最重要的一条，已升为方法论）**：
  > **先保证质量，从高模型往低模型上降，而不是先降模型、拿到一个很低的分数再想办法提分数。**
  > 既然已经有 Sonnet 几乎全对、Haiku 加轻量主控介入也基本全对的情况，
  > **不应该容忍分数掉到 40–70% 再想办法提升。**
  > 「之前的成绩是假象」= 指**「Haiku 纯自己做到全对」是假象**，
  > **不是**指那个 100% 是作弊 —— 100% 是真的，只是不是低档模型的单一功劳。
  > **应该思考的是怎么把这条已经存在的正确路径让 Haiku 也掌握，
  > 而不是为 Haiku 或为这两个 case 定一套方案然后想办法迭代。**

## 0. 一句话结论

**减卷（把考试范围从五张图砍到两张）不只是让判卷失真，它真的把识图质量压下去了。**
同模型、同文档、同零监督、同一把尺子，**唯一差别是考几张图**：

| | Haiku d1（减卷） | Haiku d2（减卷） | Sonnet（减卷） | **Sonnet（全卷）** |
|---|---|---|---|---|
| **内墙命中** | 5.18/57.86 = **9.0 %** | 14.34/57.86 = **24.8 %** | 41.01/57.86 = **70.9 %** | **53.31/57.86 = 92.1 %** |
| **外轮廓** | 60/60 = 100 % | 60/60 = 100 % | 29.26/60 = **48.8 %** | **60/60 = 100 %** |
| **多画** | 59.36 m | 79.14 m | 46.01 m | **6.77 m** |
| 平面窗 | 0/11 miss | 0/11 miss | 7/11 existence 命中 | **11/11 conflict** |
| 工具调用 | 3 次探针 | 0 次 | 46 次（36 crop_zoom） | 38 次探针 / 198 条访问 |
| 用时 | 6.2 min | 6.9 min | 42 min | 46 min |

**内墙分母（57.86 m）与外轮廓分母（60 m）在四轮里逐字相同**，容差同为 wall 0.30 / window 0.40。

**⇒ 用户假设成立。** 合理机制解释：**五张图之间本来互为佐证**（平面判不准处可由立面校核），
减卷把这层冗余砍掉了 ⇒ 外轮廓从 100% 掉到 48.8%、多画从 6.77 m 涨到 46 m。

**⇒ 墙这一侧，Sonnet 无监督基本达标**：17 段内墙命中 14 段（2 完全 + 12 容差内），漏 3 段；外轮廓全中。

## 1. 两个 run

| run | 范围 | 模型 | 结果 |
|---|---|---|---|
| `run_2026-08-01_sonnet_pathref_s1` | 减卷（1f + South） | Sonnet 5 | 内墙 70.9 % · 外轮廓 48.8 % |
| `run_2026-08-02_sonnet_full_unsup` | **全卷五张** | Sonnet 5 | **内墙 92.1 % · 外轮廓 100 %** |

两轮的无监督定义相同：**零 directive · 零 feedback · 零中途反馈 · 不跑预扫**
（预扫按 08-01 用户口径属「质量之后的提速项」，两份历史达标产物都没有它）。
硬隔离 clean-room、判卷绑定文件 `b76c35c4…` 与 W5 两抽逐字相同。

### 1.1 减卷那轮的失分是「基准」不是「没测量」

Sonnet 减卷那轮**每一条轴线都落在 0.30 m 容差内**（10 条轴线最大偏差 0.25 m），
但线段级（端点 / 重叠范围）判不过。它在产物里写明：局部原点 = 外墙**中心线**交点，
按图上 240 墙厚推出真正的西南内角在 +0.12 处，并用 200 m² 建筑面积交叉验过。
⇒ **它做了一个经过论证的基准选择，只是与 GT 的基准不一致。**
⇒ 撞上 2026-07-08 就登记、至今未收口的 [[wall-thickness-dimension-basis-direction]]：
**尺寸基准是轴线还是墙面从未钉死；认真按像素量的会踩，抄整数的反而蒙对。**
（Haiku 外轮廓拿 100% 正是因为它把尺寸链上的 `0 / 10 / 20` 直接抄进去，恰好等于 GT 的框。）

### 1.2 窗：失败形状变了，缺口仍在

- 减卷：existence 7/11 完全命中；
- **全卷：existence / along / width 三项全部 11/11 `conflict`** —— 不是漏画，
  是**它的平面与四个立面对同一个窗说法不一致**，判卷器两边都不敢算；sill/head 11/11 miss。
⇒ **窗是墙之外唯一的真缺口**，且现在有了精确的形状描述（跨视图矛盾），可用现成产物离线定位，无需重跑。

## 2. ⛔ 本轮撞出的六条机制缺陷（全部是近期新增的东西）

用户判断「**主要原因是这段时间把机制改坏了**」，本轮逐条坐实：

| # | 缺陷 | 影响 | 何时引入 |

| **M-1** | **渲染整个不跑**：`_render_stage` 按 `0_reading/*_view.json` 找产物，硬隔离 merge 把产物放进 `attempts/NNN/output.json` | **07-08 起每一轮识图都零渲染**，用户看不到任何产物图 | 07-08 硬隔离强制化 |

| **M-6** | **gate① 与 CV 证据零接线**：`src/validator/` 全仓对 `cv_evidence` / `prescan` / `candidate_id` **零引用** | 确定性层看不到任何测量证据 | — |

## 3. Fable 点射（设计稿两版）

- 问题书 [request/2026-08-01_reading_completeness_design_brief_fable.md](../../reviews/request/2026-08-01_reading_completeness_design_brief_fable.md)
- 设计稿 [verdict/2026-08-01_reading_completeness_design_fable.md](../../reviews/verdict/2026-08-01_reading_completeness_design_fable.md)（含修订说明）
- **v1 建在预扫候选上 ⇒ 用户判「预扫不是杠杆」整版撤回**；
  v2 改为「尺寸链闭合当分母 + 读图器自己的验证痕迹当工作量账本 + 双读 diff 当二级复核」。

**主控核验结果（一对一错）**：
- ✅ **双读 diff 数据独立重算逐条吻合**：d1/d2 只有 4 条对得上、且中点距离**精确 0.00 m**（全是外轮廓），
  内墙 0 条对得上（最近 0.60–3.86 m）。**含义：抄数字的可复现，目测的不可复现**
  ⇒ 不看答案就能分出「这条墙是抄来的还是编的」。
- ❌ **「两抽都零验证工作量」的推断被证伪**：查考场访问日志，**d1 实跑 3 次探针**（d2 确实 0 次）。
  侧车在运行目录里是零，是因为 **merge 只搬答卷、不搬考场草稿** ⇒ 那个计数器量的是搬运策略。
- ⭐ **由此挖到更好的账本**：**考场守卫写的 `access_log.jsonl` 已经存在**（每条命令原文 + 放行/拒绝 + 理由，
  按 attempt 归档、进指纹、**被测者伪造不了**），**同样零消费者**。
  ⇒ 今天第三次撞见同一个病：自评字段 / CV 证据 / 访问日志 —— **信号都产出了，没人读**。
