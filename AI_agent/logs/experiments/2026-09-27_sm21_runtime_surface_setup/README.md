## 结果

1. 工具从36变39：新增replace_claim_sources、view_claim_evidence、record_work_review；共有36个工具的输入schema全部相同，仅build_bim、get_bim_reference、record_claim、revise_bim、view_image的说明变化。工具元数据JSON字符数32634→35984，不能当作实际模型token数。这四次主调用均没有直接调用新增三工具；它们仍出现在清单中，不能因此排除对模型选择的间接影响。
2. reconstruction、plan_partition、plan_assembly、geometry、facade_correspondence、opening_review、wall_dimensions七份参考逐字不变。claims、edits、parametric有变化，naming、room_types为新增。run69/72在首个成功候选前读了room_types，run71没有读；三次都先读了未变的reconstruction/plan_partition/plan_assembly。不能把所有新增内容当作初稿之前实际读过的内容，也不能据此证明目录没有间接影响。
3. 共核23份成功候选回执；全部包含可完整解析的几何JSON，预期平面回叠/源平面图的数量均齐全。run69一份、run71两份、run72两份后期revise_bim回执含25000-token截断提示，旧run58没有。**仅凭提示不能断言几何JSON或图像已经丢失，也不能证明供应商内部上下文完整**；本轮仅核实际归档外层回执。图像像素/字节核验复用上轮证据，不将计数冒充本轮像素复核。
4. 新增room_use_review只占这些回执740–1284字符，较大的项是回叠几何、门窗清单和修改记录。没有证据支持“用途反馈把初稿几何告警挤掉”。首份成功候选均无截断提示；run72第一次build_plan_bim已经把15000/8000填入米标定，早于任何成功候选的用途反馈。旧版schema也要求米，不能靠后期裁图/续查反馈解释这次单位错误的起点。
