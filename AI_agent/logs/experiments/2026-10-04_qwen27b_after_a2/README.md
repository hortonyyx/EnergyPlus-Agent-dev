# 27B 抽测：吸收包第二批合入后再跑 sm24（10-04）

**目的：** 同日 [27B 摸底](../2026-10-04_qwen27b_probe/README.md) 的 sm24 建模质量很好（位置 20/21、高度 14/14），但 97 次工具调用里 36 次花在依据手续上，交付前碰到 600 万 token 硬停，没有自己交付。A2-T 把“登记 → 采纳 → 确认”合成一次调用，并让没变的目标受控继承依据。这次只换 Agent 版本（`t1-20261004-a1t.1` → `t1-20261004-a2t.1`），其余条件与摸底逐项相同，看依据手续是否真的变少、能否在预算内自己交付。

**批准依据：** Paratera 开发期额度 50 元内由 Opus 安排（10-03 用户：“我先批准50块吧，这部分你可以自由调度测试”），事后报实际用量。批准以来累计估算约 15 元。

**条件：** 配置 [`configs/sm24_qwen27b_after_a2.json`](configs/sm24_qwen27b_after_a2.json)，由摸底配置只改批次、批准说明与输出目录；同原图、同任务正文、6000 秒、24 个候选、无委派；`enable_thinking`、温度 0.7、输出上限 16,384、上下文上限 262,144、15 万压缩；**硬停 600 万 token**，最坏约 25 元，预计约 9–10 元。开跑前 `runtime_configuration check` 通过。同时段本机另有 Astra 两个开发会话（A3-T、A3-R）在跑检查。

**看什么：** 依据相关调用次数与占比（摸底：36/97）、是否用了新的依据事务；能否自己交付、用时与 token；质量（同一套 sm24 评分）；花费。单次样本，只看有无明显变化。

## 结果（19:24–20:31 UTC）

评分：[`evaluation_sm24_qwen27b_after_a2.json`](evaluation_sm24_qwen27b_after_a2.json)。

- **结束方式：又碰到 600 万 token 硬停。** 3,620 秒（60 分钟），51 次请求、83 次工具调用（0 失败、0 重试），报告用量 536 万；底座交出唯一一版完整稿 `candidate_01`（不是模型自选）。底座估算 **9.59 元**，缓存命中 81%，每次请求平均输入 10.1 万、输出 4.1k、71 秒。
- **过程与摸底完全不同：** 83 次工具调用里看图 35 次、像素剖面 34 次，平面建模 3 次，只存了一版稿，**一次依据操作都没有**。所以 A2-T 的依据事务这次根本没用上，**它的效果这次无法判断**。同一型号、同一条件、只换 Agent 版本，两次的做事路径差这么多（摸底：六版稿、依据手续 36 次），单次样本不能归因于 A2。
- **质量（`candidate_01`）：房间 8/8、位置 21/21、挂墙 21/21、门连通 10/10，参照里的 14 扇外部高度全对；但多建了 3 扇窗** `T_bottom`、`T_right`、`T_top`：三扇外门正上方 2.6–3.0 m 各一扇约 1 m 宽的“亮窗”。南立面的尺寸链是“地坪上 200、门洞 2400”，亮子画在 2.4 m 门洞以内（约 2.2–2.6 m），模型把 2400 当成门扇高度、又在门洞上方加了窗，属读错。
- **判断：** 两次 27B 都在约 60 分钟、约 9.5 元时被 600 万 token 硬停截住。真正卡住的是每次请求约 10 万 token 的上下文（大部分走缓存，按 token 计硬停把便宜的缓存也算满了），而不只是依据手续。下一步：① 27B 的保护线改为按金额封顶（缓存 0.6 元／百万，同样 10 元能走得更远），或明确提高 token 硬停；② A3-T 的工具返回瘦身直接减每次请求的输入；③ 27B 大量看图、测剖面而迟迟不建模的行为，留给行为记录分析。
- **花费：** 10-03 批准 50 元以来累计估算约 24.7 元（10-03 下午约 5.7 元、摸底 9.44 元、本次 9.59 元），以账单为准，剩约 25 元。
