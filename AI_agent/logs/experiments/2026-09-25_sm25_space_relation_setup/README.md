# sm25：观察到的空间关系与实际源归属

run44 中观察称原图为同一连续空间，但实际源将其分成两个空间、用敞开通道连接；run45 经开发明确指出位置和错误性质后才修复。本节点补通用只读查询，不通过解析自由文本自动决定墙/空间语义。

`check_source_space_relation` 接收模型选择的原图两点、预期同一/不同/不确定及观察依据，使用登记的图面标定查询当前源空间 ID 和直接连接。不同空间通过门或敞口连接仍是不同空间；边界、重叠、模型范围外点不作一致性判断。结果绑定源、图像与标定，修订后旧结果在交付中标为过期。采样一致不等于全层保真。

新纯函数、stdio接线及共享交付/平面相关检查共55个不同测试通过：首轮11项，后续45项含1项重合。历史[开发回放](developer_replay.json)确认run44两点归属不同、run45归属相同；回放坐标和成功源不提供给工作模型。

[运行脚本](run_recovery.py)只向GLM提供原图、run44最终失败像素声明与通用复核要求，不点名错误区域、对象ID、正确数量或采样点。独立输出为 `../2026-09-25_sm25_space_relation_glm_run46/`，这属于旧稿恢复，不能计为原图独立冷启动。源码与输入哈希保存在运行前的 `frozen_method.json`；新增查询模块本次由此冻结记录覆盖，旧入口的运行manifest尚未列该新模块，事后核对分别报告。

[独立核验](audit_run.py)只在生成完成后执行：重放源/显示、局部声明修订、实际空间关系查询，复用既有原图独立参照和GT核空间/宿主/连接，并审计真实图像运输。运行结果见[统一交接](../../worklog/2026-09-25_dual_manager_development.md)。
