## 清理依据与安全边界

最大两项目录 `lite-full-tests`（12.874 GiB）和 `runtime-integration-final-20261010`（2.216 GiB）是测试复制的案例、仿真输出及测试产物。另核定的 `opus_checks` 十二个子目录合计 3.034 GiB，经独立只读审阅确认属于离线 pytest 夹具；`cleanroom-source0` 属于测试生成的源副本，模拟模型流来自离线 mock。六份根目录 TXT 汇总保留。

全部目标删除前都验证为 Git 未跟踪、被忽略的明确测试目录。执行脚本使用固定 35 项允许清单，核对绝对路径位于 `local_backup` 内，检查根目录及祖先没有 reparse point，再核对 Git tracked 集合为空。内部链接先用 PowerShell 原生 `Remove-Item -LiteralPath` 单独解除，确认没有剩余 reparse 项才递归删除普通目录；没有沿测试制造的断链、循环或外部链接访问目标。删除范围与链接处理另经子代理只读复核。

原始案例、正式实验记录、建模输出、迁移备份、`takeover_20261008`、`.git`、`.venv` 和 D 盘旧工作树均保留。过去因自动审批被拒绝的目录本轮未重试；这不属于本轮清理失败。没有清理尚不能确定是否包含独有运行证据的其他目录。

## 体积增长原因与后续

此前主仓库无链接重复计数的文件体积约 35.17 GiB；若目录统计继续跟随测试中的别名链接，会额外重复统计约 16.74 GiB，呈现约 51.91 GiB。测试把带历史仿真输出的整个案例复制到临时目录，再长期保留，是实际体积增长的主要来源。

本轮只落实清理，未改测试策略。后续可单独处理案例夹具的最小化、临时目录位置及保留周期，避免每次测试再次复制完整历史输出。
