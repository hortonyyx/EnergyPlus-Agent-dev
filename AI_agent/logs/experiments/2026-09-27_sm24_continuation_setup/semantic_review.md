# 生成后独立语义核查

Astra直接复核五张原PNG、保存源模型和实际工具回执。本页及下述评价只在生成结束后落入评测侧，没有送回工作模型。用途参照为上一节点已保存的[独立原图观察](../2026-09-27_sm24_room_types_setup/semantic_reference.md)，不按任一开发解释强造唯一真值。

三次均保留seed的8空间、54边界、21门窗、10连接；各空间多边形、楼层、高度及宿主/关系完全不变。独立原图仍8空间对应、位置15/21、宿主21/21、门连接10/10，最大端点差0.2475925846m。typed-GT十四外开口位置/宽/高/宿主在原容差内，严格及原图分区仍severe，无房间身份/错拆错并信号。元数据完善没有修正这些尺寸偏差。

## 用途

三次均实际读固定表并保存7项inferred和1项unknown。run63北侧大室为lobby、东北小室storage、东中部unknown；run64/65北侧为office、东北unknown、东中部会议。办公桌椅、南侧长会议桌、连续走廊都有相应解释且未据用途拆房。北侧L形家具仍可能是坐具而非办公桌，东北长条家具也不能唯一证明储藏；这些分歧未被当前自主续查解决，不称“8/8用途正确”。run63的unknown活跃依据主要保留坐标，具体替代解释只在修订理由/回复中；说明“有依据字段”也不是解释完整度判定。

run65最初一次用途修订用了非表内`conference/meeting`，工具拒绝且未保存候选；模型自行改为合法`conference/meeting/multipurpose`，随后成功。失败应用记录保留。纯用途编辑后3条已确认高度claim仍为当前有效，未因用途/来源变化错误失效；这是真实贯通验证。

## 高度：数值与证据区域分别核查

## 自主续查

run63/64在续查阶段都只记录stop并finish，没有查证其停止理由；remaining_seconds仍充足。两次恢复scope的高度要求比原整案任务宽松，所以保留为失效机制观察，不称同任务能力对照。

run65恢复明确高度记录要求后，初始主调用先确认高度、再保存用途；这两类动作不是续查阶段新增。第一轮续查自主选缺失的空间关系验证，实际重看原平面、注册10m×20m标定回叠并执行7对样本（3 same / 4 separate），结果与源分区一致。没有开发局部提示、手动插话或改源。第二轮基于保存记录停止；这个理由能解释保留7内门假设，却未发现上述证据框缺陷。

因此本轮证明了一次“保存状态 → 模型选题 → 实际续查 → 保留几何”的执行，同时保留两次提前停止及证据定位缺陷。三次没有冻结同范围重复，不证明稳定整案自主完成。下一项优先让模型直接查看并修正自己引用的原图区域；可复用已有view_image/claim接口，不把coverage计数当通过门槛。
