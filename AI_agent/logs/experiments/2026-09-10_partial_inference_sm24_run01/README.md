# sm24 四立面部分推理：首份明确简化的源 BIM

[模型与实际交付](delivery.html) · [独立诊断](evaluation/index.html) · [外部开口坐标对照](evaluation/opening_coordinate_diagnostics.json)

输入来自 [受控缺信息案例](../../../../case_tests/partial_inference/sm24_exterior_only/README.md)：只提供四张原立面和原声明中的深圳、办公、一层、约 200 平方米。唯一平面、房间数量、GT、历史 reading/correction/生成结果均未提供，无 seed。开发助手负责选择资料子集和确定允许合理简化的研究范围，没有给内部方案或开口答案。生成只读冻结的四张图片及 scope，属于受控缺信息独立启动；案例本身不是未见泛化样本。

主模型实际 `claude-sonnet-5`，medium effort；175.96 秒正常结束，一次 Claude 订阅调用，CLI 估算 $0.5141352，不是订阅账单。模型没有调用局部 Haiku；目标档局部任务待后续有界验证。不使用 DeepSeek、付费 API 或 EP。

## 已交付与真实边界

- **1 个整层合并空间、6 源边界、11 窗、3 外门**，200 平方米、4.5 米高；源几何通过，无未建开口，可查看。尺寸来自四立面，整体边界为 10×20 米矩形。
- 模型没有凭朝向切出房间，明确内部格局/隔墙/走道/内门未知，直接生成合并表达。这证明缺少内部平面时可以交付有用的粗模型，**没有验证逐间内部推断或真实房间恢复**。`office_open_plan` 是合并方案的标签，不是已确认建筑实际开放布局。
- 朝向左右约定、墙厚省略、门状态和内部未知随 proposal/source 保存。窗/门高度按图上重复尺寸规律采用，不能把类型假设全说成逐对象实测。
- 原四立面事后核对及 typed GT 的直接世界坐标诊断支持 14 个外部开口对应，其中南侧右窗 W_S2 沿墙位置错 0.48 米，其余 13 个开口的沿墙端点一致，约 0.0000112 米高度差属参考提取数值残差，不作精修目标。这个坐标诊断是同楼层/方向/类型等数量组内按位置排序配对，不是完整 typed claim 评分，也不独立证明像素身份。

南立面原尺寸链为 540/1500/2500/900/2520/1500/540 mm。按同一标注累计，右窗应为 x=[7.96,9.46]，模型却写 [7.48,8.98]；这不是内部信息不足或合法简化，是已有标注的换算错误。该发现只在生成后记录。源坐标对照脚本读取真实 source vertices 和经验证的 v3 GT，没有拟合镜像、压平成旧 GT、倒改参照或把结果送回生成。

## 回查与诊断缺口

本轮对四张立面保存了 7 份门/窗回查，但旧接口只能声明楼层/类别范围。模型把单立面 complete 当作该面完整，工具则将其他立面的开口列为未匹配，所以实际交付显示需跟进；不能把它解释为整楼真的漏了其他面开口，也不能让口头“全对应”覆盖工具记录。下一增量补显式立面范围及零开口立面的完整性保留，旧结果原样保存。

共用分区诊断保留完整参照 8 空间对本次 1 合并空间的 severe 原始差异，但本次没有内部平面、允许合并，**这个差异不作为漏房/错分区的验收失败**。隐藏布局能否合理推断尚未测。

首轮诊断误将 v3 参照传给旧 v2 窗评分器，发生 KeyError: W_m。失败输出留在 evaluation_incomplete_legacy_windows/；修复入口后在新 evaluation/ 明确 typed 窗评分未接、保留分区与实际数量，不伪造匹配分。另以本目录 evaluate_opening_coordinates.py 完成上述有界原生 v3 坐标诊断。
