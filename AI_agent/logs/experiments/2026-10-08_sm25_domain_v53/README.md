## 全流程行为观察

原始事件日志保存每次请求、工具参数与返回、产物、候选及运行回执。dev model 逐角色观察并记录：

1. 调度员盘点输入、派读图任务的顺序与并发；服务拒绝、排队和重试。
2. 读图员看整图、裁剪、量测的选择，首次试建与成功试建、首次错误、根据反馈修改的内容、实际提交。
3. 一步建楼的每次尝试与成功时刻；跨层对齐、开口宿主、装配复核是否重复。
4. 高度的依据与应用；超过 30 cm 的平面／立面开口位置分歧数、双原图查看、裁决、重读与重新装配。
5. 调度员返工是否修到问题、是否引入新错误，最终交付或停止原因。
6. 各角色请求数、耗时、token 与缓存；总用时及关键路径，和 domain v52 的对应行为对照。

`observe_run.py` 的里程碑只代表首次工具调用，必须结合工具返回核实成功；调用 `finish_bim` 不等于交付成功。正确阻断未裁决的分歧不记为 domain 故障。

### 定位到的问题

1. **domain / kernel：确定性异常与拓扑变化。** 首轮 `StopIteration` 已用原始建模声明纯函数重放，源于 Q1 时引入的尺寸对齐器，早于 v52、v53。第二轮一处原本 0.05 px 的接头误差被规整放大到 4.9 px；二层一条 13.8 px 台阶段被规整成零长边。见[异常调查](unknown_write_investigation.md)及[第二轮几何追踪](second_round_geometry_notes.md)。这些是实证，不是猜测。
2. **runtime：共享时间预算与失败可见性。** 暂时被另一角色预留完的余额，会使一层永久停止；二层释放余额后却继续运行。异常捕获又未保留原始 `StopIteration`，调度员只得到 unknown，难以形成具体返工。见[预算调查](budget_stop_investigation.md)。正确阻断不确定写入和截断输出应保留，不能以绕过保护解决问题。
3. **work model 与 domain 配合：长时间读图、格式返工和实际读错同时存在。** 首轮一层建模声明把墙延长穿过走廊、把西南外门画成内门，另有约 0.43 / 0.69 m 的门端点偏差；第二轮多数约 5 px 断点原来就存在。见[有限质量复核](independent_quality_notes.md)。两轮均出现 `printed_segments_mm` 等错误字段；guidance 措辞和首份完整建模声明负担可能有关，**只是待检验假设**。不能把修掉 kernel 异常等同于读图质量恢复。
