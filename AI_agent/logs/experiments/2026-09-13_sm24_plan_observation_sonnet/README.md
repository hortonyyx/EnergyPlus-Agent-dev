# sm24 平面图证账本模型能力对照（Sonnet）

本目录是 Haiku 图证账本探针的同条件 Sonnet 对照。两臂使用同一张 sm24 原始平面、同一问题、同一只读 system prompt、同一工具集和 240 秒上限；没有旧候选、正确房间数、正确坐标或 GT。它仍是开发助手发起的辅助局部方法试验，不是历史方法完整复现，也不是生产 BIM Agent 的整案 A/B。

## 结果

**超时，未交付图证账本，不可送入 BIM。** 实际模型 `claude-sonnet-5` 在 240.57 秒达到上限，`response.json` 记录 `completed: false`、`timed_out: true` 和 `No completed answer`。因此没有可评价的最终墙、门或空间 JSON，也不能从内部工具探索替模型补写答案。

## 超时前的真实工具轨迹

Sonnet 实际调用 `inputs` 1 次、`view_image` 26 次、`pixel_profile` 5 次；没有调用 `map_pixels` 或 `map_dimension_chain`。它反复裁看中央竖带、横墙交点和下部平面，最后一次工具返回后没有来得及输出文本账本。工具回传中的 `remaining_seconds` 始终为 `null`；外层虽在 240 秒杀停，子会话没有收到递减的剩余时间提示，这是本次交付失败的一个真实运行条件，但不能据此推断修复后一定成功。

局部轨迹里有一项可复核命中，但这里只能作为**事后工具事实**：在 y=340–360 的灰色横向剖面中，它得到 x=360–361、402 和 457 三组 run；其中 x≈402/457 与原图中央走廊两侧可见灰/白墙带对得上。它还沿 x≈398–407 做了纵向剖面，得到 y≈296、392–418、451–598、631–751、755–867 等离散区间。宽容差会混入灰白家具和墙交点，而且模型没有提交这些 run 的语义处置；不能据此说它识别了墙、理解了开放段或总体优于 Haiku。

## 与 Haiku 的简短对照

| 项目 | Haiku | Sonnet | 可下结论 |
|---|---|---|---|
| 完成情况 | 129.98 秒完成，给出长账本 | 240.57 秒超时，无账本 | 两臂都没有产生可进入 BIM 的结果。 |
| 真实调用 | 16 次看图、3 次剖面 | 26 次看图、5 次剖面 | 更多调用消耗了完整预算，不等于成功。 |
| 图层/墙带线索 | 把青色当主隔墙；青色剖面为 0 仍称 confirmed | 灰色剖面命中 x≈402/457 等可见墙带，但没有最终分类 | 只能记录一次局部像素命中；无交付，不能评价墙/门账本准确率或模型优劣。 |
| 证据使用 | 离散 run 被改写成连续整墙，工具反证未处理 | 工具轨迹保留离散 run；没有结论可检查 | Haiku 是明确的语义失败；Sonnet 是明确的时限/交付失败。 |
| JSON 可用性 | fenced JSON 加说明文字，且内部引用不一致 | `No completed answer` | 均不满足可直接消费的结构化中间产物。 |

这次对照只支持两个窄结论：换模型没有让当前方法在固定时限内得到可用结果，时间编排是方法的一部分。当前子会话没有剩余时间信号，也没有阶段性提交，最终留下很多工具轨迹却没有可消费产物。下一轮若继续，应该要求先在较短时限内交付最小可解析账本，再用剩余预算补证；声称由量测确认的结论需对应真实剖面结果；零匹配、离散 run 和冲突应触发回看或换证据，不能伪称该次量测已证实。未检出仍允许原图支持或明确推断，不据此自动拒绝建模。修复剩余时间传递只修正实验条件，不能预先算作模型成功。

实际图像重放与只读输入隔离检查见 [execution_verification.json](execution_verification.json)，全部返回图像逐像素一致；事件流已无损压缩，往返校验及原流摘要见 [stream_archive.json](stream_archive.json)。这些检查只证明运输/隔离，不证明图意正确。
