# 同色连通范围：现有工具与旧 `window_cc_detector` 的取舍

本次只核对当前源码、`723b0f9` 中的旧 CV 工具源码及既有历史 sidecar，没有读取 GT，也没有查看 run08/run09 的新扫描结果。

## 建议

当前需求若严格限定为“查看某种颜色在原图上的完整连通范围”，可直接复用现有两步工具，不必新增 API：

1. 用 `view_pixel_region_overview` 按目标 RGB 和较低容差列出 4 邻域连通块；把 `min_pixels` 调到足以保留细窗框，并检查 `region_exclusions`，避免小块过滤、边界过滤或 `max_regions` 截断造成假遗漏。
2. 让模型在原图上选择候选，而后把 overview 返回的 `seed_pixel` 交给 `view_pixel_region`；将 `simplify_pixels=0` 可保留像素边界。后者返回该种颜色从种子可达的完整连通块、原图半开 bbox、像素数和外轮廓，可作为“这片颜色实际连到哪里”的证据。
3. 模型仍须根据原图判断该连通块是不是窗框、一个窗由几个块组成，以及 bbox 是否可作为所需端点。工具输出不能自动命名为窗，也不能由“没有连上”推出没有窗。

这条路径尤其适合核查单个同色、确实连通的窗框。若框线被抗锯齿、断点或其他颜色切开，现有工具会诚实地返回多个连通块；若它与同色墙线、文字、尺寸线或其他窗相接，也会诚实地泄漏为一个大块。可先通过低容差、overview 全局盘点、逐种子 detail 和原图复核处理这些情况，不应为了得到预期窗数而扩大容差。

## 与 `723b0f9` 旧工具的实际差异

| 项目 | 当前 `view_pixel_region_overview` / `view_pixel_region` | 旧 `window_cc_detector` |
|---|---|---|
| 颜色掩膜 | 到调用方指定 RGB 的欧氏距离，容差可为 0 | `clean_vector_v1` 固定灰度族：均值 60–230、RGB 通道差不超过 8 |
| 连通性 | 4 邻域；对角接触仍分开 | 8 邻域；对角接触会合并 |
| 输出 | overview 给所有保留块的 bbox/种子；detail 给单块像素数、bbox、外轮廓及洞 | 批量给 component bbox、质心、面积和 component id；不返回精确轮廓 |
| 过滤 | 面积、是否触边、最多返回数 | 面积，以及可选宽、高、长宽比范围 |
| 跨缝组合 | 不自动组合 | 按 bbox 的小间隙+正交重叠或 IoU 反复合并，默认 gap 2 px、重叠比 0.5、IoU 0.2 |
| 语义 | 明确是非语义颜色候选 | 输出曾直接写成 `candidate_kind=window_rect`，但算法本身仍只有灰色连通块和框合并证据 |
| 坐标/审计 | 原图坐标、预览映射，工具调用保存记录 | 支持 crop/scale 反变换及 append-only sidecar/overlay |

旧工具的优势是批量形状筛选和把断成几片、但相距很近的框合成 bbox；这已经超出“完整连通范围”，属于启发式组合。历史 sidecar 也显示它会在一张图上给出很多候选（所核两份分别为 148 和 53 项），不能把候选数量或 `window_rect` 标签当成窗清单。

因此下一轮优先沿用现有 overview → seed → detail。只有在多个案例都证明“正确窗框经常因固定的小缝断开，且模型无法稳定逐块组合”后，才值得补能力；届时应复用旧算法的通用 bbox 过滤/显式合并参数，继续命名为非语义 raster/component candidates，并把原 component、合并理由和未合并清单同时保留，而不是恢复自动 `window_rect` 认定。
