## 先前实际怎么做

1. 09-10 开发助手用脚本直接判读、量测和装配过展示模型。最终第一版的有效操作主要在 `refine_asset.py`；最早 `build_asset.py` 的规则窗排并非最终成功方法。已有米制正投影、窗组像素换算、窗间隔墙约束、源装配、连续竖向空间和覆盖检查等可复用动作。
2. 但这些动作与 Voimatalo 的人工坐标、窗框、层高和空间方案混写；关键取舍多数只剩最终常量。展示第二版还使用了去标签父瓦片，补裁剪漏掉的凸出交通体量，并结合用户建议推断用途。
3. 09-14/15 主要改为“工作模型先试 → 开发定位失败 → 补工具/提示 → 恢复重试”。原资产观察、显式坐标关系、叠图和分页由此变得可用；尚没有一份完整、可重放的开发示范作为整栋方法基线。

因此当前调整研究顺序：开发助手先把完整案例的方法走通并留下依据，再提炼操作支撑、交 Sonnet 实际执行。局部工具修复继续按需要做，整栋结果与迁移效果仍分别验收。

## 接下来完整示范要交什么

以下是本次开发任务的安排，不是所有建筑必须经过的产品流水线。

1. **整体解释与外部约束。** 对应主楼、附属体、退台、屋顶及缺面；用局部墙面证据、不同高度剖切和纹理确定可支持的轮廓。保留原量测、规整值及差异，不只留最终坐标。
2. **楼层和开口。** 将声明与可见窗排联系起来；逐面记录观测范围、重复规则、门/窗/模糊斑块的取舍。检查像素是否命中目标墙，遮挡或裁剪透出的另一面不直接纳入当前窗清单。
3. **内部方案。** 在既定简化意图下提出一种自洽的办公/交通/服务空间假设。内部未知不能靠网格验证；不得将窗排机械变成逐窗房间，或把连续空间按朝向切开。连续竖向空间避免逐层假楼板。
4. **源装配和返工。** 使用共同源入口生成新候选，保存输入、失败、修改和实际源回叠。检查外形、分层变化、门窗宿主、空间覆盖、相邻与连通；自洽检查与原资产符合程度分开报告。
5. **方法提炼与实测迁移。** 从实际有效步骤提炼工具、参数解释、证据格式、检查和返工办法。保留明确适用范围；开发完整结果、Sonnet 教学辅助结果、Sonnet 自主执行结果分别报告，再按失败环节补支撑。目标模型仍可自主挑观察角度/参数，不要求全部观测预先固定。

完整示范的完成依据是有可查看 BIM、已知信息/内部假设清楚、主要矛盾已处理且剩余缺口如实列出；不要求无内部真值时宣称真实布局复原。单例成功也不证明稳定或跨例泛化。
