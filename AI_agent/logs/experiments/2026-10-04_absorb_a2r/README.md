图片仍保留原始字节与原编码；图片模板、文本和工具目录也复用哈希节点。发送前重建全部真实正文并核对完整哈希。读取验证每个附件及重建正文，损坏、缺失、哈希不符均显式失败；缓存只加速编码，不跳过读取校验。旧普通 JSON、A1-R 图片捕获和旧待呈现图片指针继续可读，运行恢复仍遵守原有版本绑定。

运行时行为报告只保存事件文件的相对路径和哈希，`load_behaviour` 重建完整行为；事件变化后旧报告明确失效，结束运行后重新生成。引用报告再次导出仍指向原事件文件；历史完整报告可继续读取和导出。

## E：小测结果

先只读核对本轮新线路全部 31 次响应：缓存读取为 64 token 的整数倍，第 12／13／14 次分别读 85,696／43,328／85,696。该现象与多服务器缓存解释相容，不能单凭序列证明服务端分流；见 [缓存序列](cache_observation.json)。

小测使用 Anthropic 公开 [metadata 定义](https://platform.claude.com/docs/en/api/messages/create) 中的 opaque `user_id`，按本批运行生成随机值，不含设备信息，不加入 Claude Code 会话头或 User-Agent。两组各六次，交错发送；每组前缀分别采用新的等长随机标记以避免交叉暖缓存，组内请求正文逐字节相同，总输入均为 3,360 token。

| 组别 | 六次缓存读取 token | 去掉每组首次后的缓存占比 |
|---|---|---:|
| 无标识 | 0、0、3328、3328、3328、3328 | 79.24% |
| 有标识 | 0、0、0、3328、3328、3328 | 59.43% |

差 −19.81 个百分点，没有达到预先规定的收益门槛，因此正式请求不加入此字段。六次／组不证明该字段普遍有害，也不足以定位服务端机制。

12 次 HTTP 全部成功，无重试；8 次正常结束、4 次达到小探针的 64 输出 token 上限，截断不当作任务完成。服务端共报输入 17,024、缓存读取 23,296、输出 315，合计 40,635 token；订阅不作按 token 货币估价。原始 38 个文件压缩为 6,533 字节，文件哈希已校验。忽略的 `probe/` 保留本批防重跑配额账；12 次额度已用完，复跑不能视为获批。

完整联合检查为 432 通过、1 失败，耗时 2,497.515 秒；10 项长任务与 3 项真实工具检查均通过。命令意外重复列过 `test_stage1_behaviour.py`，但 XML 实际包含 433 个不同节点，没有重复计数。

联合检查加载源码后补修了报告再次导出，只有 `runtime_behaviour.py` 和对应存储测试两文件改变，因此原记录的 `source_unchanged_during_run` 如实为 false。之后固定源码与提交号，补跑整个存储／报告、阶段 1 行为、阶段 2 接入三个文件，**21 项通过**（112.763 秒），源码一致性为 true。用这三个文件的新结果替换旧覆盖后，当前版本 **435 项不同检查全部通过**；不把重复执行相加。
