## A. 按金额封顶（完成）

- 依据仓库登记的 Paratera 人民币单价接入请求前预留、请求后结算；文字、缓存、输出分价，图片另收一次。估算不等于平台账单。
- 与 R1b 一致：实报超出预留时按实记账，检查总账；用量缺失时停止。
- 金额上限与请求数、时限等保护并存，token 硬停可显式不设，不静默放宽旧配置。
- 核对中断时保留最近完整稿，以及恢复、重试和并发委派的预算路径。
- 离线反例覆盖高/低缓存、多/少图片、上限前一步、用量缺失。

运行配置可写 `"limits": {"model_calls": 200, "tool_calls": 1200, "seconds": 6000, "tokens": null, "money_cny": "15"}`。金额配置下可省略 `tokens`；旧配置仍需显式给出 token 限额。CLI 对应 `--money-cny 15 --no-token-limit`；只加金额参数会保留 CLI 原有 token 默认限额。

请求前按“全部输入按未缓存价 + 最大输出和推理额度 + 图片另收一份”保守预留，不预测下一轮缓存命中；收到原始 usage 后按输入、缓存、输出和图片登记价格核算，释放差额。原始 usage 与人民币估算分开存储，每次预留保存单价及来源。金额是按登记单价计算的估算，不是平台账单；原有 token 估计偏差也可能导致实报超出单次预留，按 R1b 保留完整超额，按总额度决定能否继续。

未知用量、无法核算的 usage 或中断后尚未结算的响应阻止继续发请求；未知用量保留原预留。重启不能退回已发生的金额。两条并发子任务共用根额度。保留次数、时限、上下文、输出限制；只允许显式关闭总 token 限额。

金额封顶目前接受已有完整价格表的 Paratera Qwen3.8-27B 与 Qwen3.8-Flash。GLM 订阅不接金额估算；Paratera GLM 缺缓存与图片登记单价，发送前拒绝金额配置。协调器入口的金额只覆盖本地观察任务，外部协调模型用量仍不可见，CLI 说明此边界。
