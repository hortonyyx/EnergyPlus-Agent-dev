# GLM Flash 独立试跑（2026-09-30）

用户要求先试 GLMFlash，不替代主开发。选 sm21，与 run98 使用完全相同的六张原图、任务、系统指引、44 个生产文件和预算；仅调用通道与工作模型改为现有 GLM 订阅的 `glm-5.3-flash`。单次冷启动，3000 秒，最多 24 个候选，无续接、委派、自动重试或付费 API 回退。

`trial.py prepare` 在进程启动边界阻断模型调用，核对原图、完整提示、生产文件和实际 MCP 工具；`trial.py run` 只启动批准的独立目录一次。`preflight.json` 保存准备证据，运行目录保存请求、回执、输出和生产代码快照。现有 Sonnet run99–103 编号及审批保持原样，结果不作为模型切换或稳定性结论。

实验脚本不重试；Claude CLI 内部的请求重试不受本脚本控制。与 run98 一致，禁委派写在任务中，`review_detail` 仍暴露，生成结束后检查是否实际调用。

工作树缺少私有 `.env`，本地仅建立指向主工作树 `.env` 的忽略链接供现有订阅启动脚本读取；密钥不进入记录或 Git。CLI 版本为本机已核对的 `2.1.284 (Claude Code)`。

评估在生成结束后使用现有 sm21 原图/GT 对应核验及 run98 的房间一一对应、外部门窗高度 5 cm 标准。GT 不传给生成模型。CLI 金额仅为客户端估计，不是订阅账单。

`audit_sm21.py` 复制自 `2026-09-27_sm21_current_tools_setup/audit_run.py`，仅将订阅回执断言改为 GLM/Flash，并移除与旧 run58 的任务比较尾段；评分函数和参考数据不变。`evaluate.py` 复用 `instruction_fix/evaluate.py` 的行为和高度检查；房间一一对应使用新换例检查的通用实现及原 sm21 参照，避免把楼层命名差异当成几何错误，要求仍为全部参照房间与源空间双向一一对应。独立写 `trial_evaluation.json` 及与 run98 的 `comparison.json`，不伪装 Claude 回执。

## 行为与限制

- 建模前 6 张全图、9 张局部图、31 次像素量测；两层先量测后建。首次失败为外墙开口未落在声明边界上，模型自主修正，随后两层均编译成功并装配；后续交付没有开发者介入或修图。
- 第一份失败草稿报告 2 个未声明门洞缺口，后两稿报告为 0；只记录实际反馈变化，不能从本次独立结果推断检查模块的因果收益。
- CLI 工具错误 10 次（run98 为 6 次），包括图片名、平面修改参数、过期 claim、备注格式。4 次备注匹配失败的请求中，目标文本实际上各出现两次，`replace_note` 要求恰好一条；不是原文抄错。这是现有重复备注与单条替换接口不相容的具体例子，留给主线接口整理，不在试跑中改工具或人工修候选。
- 最终仍记录西门在平面/立面的宽度冲突、二层南侧一道隔墙的读数不确定，以及两条重复的“标定未经独立验证”说明；不把高度/宿主满分称为所有交付要求都已满足。
- GLM modelUsage：输入 470941、缓存读取 4961536、输出 96179；Sonnet：输入 152、缓存创建 513825、缓存读取 18441852、输出 103793。按回执原字段保留，模型计数口径和上下文压缩不同。GLM CLI 显示 USD 4.7996512，但 `costBasis=unknown`；Sonnet 显示 USD 6.7819044，两者均非订阅账单，不能据此计算真实省费比例。
