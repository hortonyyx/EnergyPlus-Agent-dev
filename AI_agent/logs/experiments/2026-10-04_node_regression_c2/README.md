## 条件

- **Claude Code**：[`claude_code.py`](claude_code.py) 原样复用 T1 启动器（同原图、同任务、medium、24 候选、无委派与续查、6000 秒），只把预备记录和运行目录换到本目录，T1 的旧运行不覆盖。预备时探测到的 42 个工具是完整目录；实际启动带 `--enabled-only`，模型看到 40 个，与新底座相同。
- **已知差异**：Claude Code 走智谱 Anthropic 兼容端点、自适应思考；新底座走 OpenAI 兼容端点、无自适应开关。
- **顺序**：sm24 两条线同时开跑（同一时段、同一订阅，服务状况相同）；两者结束并核过回执后，再单独跑新底座 sm25。遇到额度用尽即停，不补跑。

## 判定口径（开跑前写定）

1. **底座本身**：正常交付或到点交出最近完整稿；记录完整；没有底座引起的失败。临时故障被重试救回的次数单列。
2. **模型每轮看到的量是否接近 Claude Code**（本次的主要问题）：每次请求平均输入 token、缓存命中占比、每轮平均用时、每轮平均输出。新底座缓存命中与 Claude Code 相差在 20 个百分点以内、每轮用时在 1.5 倍以内，记为“接近”；否则写明差在哪里。
3. **质量**：sm24 看房间一一对应、挂墙、门连通、门窗位置、外部高度，对照 10-02 基线（20/21、12/14）、T1 sm24（19/21、14/14）与同期 Claude Code；sm25 对照 T1 sm25（Claude Code，一层 14/14，二层多拆一间，位置 41/61，高度 25/34）。每次单次样本，只判有没有明显变差，变差的要按行为记录找原因。
4. **时间**：6000 秒内交出完整全楼稿。

- **按判定口径第 2 条：** 缓存差 26 个百分点、每轮用时 2.3 倍，**仍未达到“接近”**，但比清理前明显缩小（缓存从约 10% 到 66%，每轮用时减半）。相邻请求的消息序列核对过：每次都以上一次为前缀，只有末尾的状态消息不同，所以剩余的缓存未命中不是我方前缀造成的；新底座请求间隔 1.5–3 分钟，Claude Code 约 26 秒，智谱这条端点的缓存在长间隔下多次没命中。剩下的主要差距是思考量：medium 下每轮仍有 4–11k 的大轮，Claude Code 有自适应思考，将近一半轮次不思考。下一步提速首选：让新底座走智谱的 Anthropic 兼容端点（与 Claude Code 同协议，可用自适应思考）。

### sm25（新底座单独跑，01:46 UTC 起）

评分：[新底座](evaluation_sm25_runtime_subscription.json)。

- **底座：** 5,789 秒（96.5 分钟）正常结束，模型自选 `candidate_06`，两层完整全楼稿；69 轮、120 次工具调用（报错 13）；压缩 9 次；没有服务端临时故障。T1 的时间提醒在新底座上真实送达（含 C2 改写后的“剩余不足 15%，停止新范围探索…”），模型在剩 4.5 分钟时收尾。每次请求平均输入 9.0 万，缓存命中 46%，每轮输出 3.8k、每轮 84 秒。
- **质量：严重失败，整栋按毫米建模。** 交付稿两层 30 个空间、59 个门窗，数量上合理，但坐标范围是 0–25,152 × 0–20,000，是按米应有尺寸的 1000 倍；位置、挂墙、连通、外部高度在评分里全部为 0，严格分区 severe。原因已查到：第一次平面建模就把尺寸链上的毫米数直接当作世界坐标（`x_anchors:[[282,0],[975,15000]]`），同一份输入里层高却写 3.6（米）；平面编译器接受了这种单位混用，没有任何提示，交付时还标为“完整全楼”。6 版候选全部如此。09-27 run72 在 Claude Code 线上出现过同类错误；T1 sm25（Claude Code）这次用的是米。单次样本，不能据此说新底座导致；但工具里缺一个确定性的尺度合理性检查是确定的。
- 首次平面建模在第 41 分钟，比 sm24 晚得多。

## 结论

1. **底座本身：通过。** 三次都正常结束，记录完整，没有底座引起的失败；T1 的时间提醒与到点交付在新底座上真实生效。重试路径这次没有遇到服务故障，未经真实触发。
2. **模型每轮看到的量：明显改善，仍未“接近”。** 新底座缓存命中从清理前约 10% 升到 46–66%，每轮用时从 91–136 秒降到 61–84 秒；Claude Code 同期 92%、27 秒。消息序列已核实逐次只追加；剩余差距主要是思考量（无自适应思考）和该端点在长间隔下的缓存未命中。提速线第一项：新底座走智谱 Anthropic 兼容端点。
3. **质量：** sm24 新底座与 Claude Code 同档（19/21 对 16/21，高度都 14/14），多建一扇北窗属模型读错；sm25 新底座按毫米建模，整栋失败。
4. **因此排进吸收包最前面的三项：** ① 平面输入的尺度合理性检查（世界坐标跨度与层高、尺寸链总长的量级对不上时拒绝并说明，不自动换算）；② 请求记录里的图片按引用保存，不再每次内嵌；③ 走 Anthropic 兼容端点的适配（提速线）。
