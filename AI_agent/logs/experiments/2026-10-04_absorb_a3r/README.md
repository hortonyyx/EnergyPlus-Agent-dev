## B：长序列对照（发请求前冻结）

**以下方案与脚本先提交，再发第一条请求。** 不把旧 A2-R 的 3,360 token 同文小测当作本轮结论。

| 项目 | 预先确定 |
|---|---|
| 服务 | 仅现有 GLM 订阅 Anthropic 兼容端点，`glm-5.3-flash`，adaptive thinking、medium；现有 beta 头保持 |
| 三组 | 现状：非流式、无标识；流式：仅 `stream=true`；标识：非流式、仅随机 `metadata.user_id` |
| 序列 | 每组两条独立序列，每条 **12 步**；计划 **72 请求**。不自动加第四组，不使用剩余 8 次追样本 |
| 内容 | 受控的增长文本会话：首步 1,200 行，之后每步增加 250 行；使用 A2-R 已实测的同一种参考行格式，预计首步约 **2.9 万 token**、每步约 **6 千 token**，落在两例实际增长量附近；末步约 9.7 万。每步换末尾小状态，之前文本及简短历史回复保持 |
| 隔离 | 每组每条序列在最前系统文本放不同的等长随机值，避免交叉暖缓存；标识组两条序列各一个随机 `user_id`，不含设备信息。不同组只差实验变量和等长前缀隔离值 |
| 顺序 | 第一批顺序：现状→流式→标识；第二批反序。每批交错推进三组，同一时刻最多一个 HTTP 请求；第二批只在读完第一批回执、确认没有失败后另行启动 |
| 间隔 | 同一序列前次响应结束后等 **45 秒**，再发送下一次；记录实际间隔。每条 11 个间隔至少 10 个须处于 30–60 秒，否则该条时间条件不充分，不采纳 |
| 输出 | 只要求回复 OK，最大 256 输出 token。逐条原样保存响应；达到输出上限单列，不能当任务完成；没有工具调用、BIM 生成或整案评价 |
| 总上限 | **80 请求／500 万 token**，含未缓存输入、缓存读取、缓存创建和输出；计划约 450 万。请求前用整份 UTF-8 正文字节数＋输出上限＋4,096 协议余量作保守 token 预留，不够就停；失败或结果不明的请求也占次数，禁止自动重试／恢复 |
| 停止 | 任一 HTTP／SSE 故障、用量缺失、输出类型异常、上限不足或未知在途请求，立即停批；不切换服务，不补跑。Paratera、DeepSeek 为 **0** |

**预定采纳门槛：** 主指标去掉各条首步后，`缓存读取合计 / (未缓存输入 + 缓存读取 + 缓存创建)合计`；输出不进分母。与现状相比，候选组的汇总命中率及两次独立重复各自的命中率都须 **高出 20 个百分点以上**，并满足间隔、完整用量及无服务失败条件，才实现。另报含首步的比例、每步输入／缓存读取／输出、首字节及总耗时，不据耗时单独放宽门槛。两项都未通过则生产代码不改。

这是缓存和传输方式的受控序列实验：长度、增长和间隔接近真实，**没有复现图片、真实工具交互、长思考输出或上下文压缩**，不能替代整案速度或质量回归。初始约 3 万 token 依据旧探针实报比例估算，本次实际长度由逐次服务回执核验；明显偏离时结果记为条件不足，不后改口径。

实现与防重跑账在 [sequence_probe.py](sequence_probe.py) 及忽略的 `probe/`。原始请求压缩保存、响应保留原 HTTP/SSE 字节，journal 在发送前持久化意图。公开协议依据：[Messages 的 metadata 定义](https://platform.claude.com/docs/en/api/messages/create)、[SSE 事件与累计用量](https://platform.claude.com/docs/en/build-with-claude/streaming)；它们只定义字段/解析，不保证智谱的缓存或粘性实现。
