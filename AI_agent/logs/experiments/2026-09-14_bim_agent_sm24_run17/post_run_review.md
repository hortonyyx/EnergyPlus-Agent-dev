# run17 平面草案事后复核

结论：**没有可采用候选。** Sonnet medium 在 300.55 秒超时前提交两份草案，两次 `build_plan_bim` 均报错，`summary.json` 明确为无 candidate、无 delivery、无可查看源 BIM。以下判断只对照原平面、两份草案/编译结果和工具轨迹；主助手另做的排除全部开口诊断不是模型生成候选，也不改变本结论。

## 主要保真问题

1. **把真实走廊读成贯穿全楼的一根分隔线。** 两稿都用 `spine: x=403, y=148..878` 把建筑从北到南切成左右两列。原图北端是一个横跨整宽的完整房间，约在 `y=299` 才与下方空间分开；这根线却把它假拆成 `top_left_reception` 和 `top_right_lounge`。同时八个种子中没有走廊，真实的双边界走廊被相邻“房间”占掉。事后保持 draft_002 墙位、排除开口的叠图清楚显示为 2×4 矩形格，这正是错误墙网，不是八个物理空间读准。

2. **右侧横墙端点与走廊关系错误。** 原图右侧房间的西边界约在 `x=456`，与左侧约 `x=403` 的墙共同限定走廊。draft_001 的 H5 从 `x=480` 起而成为悬空线；draft_002 为消除 dangle，直接把它延到错误的 `x=403` spine。H6 也从 `x=403` 横贯到东墙，而原图相应墙段从走廊东边界附近开始。结果是横墙穿过应连续的交通空间，生成一组规整矩形，而非原图的房间—走廊关系。

3. **漏掉走廊南端折角并把东南房间矩形化。** 原图走廊在约 `x=400..458、y=698..753` 还有一段短折角，在 `y≈753` 实体横墙处截止；下方及南外门属于 L 形东南房间。两稿明确把该折角/凹口省略成矩形。这会改变局部实体分隔和共墙长度，不能作为轻微尺寸简化。南外门归东南房间本身正确，不判成走廊门。

4. **内门数量、方向和连接均不可信。** 草案只声明 SD1–SD3 三段“spine door”，而原图还能看到右侧两个房间通走廊的门、东南房间通走廊的门，以及多处分开的左侧门。SD1 被画成 `x=403` 上的竖向门，但北端房间通走廊的双门实际位于约 `y=299` 的横墙；SD2 从 `y=390..460` 连成一整段，跨过 T 点并把相邻的不同门位合并。右侧和东南内门则没有按真实宿主单列，因此即使墙网能编译，也不能得到正确连通。

5. **部分外墙开口错位或合并。** D_top 和 W_top 都放在 `y=150`，与声明的顶外边界 `y=148` 相差 2 px，draft_002 首个实际宿主检查即因此在 D_top 处失败。W_r2 从 `y=310..460` 跨过右侧分隔，合并了不同房间范围；SD2 同样跨 T 点。东墙约 `y=614..669` 的双外门区域被声明成 W_r3 窗，而 D_r1 又放到更南的 `y=690..750`，形成错类/错位组合。西侧五窗及南门、南侧两窗的粗位置较接近原图，但不足以抵消墙网和连接错误。

## 两稿修订是否有新图证

没有。第一次编译在剩余约 29 秒时报 H5 dangle；第二次调用前没有新增 `view_image`、pixel profile 或其他观察。draft_002 唯一实质墙位变化是把 H5 起点由 `x=480` 改成 `x=403`，其说明也直言这是为了“joined for closure”，并保留“原图看起来从 x≈480 开始”的旧观察。这是按编译错误闭合图形，未用新原图证据恢复实际 `x≈456` 的走廊边界。第二稿随后在 D_top 宿主处再次报错，剩余约 9 秒，没有第三稿。

## 实际验证了什么

- 本次确实只向生成会话提供一张原平面和原始建筑声明；声明里的四张立面路径都标为不在授权图片清单，模型也将层高和开口高度记为未核假设。
- 模型实际调用了新平面编译入口，两份原始 `plan.json`、输入图摘要和错误结果均被冻结。编译器分别识别出悬空分隔线和不在完整外边界上的开口，没有把失败草案静默产成源模型。
- 两次像素 profile 实际量到了东西外墙青色标记位置；这些数据最多支持部分外墙开口候选，未支持模型提出的整套内部墙网。
- 主助手的事后诊断证明：只排除全部 17 个开口时，draft_002 的墙线可被确定性代码闭合为 8 个矩形空间，并在原图回叠中显示其错位。它诊断墙网，不是模型完成的候选或修复。

## 没有验证什么

- 没有任何成功 source model、viewer、source plan、原图回叠、实际 opening host、修订候选或最终交付，因此没有验证新入口能在真实 case 上完成“平面声明→可查看 BIM”的闭环。
- 编译报错不等于草案只差接口格式；墙网本身已严重错分、漏走廊。事后排除开口后能得到 8 个面，也只说明线网闭合。
- 八个种子与 `thermal_zones=8` 相同不能证明八个实体空间正确：草案通过假拆北端房间、漏掉走廊恰好仍得到八格。模型文字上声明未把热区数当物理房数，但本次不能排除数量锚定。
- 仅有平面，未验证真实层高、门窗高度或四立面开口；也没有独立证明东、西立面开口序列完整。

这次可保留的结果是输入隔离和编译器拒错证据，以及“首轮墙网仍会把走廊读丢”的明确失败样本；不能保留任一草案作为几何基点。
