## 复现边界与宿主缩放

16份旧文件来自723，另有2份空包兼容标记。模型得到一层原图、原建筑声明、完整旧规则及六CV入口；去除含同墙网的格式示例、GT和旧输出。模型只能使用白名单MCP，没有历史Bash/Python、自写helper或任意文件访问。因此本次是“旧规则/CV在当前宿主下的独立输入试跑”，不是完整历史环境重放，也不能推断旧方法失效或模型能力上限。

离线真实MCP的原图和整数裁图像素核验通过；但实际CLI流中的原图从2133×1345变成1999×1261，大图运输并非逐像素相同。必须保留这个宿主差异，不能宣称已排除所有运输影响；缩放诊断与逐轮verification保留原始失败。该缩放也尚不足以解释所有错误，特别是相同错误锚点未改、自检声称成功与明显错位冲突。未修改运行中的工具来追补成绩。

## 机械核验结果

两轮分别23次调用（18成功、5错误）和10次调用（9成功、1错误），无未返回调用。首轮错误为两次axis取值、一次提交锚格式、一次无效JSON及一次把非图产物当图查看；返工一次台账status取值错误。错误均保留，不计作成功工序。

实际返回图首轮5/16、返工3/15逐像素相同；其余11/12张均符合宿主限幅的近等比例缩放，六种Pillow采样诊断中LANCZOS最接近但不精确相同。因此两轮`verification.json`都明确为`completed_with_integrity_failures`，保留图像不一致这一失败；其他权限、模型、输入/实现/快照散列、sidecar、提交文件及回执检查通过。首轮核验器开发中间版本v1/v2另存，v2曾将近似缩放放行，此结论已撤回；仅当前严格版有效，不删除中间记录。
