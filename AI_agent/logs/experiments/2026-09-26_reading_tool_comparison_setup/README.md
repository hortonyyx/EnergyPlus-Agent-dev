## 实际发现

visual认错目标，描述八椅会议桌，返回的矩形跨越实际隔墙。measured找对大致范围，但把profile的局部墙支持延长成连续墙、漏掉折角；一扇门甚至在自己声明的房间边界之外。六个引用profile确实存在，引用存在不等于解释正确。

随后开发用**现有**region工具选择空白地面，确认工具能返回含折角的完整轮廓，于是另开region_first：只给通用操作顺序，要求选地面背景、读完整轮廓、区分门弧/家具、核门与边界，不给种子、颜色参数、正确坐标或答案。Haiku自主选对R05及region_001，但最终仍将轮廓换成包围矩形，误置一门、反判内外。这次不属于原对照的独立重复，也没有证明方法迁移成功。

因此没有把未成功指引直接写进生产、没有删工具、没有提升低档模型的能力结论。区域着色确实提供了正确的非语义形状证据；模型如何采用仍有缺口。颜色筛选受线条深浅和抗锯齿影响，单色profile可能只看到一侧墙面；无匹配不等于没有墙。局部失败不外推到其他图纸类型。

用户随后重申：**先稳定做好，再降低依赖、提速、省成本；工具应保持丰富，不能因几个case没用就判断其他类型也没用。** 本轮至此停止低档局部追加，转回sm25整栋独立重复，见[稳定性设置](../2026-09-26_sm25_stability_setup/README.md)。
