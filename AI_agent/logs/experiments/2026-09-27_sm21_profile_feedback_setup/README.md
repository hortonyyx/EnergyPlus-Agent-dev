## 具体定位与修订

run71在首次建模前，用pixel_profile量测尺寸线。第15次工具调用返回整段正支持范围x=419..1821、首个最高峰425；第17次返回y=340..1093、首峰346。随后首份build_plan_bim明确采用前两个范围的端点，分别对应15m和8m。其basis也直接写这两段像素范围。这证明采用了含箭头延伸的区间值，不证明模型内部思考过程或全部退步根因。

旧摘要每个相连色线区间只给一个argmax，省略其他峰；这一行为早于本轮退步，属于被实际误用暴露的已有反馈缺口，**不是已经找到某次新增提交造成退步的根因**。原图与历史请求只供开发诊断，具体坐标不进入生产提示或工具。

当前pixel_profile保留原axis/runs/pixels/peak/max_count/matching_pixels及空滤波诊断，新增：

- 每个正支持区间的`support_peaks`：所有正的局部最大值平台及计数，含不等高峰；平台严格高于相邻计数，区间之外计数取0，连续同高平台合为一个闭区间。没有平滑、阈值筛选、排序取前N或语义端点选择。
- 输入原图名、原图裁框、横向计数长度和坐标单位，避免把并行量测的坐标当成另一幅图或局部裁图坐标。
- 明确区间包含线、文字和箭头，首个峰/局部峰都不是自动认定的尺寸、墙或窗端点；噪声同样保留，仍需查看原图或已有view_pixel_profile。

实际重放中，x另有428及1815..1816的较弱峰，y另有349、1084和1087的峰。仅补“同高最高峰”仍会丢掉横向另一端，因此最终保留所有局部峰。工具不挑出所谓正确两端，也不修改标定/BIM。图像渲染、工具清单/输入schema/说明、GUIDE/按需参考、命名/用途、几何计算和额度均未改变。

run69将实墙尺寸段对应成窗段、run72把mm填入米字段、多个run套错窗高，仍分别保留为未解决问题。本改动不能自动修正这些语义/单位错误，不能把端点局部改善当作整案成功。
