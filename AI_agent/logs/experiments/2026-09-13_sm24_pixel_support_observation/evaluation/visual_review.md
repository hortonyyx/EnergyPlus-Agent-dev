# sm24 像素支持探针独立原图复核

本复核只读取探针原图、实际工具轨迹、六份 `view_pixel_profile` 记录及返回图，不使用 GT、历史正确坐标或模型。结论未回注正在运行的恢复任务。

## 结论

像素工具按请求工作，候选编号、原图坐标和峰值处断续支持均可复查；Haiku 对这些像素的建筑语义解释明显错误。最终回答所称四段“室内边界”和两处“门洞”没有一项由其量测证明为目标对象。它主要量到了办公家具边、东侧外墙、南侧外墙及南面外窗，并把这些对象拼成一个并不存在的目标边界。

因此，本次结果证明新工具能把“测到了什么像素”与模型说法拆开检查，但没有证明 Haiku 已恢复正确局部定位或量测后的对象判断。

## 实际量测与回答的对应

| `x≈606` | profile 001/006 的 C02；峰值 x=606，主要连续支持 y=680/700–877 | 建筑东侧外墙 | 数字来自量测，但不是与走廊相接的内边界 |

profile 003 同样只有散落青色匹配像素、没有候选。回答把“cyan arc profiles”统称为已用测量，但真正产生候选的青色 profile 004 是南面外窗；针对上部区域的 profile 005 没有候选。

## 裁图范围

模型先查看了整图，但用于主要判断的前三个局部裁图分别从 x=480 开始。目标空间靠走廊的西侧内边界位于该范围左侧，因而没有进入这些裁图。后来一张 `[470,680,750,950]` 仍未覆盖该边界；最后用于灰色 x 剖面的 `[540,680,750,950]` 更是只保留房间内部家具和东侧外墙。

局部裁图覆盖了目标空间上侧与走廊相接的区域，但模型没有沿该边界设置窄剖面，也没有用候选支持区间量出实际转折和开口端点。它对题目要求的“实际边界路径、方向变化和一个可见开口”均未完成可检查量测。

## 回答中未获量测支持的内容

- 四条 wall segment 的对象身份均错误；所谓 top-right 和 bottom-left 也只是从外墙、家具及未量测视觉估计拼成。
- 两处 door opening 的身份均未建立。第二处明确是外窗；第一处虽在真正开口附近描述了一段弧，但所报端点没有对应候选或支持区间。
- 最终 polyline 的各顶点没有从 profile 候选推导，且连接了家具边与建筑外墙。
- “opens toward circulation area”及 northeast/south 开向没有工具证据，第二处对象本身也不是门。
- 回答说只剩上部门弧端点需视觉确认，低估了对象身份、边界范围和整个折线路径的不确定性。

## 工具本身的表现

六次 profile 均保存了原图哈希、裁区、阈值、候选和返回图，已有独立运输核验确认原图及支持区间一致。`min_fraction` 成功阻止 profile 003/005 的稀疏青色笔画直接形成候选；profile 002/004 又把南墙断口和四条外窗笔画明确分开。这些信息足以让复核者发现回答错误。

当前工具只报告所选颜色与裁区中的像素，不负责找对目标、选择窄条或判断家具/墙/门窗。若模型先裁错范围，正确的像素表也无法补回遗漏对象；候选峰值只描述该坐标上的支持，不证明整个候选带连续或具有墙体语义。
