# sm24 两处墙结点返工离线复核

日期：2026-09-14
结论：A 的完整端接与分隔关系已纠正，B 也撤回了“单墙中央门洞”；但返工仍误读左侧真实横墙、门的位置和两侧空间，不能把整份观察交给机器修订

## 复核边界

本项逐条判断只以本目录保存的 `1f_view.png`、完整前次回答、返工问题、`observation.md` 和 `execution_audit.json` 为依据，没有用 source 或 GT 为 A/B 定真。这是了解项目历史的开发侧事后复核，不是盲评；返工模型运行时未获候选 source、GT、正确结点答案或其他模型观察。本复核没有调用模型/API。

审计显示原图与隔离副本像素一致，7 次工具调用全部是 `view_image`，包括 A、B 的无网格 6 倍局部和带坐标的周边裁图；没有 source 查看、派生图或修改工具。运输通过证明返工看到了真实局部，不能替代下面的语义复核。本次也没有发生任何 source 修订。

## A：y=367/371 横墙与 x=457 纵墙

### 得到原图支持的修正

返工正确撤回了此前的 `wall_fragment / 端接未明`：无网格放大图清楚显示两条平行横线在 x=457 纵墙的墙厚边缘形成实体接头，横墙向东继续。它不是家具边或自由端墙片；其上、下是两个被物理隔墙分开的东侧空间。因此：

- `object=physical_wall` 有支持；
- `relation=separates_spaces` 有支持；
- `prior_claim_action=revise` 正确；
- “横墙接到纵墙、不是偶然相交”这一局部结论可保留。

### 仍不可靠的表述

- `load-bearing-drawn partition` 没有图像依据。墙线画法只能支持它是图中的物理隔墙，不能判断承重属性；本任务也不需要该属性。
- JSON 的 `joins` 把 x=457 纵墙引用成 “peak y=415–587 run”。A 的结点在 y=367/371，实际对应 C02 的 `[356–382]` 支持段；`[415–587]` 是更南的一段。对象 ID 对了，精确区间引用错了，不能据此做自动重放。
- “纵墙连续穿过 y=367/371”可理解为实体结点成立，但原图同时显示该短墙段上下邻近门洞；不能把局部灰线连续扩大成整根墙无开口。
- “cabinet/shelf area”只是家具描述；空间分隔来自墙与端接，不来自家具用途。`load-bearing` 和家具用途都不应进入几何修订依据。

**A 总评：拓扑结论正确，证据引用需改正，额外墙类型陈述需删除。**

## B：y=583/587 的左右支持与 x=402 门

### 得到原图支持的修正

返工正确否定了前次“C06/C07 是一条横墙，中间 x=397–462 是门洞”的解释。原图表明：

- 中间约 x=402–457 是中央狭长空间的完整宽度，没有横墙把它封住；
- 东段 x≈462–611 是一条独立实体横墙，接在 x=457 纵墙上并向东外墙延伸；
- 附近青色门扇属于 x=402 方向的纵墙，不属于横跨中央空间的墙。

所以 `relation=not a single horizontal wall with a central door` 和“中央间隔是开放空间”有清楚图证。这是本次最重要的有效修正。

### 左段被错误撤销

返工把 C06/C07 西段 `[360–397]` 解释为“door-leaf head/sill cap”，这是错误的。原图显示 y=583/587 的两条平行灰线从裁图左侧继续到 x=397，接在 x=402 纵墙的墙厚边缘；它们是西侧另一条真实横向实体隔墙的两条画线。青色门扇在更南、约 y=598 以后，不能把 y=583/587 的灰色墙线改称门扇头槛。

因此 B 不是“一个不确定复合对象”，而是至少三件需要分开的对象：

1. 西段真实横墙，接到 x=402；
2. 中央开放空间，不存在连接左右的横墙；
3. 东段真实横墙，接到 x=457。

若机器采用当前 `separate_runs`，会保留东墙却丢掉西墙，仍会改变真实分区。

### 门的位置、朝向和两侧空间仍错

返工识别门属于 x=402 纵墙，这一点正确；其余描述不可靠：

- 门洞不在 y≈583 的横墙行上，而在其南侧，墙线在门洞处实际中断；“x=402 纵墙连续穿过 y=583–650”把实体墙的拓扑延续与灰墙无开口混为一谈。
- 返工称门“near (402,583)”，与原图门扇/圆弧所在范围不符；y=583/587 是西侧横墙的两条灰线。
- x=402 左侧是西侧房间，右侧才是中央狭长空间。青色圆弧画在墙左侧，返工却说“向左摆入走廊”，把左右空间认反。
- “flat head/sill ticks at x≈360–397”并非门框端点，而是上述西侧横墙本体。

返工自己的 `unresolved` 承认门铰和摆向只凭圆弧、未独立核门框，却在正文中给出确定的铰点、方向和空间名称，证据等级不一致。

### “没有任何方向墙线”表述过强

“x=397–462 之间没有任何方向的墙”若按字面也不准确：该范围端部存在 x=402、x=457 两道纵墙。原图支持的结论只是**没有横墙连接这两道纵墙**，中央区域沿南北保持开放；不能把局部开放误写成所有方向都无墙。

**B 总评：撤回横贯墙和确认中央开放是正确的，但西横墙、门位与两侧空间仍严重误读。**

## 可采用与不可采用范围

可作为开发侧证据保留：

- A 横墙真实接到 x=457 纵墙并分隔上下空间；
- B 左右支持不是一条带中央门洞的横墙；
- B 中央没有连接 x=402 与 x=457 的横墙，保持开放；
- B 右横墙接到 x=457，附近门属于 x=402 纵墙而非横墙。

不可交给机器修订：

- A 的 `load-bearing` 断言及错误 C02 支持段引用；
- B 将 `[360–397]` 真横墙改称门扇头槛；
- B 的门铰位置、摆向和“左侧是走廊”描述；
- B 把 x=402 纵墙说成灰线连续无门洞，以及“中央没有任何方向墙线”的过强陈述。

这次局部反馈证明，给出由 profile 端点和间隔计算的高倍裁图能够促使模型修正“自由端”和“中央门洞”两个关键判断；它还不足以生成一份可直接消费的完整关系记录。下一步应把可采信的局部结论转成更窄的结构化反馈：只记录 A 的端接、B 的左右墙段分离与中央开放，不携带承重、房间用途、门摆向或未经核准的支持段。后续 source 检查仍只能报告与这些供给观察的条件性矛盾，不能认证原图真值或自动改 BIM。
