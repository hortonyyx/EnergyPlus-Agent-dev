# trace_001 原图与叠图复核（更正）

本记录只复核 `detail_01/space_traces/trace_001.{png,json}` 与同次输入
`images/1f_view.png`；未把任何坐标、门或空间关系写回生成输入。先前版本把叠图中
的空白走廊误判为灰色隔墙，结论错误，现以本文件为准。

Sonnet medium 在 180.49 秒超时，`selection` 为 `null`；最后一次
`preview_space_trace` 已没有剩余时间，模型没有查看或修订自己的叠图。虽然 JSON 的
环通过了几何/运输检查，这一检查不评价原图保真。本次视觉结论是 **reject，不能用于
空间替换或开口更新**。

## 像素支持复核

- 洋红路径 `x=403, y=600..` → `y=600, x=403..557` → `x=557, y=600..700`
  没有连续的灰色墙线支持：横段和竖段均落在空白走廊。模型据此构造的上侧凹折没有跟随
  真正位于更下、更左位置的灰色台阶墙线，是本 trace 的主轮廓错误。
- `x=403, y=841..874` 是连续的竖向隔墙，附近没有可支持该两端点的门框缺口或门扇。
  因而 `door_to_dining_room` 是凭空增加的室间门，且模型把它对应的封闭边错误解释为门。
- 模型称南侧 `x=537..592` 的青色构件为窗、所以排除开口；原图中该构件是横向外墙上的
  青色门。此处遗漏了实际外门，不能以“没有门扇”为理由改判为窗。
- 因主路径不在墙线上，`door_to_north_room` 虽有一段橙色横线，也没有可独立确认的正确
  宿主。不能由模型的 `basis` 文本或几何可执行性反推它为真门。

## 处理边界

本 trace 的 `drawing_fidelity` 本来就是 `not_evaluated`，且标定仍标为
`calibration_unverified`。它使用 `x=611`、`y=876` 的外墙外皮，而尺寸锚点为
`x=610`、`y=880`；即使主轮廓正确，应用前也仍需将外缘参考面显式归一化并记录偏移。
这项参考面处理不能修复本次错位的内墙路径，也不得向旧内部共墙自动吸附。

后续若继续，只能用原图的实际灰色线段和已观察到的南侧外门重新定位；可用确定性区域
候选工具帮助暴露可行线段，但它不是本 trace 的正确坐标来源。本记录不回注生成，也不把
这次错误观察作为下一次模型的正确答案。
