# 09-09 继续 M0：从已有读图记录自动接入门洞

用户要求先用白话解释 M0，再继续施工。已说明 M0 先守住房间、隔断、门窗和空间关系，允许有记录的小尺寸修正，但不能因计算方便拆房、丢墙或封门。本程按用户授权继续分工：主助手负责 CLI、来源重放、保存检查、诊断产物和文档；同模型子助手实现门洞提取，另一子助手只读定位未建三组。均为离线开发，没有外部产品模型、付费 API、GT 生成侧输入或 EP 调用；DeepSeek 无本批许可。

这是前两程 [源分区](2026-09-09_m0_source_partition.md)、[显式门洞和贴边窗](2026-09-09_m0_wall_openings.md) 之后的第三个有界增量。实现提交 `d401e35e`；M0/M1 整体未完成。

## 本程交付

- 直接消费已有结构化平面记录中的 door/passage/open、候选跨度和墙面 gap 引用。验证编译墙来源字节、指针和对应墙面；同墙两面的重复记录归并为一个源开口，保留两个引用。sm21/sm24 旧说明文字没有强转坐标，本程没有逐门手工组房或填位置。
- 门所在墙和两侧房间由最终边界确定。同组两面跨度分别检查，不因挑较方便的主记录掩盖跨房。外墙跟随范围以编译半墙厚为界，逐项记录移动与上限；沿墙跨度保留原观测，不通过移动或缩门消除冲突。高度暂假设 2.1 m；door 状态 unknown，passage/open 为 open。
- 建成、重复观测、墙位跟随、未建均有逐项记录；明确未建记录同时写入权威源模型。完整性检查在 exploratory 下也阻塞，候选仍可通过独立诊断查看。不能只写附带报告却把缺门模型报成接受。
- 新 CLI 在楼层协调和补窗后接入门；新来源配方记录版本和假设高度，保存时从冻结输入独立重放。旧配方缺省不补门，历史内容摘要保持原意。
- 核对实际保存边界时发现：上一程核心投影已含 openings，但 writer 的手写比较字段名单没有加入它。本程改为比较全部核心投影字段，改动日志保留已有单独检查；用内容自洽但门已移动、关闭或删除的候选验证拒绝。没有靠放宽既有检查接通新路径。

## 顺带定位的源分区问题

未建三组的只读复现见 run 内 [脚本](../experiments/2026-09-09_m0_reading_openings_run01/diagnose_unbuilt.py) 与 [输出](../experiments/2026-09-09_m0_reading_openings_run01/unbuilt_diagnosis.json)。主助手复跑断言通过。

第一组门无宿主的根因是原隔断丢失：西外墙被尺寸校正移动 5.3 mm，隔墙原本在半墙厚范围内能接上，移动后端头未跟随，延伸失败；房间提取丢掉悬挂隔断，门两侧进入同一源空间。这是小尺寸规整改变拓扑的具体反例。下一有界增量优先保持校正前已有端点—宿主关系，并兼顾历史重放配方，不用全局粗容差掩盖。

另两组分别越过有独立读图来源的 T 墙，两个墙面记录的门段端点又相差约 0.2 m；暂不能证明是多余计算隔墙，也不能直接剪门或吞并。需根据门符号、墙面/轴线与 gap 的关系形成有依据的派生位置。本程没有据 27/29 数量差断定缺哪两间房。
