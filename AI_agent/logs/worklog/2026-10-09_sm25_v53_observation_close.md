# 10-09 sm25 分工实测：全流程观察与失败定位

## 本轮结果

用户批准“GLMFlash 使用现有 runtime、修复后的 domain，以分工模式做一次 sm25”，并重申每次测试均须观察记录全流程行为。唯一一次实测已执行结束：**104.68 分钟，没有成功平面稿、整案候选或交付稿**。没有追加案例、外部重跑、付费回退或运行中人工纠正。完整结果与后续入口见[实验报告](../experiments/2026-10-08_sm25_domain_v53/README.md)。

work model 为 `glm-5.3-flash`，调度员、平面读图员、立面读图员均请求 medium；runtime v1 / domain v53，分工模式。原图、任务说明、角色配置、并发上限和保护线与前次 v52 对齐；冻结在 `b55d47e7`。本轮不修改生产代码，不登记新版本。

## 观察所得

- 四个立面在约 4–7 分钟提交 accepted。两层平面成为关键路径，整案共 22 次试建调用，无成功。
- 首轮一层修正格式后，尺寸对齐器确定性抛出 `StopIteration`。已在冻结代码上做不含模型/API/MCP调用的纯函数重放，定位到 Q1 引入的既有 kernel 缺陷，早于 v52 / v53；runtime 只记录 unknown，未保存原始异常。
- 首轮二层连续三次 32,000 token 截断，无平面试建。runtime 正确地没有执行截断工具调用。调度员等待整批返回，约 48 分钟重派两层，但返工说明只复述失败状态，未给出具体纠错方向。
- 第二轮的格式与几何错误逐项变化，墙线断点明显减少，不能说 work model 完全不利用反馈；但原始建模声明仍有读错和错误拓扑。独立核对同时发现 domain 把小接头误差放大、把一段轮廓规整成零长边。读图错误、工具格式使用和确定性代码缺陷分别留证。
- 一层在约 94 分钟被共享预算永久停止：已结算请求时长加二层在途预留占满 10,800 秒，稍后预留释放，一层却未继续。二层最终请求只获约 7.653 秒并超时，随后调度员停止。**这里是并发角色累计请求时间与预留，不是运行满 180 分钟墙钟时间。**
- 没有进入整案装配、装配复核、全楼高度应用、>30 cm 双原图裁决或交付，相关 G1 修复的真实效果仍未验证；严格位置裁决规则不变。比上次更早失败不是提速成功，也不能以这一次差异证明 v53 导致全面退步。

## 完整行为与用量

原始事件共 1,381 条。105 次请求尝试、100 次响应；5 次失败为 429×3、HTTP500×1、TimeoutError×1。137 次工具执行：110 succeeded、26 failed、1 unknown。根回执 `model_calls=4 / tool_calls=5` 仅指调度员；全案计数由独立事件审计核对。

100 次已知响应报告 input 2,637,143、cache_read 1,753,920、output 501,027，合计 4,892,090 token。input 不含独立 cache 列；5 次失败缺 usage，不把已知合计当完整账单。GLM 既有订阅；Claude、Paratera、DeepSeek work model 调用均为 0。主助手和三位 GPT 侧 dev model 的完整 token 回执未取得，不估算。

本轮 dev model 分工：独立行为观察与终审、确定性异常/预算调查、有限原图质量复核。各角色的工具参数、返回、首次错误、反馈修订、产物及用量均保存在[独立行为记录](../experiments/2026-10-08_sm25_domain_v53/independent_behavior_notes.md)与[结构化审计](../experiments/2026-10-08_sm25_domain_v53/independent_behavior_summary.json)。只用外显行为和实际产物作判断，没有向运行中的 work model 注入 GT、纠错或新代码。

`observe_run.py` 漏识别嵌套业务错误，requests 实为响应数、里程碑实为调用；其原始汇总另存并明确标为非权威，不用零错误字段作结论。没有整案候选，因此未运行整案 BIM 评价，不生成虚假查看页。有限质量结论仅适用于未编译建模声明。
