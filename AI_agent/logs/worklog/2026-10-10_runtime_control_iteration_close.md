# 10-10 runtime 可控续跑与开销迭代交接

用户授权先迭代 runtime，需要测试时优先调用 GLM 订阅。domain 下一轮设计留待讨论，sm25 仍为后续建模对象。本轮按[前置独立审阅](../reviews/2026-10-10_runtime_independent_review/summary.md)实施，完整验证、失败与复验记录见[本轮报告](../experiments/2026-10-10_runtime_control_iteration/README.md)。

## 实现和版本

最终 **runtime v5 / domain v60**，生产修复提交 `f54dd9f3`，版本登记 `b27405fa`。起点 `83cf373b`，中间 v3/v58、v4/v59 及所有旧记录、别名均保留不变；模式的工具/指引指纹未改变。

- 定向 message / pause / resume 持久化，完整请求与工具交互之后接收；目标为既有 task ID。指令有幂等 ID 和回执，检查点保留已接收消息及暂停状态，重启不重复注入。
- 恢复沿用原始时间和预算。未发送预留可追加释放；缺 usage 只能凭绑定原请求的真实证据补账，原未知记录保留。补账后主循环与父子预算使用有效结算，真实超支仍停止。
- 纯读取的恢复许可与 read_only 权限分开；委派保存完整批次，按原 task ID 恢复，复用已完成子任务。未知非幂等写继续要求状态证据。
- 事件追加增量校验、按任务/预算建立索引、预算投影按相关事件失效；保留 fsync、哈希、单写者锁与打开/审计的完整校验。实际连接身份与 adapter 同源，角色上下文配置贯通，拆出运行阶段计时。
- domain 只改恢复接线、配置和必要的 UTF-8 读取。Windows 子进程默认 GBK 导致建模源、候选修订、检查与交付失败；候选统一按 JSON 字节读取，显式强制 GBK 的测试覆盖实际报告及 source 哈希。没有扩展建筑规整或识读方法。

操作入口见[控制与恢复说明](../../workflow/runtime_controls.md)。父调度员在委派工具内等待时，暂停需等整批交互结束；要介入批次内部，应指定读图员 task ID。`applied` 表示运行时已接收，后续效果需看模型行为。

## 验证与实测边界

初轮 824 项相关离线检查为 793 通过、30 失败、1 跳过。后续复验逐步暴露响应解析的遗留诊断时钟调用、早停初始化、UTF-8 候选读取与两项旧测试约束；保留每批 XML 和失败记录，不把后续通过改写为首轮全绿。最终各批结果在本轮报告与 `verification.json` 汇总，重复范围不累加冒充检查总数。

最终去重826通过、0失败、1显式跳过，初轮30失败全部已对账消除；这不是最终HEAD的全项目重跑。最终v5/v60的57项runtime检查（87.99秒）与16项真实工具、恢复、GBK、版本检查（740.75秒）全过。75步回放76个脚本响应、75次真实工具调用、85.547秒，7处错误与原历史预期完全一致；另68项领域工具检查通过。旧1269前缀测试在普通集成中跳过，在journal独立检查中完整执行。

GLM 只开了一次订阅协议 run：`glm-5.3-flash / low`，runtime v4/domain v59，提交 `69ea0957`。2 次请求、1 次只读 probe、8.625 秒，输入 623/输出 31 token，14 项检查全通过，无重试、截断恢复或回退。过程为在途请求时排入暂停与纠正 → 完整工具交互后暂停 → 继续 → 第二次请求采用纠正并完成。最后的 v5/v60 仅补齐同类诊断时钟隔离与候选 UTF-8 读取，未追加真实调用。

原始 GLM usage 中缓存输入为 256/623（约41.1%），统一 receipt 的缓存字段仍为 null；报告按原始回执列出，未修改回执。原运行完整压缩归档逐文件核验哈希；便利 `versions.json` 从请求事件导出并注明来源，驱动已补写该文件，改后只做离线验证。

1,269 个冻结事件的全部前缀已做全量/增量与预算一致性验证。微基准只测预加载事件的校验开销，不证明整体速度超过 Claude Code，也不证明整案约30分钟达标。75步真实工具历史回放与脚本化分工恢复验证均属于离线，模型响应为夹具，不能当作新建模质量。

## 下一入口与保留事项

1. 与用户讨论 domain 有界收缩：可保存/局改的声明、近轴接头和尺寸链、整图标注与规整步长、按角色参考和机械负担。
2. 设计确定后，再在新run中验证 dev model 调度读图员完成 sm25 规整交付。新控制接口不能替代空间、隔墙、门窗和连接质量验收。
3. runtime 观测的小缺口：统一汇总读取 GLM 原始 `prompt_tokens_details.cached_tokens`；真实供应商缺 usage 后到凭据补账尚无实测，不把离线账本验证外推到供应商恢复能力。
4. 非当前恢复链必经的 `inspect_inference` 默认文本读取仍可能受 Windows locale 影响；本轮不为无关路径扩大修改，后续相关工作应明确 UTF-8。
