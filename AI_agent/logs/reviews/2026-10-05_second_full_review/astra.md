五例合计 247 次请求。前一次 C2 对照（按 A1 目录中改正的请求口径）：Claude Code sm24 为 29 请求、1273 秒、平均输入 97,497、缓存 92.02%；新底座 sm24 为 42 请求、2540 秒、约 9.3 万输入、66% 缓存。首次审查滑动窗口期约 8–20% 缓存的主要结构问题已有改善；新线路仍未达到同期 Claude Code 的缓存水平。每请求用时 73.8 对 50.0 秒，1.48 倍，不是旧报告误用 CLI 轮数所得的 2.3 倍。不能把缓存差全归因于某一个头字段；已有长前缀/流式/会话标识调查也未证明能修好。

质量要同时看多建和空间关系：新底座 sm24 位置 18/21、高度 14/14；sm25 位置 48/61、挂接 58/61、门连通 28/30、高度 33/34，仍有走廊错拆。27B 首次位置 20/21、高度 14/14，后次参照开口位置 21/21、高度 14/14，**却多了三扇门上窗**，把门洞总高读成门扇高再加亮窗。参照召回全对不是完整交付通过。A5-R 七份重评保留了这些严重项，没有用约定差掩掉。

### 2. 对 27B 最有约束力的证据

首次 97 调用有 36 次依据手续（37.1%），6 版可用稿；A2 后 83 调用里看图 35、剖面 34，**事务/依据 0 次、首稿后修订 0 次**。两次可用首稿都在 31–32 分钟，已接近产品约 30 分钟的整案期望，因此提速仍有实质工作。这些是 Paratera 路由下的本地级模型证据，不是本地硬件吞吐实测。后次第 52 步出稿，之后 31 次调用仍以只读观察为主，直到预算停；不能把调用次数下降 14 次当成事务生效。

本次取出最后工具时间行：首次最后一次已送达的决定仍显示约“剩余 36.9 分钟”；A2 后最后一次已送达的看图显示“剩余 41.1 分钟”。各自最后准备的工具结果未发给模型，不能把其中 36.5/40.3 分钟当成模型已看到的内容。停止原因都是下一请求保守预留不够 `token_budget_exhausted`，不是时间到；600 万是保护线，实报总用量约 545 万/536 万就可能停止。

`bim_agent_budget.py:100` 只按时间产生过半/15% 提示；`runtime_entry.py:99` 与 `loop.py:285` 按 token、金额、调用等维度预留和硬停，但 `runtime_context.py` 没把这些剩余额度呈现给模型。A4 已支持人民币预算和可选 token 上限，**不等于已经解决有效额度下的收尾**。开发协调器已有 `runtime_state`（`runtime_coordinator.py:261`）可取账本，不能说整个系统没有预算查询；但单模型循环未呈现，协调器返回的是账本明细而非统一短剩余状态。外部开发模型自身的私有用量仍不可见，不应把子请求账本冒充全系统账单。建议复用现有账本和入口，把限制维度与保守剩余额度作为一个短状态，由开发调度者据此缩小任务、停止新增观察、处理已知严重问题及交付；不要直接把硬限额放大当修复，也不要机械禁止必要看图。

### 3. 底座开销、未用能力与复杂度

用 `adapter_request→model_response` 事件间隔统计模型服务阶段（含网络和部分本地处理），用 `tool_invocation→tool_execution` 统计工具阶段；剩余是本地准备、日志、状态索引等以及未分摊间隔，并非纯 CPU。不同运行同机有其他任务，不作受控性能因果判断。

| 新底座运行 | 模型服务阶段，秒 | 工具阶段，秒 | 其余，秒 / 总耗时 |
|---|---:|---:|---:|
| GLM sm24 | 1830 | 77 | 379 / 16.6% |
| GLM sm25 | 4404 | 223 | 1025 / 18.1% |
| 27B 首次 | 2717 | 223 | 899 / 23.4% |
| 27B A2 后 | 2840 | 73 | 708 / 19.6% |

因此不能沿用首次约 2–8% 或迁移期约 5% 就说目前底座成本可忽略。这里的残差包括本机负载、文件系统和统计边界，不能直接宣称纯底座 CPU 回退了同等比例。明确热点候选为 `EventStore.append` 每条事件全前缀校验＋同步落盘（`store.py:280`），每次工具后重新扫描/读取全部视图、依据与源文件（`runtime_context.py:49`），预算多次从事件恢复。应先做阶段计时再增量化，不取消写意图、哈希校验或未知写保护。

存储确有成果：C2→A1 sm24 约 141→64 MB，A2 同一历史序列重放约 63.4→32.2 MB；27B 两次实际目录约 111→41 MB，但运行长度不同，不把全部差额归因于存储改动。哈希树共享避免重复大块数据，换来了较多小文件（1971→4012）。

当前单模型 CLI 有 46 个 `add_argument`，协调器 26 个；主循环 1293 行、上下文管理 1543 行。多维预算、双协议、恢复、只读角色与委派有明确下一阶段用途；近期五例无委派、无恢复、无模型重试触发，不代表这些都应删。模型生成摘要默认未开启，暂不继续加复杂摘要策略；配置按运行角色收敛常用面，低频参数留高级入口。把工具执行两套实现合并及状态/日志增量化列为后续提速，避免与本轮有限分界修复混在一起。
