## 五、⭐⭐⭐ 派工单**未预见**的四条（三条是承重的，我都改了；每条都写清为什么必须改）

### 5.1 ⛔⛔ **`side` 是拿一个【全局代表点】判的，对凹腔就是错的**（承重，已修）

`side`（腔在这条边的哪一侧）原来是 `-1 if representative.x < cavity_const else 1`。
`representative_point()` 是**整个腔一个点**；L 形走廊是凹的，于是它对**部分边落在错的一侧**。

**实测（走廊腔第一次成环后立刻现形）**：
```
edges whose near-face reading is NOT the ring constant: 9 / 169
edges whose adjacent_cavity_id == own cavity: 7
```
⇒ 有 **7 条边声称 `interzone`，而它记下来的「隔壁那间房」就是它自己**。
连锁后果：near/far 面读数对调 · `outward_normal` 反向 · 出口射线打回腔内。
**⛔ 这不是外观问题**：`exterior` 的投影偏移是 `t`（不对称），side 反了就会投到墙的另一侧。

**修法**：side 改由**环自己的绕向**判（`cavity.exterior.is_ccw` + 该段的走向），这是**局部事实**。
**实测修完**：`self-adjacent edges: 0`，25 个健康腔的记录**逐字节没变**（凸腔两种算法同解）。

### 5.2 **细分单元按坐标升序发出，而环可能是降序走的**（承重，已修）

`_boundary_transition_points` 返回 `sorted(cuts)`，切出来的 cell 按坐标升序 append，
**不管环是往哪个方向走的**。以前从没暴露过（健康腔从不细分，走廊腔死在更早的 `owner_count`）。
现在走廊腔成环，环序被打乱 ⇒ 支撑线收不成连续段。
**修法**：父段是降序走的就把 cell 列表反过来。**实测**：`plan-F1` 走廊 merged span **44 → 32**。

### 5.3 **`as_measured_boundary_merge_changed_logical_status` 会把整份文档打崩**（已改成具名 per-cavity loss）

两条**各自都分类成功**的相邻 span 合并后，合并体的**新中点**可能正落在接头上 ⇒ 分类翻成 `unknown` ⇒
原代码 `raise ValueError`。端头一旦被认出来，**sm24** 就有一个腔撞上它：
```
ValueError: as_measured_boundary_merge_changed_logical_status:cavity:78c72977c3b7e2c2
```
`tests/test_as_measured_facts_layer.py::test_r3_audit_sm24_...` 直接崩。
**修法两步**：① 细分出来的 cell **永不参与合并**（它的见证点只在自己内部有效，
再合并等于给合并体换了一个新的单点见证 —— 那正是细分机制要防的事）；
② 仍然翻的情况**不再 raise**，改成该腔的具名 loss `merged_span_has_no_supporting_witness`。
**理由**：这是**单个腔**的性质，per-cavity 具名比「整份文档连同另一个 view 一起崩」更诚实、也更可观测。
⚠️ **这是把一个响亮的 `raise` 换成了台账条目 ——【请复核方判一下这是不是放水】**。
我的理由：台账条目本来就是 ②-1d 声明的「这个腔没出环」的唯一合法出口，且它会被
`reconcile_boundary_basis` 当成 exclusion 依据点名，⛔ 不是静默吞掉。

### 5.4 ⭐⭐ **「支撑线」在探针里和在生产代码里不是同一个东西**（这条决定了验收 7 的偏离）

`probe_3/4` 按 `(axis, const)` 合并 ⇒ 走廊 F1 得 **24 条支撑（14 有面 + 10 端头）**。
生产代码的合并键是 `(axis, const, side, group, boundary_condition)` ⇒ 同一条支撑线上
**基准一变就切成两条记录**（`x=57600`：一段 `interzone`、一段 `exterior`）。
⇒ 我把「支撑线」和「edge 记录」**显式分成两层**（`_boundary_support_lines`）：
拐角只在**线与线**之间出现，线内的切口不是拐角。
⇒ 但投影侧没有这一层信息可用（它只看已存的 edge），所以基准切换在投影里表现为
**两条平行的相邻支撑** ⇒ 环建不起来 ⇒ 验收 7 的 `1.800000` 在产物侧读不出来（见 §三 验收 7）。

⭐ **方法论**：这是 [[gate-measures-right-but-carrier-gets-swapped]] 的又一例 ——
探针量得准，但它量的**那个「支撑线」被换掉了**。派工单 §一.2 的 `parallel=0` 复现得出来，
**可它是在探针的载体上成立的**。
