## 1. Independent cause and premise checks

### Wrapper cause

Independent code inspection confirmed the branch-order bug. `anchors_json` and
`candidates_json` were members of `PATH_KEYS`, and that branch ran before the generic dict/list
serialization branch. Therefore strings were always staging-root-prefixed and arrays never reached
`json.dumps`.

`git blame` traces the four-key `PATH_KEYS` set to initial isolation commit `df6f249`; inspection of
that commit found only the general hard-isolation path-containment rationale, not a distinct attack
that requires inline JSON payloads themselves to be interpreted as file paths. The fix therefore
retains containment for every non-inline string rather than removing these arguments from security
handling altogether.

The premise that `candidates_json` has the same bug is confirmed by a separate production-entry
lock. Before the fix, the wrapper prefixed the inline candidate array with the staging root and
upstream argparse rejected it. After the fix it creates the overlay-logger sidecar and overlay.

`run_cv_probe.py` now names `anchors_json` and `candidates_json` as JSON-or-path parameters and
dispatches them deterministically:

- dict/list request values are compactly JSON-serialized;
- a string whose first non-whitespace character is `[` or `{` remains inline JSON;
- every other string follows the unchanged `_resolve` staging-containment and symlink checks;
- other value types fail with an explicit JSON-object/array-or-path error.

The new branch precedes `PATH_KEYS`, but `PATH_KEYS` itself remains intact. `image`, `out_dir`,
`OUTPUT_ROLE_KEYS`, `OUTPUT_ROOT_DIR = "out"`, `_resolve`, `_resolve_output`, and `guard.py` were not
changed.
