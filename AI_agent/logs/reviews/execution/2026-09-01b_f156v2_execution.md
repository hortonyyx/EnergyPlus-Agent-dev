## 十、§三 待签字设计决定：**我的建议方案 + 代价**（⭐⭐ **这是待签字的设计决定，不是我自行拍板**）

**建议：端头支撑线只作【角点构造器】，永不成为 `boundary_edge` 记录。**

| | 内容 |
|---|---|
| **做法** | 环的支撑线分两类：**有面支撑**（`_boundary_owners` 恰好 1）出 edge 记录；**端头支撑**（无面主、端头归属候选恰好 1）只参与求交出角点。两类都不许缺、不许多，否则响亮失败并点名。 |
| **为什么诚实** | 端头面是**真实测到的**线（墙带的 `along_min/along_max` 平面），拿它求交不编任何数；而**不给它发 edge**，就永远不用去填那三个填不出的字段（配对平行面 / `thickness_units` / 两侧面线）。⛔ 零编造。 |
| **实测可行** | `probe_3`：排除端头后剩余支撑**两两仍垂直**（`parallel=0`），环合得上；两个走廊腔分别剩 **14 / 10** 条 |
| **有先例** | 答案侧自己就这样：`F1-z0` **18 个多边形顶点 / 16 条 edge**，基准切换的连接段同样无 edge |
| **代价 ①** | `boundary_edges` **不再覆盖整圈周长**（每个端头缺 0.12/0.24 m）。凡按「边加起来 = 周长」读它的消费者会读错 ⇒ 必须把这条写进契约并加一把锁 |
| **代价 ②** | `facts_polygon = Polygon([edge.p1 ...])`（`answer_compiler.py:1155`）建出的环会**切掉端头小角**（每处 0.0144 m²）。它只用于 `representative_point` 找 zone，实测不影响判别，但**该换成用完整支撑环** |
| **代价 ③** | 端头段的 `boundary_condition` **不再被记录** ⇒ 「墙端头那 0.12 m 到底邻着谁」这个信息从产物里消失。若下游 EnergyPlus 侧需要它，这条路要重开 |
| **配套（同样待签字）** | §三.4 的**端头准入规则**（端头 `const` 必须落在某条平行墙带的已测面上）。它是让 28.68 留在 loss 台账的**唯一规则形态出路**；代价 = 「自由端隔墙」这类形态会被判响亮失败，需要单独形态支持 |
