### §五.3 `_same_floor_sliver_conflict` —— **我不同意「方向反了」这个措辞，但不构成停报**

派工单的**事实判断我复现了、是对的**：实现是同层两值相距 **≥ `min_edge_length_m`(=100mm)** 才返 True，
对 60 mm 返 False ⇒ 放行合并。

但我读它的**语义**与派工单不同：

```python
def _same_floor_sliver_conflict(a, b, tol) -> bool:
    for floor in set(a.support_by_floor) & set(b.support_by_floor):
        for av in a.support_by_floor[floor]:
            for bv in b.support_by_floor[floor]:
                if abs(av - bv) >= tol.min_edge_length_m - _EPS:
                    return True
```

它上方的注释写着「**valid same-floor Phase A separations** are never silently collapsed」。
按这个立意，`>=` 的方向是**对的**——「这两组在同一层上握着两条【真正分开】的轴，合并会毁掉一次真实分隔」。
真正可疑的是**阈值选错**：注释说的是「Phase A 保下来的分隔」，那道门是 `axis_jitter_tol_m`(50mm)，
这里却拿 `min_edge_length_m`(100mm) 去量。而外层进入合并的条件本身就是
`b.canonical - a.canonical < min_edge_length_m` ⇒ **对「直接相邻的两条同层轴」这个主场景，这道守卫近乎恒假**
（只有已经并过一次、支撑里带多值的组才可能触发）。

⇒ 我的结论：**不是符号反了，是量错了尺子**，且它今天基本不承重。
⛔ **按派工单，本单没有改它。** 且我不建议下一轮直接把阈值换成 `axis_jitter_tol_m` —— 那会同时保住
60 mm 的真台阶**和**每一次 60 mm 的模型抖动，正是 §三 说的抛硬币，换汤不换药。

## 三、逐条做了什么

### R1 · 同层合并响亮记账（`deterministic.py`，+117 行）

新增 `rule_id = "deterministic_core.same_floor_axis_merge"` 的审计行，落进 `corrections`。

**为什么落 `corrections` 不落 `conflicts`**：`conflicts` 在本仓语义是「核心决不下来、要仲裁」，
`validator/checks/correction.py:519` 把两者一起读；但把一次例行合并塞进 `conflicts` 会改变下游门的含义。
`corrections` 是既有且已接线的通道（`deterministic.py` 里 `corrections.extend(x_audit)`），
新行带 `rule_id`/`stage`/`reason` ⇒ 过得了 `correction.audit_completeness` 的 provenance 检查；
且**不带** `kind: "debt_resolution"` ⇒ 结构上不可能误销一条 evidence debt。

**两处都覆盖**（⛔ 派工单点名只覆盖后者会漏掉 <50mm 整段）：

| 记账点 | 位置 | `step` 字段 | `tolerance_name` |
|---|---|---|---|
| per-floor 身份聚类，`len(cluster.raw) > 1` | `_reconcile_cross_floor` 建 node 的循环 | `identity_cluster` | `AXIS_JITTER_TOL` |
| Phase C 碎片守卫合并，且 a/b 在**同一层**都有支撑 | `_merge_axis_groups` 调用点前 | `sliver_merge` | `MIN_EDGE_LENGTH` |

**跨层不记**：只有 `set(a.support_by_floor) & set(b.support_by_floor)` 非空才记，
纯跨层合并（这个参数的立意，已有 `cross_floor_align` 记账）不落新行 —— 有专门夹具
`test_cross_floor_merge_is_not_recorded_as_a_same_floor_merge` 钉住。

**可定位**：每行含 `floor` · `axis` · `original_value`（被并掉的全部相异原值）· `resolved_value`（最终落点）·
`per_value_delta`（各自挪了多少）· `separation` · `step`（哪一步造成）· `target`（字符串形式，含层名与两原值）。
⛔ 不是计数。最终落点是在整个 reconcile **收敛之后**用 `mapping` 反查的（一个已并组还可能再并），
不是合并当时的中间值。

⛔ **纯观测**：不动任何坐标、不动任何分组判定、不动任何容差。

### R2 · `_MIN_EDGE` 与 `min_edge_length_m` 合一（值不变）

  import 时绑死会把 R2 想关的那条缝原样再开一遍。`load_core_tolerances` 是 `lru_cache` 的，代价=一次字典查。
- 核过没人 import 这个名字：`split_pairing.py` 只 import `_AREA_MIN` / `_Z_TOL` / `_iter_segments`，
  `_MIN_EDGE` 全仓零外部引用。

**`envelope_transform.py` 的语义挪用**（派工单要求只加注释、⛔ 本单不改）：
在 `window.span/z < tol.min_edge_length_m` 那处加了 12 行注释，点名
