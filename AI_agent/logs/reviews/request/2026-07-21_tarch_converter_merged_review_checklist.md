## 1. 上下文（读懂命题所需的最小背景）

本项目用「评测标准答案（gt）」给识图/建模管线判卷。gt 来自用户天正 CAD 画的图 → 图形导出 DXF →
提取器 `src/agent/judge/gt_extraction.py`（GT v3）→ `gt.json`。

**今天实测发现**：天正真实建筑墙线**喂不进** v3 提取器 —— v3 要**单线**区划边界（相邻房间共享一条线、
polygonize 后每面正好一个房间），天正画的是**真实建筑图**（墙是**双线**、门窗洞处墙线**断开**）。
⇒ 要做一个转换器。用户拍板：**不改变人类正常画图习惯**（否决了"让用户手画区划线"）。

**被审的裁决稿**选定了 opus 稿的「腔体 + 逐边外扩」路线（补洞 → polygonize → 面积二分出腔体 →
逐边向外测厚、外墙外扩到外皮 / 内墙外扩半墙厚到轴线），**明确不做双线配对**；
并从 sol 稿并入 7 条证据纪律与边界情形条款。

**最高优先级的失效模式**：这是**答案生成器**。静默产出一份**错答案**比崩溃危险得多
——错答案会把正确的产物判成错误，且无人发现。**任何"猜一下把图补闭合"的路径都是致命入口。**

## 2. 十二条待核命题

### C1 主干裁定理由 1：「腔体路线真的不需要双线配对」
**验什么**：裁决稿 §0 理由 1 声称 opus 路线不需要解决"双线配对"。但 S7 逐边外扩要
「向外法向做射线、求射出 `WallRegion` 的距离 d」并按远端分类决定扩 d 还是 d/2。
请判定：**这个测厚+分类过程是否隐含地在做配对**（即是否存在一种输入，使它必须先知道"这两条线是同一道墙的两侧"才能给出正确答案）？
**判定标准**：能构造出这样的输入 ⇒ 不成立；论证其只依赖"腔体边 + 墙体域"两个已定量、与配对无关 ⇒ 成立。

### C2 §2.3 改了 outer skin 求法后，S7 的远端分类是否还自洽
**验什么**：基线 S7 步骤 2 用「射出点是否落在 **Footprint 外环**」区分外墙/内墙，而 Footprint 在 opus 原文里
= `unary_union(全部面)`；裁决稿 §2.3 把 outer skin 改为**无界 flood-fill** 求。
请判定：**改法之后 S7 的分类判据是否仍然成立、是否需要同步改写**（含带洞/多部件情形）。
**判定标准**：存在情形使两种求法给出不同外环、进而导致 S7 误分类 ⇒ 不成立（并指出该情形）。
> 这是主控自查时发现的疑点，**大概率有问题**，请重点核。

### C3 内部洞口不可表达（D5）对 sm24 的实际后果
**验什么**：裁决稿 §5-D5 记载「内部洞口在 v3 不可表达（边界段只由外环导出）；sm24 21 个洞中仅 14 个外围」。
裁决稿**没有说清**剩下 7 个内部洞口（内墙上的门）在 gt 里怎么办、对判卷有何影响。
请判定：**这是否构成一个必须在施工前解决的缺口**；若是，最小可接受的处理是什么（记入 gt 的哪个字段 / 显式声明不判 / 其它）。
**判定标准**：查 `gt_schema.py` / `gt_extraction.py` 确认内部洞口确实无处安放 ⇒ 缺口成立。

### C4 面积二分的歧义是否真被堵死
**验什么**：裁决稿 §2.2 规定 `A_room` 只作分桶提案、必须与人声明房间数一致、**严禁自动调阈值**。
请判定：**是否存在绕过这道纪律的路径** —— 例如：两个误分互相抵消（一个小房间被当墙 + 一个墙洞被当房间）
导致数量**恰好**吻合但分配错误，而 G6 只比数量、抓不到。
**判定标准**：能构造出数量吻合但分配错误的情形 ⇒ 不成立（此时需要比数量更强的闸门）。

### C5 G8「反演重建门」是否真能挡住静默错答案
**验什么**：opus 稿 §7 的 G8 = 由输出反算墙体域、与实测墙体域对账，被裁决稿列为"主保险"。
请判定：**G8 能挡住哪些错、挡不住哪些错**。特别是：若外扩把某条边扩错了方向（内墙当外墙），
反演出的墙体域是否必然与实测不符、从而被抓住？
**判定标准**：能构造出「输出错误但反演仍对账通过」的情形 ⇒ 不成立。

### C6 实测数字可复现性
**验什么**：裁决稿 §0 引用的实测数字 —— 洞口 21/21、补洞后 `dangles/cuts/invalid` 全 0、
Σ面积 200.00 m²、腔体 8 个、L 走廊单面 30.82 m²、外扩后对称差 0.000000 m²、两两重叠 0.0 m²。
**判定标准**：自己跑探针复核。**任一项复核不出 ⇒ 不成立**（并给出你测到的值）。
> 你不必重实现整条算法；至少复核「补洞后拓扑三项全 0」与「Σ面积 = 200.00 m²」这两项可独立验证的。

### C7 「墙厚不统一」修正是否已在稿中彻底贯彻
**验什么**：事实修正 D1 = 外墙 240 / 内墙 120 混用。请**全稿搜查**是否还有任何地方
隐含"墙厚统一/恒定偏移/全局默认厚度"的残留（含 §2.1 并入的六类厚度证据本身是否自洽）。
**判定标准**：找到任一处残留 ⇒ 不成立。

### C8 fail-closed 是否真的无降级路径
**验什么**：全稿所有失败分支，是否**全部**导向"停止 + 诊断"，**没有**任何
"降级近似 / 取最大 / 取最近 / warn 后继续"的路径。
**判定标准**：找到任一条降级继续的路径 ⇒ 不成立。特别检查：S5 腔体分桶、S7 沿边一致性、
S3 无块（炸开图）时的续接规则、§2.6 自由端处理。

### C9 不变量 #6（复杂度可扩展性）是否守住
**验什么**：项目硬约束 = 不得把「墙厚统一 / 矩形网格 / 单层 / 各层同 footprint / 无洞」这类
当前简化假设**烤死到无法松动**，必须能长到 L 形(sm25) / U 形(sm26) / 回字形(sm27)。
**判定标准**：找到任一处烤死 ⇒ 不成立。注意区分「本轮不做」（合法）与「烤死到以后长不出来」（违规）。

### C10 「种子点不自证」防线的实际强度
**验什么**：两稿独立指向同一结论 —— 种子由转换器自己的面反推 = 自证同义反复。
裁决稿的拆法是「坐标归机器、数量与房名归人」。
请判定：**在 sm24 的具体流程里，这条防线是否真的成立**（人给的"8"这个数字，是否可能是从
转换器输出/管线产物倒推来的，而非独立来源）？
**判定标准**：能指出数字实际来自被测系统 ⇒ 不成立。

### C11 gt 隔离铁律是否守住
**验什么**：转换器属 judge 侧，`gate①`（`src/validator/checks/*`）与执行器（`src/agent/pipeline.py`）
**绝不**可 import；有 `tests/test_gt_discipline.py` 机械守。
另：天正专有规则（`WALL`/`WINDOW` 层名、块名前缀）**不得**渗进 `0_reading` / correction / 执行器 / gate①。
**判定标准**：稿中存在会导致上述渗透的设计 ⇒ 不成立。

### C12 §6 三处仓库内部不一致的处理是否足够
**验什么**：裁决稿 §6 登记了 D6（保护路径与 bundle 约定打架，要求"施工必须在 staging 跑"）、
