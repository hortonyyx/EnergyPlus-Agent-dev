## 1. 背景（这是什么活）

判卷子系统拿模型产出的几何跟 gt 对账。gt 里的外轮廓真值是**外墙外皮**尺寸（`15 × 8`），
gt 另外存了 `wall_thickness_m`（本 case = 0.24）。

07-08 写判卷时，模型产物的外轮廓落在**墙中轴**框上（`[0.12, 14.88] × [0.12, 7.88]`），
所以判卷侧写了一段「中轴 → 外皮」的单向换算，把产物往外扩半个墙厚再跟 gt 比。**当时是对的。**

**08-09 的 F-17 修法把 envelope 变换修好之后，产物自己就落在外皮框 `[0, 15] × [0, 8]` 上了，
判卷侧没跟** ⇒ 又外扩了一次 ⇒ **系统性偏 0.12 m**。

用户 08-10 已定：**目前只保留一种出模形式**（外墙外包 + 内墙中轴，因为现在的图就是这么标注的）；
「标注 / 墙厚 / 出模」作为专项后面单独解决。
用户 08-11 补定：**本批要给那个出模专项留好接口（接缝），但现在只实现固定的这一种形式。**

## 3. 要做的三件事（范围写死）

### 3.1 把唯一那种出模形式写成**一处声明**（单一来源 + 未来接缝）

- 判卷侧对「产物坐标系是什么框」的假定，**收敛成一处具名声明**（常量 / 枚举 + 文档字符串），
  内容 = **外墙取外皮、内墙取中轴**；判卷各处**读它**，⛔ 不许再各自假定。
- **这处声明就是将来「出模专项」插开关的接缝**（铁律 #6：为复杂度升级留路）。
  结构上要能容纳第二种出模形式（例如轴线框），**但本批只实现这一种**：
  **⛔ 不实现开关、⛔ 不加配置项、⛔ 不加 if 分支、⛔ 不造只有一个实现的抽象层。**
  留路 ≠ 提前造抽象；判据 = 「将来加第二种时，改动是否集中在这一处声明及其读取点」。

### 3.2 删掉两处单向换算

`_boundary_centerline_to_outer`（`:252`）**和** `_expand_boundary_span`（`:125`）。
产物本就在外皮框、gt footprint 本就是外包 ⇒ **两边本该直接比**。
⛔ **不许只删第一处**（那样内墙 9 段会继续被冤枉）。

### 3.3 给外包边界补上缺的「容差内 = 橙色」档

与墙段同口径三档：`≤ complete_eps(0.05)` 绿 / `≤ position_tol(0.30)` 橙 / 否则红。
`LineMatch` 需要能表达 status；**渲染与报告侧要真的用上**
（自己去找消费方：`scripts/tool_scripts/render_grade.py` / 报告装配 / certifier / 侧车 schema —— 这份清单可能不全，请自行全仓核）。
