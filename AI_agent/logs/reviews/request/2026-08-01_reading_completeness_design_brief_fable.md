## 1. 系统背景

这是一条「建筑图纸 → EnergyPlus 能耗模型」的管线。第一段叫 **0_reading（识图）**：
一个 VLM 看图纸 PNG，输出结构化 JSON；**之后所有几何都是确定性代码**（造面、配对、切分、装配），
所以**识图的坐标精度直接决定整条链的上限**。

- **输入**：干净矢量 CAD 导出的 PNG（本例：1 张一层平面 + 1 张南立面），**带完整尺寸链标注**（tick + 数字 + 延伸线）。
- **输出**（单图一份 JSON，image-local，米制）：
  - `strokes[]`：墙线段等笔画，`geometry.p1/p2`（米）、`pen`（wall/window/door/…）、
    `provenance`（`seen` / `dimension_derived` / `estimated`）、`confidence`、`dimension_refs[]`、`note`；
  - `dimensions[]`：**结构化尺寸链**（`text_verbatim` 原字符 / `value_m` / `axis` / `chain_id` / `role=overall|segment` / `order`），
    设计上支持「Σ 分段 == 总长」的闭合校验；
  - `openings[]`（门窗）、`ocr_texts[]`、`uncaptured[]`（**看见了但故意没画**的显式登记）、`self_check{}`（自评）。
  - **明令不许做拓扑**（不许分组房间、不许判内外、不许配对父子）——那是下一段 `1_correction` 的事。
- **目标模型档 = Haiku 4.5 级弱 VLM**（北极星就是「弱模型也要能做对」），单次读图会话约 **400 秒**。
- **它手上已有的确定性 CV 工具箱**（命令行探针，单次调用，产 JSON 侧车 + overlay PNG）：
  - `crop_zoom`（裁剪放大 + 逆变换链，crop 局部像素可还原回原图）
  - `wall_line_profiler`（行/列投影，出线候选：位置 + prominence 强度 + FWHM 宽度）
  - `px_m_calibrator`（尺寸跨度 → `px_per_m`，过原点最小二乘 + 逐锚残差；**x/y 双轴独立拟合必须一致到 0.30%，否则直接 raise**）
  - `window_cc_detector`（8 连通域 → 窗矩形候选）、`storey_line_profiler`、`overlay_logger`
  - **`prescan-plan` / `prescan-elevation`**：**开考前由确定性代码跑的固定档宏观预扫**，产：
    编号候选线带 + tick + `diagnostics.axis_summary`（按投影峰归组）+ 两个派生视图 ——
    `calibration_span_candidates.json`（垂直延伸线交点定出的标定跨度）与
    `long_structural_lines.json`（把被门窗打断的强线带按互为正交的交点桥接成整条，附 `source_candidate_ids` / 支持覆盖率 / 桥接缺口）。
- **纪律文档**（skill 库，产品随附）已经写了：先标定后画图、坐标必须来自工具测量、
  `v_m=(px-origin_px)/px_per_m` 且要留可复算 provenance、候选必须逐条裁图核验、拒绝的候选也是证据。

## 2. 判卷（只存在于开发期，不得进入机制）

- 有一份**签字转正的标准答案**（坐标级），判卷器逐元素对账，容差**墙 0.30 m / 窗 0.40 m**；
  内墙分数 = 命中长度 / 答案内墙总长（57.86 m），另有「多画」（答案里没有的墙长）。
- **铁律**：标准答案**只有判卷和人可读**，任何生产机制、任何确定性门**绝不可以依赖它**
  （dev/prod 一致 + 防照抄）。⇒ **你的方案不能以「跟答案比」为机制的一部分。**

---

## 3. 硬约束（违反即方案作废）

1. **环节内部禁止人/更强 agent 在环**：每个环节必须自己从「输入」走到「输出」，
   中途不许停下等人回答、不许接收「你哪里错了该怎么改」。
   **唯一允许的外部出口 = 整轮盲重抽、零信息**（相当于另换一个学生重考一次）。
   **且盲重抽只能当兜底、不能当依赖机制**（≤3 次，且一次 400 秒，靠重抽刷分效率不可接受）。
2. **不许把「主控/人的临场判断」当成某环节的输入**。**随产品发布的固定档参数是合法的**
   （比如预扫参数写死在 skill 库里就合法，主控每轮临时挑就违规）。
3. **确定性代码不算监督**。代码想做多少就做多少 —— **这是你最大的自由度**：
   把工作从 VLM 手里搬进代码，不违反任何约束。
4. **标准向前看，不为历史产物让步**：新判据把过去的「好成绩」判红是可以接受的，
   **不许为了让历史产物通过而把判据写软**。
5. **建筑复杂度可扩展**：现在只处理正交、各层共底面的简单体量，但未来要能长到
   非方形 / 退台 / 挑空双层高 / 中庭竖井。**只对当前这栋楼成立的机制没有意义。**

## 4. 现况数据（全部实测，逐条给数）

### 4.1 成绩：同一套配置、完全独立地考两遍

| | d1 | d2 |
|---|---|---|
| 内墙命中 | **5.18 / 57.86 m = 9.0 %** | **14.34 / 57.86 m = 24.8 %** |
| 多画（答案里没有的墙） | 59.36 m | 79.14 m |
| 外轮廓 | 60.00 / 60.00 m **pass** | 同，pass |
| 平面窗 | **0 / 11** | **0 / 11** |
| 会话时长 | 412 s | 373 s |

**同模型、同图、同文档、同考试范围、同预扫档，唯一差别 = 抽样。相差 2.8 倍。**
⇒ **这个量级的单次成绩就是噪声**；任何方案的验证**必须至少两抽**。

### 4.2 失守点已定位：标定很好，但每条内墙仍然靠目测

- **d2 的标定质量已经很好**：直接消费预扫的 `calibration_span_candidates`，
  两轴独立拟合得 36.4 / 36.375 px/m、**跨轴一致 0.04 %**（门限 0.30 %），并显式记录「标定接受」。
- **但标定本身不产生内墙位置**。d1 自述内墙是
  *"traced via visual inspection rather than dimension derivation"*、精度 ±0.2 m，
  并写明「时间花在外轮廓和主分隔上，内部没余力」。
- ⇒ **「先量再画」被理解成了「先把比例尺量准」，而不是「每一条墙的位置都要量」。两抽在同一处失守。**
- 附带：**探针调用次数不是「有没有去量」的代理指标** —— d1 调 5 次探针拿 9.0 %，d2 只调 1 次拿 24.8 %。

### 4.3 完成度判定目前只有自评，且无人消费

- 产物里有结构化字段 `self_check.all_visible_strokes_captured` / `all_dimensions_transcribed`。
- **d1 诚实地填了 `false`**，并附文字「只描了主要分隔」「窗检测到但没画」。
- **该字段在整个生产代码里零个消费者**（全仓 grep：只出现在 schema 文档和产物里）⇒ 确定性门 0 阻断、直接放行。
- ⇒ **读图器没有不听话：它读了自检清单、诚实自评、正确判定自己没做完、写进指定字段、提交。
  没人说过 `false` 不许提交，也没有人去看。**
- **⚠️ 把它变成阻断项的已知反效果（冷水，请务必正面处理）**：
  **d2 四个自检字段全填 `true`，成绩仍只有 24.8 %。**
  ⇒ 变阻断只能抓「诚实的没做完」，**抓不住「自信的做错」**，
  且最可能的结果是**把 d1 训练成 d2**（学会填 true）。

### 4.4 确定性门（gate①）对识图质量的分辨力 = 0

- 现有 11 类阻断检查**全是结构 / schema 类**（id 唯一、几何非退化、尺寸可解析、不许写拓扑字段…），
  **没有一条判「画的跟图纸对不对得上」**。
- **判决性实证**：把历史上一份 8/8 满分产物和一份 1/8 崩盘产物各跑一遍最严格档，
  **阻断层结论逐字相同、都是 0 block，连非阻断失败条数都同为 6**。
- 旗标层**其实有信号**（`stroke_dimension_consistency`：d1 命中 1 条墙落在尺寸链累加位置、d2 命中 4 条），
  **但没有阻断权**。
- 代码注释里写着病根的书面形态：*"advisory only… **J0 must verify**"* ——
  **确定性层每遇到判不了的就写一句「交给 judge」，而 judge 就是那个不该在环里的人。**

### 4.5 现有 schema 判不出「量没量」

`provenance` 字段与成绩**完全不相关**：历史上那份 9/9 的满分产物 **全是 `seen`、`dimension_refs` 全空、零像素痕迹**；
另一份 8/8 的 **全是 `dimension_derived`**。⇒ **不能拿 `provenance` 当「有没有测量」的判据。**

### 4.6 确定性候选的召回不够当分母（这是最硬的卡点）

预扫的 `long_structural_lines` **只有 5 条**，其中 **3 条精确命中答案里的内墙（误差 0.06–0.07 m，容差 0.30 m）**，
**但答案里有 16 段内墙**。
⇒ **确定性候选集精度很高、召回很低**，直接拿它当「完成度分母」会把「漏画 11 段」判成合格。

### 4.7 「把话说清楚」已经连败三次

① 把纪律写进 skill 库 → ② 把「先量再画」提到启动文件顶层、标为非可选 →
③ 把**正确写法**写进探针的报错回执（`did you mean --tool prescan-plan?`）。
**第三次等于把标准答案递到手上，读图器仍然放弃了那条路径。**
⇒ 结论：**文档不可能验证别人有没有遵守自己。**

## 5. 要你回答的问题

### Q1（主问题）**完成度由谁判定？**

在**没有标准答案、没有人在环、被测者自评不可信**的前提下，
怎么判定「这张图**读完了**」？

要求你的方案正面处理：
- 不依赖被测者自评（§4.3 已证自评会被优化掉）；
- 能分辨「**诚实的没做完**」与「**自信的做错**」这两种失败（后者是 d2，更难）；
- 误报（把做完的判成没做完）与漏报（放行没做完的）各自的代价，以及你怎么选这个平衡点；
- 判定不过之后走什么（记住：整轮盲重抽是唯一合法出口，且不能当依赖机制）。

### Q2 **怎么让每条内墙的位置真正来自测量？**

我们已登记的候选方向是：**把测量整个移进确定性代码，识图降级为「在确定性候选上做分类 + 查漏」**。
**实测卡点见 §4.6：召回 5/16。**
你可以采纳它并解决召回问题、可以改造它、**也可以否掉它给出别的方案**（比如换产物形态、
换任务分解、换人机（机机）分工、让 VLM 只回答它擅长的问题类型）。
请说明你的方案对「多画 60–80 m 虚构墙」这一项有没有效 —— 那是比漏画更脏的失败。

### Q3 **平面窗 0/11 连续三轮全崩**

同一张平面图上的窗，三轮实验（不同配置）**全部零命中**；同时立面窗几何也是 0/8。
这与 Q1/Q2 是同源问题，还是独立能力缺口？要不要单独立项？给你的判断依据。

## 6. 交付形态

一份**中文设计稿**，落到 `AI_agent/logs/reviews/verdict/2026-08-01_reading_completeness_design_fable.md`，包含：

1. **方案主张**（一句话说清你要改什么）；
2. **机制怎么工作**：输入 / 输出 / 谁判 / 判什么 / 判不过怎么办（可写伪码或接口草图，**不要写可提交的代码补丁**）；
3. **为什么不违反 §3 的五条硬约束**（逐条对照）；
4. **落地分期**：第一步做什么、做完能拿到什么信号、**什么信号出现就说明这条路错了**；
5. **⭐ 你自己的反对意见**：这个方案最可能怎么废、最脆弱的假设是哪一条；
6. **验证方案**：怎么证明它有效（含「至少两抽」纪律，以及你要看哪个数字）；
7. **明确区分**：哪些是你的假设、哪些是我们要去实测确认的。

**同时明确回答**：如果你认为这三个问题里有某一个**问错了**（问题本身预设错了方向），请直接说，
并给出你认为该问的问题。
