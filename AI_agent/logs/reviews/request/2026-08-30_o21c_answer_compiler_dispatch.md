## 一、承重前提（⛔ 请自己复核，第 4 条尤其）

### 1.1 今天的 `gt.json` **就是形式 B**（我实测，非引用文档）

[`_offset_for`](../../../../src/agent/judge/tarch_normalize.py#L1058) 逐字是：

```python
def _offset_for(basis: EdgeBasis, thickness: float) -> float:
    return thickness if basis == "outer_skin" else thickness / 2.0
```

⇒ 外墙偏 **t**（走外皮）· 内墙偏 **t/2**（走中轴）= **形式 B 的定义**。
⭐ **这给了本单最便宜也最锋利的一条验收**：编译器出的**形式 B 多边形，必须能复现今天签字的 `gt.json` 的 zones**；
逐位不同的地方**必须逐条指到 ②-1b 的某条 revision**（sm25 那 5 条线），⛔ 不许有第三种解释。

### 1.2 出模两种形式，⛔ 净空不是出模档位

**形式 A** 全中轴 · **形式 B** 外墙外皮 + 内墙中轴。
⛔ **净空（纯内包）不做出模形式**：A 房间东面 x=5.00、B 房间西面 x=5.24 ⇒ **两个面配不上对**
⇒ ① InterZone 门直接红 ② 绕过去则**相邻房间之间的传热断了** = **跑得通但物理是错的**。
⭐ **但净空不丢，它是【派生量】** —— 房间使用面积本就是净空口径，事实层有 `(两端点, basis, thickness)` 就算得出。

### 1.4 ⭐⭐⭐ **顺序张力：形式 B 需要「内外身份」，而 ⛔ 不许吃 converter 的 `basis`**

sol 的 **B5** 裁定（逐字）：现有 `basis` 由「穿过墙后是否落 footprint exterior」判出并**立即决定输出偏移**，
它**是已经坍缩的投影选择**；让 exterior profile 直接吃它**等价于 identity**（转换器判什么，编译器就复述什么）。
sol 要求 profile 这样映射：

```
axis:      any resolvable wall boundary -> wall_axis
exterior:  exterior -> outer_skin; interzone -> wall_axis;
           unclaimed_void/unknown -> unprojectable（仅传播到依赖闭包，见 B6）
```

⇒ **这看起来把 ②-1d（`boundary_condition` 字段化）拽到了 ②-1c 前面。我判断【不用调换顺序】，理由如下，⛔ 但这条请你复核，不成立就停下上报**：

- sol 禁的是**吃那个已存的字段**，⛔ 不是禁「判定内外」这件事本身；
- 「穿过墙后是否落 footprint exterior」是一条**外部可证伪**的判据（外轮廓在事实层里），
  编译器**从事实层重新判一遍**不是 identity —— identity 是复述**存储值**；
- ⇒ **本单自己重新判定，并把判定依据留痕**（每条边记：用了哪条外轮廓边、法线朝向、判定结果）；
- ⇒ **②-1d 是把这件事【字段化 + 配投影前证据】**，不是本单的前置。
- ⛔ **硬禁令**：不许从 `as_measured` / `as_signed` / S7 的任何字段**复制** `basis`；
  ⭐ **验收**：把事实层里所有 `basis` 相关字段**整列抹掉**，编译器**输出必须逐位不变**。
  （这一条同时把「有没有偷吃」变成可测的，⛔ 不是纪律。）

## 二、要做什么（六件）

### R1 · `AnswerCompiler(profile)`：一份事实，多个出口

```
as_signed.json ──→ AnswerCompiler(profile) ──┬─→ 形式 A 房间多边形
                                             ├─→ 形式 B 房间多边形
                                             ├─→ reading 题目册（该画哪些面线）
                                             └─→ 净空面积表（派生量）
```

⭐ **一份事实 + 同一个派生器出多个出口，⛔ 不是两份并列的答案**（并列必各自漂移 = **F-130** 的形状）。
- `profile` 是**显式参数**，⛔ 不许由证据/阈值选形式；run config 只选**哪个是正式成绩**。
- 编译器**纯派生、无人工通道**；**派生器版本进答案键**。

### R2 · 6a / 6b / 6c 三条，各配一个会红的夹具

⛔ 每条都要能回答「**不加这处改动，这门本来红不红**」，并实测它**真的会红**。

### R3 · **依赖闭包**作废半径（sol B6，六条传播规则逐条实现）

1. **segment 的 thickness/boundary 缺失** ⇒ 作废该 segment、两端 junction、**所有 incident zone ring**，
   传播到每个 ring 重新闭合且**共享边双侧一致**为止。
2. **junction/corner 不确定** ⇒ 作废该 junction 的**全部 incident segments 与 rings**，⛔ 不是只杀报错边。
3. **view affine / 标定失败** ⇒ 该 view/floor 的坐标类指标**整 view/floor NA**（同源）。
4. **opening 局部歧义** ⇒ 默认只作废该 opening + host segment + 消费它的 opening 指标；
   ⛔ **一个洞口不得无条件杀 zone 数 / 外轮廓**（2026-08-21 实犯：一个角部歧义洞口作废整份判卷，
   而那份产物实际外轮廓 **94.4%** / 窗 **8/15**）。
5. **profile-sensitive** ⇒ 作废的是 **`(component, profile, metric)`**，⛔ 不是裸 floor；
   boundary 缺失可能让 `exterior` NA，而 axis 若 baseline/thickness 完整**仍可出**。
6. **评分层** ⇒ 每个 metric 声明 required components + coverage；缺 required ⇒ 该 metric NA，
   ⛔ **不得对剩余边重归一化**。

⛔ **sol 的两条硬线不得破**：不得破坏几何不变量 · **不得因缺失而缩分母获益**（缺掉的目标仍进分母，只记 NA）。
⚠️ **实测尺度**（sol 已核）：sm25 共 **136 edge**，按 `(floor, 无向 p1/p2)` 合并后 **108 条几何边**，
其中 **28 条被同层两个 zone 共享**（56 个 edge instances）⇒ **「逐边作废」会立刻破坏相邻 zone 的共同边**，
**「整层作废」又会杀掉 80 条不相干的边**。这就是为什么半径必须是闭包。

### R4 · reading 题目册改从**事实层**出（⇒ F-130 自动消失）

今天题目册是 [`denominator(dxf, request_path, view_id)`](../../../../src/agent/judge/as_drawn/denominator.py#L483) **现跑转换器**算的，
而 correction 的答案是**冻在盘上的 gt.json** ⇒ 一改转换器只有一边动。
⇒ 改成从 `as_signed` 派生。⭐ **验收**：改前改后**同一份 reading 的分数逐位相同**
（⛔ 若不同，先解释清楚差在哪，再决定哪个对 —— 不许直接接受新值）。

### R5 · 两形式之间的 metamorphic 门

- **内墙边**：形式 A 与形式 B **逐位相同**（两者内墙都走中轴）；
- **外墙边**：两者只差**声明的 t/2**（B 比 A 多外推半个厚度）；
- **往返可恢复**：由任一形式 + 事实层能回到另一形式；
- **缺资料** ⇒ 整份 `unprojectable`，且 **⛔ 坐标零泄漏**（不许在 NA 的产物里带出半算的坐标）。

### R6 · 净空面积表（派生量）

逐房间使用面积（净空口径）。⛔ 它**不是出模档位**，⛔ 不进出模 profile 的枚举。
