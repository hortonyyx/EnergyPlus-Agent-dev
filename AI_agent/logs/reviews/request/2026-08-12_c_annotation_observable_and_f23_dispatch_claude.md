## 摊 C · 让「这张图按哪种标注法」可见

### C.1 背景（一句话）

同一套机器，喂一张**按墙外皮标总尺寸**的图和一张**按轴线标总尺寸**的图，
会得到**差约 4.8% 全楼面积**的两个模型，而**生产链一声不吭**
（0.12 < 0.30 容差）、EnergyPlus 照样 0 Severe、判卷照样全绿。
本摊**不修这件事**（那归后面的「标注/墙厚/出模」专项），**只让它可见**。

### C.2 ⚠️ orchestrator 发单前实测，**推翻了 plan.md 里写好的解读规则** —— 请按本节施工

`AI_agent/plan.md`「〇-C」写的观测量 = `corrections[].intents` 的逐侧 `old_value → new_value`，解读规则：

| 每侧位移 | 说明这张图 |
|---|---|
| ≈ 半个墙厚（今天 0.12）| 按外包标注 |
| **≈ 0** | **按轴线标注** |
| 其他值 | 需人工判读 |

**实测这个观测量有三个结构性空洞**（`src/agent/correction/envelope_transform.py:111-165`）：

```python
if abs(float(new) - float(old)) <= tol.output_precision_m:        # = 0.010
    continue          # ← 位移 ≈ 0 ⇒ 根本不生成 intent
if abs(float(new) - float(old)) > tol.envelope_reconcile_tol_m:   # = 0.30
    continue          # ← 位移过大 ⇒ 也不生成 intent
```
外加该轴 `resolution.status != "accepted"` ⇒ 同样 `continue`。

⇒ **「没有 intent」这一个状态，同时代表三件完全不同的事**：

| 无 intent 的真实原因 | 含义 |
|---|---|
| 位移 ≤ 0.01 | **按轴线标注** —— 正是最该被看见的那一档 |
| 位移 > 0.30 | **超出容差** —— 正是最该报警的那一档 |
| 该轴 envelope 非 `accepted` | **无权威证据** —— 无信息 |

⇒ **照 plan 原样施工（把 `intents` 列出来当观测量），最该被看见的两档恰好是一片空白。**
这与本项目「只有负向断言的门 = 恒红、结构上不可观测」是同族缺陷：
**缺席不是信号，除非你显式把缺席变成信号。**

### C.3 ⇒ 修正后的施工要求

1. **观测量必须是逐侧实测位移，在 intent 生成之前算** ——
   `footprint_bbox(geom)` 的每一侧 vs `authoritative_envelope` 对应侧的差值，
   **四种状态各自具名**（名字你定，语义必须是这四种，不许合并）：
   - 位移 ≤ `output_precision_m` ⇒ 「按轴线标注」
   - 位移 ≈ 半墙厚量级且 ≤ `envelope_reconcile_tol_m` ⇒ 「按外包标注」
   - 位移 > `envelope_reconcile_tol_m` ⇒ 「超出容差，两者都不是」
   - 该轴无 accepted 权威 ⇒ 「无权威证据」
2. **⛔ `claim_kind` 有两种，只有 `overall_bound` 能判标注法**。
   `wing_break_endpoint`（`side="internal"`，翼部断点）语义完全不同，
   **⛔ 不许混进同一个数**。（这条同样请独立核实，见第 3 节。）
3. **露出位置** = 报告 / 判卷侧车里**一行 + 一句解读规则**。具体落点你自己定，
   但**必须能被人在正常看报告的路径上看到**，不能只落在机器记账文件里。
4. **⛔ 本摊明确不做**（做了就是预设专项的解法）：
   出模开关 · 第二套换算 · 动内核的 reconcile 逻辑 · **任何门 / 阻断 / 改变既有判定**。
   **纯观测。加了它，所有现有测试的结果必须一字不变。**

### C.4 锁

- 四种状态**各一把正向锁**，且**每把锁自证前提**（先断言「没有这处改动时它确实是另一个结果」）。
  ⚠️ 「按轴线标注」那一格**必须真的构造一份位移 ≈ 0 的输入**，
  ⛔ 不许因为「今天的语料造不出」就跳过——造不出请**停下上报**。
- 一把**不变性锁**：加了观测之后，既有判定/分数/产物**逐字节不变**。
- ⛔ 恒等锁不算正确性锁：不许只断言「字段非 None」「总数变了」。

## 摊 D · F-23：一条测量工作目录、而不是测量提交的断言

### D.1 事实

```python

    ["git", "diff", "--name-only", "--", "case_tests"], check=True,
    capture_output=True, text=True,

```

- **它想守的**（按测试名 `..._d6_new_judge_modules_stay_judge_only`）= judge 模块不许改动 case 素材。

  ① 任何人在 `case_tests/` 下有未提交改动就红（orchestrator 改一个 README 就把它打红了），
  ② **只要 `git add` 或 commit 一下就变绿** ⇒ 对它真正想防的场景反而失效。
- **与 F-8 同族**：「全仓绿」成了这台机器工作目录的属性，而不是这个提交的属性。
