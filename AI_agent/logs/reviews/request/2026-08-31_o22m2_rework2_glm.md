## 一、阻断 B-1 · **载荷可以来自【别的来源】而门看不见**

**复核方的复现**（⛔ 请自己复跑）：bundle 同时冻结 `tiny`（有载荷）与 `empty_plan`（合法空产物）；
把 `channel_status.walls.source_input_ids`（或 `plan_openings` 的）**单独改成 `("empty_plan",)`**，
而载荷仍全部来自 `tiny` ⇒ **两种形态都放行**。
```
FAILED ...payload_must_come_from_the_channel_declared_source[walls]        DID NOT RAISE
FAILED ...payload_must_come_from_the_channel_declared_source[plan_openings] DID NOT RAISE
（同一轮 4 个 PASS 是 F-2 的跨来源探针 ⇒ 这红不是探针整体失效）
```
**根因**：`_channel_has_payload()`（`evidence_contract.py:679-691`）只做
`bool(bundle.wall_claims or bundle.face_dispositions)` / `bool(bundle.opening_claims)`，
**完全不与 `status.source_input_ids` 相交或对账**。
⇒ ⭐ **同一病族又换了一次载体**：上一轮是「**全局空载荷**」，这一轮是「**错误来源的载荷**」
（[[gate-measures-right-but-carrier-gets-swapped]]）。

**补法（复核方给的方向）**：对两条**有载荷**的通道建立**来源闭合** ——
每个 wall claim / face disposition 的来源必须属于 `walls.source_input_ids`；
每个 opening claim 的来源必须属于 `plan_openings.source_input_ids`。
⭐ **并要处理反向**：状态列出的某个来源若本次无载荷，应有**按来源定域**的 zero-payload debt
—— ⛔ **不能用一条 channel 粒度的全局 debt 覆盖整路**。

## 二、阻断 B-2 · **没有载荷载体的三个通道，被 zero-debt 洗成 `present`**

`dimensions` / `room_roles` / `elevation_openings` 在 bundle 类型里**根本没有对应的 payload 成员**。
上一轮裁决与返工单给的边界是它们「**只能 `absent+debt`**，`present` 无意义」。
但当前逻辑：`_channel_has_payload()` 返回 `False` 后，**只要存在同 channel 的 `zero_payload_channel` debt 就跳过报错**
⇒ **`dimensions=present + zero_payload_channel(dimensions)` 被放行。**
```
FAILED ...test_f1_channel_without_any_payload_carrier_can_never_be_present   DID NOT RAISE
对撞（证明不是「任意 debt 误命中」）：
  walls 空载荷 + zero_payload_channel(plan_openings) ⇒ PRESENT_CHANNEL_WITHOUT_PAYLOAD（红，对）
  walls 空载荷 + zero_payload_channel(walls)         ⇒ 放行（这就是那张通行证）
```
⇒ 问题不是「debt 匹配错了」，是**把这张通行证也开放给了永远不可能携带 payload 的通道**。

**补法**：在这三个通道获得**真实 payload 成员**之前，校验器应**拒绝它们的任何 `present` 状态**，
只允许 `absent + missing_channel debt`；`zero_payload_channel` 这个出口**只适用于本层能检查 payload 的
`walls` / `plan_openings`**，并按 B-1 补上来源定域。
