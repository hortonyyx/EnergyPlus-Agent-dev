## 0. 一句话

**让「目测」和「左右反向」在接口上表达不出来**：读图器不再写公制坐标，只写源图像素锚点 +
它引用了哪几条尺寸标注 + 标定变换；**公制坐标由确定性代码唯一换算**。

## 1. 背景：为什么是这个，而不是「再教育读图器」或「加一个 controller」

### 1.1 已经确定的事实（这些不需要再论证）

- **正确路径确实存在，且已被同一把尺子量过**：07-07 的老产物（Haiku 4.5 + CV 工具箱）喂进今天的 v3 判卷层
  （同 GT / 同 bindings / 同容差 / 同全卷五张）⇒ **内墙 57.86/57.86 = 100 %（20 行全精确命中）· 外轮廓 60/60 · 多画 0 m**。
  今天 Sonnet 无监督全卷 = **92.1 % · 60/60 · 多画 6.77 m**。
- **两者的差别写在 provenance 里，不在模型强弱上**：
  老件 14 条平面墙中 **13 条 `dimension_derived`**（单条最多引 12 条尺寸标注）、38 份 CV 证据、crop_zoom 11 次；
  今天 10 条墙 **10 条全 `seen`**、引用 ≤2、**crop_zoom 0 次**。
- **07-07 那次「打回」不是临场干预**：启动 prompt 已从 git 复原
  （`git show 891356d:skills/intake_pipeline/0_reading/session_kickoff.md`），
  其 Workflow 段逐字写着 *"Do one pilot image first / Stop and wait for review of that pilot"*
  ⇒ **是产品 skill 里写死的 review 环**。
- **⭐ 打回起的作用是切换工作模式，不是修具体的错**：13/14 `dimension_derived` + 11 次 crop_zoom
  这种形态，**返工两轮造不出来——它从第一笔就不同**。
  ⇒ 「杠杆不在那一两次纠偏上」；**回纠依赖「事后有人发现」，在没人看的那一轮自动失效（07-08 至今即是）**
  ⇒ **⛔ 回纠应退化成异常路径，不做主机制。**

### 1.2 ⭐ 本单出题时新查实的一条（**请把它当作核心病灶**）

gate① 里**已经有**一条检查在管「`dimension_derived` 的 stroke 必须真的引用得到尺寸标注」——
`src/validator/checks/reading.py:793 _dimension_derived_refs`。

**但它的第一行是**：

```python
if getattr(s, "provenance", None) != "dimension_derived":
    continue
```

**⇒ 读图器把 `provenance` 写成 `seen`，这条检查就整个跳过、落成 `NOT_APPLICABLE`。**

也就是说：**考生自己填的一个字符串，决定了这道题考不考。** 今天 Sonnet 那 10 条墙全写 `seen`
⇒ 引用检查零压力、零阻断。**这与批 B 正在修的 L-22「产品内容不得决定考卷」是同一个形状的病**，
只是那边是 `dimensions[]` 非空反推，这边是自评标签自动豁免。

**这是本项目第五次撞见同一族问题**（自评字段 `self_check.*` 零消费者 / CV 证据零接线 /
`access_log.jsonl` 零消费者 / 立面方向契约零校验 / **本条：自评标签控制检查是否运行**）。

## 2. 要解决的问题（**这是命题，不是方案**）

**P**：让「读图器没有真的去量」和「读图器把左右读反了」这两类错误，**在接口层面就无法被表达出来**，
而不是靠事后检查、事后打回、或再加一个更强的模型去盯着。

**附带要求**：这条路径**不应当需要任何 controller**（`reading-agent`）才能成立。
`reading-agent` 的存废由 R1.5 之后的**实测两抽**决定，**不由设计辩论决定**（用户 08-03 定）。

## 3. 必须回答的命题（**逐条给答案 + 反例检验**）

### Q1 · wire 形态

坐标载体应当长什么样？具体到：一条墙 stroke 的两个端点如何表达；引用的尺寸标注如何标识；
标定变换放在哪一层（per-view？per-chain？）；`estimated`（真的无标注可依）这条合法路径怎么留、
**又不让它变成绕过通道**。

### Q2 · 标定变换的来源与可验证性

px→m 的变换由谁产出、由谁验证？读图器声明两点 + 已知距离，还是代码从尺寸链拟合？
**跨轴一致性 / RMSE 门限**怎么定，超限时是 fail 还是 flag？
（已知数据点：08-01 的 d2 从预扫 `calibration_span_candidates` 得 36.4 / 36.375 px/m、跨轴一致 0.04 %，门限 0.30 %。）

### Q3 · ⭐ 「引用了这条标注」能不能被机器验真（**本单最重要的一问**）

读图器可以乱引 ID。**能不能用确定性代码验证「被引用的标注确实位于该锚点附近」以及
「该标注的数值与两锚点之间的像素距离一致」？**

这一问之所以承重：**sol 的架构审已用仓库里的反例证明「尺寸链闭合」证明不了「量对了」**
——`test_self_consistent_wrong_dimension_passes_linter` 的 docstring 自陈：
一条闭合的尺寸链**哪怕每个数字都与真实图纸不符**也不许阻断（`3+3+3+6=15` 即 pass）。
⇒ **如果 Q3 成立，它就把「自洽」升级成「与像素一致」，这是本方案真正的杀手锏；如果不成立，请明说，并说明剩下什么。**

### Q4 · 无标注区域

图上真的没有标注的位置怎么办（已在册：链算术 → prior 阶梯）。
**关键不是「怎么估」，而是「怎么让『估』无法冒充『量』」**，且**不因此把合法的估算路径堵死**。

### Q5 · 方向（吸收 sol 的 N-6 结论）

立面 x 方向已由用户拍板钉死 left-to-right、`local_x_positive` 降为废弃字段。
但 sol 已证明：**四条候选信号抓不住反向**（把所有 x 写成 `W−x` 可四项全绿），
且**「分数低」不是答案**——近似对称的立面反向后分数可能不低，GT 几何根本区分不了。
sol 也明确否掉了「只把字段改名叫『距左缘』」（模型照样能把距右缘的数填进去）。
**⇒ 请给出让反向在接口上表达不出来的具体形态，并自己找反例攻它。**

### Q6 · 迁移与冻结顺序

现存 ~90+ 份历史产物、gate① / 判卷层 / correction 全在消费公制坐标。
新旧如何共存？**哪些消费者必须改、哪些可以只读兼容？** 与 R3/R4 的接口冻结如何排序？
⚠️ **不得先跑新基线再补方向证据**（否则「方向错」与「画错」混成同一个低分，实验白跑）。

### Q7 · 剩下的真缺口

sol 的 P-1 反例：**工具找到了真墙、读图器 crop 看了、判成家具、老实写 `rejected`**。
测量强制解决「没去量」，**解决不了「量了但语义判错」**。
这块需要眼睛，但性质变了（**逐候选、有界**）。
**问：R1.5 要不要为它预留接缝？如果要，接缝长什么样？**
（orchestrator 现倾向的形态 = **「只看被点名 crop 的小复核」**，无指挥权、只对代码点名的候选说 yes/no，
**不是一个 Flash 档领导** —— 但这只是倾向，**请独立判断，也可以反对**。）

### Q8 · 复杂度可扩展性（不变量 #6，硬约束）

像素锚点 + 标定变换的方案，在 **非方形 / 退台 / 挑空双层高 / 中庭竖井**、
以及**同一 case 内多张图比例尺不同 / 局部详图**的情况下能不能长？
**⛔ 纯只适用当前情况（正交 · 共底面盒子）的方案没有意义。**
⚠️ 同时注意用户 08-03 定的分界：**确定性换算**（像素→公制、链闭合、标定 RMSE、跨图对齐）= 纯算术、
不含建筑学假设 ⇒ 随复杂度长得很好、该多投；**确定性判据**（什么算画完 / 这条墙合法）= 含建筑学假设
⇒ 复杂度上来会失效 ⇒ **必须带 profile + 明确适用域 + 允许弃权**。**你的方案落在哪一侧，请自己判定并说明。**

### Q9 · 这条路能不能少一个环节

如果测量强制成立，**`reading-agent`（子环节内部 controller）还需不需要存在**？
请给出「需要 / 不需要 / 由实测决定」的判断**及其判据形态**——
即：**跑完两抽之后，看到什么样的结果就应当把它撤掉、看到什么样就应当保留。**
