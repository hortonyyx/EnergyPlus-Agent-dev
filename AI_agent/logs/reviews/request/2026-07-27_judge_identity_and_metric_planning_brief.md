## 1. 立项由来（三轮实证，不是推测）

sm24 端到端验收跑开跑即撞死。三轮施工/对抗审后，硬阻塞已解除，但暴露出**同一病根的三张脸**：

| 轮次 | 活体反例（均为「上游校验器 GREEN、判卷器 RED」） |
|---|---|
| r1 审 | 真实 sm24：同一接缝 `8.059999999999999` 改写为 `8.06` ⇒ 判卷器报 `invalid_interior_edge_pair` |
| r1 审 | typed correction：一侧 `0.1+0.2`、另一侧字面 `0.3` ⇒ 同上 |
| r2 审 | 量化对齐后**恰落在格边界**：`8.0600000000005` 与 `8.060000000001 - 5e-13`（相差 1 ulp）⇒ 分别落入不同量子格 ⇒ 同上 |
| r2 审 | **近正交外墙边**走 exact-reverse 退化路径时的同型假红（另一条通路） |

**审阅方结论（已复核采纳）**：单纯改量子大小、或把最近格量化换成 Decimal round，**只会移动边界而不消灭它**。

**病根表述**：判卷器要求「坐标完全相同」才认作同一几何，而上游校验器用**带容差**的判据（例如 `correction/cell_geometry.py:_EPS = 1e-9` 放行近正交边；GT 侧 `_ring_vertices` 用精确 `dx != 0 and dy != 0`，两侧口径本身也不一致）。**「上游宽松放行、判卷器精确硬拒」不可并存**。

## 2. 并案的第二半：计分度量（原 Y-2）

同一轮还证伪了主控此前的分母裁定（已收回）：

- 同一道 4m 墙**整条画漏**：切分前计 `1/1`、切分后计 `4/4` ⇒ **邻接房间越多的墙权重越高**；
- 产品若把走廊墙**正确画成一整条**，一对一匹配判 `score_match_ambiguous`（`candidate_assignments=4`）⇒ **画对了反被罚**。

**两半必须一起定**：身份（什么算同一样东西）与度量（怎么算分）耦合——分段规则改变会同时改变身份判定与分母。

## 4. 必须回答的问题

**Q1 · 数值身份合同**：判卷器认定「同一坐标」的唯一判据是什么？在哪一层建立（输入合同 / 信任边界规范化 / 上游产出端）？如何**证明**同一十进制几何的任意合法浮点写法必然共享身份，且 `1e-9` 真缺口不被吞掉？边界/歧义情形如何处置（拒绝？报错码？）？

**Q2 · 上下游口径统一**：上游校验器的容差判据与判卷器的精确判据如何对齐？是收紧上游、放宽下游、还是引入中间规范化层？谁是权威？（注意：上游是**生产路径**，判卷器是 dev 期评测路径，两者的约束不对称。）

**Q3 · 分母单位**：按「邻接界面 / 物理墙 / 长度」哪一种计分？给出该选择下「同一道墙整条画漏」「画对但分段不同」「画对一半」三种情形的具体得分，证明无权重失真、无重复计罚。

**Q4 · 分段不一致的匹配规则**：target 与 observation 分段不同时，是先按**联合切点**把双方规范化后再一对一匹配，还是允许一对多覆盖匹配？给出对 `score_match_ambiguous` 的影响。

**Q5 · 迁移与兼容**：已落地的 T 切分实现（`_tile_orthogonal_edges` / `_pair_general_edges` / `_canonical_coord`）哪些留、哪些改、哪些删？已签字的 sm24 答案怎么处置（约束 5）？
