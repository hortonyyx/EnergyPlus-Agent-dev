## 2. 清单外自主发现（与 §1 同等重要）

请特别留意本项目的历史病灶形状：

- **「门是真的、锁是缺的」**：机制正确但无任何测试绑住它；
- **「探针 ≠ 锁」**：一次性验证通过的探针不具备回归效力；
- **「非 None ≠ 成功」**：断言落在返回值存在性上 = 等于没断言；
- **「有信号、没消费者」**：今天已第四次撞见（自评字段 / CV 证据 / access_log / 立面方向约定）；
- **「边界写窄就被实现得同样窄」**：设计稿把语义定了、接口形状留给施工方猜，本项目因此连续三轮 REWORK；
- **「为当前 case 烤死假设」**：违反项目不变量 #6（方案必须能长到非方形 / 退台 / 挑空 / 中庭）。

## 3. ⭐ 追加命题 N-6（问题书当时漏问，本轮补）

### 事实

- 项目规范现已（在 R1 批 A 中）**钉死立面读图方向**：一律以图像左缘为 `x=0`、向右为正；
  读图器不再声明方向（原 `local_x_positive` 字段降级为「历史可加载、判卷永不读取」的废弃审计字段）。
- **但 gate① 对立面 x 方向零校验** —— 现有 `src/validator/checks/reading.py:597-610` 的
  `reading.facade_fields` 只检查 `view_facade` 字段是否存在。
- ⇒ **「契约钉死方向」≠「约束住了读图器真的按那个方向读」。这是两件事。**
  本项目第四次撞见同一形状：**规范写了、没有机器验证。**

### orchestrator 已试过并**废弃**的一条判据（**不要重复这条弯路**）

判据：「产物的窗区间应对齐它自己转录的尺寸链累积位置」（考生侧自洽，不需要 GT）。
**已被真实数据证伪**：`run_2026-07-27_haiku_e2e` North，
链累积 = `[0, 0.54, 5.34, 7.86, 9.46, 10]`；
产物 `S3=[0.54,4.66]`（**宽度量错**，真值 `[0.54,5.34]`）命中链上端点 1/2，
**镜像后 `[5.34,9.46]` 命中 2/2**；`S4` 原样 1/2、镜像 1/2
⇒ 合计**原样 2/4 vs 镜像 3/4 ⇒ 该判据会判「镜像」= 判错**。
**机制**：一个量错宽度的产物，恰好在镜像下看起来更整齐。
