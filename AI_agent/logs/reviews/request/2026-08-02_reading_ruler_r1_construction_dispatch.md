## 2. ⭐ 批 A 的前置：right-to-left 全语料调查（**先做这个，做完停下上报**）

**这是本单最重要的一条裁定。** sol 的 S-1 有两条互斥出路：

- **出路甲**：reviewed binding 增加 hash-bound 的 canonical local domain / facade span，
  right-to-left 产品先做 `x_canonical = L − x_product` 再投影 ⇒ **支持双参数化**；
- **出路乙**：发新 schema 版本规定几何恒用 left-to-right canonical x，
  并对所有旧的合法 right-to-left 产品做**显式迁移**。

**选哪条取决于一个事实：历史产物里声明 right-to-left 的，其数值到底有没有真的跟着反射？**
还是只是 metadata 填错？**这个事实现在没人知道，且不许猜。**

### 交付（Slice 0，只读，不改任何代码）

只读扫描仓库全部 reading artifacts，对每个立面观测收集：
`facade span` · `local_x_positive` 声明 · `mirrored` 声明 · window interval 数值 ·

① 全语料里 right-to-left 声明共几处、分布在哪些 run；
② 其中数值**真的反射**的有几处、**没反射**（= 只是填错 metadata）的有几处；
③ **据此建议走甲还是乙**，并给理由。

**⇒ 做完 Slice 0 停下上报，等 orchestrator 裁定走哪条，再开工 S-1。**

- **⚠️ 施工方必须自己跑 neuter 自查表**并如实交付（诚实披露不伪造 —— 本项目有正面样板也有反面教训）。
  orchestrator 轻门会**独立复跑**每一条。
- **交付前跑一次全仓**（当前基线 **2051 绿 + 10 strict xfail · 零红**）。
  ⚠️ 上一轮有一条真缺陷是**只在全仓才抓得到**，施工方因被 git 锁卡在交付前那一步而漏掉。
- **orchestrator 轻门 = 独立全量 + 亲核 diff + 独立复跑 neuter**，是唯一权威门。

## 5. 交付纪律

- 每个 Slice 边界提交 + 写执行日志（`logs/reviews/execution/`）。
- 「我当时的意思是……」**不是可接受的交付说明**。
- 自查表要区分「锁绿」与「锁真绑」—— 前者不算数。
- 遇 orchestrator 派工单前提有误，**停下上报**（这是既定的正面样板行为，不扣分）。
