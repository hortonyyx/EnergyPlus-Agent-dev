# Review: run_pipeline inline S1/S4 self-check proposal

Verdict: **APPROVE-WITH-CHANGES**.

The direction is correct: production `intake_node -> run_pipeline` currently has only A8 evidence-debt coverage, S23-16 kernel reporting, and the S5 construction-name backstop, while `validate_case` runs full S1 and S4 reports. However, the proposal has several factual overstatements and a few under-specified choices that would create avoidable regressions, especially around A8 semantics, `relied_on_testdata`, and any attempt to fold the kernel gate into a generic helper.

## Factual Verification

- Current `run_pipeline` facts are mostly accurate. The A8 standalone coverage gate is at `src/agent/pipeline.py:803-824`; deterministic core artifact writes are at `src/agent/pipeline.py:843-858`; kernel check/write/strict InterZone raise is at `src/agent/pipeline.py:880-895`; stage-5 `validate_contract` is at `src/agent/pipeline.py:928-938`.
- `validate_case` does call `check_correction` at `src/agent/execution/validation_run.py:154-160` and writes `1_correction/correction_checks.json` at `src/agent/execution/validation_run.py:161-163`. It calls `check_mep` at `src/agent/execution/validation_run.py:219-221` and writes `4_mep/mep_checks.json` at `src/agent/execution/validation_run.py:222-224`.
- `check_correction` does subsume evidence-debt coverage in the sense that it calls `_evidence_debt_coverage(...)` at `src/validator/checks/correction.py:86-89`. But the evidence-debt result is a `CROSS_CHECK`, not a normal invariant: `src/validator/checks/correction.py:278-289`; it blocks only for element-local debt in golden/regression by the special policy rule at `src/validator/checks/schema.py:130-136`.
- `check_mep` really has no `run_profile` parameter: `src/validator/checks/mep.py:78-86`. Its report therefore defaults to `run_profile="exploratory"` via `CheckReport`: `src/validator/checks/mep.py:87`, `src/validator/checks/schema.py:153-155`.
- `intake_node` does not pass `run_profile`, so production uses `run_pipeline`'s default `run_profile="exploratory"`: `src/agent/nodes/intake.py:64-66`, `src/agent/pipeline.py:735-742`.
- Disposition policy is as described for the schema: `ERROR` and `INVARIANT` failures map to `BLOCK` for every profile, while evidence checks are profile-gated to golden/regression: `src/validator/checks/schema.py:125-145`; `CheckReport.blocking()` uses the report's own `run_profile`: `src/validator/checks/schema.py:192-211`.
- The proposal overstates stepwise parity. `run_stage.py` does call S1 `check_correction` with policy/profile/evidence data at `scripts/tool_scripts/run_stage.py:171-175`, but its S4 `_draw_mep` call does **not** pass parsed testdata or capability profile: `scripts/tool_scripts/run_stage.py:245-253`. Therefore the newer `mep.site_matches_testdata` check is `NOT_APPLICABLE` in stepwise even when `validate_case` would compare testdata.
- The proposal also overstates "baseline recording goes golden" if read literally. `record_baseline` defaults `run_profile="exploratory"` and the CLI default is exploratory: `scripts/tool_scripts/record_baseline.py:292-308`, `scripts/tool_scripts/record_baseline.py:670-674`. It does use `validate_case`, but not golden unless the caller passes it.

## Required Changes Before Implementation

1. **Do not let `relied_on_testdata=bool(testdata_text.strip())` silently break strict-profile kernel tests.** With `raw_geom=None` and `testdata_text="{}"`, `check_correction` emits blocking `correction.audit_completeness` if the geometry has no corrections/conflicts: `src/validator/checks/correction.py:161-204`. Existing `tests/test_a8_evidence_routing.py::test_run_pipeline_fail_closed_for_kernel_pairing_gate_profiles` passes `"{}"` and monkeypatches `run_correction` to return `_minimal_geom()` with no audit rows: `tests/test_a8_evidence_routing.py:26-43`, `tests/test_a8_evidence_routing.py:374-390`. The proposed S1 gate would raise before the kernel gate and fail the test's expected error path.
2. **Do not fold the kernel report into a generic `report.blocking()` gate in this patch.** Current `run_pipeline` only fail-closes on `kernel_issues` in golden/regression: `src/agent/pipeline.py:891-895`. `check_kernel` also emits other invariant blocks such as `kernel.zone_closure`, `kernel.normals`, `kernel.spec_self_consistency`, and `kernel.coverage_completeness`: `src/validator/checks/kernel.py:70-75`, `src/validator/checks/kernel.py:93-277`. A generic `_gate(... report.blocking() ...)` would tighten kernel behavior beyond S23-16.
3. **Preserve A8's pre-core semantics unless the weakening is explicitly accepted and tested.** Replacing `pipeline.py:803-824` with post-core `check_correction` can only add deterministic-core audit rows before evidence coverage is evaluated. That can turn "LLM failed to cover reading debt" into a pass if a later core correction row happens to mention the debt. I recommend keeping the existing pre-core `evidence_debt_coverage_checks.json` sidecar and strict-profile gate for now, then also writing post-core `correction_checks.json` for validate_case parity. If the sidecar is intentionally retired, add a regression test proving the accepted semantic change.
4. **Add `capability_profile: str = "rectangular"` to `run_pipeline` and thread it through.** `run_correction`, evidence preflight, `check_correction`, `check_kernel`, and `check_mep` already accept or default this concept: `src/agent/pipeline.py:509-520`, `src/agent/execution/evidence_preflight.py:168-195`, `src/validator/checks/correction.py:66-76`, `src/validator/checks/kernel.py:58-64`, `src/validator/checks/mep.py:78-86`. Hard-coding `"rectangular"` inside `run_pipeline` would make the new inline reports less reusable than `validate_case(policy.capability_profile)`.
5. **Use exact artifact filenames, not a naive `<stage>_checks.json` derivation.** The intended names are `correction_checks.json`, `kernel_checks.json`, and `mep_checks.json`, not `1_correction_checks.json` or `4_mep_checks.json`: `src/agent/execution/validation_run.py:163`, `src/agent/execution/validation_run.py:224`.

## R1-R9 Rulings

**R1 raw_geom:** Pass `raw_geom=None` if the stated goal is report parity with `validate_case`, because `validate_case` has only snapped geometry and passes no raw geometry: `src/agent/execution/validation_run.py:151-160`. Passing pre-core geometry is a stricter audit and may be useful later, but it would deliberately make `run_pipeline`'s `correction_checks.json` non-identical to `validate_case` for the same run.

**R2 A8 standalone coverage:** Do not delete the pre-core A8 sidecar/gate in the first implementation. Keep `evidence_debt_coverage_checks.json` as a compatibility and semantic-preservation sidecar, and add full post-core `correction_checks.json` separately. Current visible tests do not assert the sidecar filename (`rg` only finds function-level A8 tests and no `evidence_debt_coverage_checks` assertion under `tests/`), but the pre-core->post-core semantic weakening is real. The visible strict-profile test that will break first is not a sidecar assertion; it is `test_run_pipeline_fail_closed_for_kernel_pairing_gate_profiles` because S1 audit would preempt the expected kernel raise.

**R3 MepOutput vs dict:** `parse_mep_fragments` itself is equivalent for object and dict inputs because `bundle_mep_text` reads either dict keys or attributes for the same six fragment fields: `src/validator/idf_fragments.py:108-129`. The surrounding structured checks also support both through `_get_value`: `src/validator/checks/mep.py:165-180`, `src/validator/checks/mep.py:310-317`. Still, pass `json.loads(mep.model_dump_json())` or `mep.model_dump(mode="json")` if exact parity with the persisted `mep_output.json`/`validate_case` path is the priority.

**R4 testdata parsing:** Add one helper that returns `dict | None` from `testdata_text`: blank, invalid JSON, and non-object JSON should return `None`; valid object JSON, including `{}`, should return a dict. Pass that value to `check_mep(testdata=...)`. For expected zones, share the same parsed dict and return `None` when no integer `Floor plans[].thermal_zones` values exist. Do not use `{}` as the invalid/blank fallback if byte-for-byte-ish report parity matters, because `_extract_testdata_site(None)` and `_extract_testdata_site({})` produce different evidence: `src/validator/checks/mep.py:270-307`.

**R5 expected_zone_total helper:** Yes, extract a shared pure helper that accepts a parsed dict. `validation_run._expected_zone_total(case_dir)` and `run_stage._expected_zone_total(testdata_path)` currently duplicate the same `"Floor plans" -> thermal_zones sum` logic: `src/agent/execution/validation_run.py:49-60`, `scripts/tool_scripts/run_stage.py:73-82`. The new `run_pipeline` helper should not create a third copy.

**R6 `_gate` and kernel:** Add a small helper only if it is filename-explicit and profile-explicit. Use it for new correction/mep reports if desired. Do **not** move kernel into it unless the helper has a kernel-specific mode that preserves today's "only InterZone issues raise in strict profiles" behavior. A generic `report.blocking()` kernel raise would be a behavior change.

**R7 exploratory invariant failures:** Accept "visible but continue" for this patch. It is consistent with the current kernel inline behavior: exploratory can produce a report whose `blocking()` is non-empty and still continue, as tested at `tests/test_a8_evidence_routing.py:336-370`. The helper must log a warning containing the check ids and write the report before continuing. Do not add selective all-profile raises for S1/S4 in this patch; if MEP parse errors or schedule incompleteness should become hard production stops, that is a separate policy tightening. Keep the existing all-profile `validate_contract` raise unchanged: `src/agent/pipeline.py:928-938`.

**R8 existing strict-profile `run_pipeline` tests:** Visible tests with `run_profile in {"golden", "regression"}` are:
- `tests/test_a8_evidence_routing.py::test_run_pipeline_fail_closed_for_regression_evidence_debt` at `tests/test_a8_evidence_routing.py:278-303`. This already raises in the preflight before the proposed new gates; no new raise path is expected.
- `tests/test_a8_evidence_routing.py::test_run_pipeline_fail_closed_for_kernel_pairing_gate_profiles` at `tests/test_a8_evidence_routing.py:374-390`. This will get a new earlier S1 `correction.audit_completeness` raise if implementation uses `relied_on_testdata=bool(testdata_text.strip())` with the existing `_minimal_geom()` fixture. Either update the fixture to include a sourced correction, change the reliance heuristic with an explicit rationale, or update the test to assert the new earlier S1 gate.

**R9 capability_profile:** Add `capability_profile="rectangular"` as a `run_pipeline` keyword and thread it into `compute_evidence_debt_from_vector_dir`, `run_correction`, `check_correction`, `check_kernel`, and `check_mep`. `intake_node` can keep omitting it and therefore retain rectangular/default behavior. This is better than a hidden constant because `RunPolicy` already treats `run_profile` and `capability_profile` as peer policy knobs: `src/agent/execution/policy.py:37-45`.

## Additional Risks Missed

- `check_mep` is stricter than `validate_contract`, not merely a duplicate construction-name check. `validate_contract` uses a raw whole-token regex over `construction_specs`: `src/agent/intakeoutput.py:60-83`. `check_mep` requires parseable IDF objects and a real `CONSTRUCTION` object index before construction coverage can pass: `src/validator/checks/mep.py:88-99`, `src/validator/checks/mep.py:337-352`. In exploratory this will surface warnings; in strict profiles it can fail earlier than S5.
- `mep_checks.json` will say `run_profile="exploratory"` even when `run_pipeline(run_profile="golden")` raises on it, because `check_mep` has no `run_profile` parameter. That matches `validate_case` today, but the error message must include the external `run_profile` to avoid confusing operators.
- If `evidence_debt_coverage_checks.json` is retired, reused `out_dir`s can retain a stale old sidecar. Either keep writing it or intentionally unlink the stale file when writing the new canonical report.
- Full S1 is proposed after deterministic core. If `apply_deterministic_core` itself raises before the S1 report is written, there will still be no `correction_checks.json` for that failure. That may be acceptable, but it should be acknowledged.
- Imports should remain lazy at the insertion points. `check_mep` pulls in the IDF parser/eppy path via `src.validator.idf_fragments`; keep it after `run_mep` and do not add module-top imports to `pipeline.py`.

## Final Recommendation

Approve the initiative, but implement it as a scoped wiring change with the required fixes above: post-core `correction_checks.json`, post-MEP `mep_checks.json`, profile-gated strict raises for the new reports, no kernel behavior change, explicit `capability_profile`, shared testdata helpers, and preserved A8 pre-core coverage semantics unless a separate test-backed decision retires them.
