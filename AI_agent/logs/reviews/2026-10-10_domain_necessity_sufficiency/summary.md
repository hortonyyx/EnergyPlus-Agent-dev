# domain 独立审阅：还原建模的充分性与必要性

审阅日期：2026-10-10。基准：`b45a9db7565dca304fced570ba06c1927bd44b76`，domain v57 / runtime v2。

**结论：存在明显的局部过重和重复，但没有证据支持整体推倒重写。必要的建模能力大多已存在；当前组织方式却还不足以让目标档 work model 稳定、低负担地完成还原。最需要收缩的是读图员承担的完整声明维护、跨角色指引和过细门槛，最需要补齐的是首稿前的可保存状态与失败后的局部修订。**

这是一次独立审阅，不是新开发包或实测批准。三名空白上下文 GPT 侧审阅者分别核查必要能力、模型接口、历史证据，之后由项目经理核对源码与反例。并非跨模型家族或双盲评审；项目经理参与过前一版实现。未改生产代码、未启动 work model 实测、未调用产品模型 API 或 MCP 建模流程。仅保存审阅文档与可重复的离线诊断。网页版见 [index.html](index.html)。

## 1. 判定标准

用户当前目标是资料基本齐全时，把建筑空间及关系还原为准确、可查看、可修改的 Lite BIM。允许明确标注和真实细尺寸规整到 10 cm。评审将三个问题分开：

1. **能力必要性**：删除后是否会丢空间、误拆误并、错挂门窗、改连通或无法形成可用源 BIM？
2. **机制必要性**：即使能力必要，是否必须由模型填写这些字段、读取这些文字、逐项确认或完整重写？
3. **充分性**：分别判断“给对声明能否建成”“目标档是否能稳定从图纸走到交付”“能否覆盖一般还原场景”。单测或一次成功不能同时证明三者。

来源：[产品目标](../../../project/goal.md)、[名词规范](../../../project/terminology.md)、[独立审查约定](../../../workflow/development.md)。源空间与后端热区分开，GT 留在评价侧；精细用途、EP 跑通、毫米级还原不作为当前源 BIM 交付前置。

| 必要能力 | 当前判断 | 处置 |
|---|---|---|
| 原图身份、单位、坐标与尺度依据 | 必要，已有 | 保留；确定性换算由代码承担 |
| 房间、物理隔墙、门窗身份与宿主/连通 | 必要；声明表达和编译已有，识读保真仍依赖模型 | 保留，不能用网格规整代替对象识别 |
| 一份可修改的工作声明与唯一源 BIM | 必要；成功后较完整，失败前有断层 | 扩展现有声明生命周期，避免另建平行状态体系 |
| 几何编译、规整、拓扑与宿主检查 | 必要；部分规整前置门槛过严 | 保留不变量，合并变换与容差语义 |
| 楼层装配、平立面对位、缺漏/冲突反馈 | 必要，已有真实成功与抓错证据 | 保留一步建楼，局部反馈与局部返工 |
| 依据、版本绑定、回叠与诚实交付状态 | 必要，已有 | 保留服务端记录，模型读取摘要与当前问题 |
| 全量用途目录/颜色、旧单模型操作说明、整份重复抄写 | 不是当前每次读图的必要负担 | 按角色投影、按需读取、由代码合并 |
| 一般内环空间、复杂跨层空间 | 一般还原的能力边界仍在 | 明确范围，不当作 sm25 本轮扩功能前置 |

## 3. 主要发现

优先级：P1 表示当前目标的重大阻塞或接口缺口；P2 表示可以收缩的负担或一般能力边界。证据强度与改动收益分别判断。

### R1 · P1：可修改状态开始得太晚，首稿前又缺少持久阶段产物

**高信心确认设计缺口；目标档提速收益仍需验证。** 当前指引要求同一次盘点完整外轮廓、隔墙、房间、门窗及全部可读尺寸链，再交完整平面。第六次观察后的早稿提醒已有，但不是可保存的对象清单、标定或部分建模声明。模型只能先在上下文里维持整层理解。

完整声明已经保存时，格式/规整前处理失败仍可能使现有局部修改不可用：`PlanTrial.baseline()` 选择成功稿或有 `compiled_numeric_plan_sha256` 的失败稿；原始声明和哈希虽落盘，没有 numeric identity 就不能作为这一类基稿。跨任务失败继承重复施加同一条件。**“不能交付”被过早等同为“不能局部编辑”。**

实证：v57 F1 五次均发送完整声明，每份 10 条尺寸链、68 个分段，均未形成 numeric identity；F2 50 次观察、零 trial。不能断言这解释了全部耗时，但可以确认现有接口未接住这些中间工作。

另有契约错位：工具 schema 仅把 `plan` 暴露为普通 object，真正严格的 15 个顶层字段、11 个必需字段及嵌套格式在另一处校验。首稿误加 `direction/origin_m` 是已发生的例子。把所有内部审计 schema 一股脑加入提示也不合理；应从现有权威格式派生精简模型接口，避免示例、说明和验证规则分别维护。

建议：在现有 trial/receipt/operations 上允许原始声明及阶段读数保存、命名、局部修订；不完整或校验失败状态明确不可提交。原图、版本、对象身份和未改部分继续受保护。新增模型角色或固定长流程不是该缺口的必要解法。

源码：`guidance.py:24–57`、`readers.py:476–494,618`、`plan_format.py:73–102`、`trial.py:806–825,947–1008`、`session.py:270–325`（均在 `src/agent/runtime_roles/`）。反证：通过后局改、已解析失败稿恢复和跨任务保护已存在；`tests/test_role_trial.py:95`、`test_role_review_regressions.py:163` 分别体现现有边界。

### R2 · P1：规整门槛没有完整服从 Lite BIM 的精度目标

**高信心，有当前代码的独立离线反例。** 保持拓扑的目标必要，但部分“先精确再规整”的机械门槛没有必要。

| 诊断输入 | 当前结果 | 为什么与减负目标有冲突 |
|---|---|---|
| 10 m 方形内，一道应近似竖直的隔墙 x 从 4.00 m 到 4.02 m；两端按 0.1 m 采用值都为 4.0 m | 在 `before_grid_compile` 以非正交拒绝；仅改端点为完全竖直即通过且拓扑保持 | 程序尚未有机会规整，模型先被要求消除厘米级斜差 |
| 两条整图尺寸链都标 10000 mm；一条端点像素 100/1100，另一条 105/1095；每端差 5 cm | 两条采用刻度均为 0/10 m、世界端点差 0，仍因原始像素比例差 1.0101% 超过固定 1% 门槛拒绝 | 数值一致的新证据反而阻断试建；近似读点仍按独立精细比例审核 |

第二例还显示固定跨链世界坐标门槛为 1 mm。不能把它单独视为所有失败的原因；本例实际触发的是 1% 比例门槛。调用端把任何尺寸链 rejection 升为 Lite 路径的整次失败。

建议：同一物理轴/接头已确认且移动有界时，将近轴整理、尺寸链联动、共享网格作为完整几何事务；先区分读点误差和真实标注冲突，再按采用精度判断。真正斜墙、歧义宿主、两门并一门、拓扑改变仍需拒绝或交模型判断。**不建议删除拓扑保护，也不建议简单调换现有 Q1 顺序。** v57 trial003 的既有离线诊断已证明单纯前移 Q1 无效。

源码：`src/agent/geometry/lite_bim_regularization.py:101–104,148–158`、`plan_regularization.py:1960–1964`、`plan_partition.py:107–117`、`plan_dimension_alignment.py:422–451`；调用处 `src/agent/runtime_roles/trial.py:150–156,217–219`。

可重跑 [reproduce.py](reproduce.py)，输出 [reproduction.json](reproduction.json)。这些是诊断当前限制的反例，不是修改后的通过测试，不证明所有近轴线都该自动拉直。

### R3 · P2：工具按角色隔离了，参考资料仍混用旧操作方法

**高信心确认接口冲突；未证明是本次 sm25 失败原因。** 读图员可调用通用 `get_bim_reference`，13 个主题仍原样来自全局参考。角色只允许一张图，`reconstruction` 却教看全套、`claim_transaction`、`assemble_plan_bim`；`plan_partition` 又教 `inspect_plan_draft`、`revise_plan_bim` 及手传 hash。这些不是读图员当前工具目录和 `trial_plan_bim(operations=...)` 的用法。

10-10 East 确实取过 `facade_correspondence`，该主题要求平立面比较，超过单图职责；但 East 成功，不能反向编造其失败。缺陷在契约本身，与本轮因果归属分开。

建议：共享建筑事实与格式定义保留一份，操作说明按角色生成；隐藏当前角色不可用主题和旧操作法。不是再添加一层“请忽略旧说明”。

源码：`scripts/tool_scripts/run_bim_agent.py:2235–2243`、`bim_agent_guidance.py:66,95–102,438–442`；`src/agent/runtime_roles/readers.py:446–469,606–615`、`guidance.py:13–16`。事件证据为本轮冻结 run 的 root `event-000083`。

### R4 · P2：常驻用途细表与立面整份重抄，是可以明确移交代码的工作

**高信心确认冗余工作；提速幅度未实测。** 平面指引无条件带入 62 类房间用途、颜色、目录来源，共 2,947 字符，占系统指引 33.3%。合理用途本身必要，但全部分类和颜色不必在每次几何决策里常驻。图像与历史消息仍可能是更大的上下文来源，不能据三分之一这个比例解释全部耗时。

立面返工已有未指向对象保护和原始/采用值审计，却仍需模型重发完整 `elevations/openings/counts/calibration/unresolved`。只改一扇窗的窗顶，模型也要抄回其他窗与标定；这些完整数据服务端已经保存。

建议：用途目录按需取、颜色确定性映射；立面修订复用 ID/字段级变化，由代码合并成完整产物后走现有校验。保留语义选择、依据和范围保护，不把用途换成无限制字符串，也不重复建设已经存在的上下文投影。

源码：`src/agent/runtime_roles/guidance.py:85`、`src/agent/roles.py:40–53`、`plan_format.py:158–162`；`submission.py:64–81`、`elevation.py:111–244,369–372`、`reader_context.py:43–87`（后五者在 `src/agent/runtime_roles/`）。

### R5 · P2：自报对象的覆盖检查，尚不能保证原图对象完整还原

**高信心；属于充分性边界，不是指控代码冒充质量验收。** 覆盖目标来自读图员自己声明的 partitions/openings/seeds，自动依据框又从同一组坐标生成。因此，一堵未被读图员声明的隔墙，不会自动成为这份覆盖清单里的漏项。代码可以证明已声明对象可追溯、几何自洽，但不能据此证明原图没有漏房间或漏门。

这与当前实现的诚实边界一致：源 BIM 明确列出图纸分区保真、未观察开口、挑空/假楼板尚未评价。现有平立面对位、回叠与模型复看能帮助发现问题，但目标档自主闭环的可靠性还没成立。

建议：围绕原图的空间与开口库存核对实际覆盖效果，尤其检查内部漏墙、两门并一门；可由现有读图员/调度员使用阶段产物和回叠完成，不预设必须增加核对员角色。不要用更多哈希、字段确认或由同一声明生成的另一张表代替图纸判断。

源码：`src/agent/runtime_roles/readers.py:201–256`、`submission.py:294–303`；`src/agent/geometry/source_bim.py:343–347`、`src/agent/runtime_roles/session.py:424–429`。

### R6 · P2：一般还原的表达能力仍有边界，不能把三例成功称为通用充分

**高信心；不是 sm25 当前已证阻塞。** 默认平面编译拒绝带内环的单个空间，例如核心筒四周连续的一圈开放办公。`Cell.polygon` 与 `SourceSpace.polygon` 是单外环，生成也仅取外环；不能靠人为加墙把空间切开来伪装支持。离线最小例已复现。

跨层挑空需要另外区分：源 BIM 有 `spanning_space_ids` 能力，但默认逐层 plan 装配明确不接受，因此是路径接线限制，不能笼统说整个 kernel 完全不支持跨层空间。

建议：当前先把 sm25 及明确的正交、逐层场景做好。若声称一般还原能力，需单列上述受支持范围与拒绝原因，再用代表性案例推进；不把“补全通用 BIM”混进本次减负包。

源码：`src/agent/geometry/plan_partition.py:328–346`、`src/agent/correction/schema.py:208,233–239`、`src/agent/geometry/source_model.py:28–32,51–78`、`source_bim.py:183–194`、`plan_assembly.py:127–128`。单个边界面的洞口 region 不等于空间平面内环。

## 4. 哪些“看起来复杂”的东西应当保留

- **拓扑签名、硬政策、编译后网格检查不是同一检查重复三遍。** 分别防止关系改变、违反产品政策、名义规整但实际源几何未落网格。0.30 m 对齐、0.60 m 空间宽度有用户既有授权，不能为了瘦身擅自删除；可把数值政策集中定义。
- **装配复核不是单层校验的副本。** 它核对最终整楼与 accepted 单层的关系，发现漏层、意外变化和错误产物血缘。平立面对位曾实际发现遗漏外门。
- **多份 JSON 不自动等于多个事实源。** raw、未对齐 numeric、对齐 numeric、实际 Toolkit 编译 numeric 是阶段快照；提交处核验成功 trial、内容和哈希。未发现足以支持“任意多主写入”的证据。应减少重复组装/投影与报告同步负担，不能覆盖原始读数来省文件。
- **回叠、原图依据与独立质量判断不可用纯编译通过替代。** 一份自洽但漏门、把两门看成一门的 BIM 仍然错误；更多几何检查不能凭空恢复被漏读的对象。
- **0.30/0.60 m 是当前产品简化政策，不是所有建筑空间的自然合法性定义。** 真正的窄管井或小退进可能被这套政策拒绝。该范围有用户既有决定，属于以后按对象/细度明确政策的讨论项；本次不擅自放宽，也不把这些阈值说成普遍工程标准。
- **测试数量本身不证明无效。** 上轮 5,969 通过、12 失败主要是新审计契约后的旧夹具；约 46.5 分钟全量已超过项目约 30 分钟方向。纯指引措辞锁有维护债务，例如 `tests/test_role_plan_revisions.py:31–34`，应合并为少量契约检查；同测试中示例能否真正编译的断言仍必要。

依据：`lite_bim_regularization.py:148–158`、`assembly_review.py:540–581`、`submission.py:224–242,290–313`、`trial.py:645–741`；政策见 [决策](../../../project/decisions.md)。测试修复提交 `3484cae5`，代表夹具 `tests/test_role_height_evidence.py:15–32`。这些结论均区分生产行为、模型所见信息和开发维护成本。

v57 的超时缺 usage 后永久费用停止、运行中不能追加消息属于 runtime 边界；历史并发拒绝属于线路/runtime。它们确实阻断任务，但不应记作 domain 冗余。费用恢复应单独讨论，不能靠删建筑检查绕过。

历史存在指引执行与首稿变晚的关联，但没有能隔离全部因素的消融实验。本次不会给“臃肿导致多少分钟/多少费用”的虚假定量归因。

## 6. 删、并、简化与下一步

建议先做一个有边界的 domain 收缩包，范围为 **tools / methods / roles / guidance 与相连的 kernel 规整边界**。runtime 费用恢复单列；单模型冻结参照不顺带改造。

| 动作 | 具体对象 | 保留的必要保障 |
|---|---|---|
| 从角色按需参考删除或改写 | 不可用旧工具说明、跨角色操作法 | 一份共享建筑事实与格式源；角色按需参考 |
| 从默认指引移出 | 常驻颜色/完整用途目录 | 常用用途选择原则、按需完整目录与代码映射 |
| 合并 | 首稿/原始失败声明/可修订声明的身份和修改入口；立面返工并入既有 ID 局改原则 | 未通过不提交、哈希/原图绑定、未指向对象保持 |
| 合并 | 近轴接头、尺寸链及网格的关联节点处理与容差政策 | 不改对象身份、宿主、房间划分或连接；真实冲突可解释 |
| 简化 | 模型手抄字段、完整重发、审计正文；schema 与说明重复维护 | 服务端保存完整依据与采用值，模型收变更和问题摘要 |
| 合并少量测试 | 逐字文案断言 | 示例编译、状态转移、真实反例和拓扑不变量测试 |
| 暂缓 | 新核对角色、更多提醒、新固定总流程、专用 OCR/自动选步长、通用 BIM 扩展 | 先检验现有 0.1 m 和少数角色能否兑现用户目标 |

离线先验证：保存的五份 F1 raw 声明可以逐次局改且未改对象保持；本报告两个规整反例可合理处理，同时真实斜墙、错宿主、冲突尺寸、删门、错哈希仍不能静默通过；当前成功稿装配/拓扑/依据保持；角色参考只出现本角色可用操作。不要只验证“字数少了”。

之后另定有界目标档实测方案，沿用 sm25，记录首份持久阶段产物、首稿时刻、整份重发量、局改成功、空间/门窗/连接质量、总时长与用量。**改动的最终判据是模型少做机械维护，同时完成正确 BIM；不是文件更少或测试更多。** 当前报告不包含实施授权或新实测结果。
