# 单模型交付标准与检查流程

用户批准先实施，再按上次的模型/预算跑一次 Go Haiku 5.5 整案。平立面回叠是读图阶段的主要正确性检查；交付后的整楼检查集中于建筑合理性。当前由同一模型承担全部职责，Haiku 调度 27B 的分工试验尚未开展。

## 主流程与交付物

| 环节 | 实际职责 | 形成的结果 |
|---|---|---|
| 输入、整套理解与标定 | 核对原件、所有楼层、朝向、公共原点和绝对标高 | 输入清单、运行记录、标定与待确认项 |
| 平面读图和局部检查 | 逐层试建；查看保存后的实际源回叠，修正空间、墙、开口与宿主 | 草稿/候选、标定、回叠、按图/楼层的检查结论 |
| 立面读图和局部检查 | 独立读取完整开口与标高；核对采用宽度和绝对高度的回叠 | 原提交、采用值、标高/开口清单、采用值回叠、局部结论 |
| 整楼装配和跨图协调 | 合并各层、检查层间关系、匹配平立面同一开口，批量应用安全高度 | 整楼源 BIM、匹配/缺失/多余/高度/位置冲突 |
| 建筑合理性检查 | 判断体量、楼层、空间与动线、宿主与高度是否合理 | 当前整楼的建筑判断、具体疑点和证据局限 |
| 定向修订 | 只返回有问题的范围；保留其它读图结果 | 新候选、受影响范围的新检查，未变范围复用 |
| 正式交付 | 确认当前覆盖、跨图一致性及建筑判断，调用 finish_bim | 源 BIM、查看器、检查记录、假设和未解决项 |

回叠由当前执行读图职责的模型查看。未来分工时可由读图员承担局部检查、调度员承担跨图协调和建筑合理性判断；本轮没有启用分工，也没有改变 reader 并发、共享预算或恢复实现。

## 实现与边界

- `process_reviews: true` 只接受 `single_model` + `drawings`；三个产品图纸示例启用，旧manifest及分工入口保留原政策。
- 平面复用既有 build/revise/assemble、实际源回叠和标定。按实际楼层XY物理范围、原图和标定绑定检查；高度改动不会使未改的平面比较失效。
- `prepare_elevation_reading` 复用现有读图 schema、墨线定位、10cm采用政策；回叠反投影实际采用宽度、窗台/窗顶和标高，保留原读数。
- `record_bim_review` 一次可保存多个图/楼层/立面的结论，整楼建筑判断另存；不增加逐对象通过登记。检查记录、实际回叠和读图版本可验证，旧版本失效明确报告。
- `apply_elevation_readings` 复用既有匹配和claim批量应用；一次事务处理多个立面。数量、缺失/多余、歧义、超过30cm的位置差、采用高度及楼层标高差分别报告。
- 图纸及匹配详情经现有有界 `tool_reports` 回读，不能仅提供模型无法读取的磁盘路径。
- 建筑事实中的门连通图仅表示已声明的门/开放通道；未表达的楼梯等需模型判断，不能当作法规或自动合理性判定。
- 模型自报检查、确定性数据一致和独立图纸质量分别记录。回叠已返回不证明看懂，局部结论也不等于独立认证；真正缺失或仍不清楚的信息可记录为 uncertain，已知错误为 needs_revision。
