# 每次会话的项目初始上下文

本文件是 Codex、Claude 及其他开发助手共用的项目入口。用户当前指令优先；项目管理、交接与项目记忆统一保存在 `AI_agent/`，不要在仓库根目录另建管理文件。

## 先读什么

每次会话先完整阅读本文、[当前计划](plan.md)、[产品范围](project_scope.md) 和 [管理体系](management.md)，再按任务读取相关源码及技术文档。[目录](README.md) 提供其余入口，不要求通读历史日志才能开工。
检查 `git status --short --branch`、`git worktree list` 和近期提交，以实际代码和产物为准。当前是单一主干 `main`；阶段状态只维护在计划中，本文不复制每日进度。
自动加载与切换工具的设置见 [会话入口](guides/session_entry.md)。

## 项目要做什么

- 核心是多种输入生成可查看、可修改、可继续加工的轻量 BIM（丐版 BIM）。EnergyPlus 是首个下游插件，几何是我方主线，物性挂接由协作者负责。
- 近期两路：现有图纸/case 的较精确重建；带表皮体量的内部推断。最终融合 CAD、文字及更多输入，输入充分程度影响精度和假设数量。
- 保留有证据的原始房间、隔断、门窗与空间关系；仿真热区是下游派生。面模型可以继续复用，全实体墙和毫米级复刻不作普遍前置。
- 信息不足允许简化、推断和默认值，要让用户看见依据、缺失和冲突。不能静默丢房间/窗、掩盖失败，或把推断当实测。
- 先取得可查看的真实 case 产物，再推进下游连通与质量。现有代码、脚手架、围栏按实际用途保留、修改或删除，不被旧排期和沉没成本绑住。
- 最终产品仍可由多个可配置模型的 agent 协作。产品运行目标档从首批实验参与，Sonnet 级为运行上限；开发模型另按 [模型使用约定](guides/model_usage.md)。

## 怎么推进

- 助手可直接设计、实现、检查、修复和提交，包括核心代码。按任务需要使用单助手或有明确边界的并行任务；用户已授权 Claude、GLM 现有订阅通道的调用与派工，无需逐次确认，其他委派遵循相应授权与上级指令。
- 保持一个主干和共享模型/内核/出口。两路输入可用短期任务分支或 worktree，不发展两套长期架构；公共接口先小步回主干。
- 验证按改动影响选择：局部行为检查、相邻真实产物贯通，必要时才全量。相同代码、相同验证范围已有有效结果可复用；收工或换模型不触发重复全量。
- 不强制跨模型复审、固定角色矩阵、批次清债或给每个改动加测试锁。现存代码检查仍实际生效；若不适合目标，应查明用途后修改并验证，不能只在文档中宣称取消。
- 遇到失败先复用已有产物定位具体阶段，再运行最短验证。新实验用独立 run，不覆盖原始素材和旧结果。
- 几何计算、变换、切配与装配优先用确定性代码；模型承担感知、语义及缺失信息下的判断。坐标、单位、方向、对象来源需明确。
- GT 留在评测侧。用 GT 调试内核要标作诊断；人工辅助、历史观测重放、冷启动生成分别报告，不把单测通过当整案完成。
- 凭据和私有配置不入 Git。普通测试离线；运行模型或大任务的资源约定见模型指南。
- **DeepSeek 直接付费，任何调用必须先得到用户对本次任务/批次的明确同意**，包括开发派工、管线运行、探测、重试和自动回退；只在已同意范围内执行。普通开发/case 授权、旧记录或已有凭据不代表 DeepSeek 调用许可，子代理也须遵守。Claude、GLM 的现有订阅调用与派工可自行安排，不自动切换为按量付费通道；详见 [模型使用约定](guides/model_usage.md)。

## 项目记忆、沟通与权限

所有助手的项目记忆都要同次写回对应管理文档，不得只存在 Codex/Claude memory、工具记忆或会话中；本地记忆只留仓库索引。事实/下一步写计划，目标写产品范围，技术结论写架构，决策和证据写对应记录。收工和切模型前再核对遗漏，敏感内容除外。

用中文先说明结果、影响和建议，再按需给技术证据。管理文件、交互记录、审计和临时项目说明放在 `AI_agent/` 下；业务源码、测试与 case 产物仍放各自既有目录。不要把所有执行输出堆入初始上下文或计划。

用户已全权授权本项目日常 Git 操作：备份、tag、建并清理分支/worktree、commit 和正常 push 无需逐次确认。保留可回退的小提交；不强推改写共享历史，不丢弃未知改动。
遇到无法安全保留的冲突、无法判定的产品矛盾或新的外部权限障碍，说明具体问题并停下确认；正常技术选择自行推进。

用户说“收工”，就执行 [开发与收工手册](guides/development.md)：更新管理文档及全部项目记忆、检查 diff 与已有验证、提交并推送、收回完成的临时树、报告结果和下一次入口。收工本身不要求全量，也不再次询问是否做 Git。

历史版本、旧要求和恢复方法见 [归档](archive/README.md)；历史中的“必须”“待审”“阻断”不自动成为现在的任务。
