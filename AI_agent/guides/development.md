# 开发、Git 与收工

约束以 [Agent.md](../Agent.md) 为准。本手册给出最少的操作步骤。

## 开工与验证

在主目录确认分支/status，读当前计划，再读本次相关代码。任务从输入、期望输出和一个可观察结果开始。
优先复用现有运行入口，改动完成后检查 diff，再做与影响面相称的验证。

| 改动 | 通常需要的验证 |
|---|---|
| 文档、索引、Git 整理 | 链接、差异、工作树和恢复检查；无需 pytest 全量 |
| 单模块逻辑 | 相关行为测试、必要时一个实际缺陷回归 |
| 段间接口/产物形状 | 相关测试 + 用相邻阶段真实产物做一次贯通检查 |
| 广泛内核、共享依赖变化 | 先局部检查，再按影响面决定一次全量 |
| 模型调用与真实 case | 独立 run，保留命令、模型配置、输出和未完成阶段 |

常用命令：

```bash
python -m pytest tests/test_w1_flow_routing.py -q -n 2
python -m scripts.tool_scripts.run_stage --help
git diff --check
```

测试文件名以实际仓库为准。`pyproject.toml` 仍默认 `-n auto`，局部检查显式用较少 worker。
受影响测试选择器可作参考；它选成全量不等于所有改动必须全量。
已有通过结果应记录提交和范围后复用，不因换角色、写报告或收工再次全量。
离线测试保留现有计费调用拦截。真实模型调用按已授权的 case 范围执行；无关付费实验另议。

## 环境

使用 Dev Container 中已经配置的 Python；本轮采用 `python -m`，未重装依赖。
多棵树共用环境时，`uv run` 的自动同步可能改 editable 路径；不在每棵树反复安装项目。
怀疑串树时直接查看被测模块 `__file__`，一次查清后继续。
未来若确需并行依赖变更，使用每树独立环境；只改文档或普通 Python 文件无需另装一套。

## 分支与存档

- `main` 是持续集成主干；常规 Git 操作已获用户授权，正常 push 无需再次确认。
- 本轮里程碑先 tag，再修改。日常已有 Git 提交就不要求按文件重复 `cp` 备份。
- worktree 用于短期且边界清楚的任务，从最新主干建；共享契约先回主干，两路输入随后跟进。
- 完成任务就回并、验证相关部分、移除临时树。未完成内容先保存，不能直接强删或扫入“文档更新”提交。
- 不强推共享历史。回退已共享改动优先 `git revert`；查看旧版本可用 tag 另开恢复目录。
- 重要未跟踪素材/实验要么明确提交，要么有持久存档及位置记录；`.env` 和私有配置留本地。

## “收工”触发的动作

1. 更新 [plan.md](../plan.md)：今天完成什么、卡在哪、下一次从哪里接、什么不做。
2. 新口径写 [Agent.md](../Agent.md) 或相关指南；架构实际变化写契约；历史过程归 logs。核对 Codex、Claude 及其他助手本轮项目记忆/会话内容，补齐尚未落文档的部分。
3. 删除/归档被新状态替代的段落。入口只留一份当前事实，不追加历史 banner，不把日记搬进待办表。
4. 核对完整 status/diff、已做的验证与未验证范围；只暂存本轮文件。
5. commit + 正常 push，按需要推 milestone tag；核对远端提交和临时树去向。
6. 用中文简报结果、提交、验证、遗留与下一步。push 或验证受阻必须说明，不能记作完成。

收工不等于额外测试仪式；有意义的验证在改动时完成。
所有助手的项目记忆在形成或更新时就同步到对应仓库文档，本地只留索引，不等收工才同步；收工和切换模型前再检查遗漏。具体归档位置见 [Agent.md](../Agent.md) 的项目记忆同步规则。
