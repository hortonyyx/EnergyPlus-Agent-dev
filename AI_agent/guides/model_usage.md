# 开发与产品运行的模型使用约定

2026-09-08 从 Codex 项目记忆同步。这里记录用户偏好，不重新引入必派工、模型阶梯或强制复审链。
原记录及当时的官方资料链接见 [模型路由历史资料](../archive/2026-09-08_codex_memory/energyplus-agent-dev-model-routing-2026-09-07.md)。

## 产品运行

目标档从首批实验参与：可本地部署级 / Flash 级，经 API 调用，Sonnet 级为上限。
各运行 agent 可配置模型，按实际质量、成本和时间比较；开发时借助更强模型不提高产品运行上限。
完整目标见 [产品范围](../project_scope.md)。

## 开发分配

- 用户希望将 GPT 额度主要留给 Astra，减少 Sol/Terra/Luna 的常规调用；它们仍可用于有理由的例外。
- 在确需委派、任务独立且已有授权时，Opus 可承担难推理/分析，Sonnet、GLM 可承担成块实现或复核，Haiku/Flash/DeepSeek 可承担适合的提取和重复任务。
- 上述为分配偏好，不是每次都要开多个助手。当前任务和系统允许的执行方式优先，不为小改造出审阅流程。
- 一次任务提供必要上下文、产物和完成标准；按实际交付、返工、耗时和总成本调整，不凭公开榜单认定建筑图纸能力。

## 费用与通道

- DeepSeek 开发调用与管线共用计费余额；凭据只注入需要的子进程，不全局覆盖模型端点，不输出密钥。
- 大任务按需检查剩余额度/余额和其他任务占用。重要资源分配不明时，先给具体范围、估算和替代方案再请用户选择；小任务不反复审批。
- 考虑峰谷与订阅额度，但不为等折扣拖住关键进度。价格、活动、窗口和可用模型在真正分配大任务时再核对。
- 历史 CLI 成本估算不等于真实账单；一次文本请求成功不等于视觉/工具能力、长期稳定性或剩余额度够用。
- 09-07 的模型通道探测和计费资料已归档，本轮没有重测、查询余额、安装调度器或改变模型配置。
