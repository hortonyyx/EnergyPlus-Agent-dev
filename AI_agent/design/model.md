# 共同轻量建筑模型

这是两路输入共有的数据要求。09-09 已落最小源对象、Stage 2 投影、显式门/空开口及已有结构化平面门洞记录的自动接入；全图开口识读、编辑回写和下游开口适配仍未完成。已实现的类型与限制见 [现有实现](implementation.md)。

## 已实现的最小源投影（09-09 M0 增量）

本节描述原 `source_bim_v1` 附带投影，仍供旧 EP 路径使用。09-09 新生成主线改用下面的独立 `source_bim_v2`；不能用旧附带投影证明源输出已解除切配依赖。

权威可修改参数在 CorrectedGeometry 的 Cell/Window/WallOpening；Cell.id 是源空间身份，不采用会重排的 Z 编号。[source_model.py](../../src/agent/geometry/source_model.py) 从它和确定性建模输出生成 `2_modelling/source_model.json`，复用 [schema.py](../../src/agent/correction/schema.py) 的 SourceSpace/SourceBoundary/SourceOpening。没有新增门洞时，既有 correction/geometry JSON/specs 字节合同保持原样；新增门洞显式写入 correction 与 geometry，不能借附带投影省略权威开口。

- 空间保存 cell ID、楼层、完整多边形、高度、role 和校正对象引用。源边界按空间与规整后的环边序编号，尺寸变化/显示面细分不依赖 Z 排序；新增/删除源边需要显式迁移边界身份，不能承诺任意拓扑编辑后 ID 自动稳定。
- 边界是有方向的空间边界，含 owner、相邻空间和对侧边界引用。同一物理隔断的两侧仍为两个相关联的源边界，不假装已建立唯一全局墙实体。当前 Cell 环按物理隔断解释，明确开口作为面内对象扣除；虚拟边界生成尚未贯通。
- 已有窗保留源 ID、宿主源边界、空间/室外、顶点和 unknown 连通状态。重复/丢失窗、窗移位或错宿主会报告严重问题。legacy 窗可贴唯一宿主墙段的边，不能跨入另一墙段；只按同房间配对墙的原端点证据补偿既有切配的 1 μm 数值侵蚀，不移动/缩小窗或泛化放宽墙宽。
- `derived` 分别将 zone/surface/window/opening 映射到源对象；源墙覆盖、派生面是否位于源边界、同一源空间内多出的墙和开口映射会检查。严重映射错误先保存候选与报告，然后阻断下游，探索模式也不例外。

源/派生内容各有摘要；查看器只在派生摘要匹配时载入附带源投影。映射检查的 2 μm 容差仅兼容现有切配的 1 μm buffer 和六位小数，不是图纸比较或规整容差。映射通过证明建模保留了校正对象，不能证明 correction 没有读错/切错房间；后者由独立分区参照与输入证据评价。

### 显式门洞与空开口

`CorrectedGeometry.openings` 保存源 ID、door/open 种类、所属房间、另一房间或明确的室外、平面两端点、高度区间、来源及假设。当前只支持正交竖墙上的矩形开口，坐标须是校正后的建筑坐标；随房间编辑变换开口尚未接线，失去宿主会在建模时明确失败。V3 确定性重放保留这些字段，实际 writer 比较全部核心投影字段（改动日志另按前缀检查），漏建、移位、改变开闭状态不能绕过重放核对。

[as_drawn_openings.py](../../src/agent/correction/as_drawn_openings.py) 在楼层协调和补窗后，消费已有 as-drawn plan v2 中明确的 door/passage/open 类型、开口候选及墙面 gap 引用。墙编译结果须匹配读图原始字节和来源指针；按同一编译墙、成对墙面和有界端点差合并重复观测，保留确定的原观测跨度。两侧房间取自最终空间边界，不用房间名或中心点猜邻居；墙法向位置可在已编译半墙厚内跟随最终边界，移动值、上限与假设留账。缺高度逐项记为 2.1 m 假设，门状态 unknown，passage/open 为 open。说明文字不自动转坐标。

`as_drawn_opening_account.json` 逐项保存建成、合并、移动和未建记录。明确开口未建时也写入权威 `unsupported`，`correction.plan_opening_completeness` 在 exploratory 下仍阻塞；候选诊断查看不等于接受或解除阻塞。开口与门窗重叠、多宿主、跨房、缺邻室或矛盾观测均不强行填入。新 CLI 和独立重放使用同一提取器，来源载体以显式 `wall_opening_policy` 固定算法版本和假设高度；旧载体缺省不补门，保持历史字节与重放含义。

[openings.py](../../src/agent/geometry/openings.py) 确定两侧完整宿主并按已有墙片切分；一面墙有多个计算片，仍对应一个源开口和一条空间连接。未知房间、错误邻居、跨墙不完整覆盖、重复及与其他门窗重叠均拒绝。源映射另核对派生开口是否缺失、移动、换种类/邻居/状态。

`connections` 明确开口连接的房间或室外及状态。门的默认开闭状态为 unknown；没有门扇的 open 固定为 open。连接记录表达潜在通路及当前已知状态，不表示所有门必然可通行，更不能由未记录开口推出两房完全封闭。

父面继续表达逻辑体积边界；物理墙面由父面减开口得到。查看器实际扣洞、保留同一源身份，并显示门/空开口和状态；地面门洞形成缺口，悬空洞形成内环，整面空口可移除整张可见墙。现有窗仍沿用覆盖显示。边界检查可显式使用未扣洞父面投影，但实际 specs/IDF 出口遇到新门洞会拒绝，避免未实现下游适配时静默封墙；这不算新增门洞的 EnergyPlus 验证。

暂不支持新开口的旧消费者须明确拒绝：`assemble_multifloor_geometry` 尚不能随层高/楼层组装变换门洞，非空输入报错；手动 GLB/PNG 工具也会报错并指向支持扣洞的 HTML 查看器。没有新开口的旧路径保持可用，不得先丢开口再继续导出。

## 独立源 BIM 生成（09-09）

`geometry/source_bim.py` 直接消费校正对象及适用的可信窗宿主证明。复用源空间/完整边界构造和多边形工具，输出楼层、源空间、完整边界、真实接触区域、门窗开口及两侧宿主、连接、来源、假设与未建项；权威文件不包含物性、EP 边界条件、一一配对面或显示映射。

一面完整边界可关联多个邻室，以接触区域记录实际范围，不拆源墙。水平接触也由真实几何求交表达；当前仍限正交、单外环、逐层统一高度的源空间，挑空/假楼板真实性未评价，不能因边界闭合就宣称这类输入已支持。

`source_view_geometry()` 生成独立显示投影，窗和门洞均实际扣洞，重复接触部分在未展开时隐藏，展开后保留两侧。显示片始终映射原边界，不生成虚构物理隔断。源 ID 保留原 cell/window/opening 身份；任意拓扑编辑后的 ID 迁移仍未实现。

源检查覆盖合法多边形、声明楼层轮廓的覆盖、空间体重叠、门窗完整宿主、实际相邻与声明连通一致、开口重叠、未解决观测。复用 `cell_polygon` 的有效性/边界框核对，不使用旧 EP 内核的 0.1 m 最短边。原图完整性与分区保真在评价侧另检，报告可直接评价实际输出的源空间，GT 不参与生成。sm25 两组未建门继续阻塞，sm24 的 8 空间历史辅助模型仍有独立分区差异。

完整契约与查看入口见 [源生成记录](../logs/worklog/2026-09-09_source_bim_pipeline.md)。新增 EP 分叉直接读取 v2：派生热区对应源空间，切配面对应完整源边界，窗对应源开口；逐面覆盖和接触区域核对通过才写 IDF。映射、坐标/北向约定及派生假设独立保存，源文件字节不变。物性模板必须不含几何，独立绑定源空间 ID 与物性热区名。目前支持外窗、理想负荷系统，以及逐源门 ID 显式提供关闭策略和不透明构造的门；源状态未知时仍保留 unknown，关闭仅为后端假设。内门两侧、外门单侧及跨父墙切片均保留来源；已知敞开/空通道仍明确阻塞。见 [EP 分叉记录](../logs/worklog/2026-09-09_ep_branch.md)；持久编辑暂缓。

## 源对象与派生对象

| 内容 | 最少需要保留什么 |
|---|---|
| 建筑与楼层 | 外形、层高、尺度、局部坐标与方向 |
| 房间/空间 | 原始空间几何、语义、所属楼层；推断空间标明假设 |
| 隔断与边界 | 物理隔断身份、两侧关系、参考面；虚拟计算边界另标 |
| 窗/门/空开口 | 形状、位置、宿主、关联空间与外部；不能只剩显示 mesh |
| 空间关系 | 相邻和实际连通分开 |
| 场景几何 | 遮阳、阳台、邻楼与重要障碍物，可不形成区域 |
| 来源与更新 | 稳定对象引用、输入依据、变换、假设、冲突和人工修改 |

源房间与隔断不因热区优化被覆盖。热区、切配面、查看 mesh、物性装配及 IDF 从源模型派生，并保存对应关系。面模型可继续作为内核，全实体墙不是普遍前置。
一个非矩形房间可以对应多个显示三角形、切配面或仿真单元，源模型仍是同一个房间，不能沿计算切线生成物理墙。物理隔断、开放区域的语义分界和用途特定的计算边界分别表示；不同房间相邻与实际有门/开口连通分开。
稳定源 ID 不依赖会随几何排序变化的 Z 编号。首次实现只补真实 case 所需的房间、隔断、开口与派生映射；到挑空阶段再补跨层空间与楼板孔洞，不能用每层造一个房间和楼板代替通高空间。
可选墙厚、窗内缩与洞深按用途表示为显式几何或可派生参数；构造层厚度与几何参考面不是同一个概念。其他求解器的开口/连通表达按各自用途转换，不直接假定等同于 EnergyPlus 的父面/子面。

## 单位、方向与参考面

输入原单位、尺度可信度和坐标变换要明确；保留局部到共同坐标的变换。内皮、外皮、轴线和厚度不得只凭数值接近混用，假设北向不伪装成观测。
现有 E4 出口用建筑坐标顶点、EnergyPlus Relative 和归零的 Zone 原点/相对转角；它是当前下游合同，不要求每种输入原本采用同一坐标系。源代码入口见 [output_coordinates.py](../../src/agent/output_coordinates.py)。

## 简化与容差

区分观测不确定度、参考面转换、数值精度、几何有效性和仿真用途简化，不共用一个未经解释的“精度值”。规整/简化记录实质改变对象、幅度、理由和来源；原始输入与观测保留，可随新证据重新生成。可编辑的源建筑模型允许是容差内规整后的几何，不必带着原始 CAD 噪声工作。
优先保住源房间、隔断、门窗及空间关系，量化精度服务于用途；生成模型内部的共享边界由代码统一生成。详见 [定性评价与容差](evaluation.md)。
当前项目存在 0.1 m 短边检查，不等于 EnergyPlus 的普遍物理下限。层间差异先核对原图、尺度、参考面和识读残差，再决定修实现还是生成用途特定的简化模型。
不能统一粗网格化、静默删窄面/房间/窗或按预测结果倒改 GT 来获得通过。展示模型与仿真模型可有不同接受状态，检查方法见 [验证与评价](evaluation.md)。
