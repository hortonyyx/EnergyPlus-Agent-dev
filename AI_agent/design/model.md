# 共同轻量建筑模型

这是还原建模、部分推理建模、完全推理建模共用的数据要求，类别按输入信息充分程度定义，见 [产品目标](../project/goal.md#按信息充分程度划分建模任务)。09-09 已落最小源对象、Stage 2 投影、显式门/空开口及已有结构化平面门洞记录的自动接入；全图开口识读、编辑回写和下游开口适配仍未完成。已实现的类型与限制见 [现有实现](implementation.md)。

## 已实现的最小源投影（09-09 M0 增量）

本节描述原 `source_bim_v1` 附带投影，仍供旧 EP 路径使用。09-09 新生成主线改用下面的独立 `source_bim_v2`；不能用旧附带投影证明源输出已解除切配依赖。

权威可修改参数在 CorrectedGeometry 的 Cell/Window/WallOpening；Cell.id 是源空间身份，不采用会重排的 Z 编号。[source_model.py](../../src/agent/geometry/source_model.py) 从它和确定性建模输出生成 `2_modelling/source_model.json`，复用 [schema.py](../../src/agent/correction/schema.py) 的 SourceSpace/SourceBoundary/SourceOpening。没有新增门洞时，既有 correction/geometry JSON/specs 字节合同保持原样；新增门洞显式写入 correction 与 geometry，不能借附带投影省略权威开口。

- 空间保存 cell ID、楼层、完整多边形、高度、role 和校正对象引用。源边界按空间与规整后的环边序编号，尺寸变化/显示面细分不依赖 Z 排序；新增/删除源边需要显式迁移边界身份，不能承诺任意拓扑编辑后 ID 自动稳定。
- 边界是有方向的空间边界，含 owner、相邻空间和对侧边界引用。同一物理隔断的两侧仍为两个相关联的源边界，不假装已建立唯一全局墙实体。当前 Cell 环按物理隔断解释，明确开口作为面内对象扣除；虚拟边界生成尚未贯通。
- 已有窗保留源 ID、宿主源边界、空间/室外、顶点和 unknown 连通状态。重复/丢失窗、窗移位或错宿主会报告严重问题。legacy 窗可贴唯一宿主墙段的边，不能跨入另一墙段；只按同房间配对墙的原端点证据补偿既有切配的 1 μm 数值侵蚀，不移动/缩小窗或泛化放宽墙宽。
- `derived` 分别将 zone/surface/window/opening 映射到源对象；源墙覆盖、派生面是否位于源边界、同一源空间内多出的墙和开口映射会检查。严重映射错误先保存候选与报告，然后阻断下游，探索模式也不例外。

源/派生内容各有摘要；查看器只在派生摘要匹配时载入附带源投影。映射检查的 2 μm 容差仅兼容现有切配的 1 μm buffer 和六位小数，不是图纸比较或规整容差。映射通过证明建模保留了校正对象，不能证明 correction 没有读错/切错房间；后者由独立分区参照与输入证据评价。

### 显式门洞与空开口

`CorrectedGeometry.openings` 保存源 ID、door/open 种类、所属房间、另一房间或明确的室外、平面两端点、高度区间、来源及假设。当前只支持正交竖墙上的矩形开口，坐标须是校正后的建筑坐标；随房间编辑变换开口尚未接线，失去宿主会在建模时明确失败。V3 确定性重放保留这些字段，实际 writer 比较全部核心投影字段（改动日志另按前缀检查），漏建、移位、改变开闭状态不能绕过重放核对。

[as_drawn_openings.py](../../src/agent/correction/as_drawn_openings.py) 在楼层协调和补窗后，消费已有 as-drawn plan v2 中明确的 door/passage/open 类型、开口候选及墙面 gap 引用。墙编译结果须匹配读图原始字节和来源指针；按同一编译墙、成对墙面和有界端点差合并重复观测，保留确定的原观测跨度。两侧房间取自最终空间边界，不用房间名或中心点猜邻居；墙法向位置可在已编译半墙厚内跟随最终边界，移动值、上限与假设留账。缺高度逐项记为 2.1 m 假设，门状态 unknown，passage/open 为 open。说明文字不自动转坐标。

`as_drawn_opening_account.json` 逐项保存建成、合并、移动和未建记录。明确开口未建时也写入权威 `unsupported`，`correction.plan_opening_completeness` 在 exploratory 下仍阻塞；候选诊断查看不等于接受或解除阻塞。开口与门窗重叠、多宿主、跨房、缺邻室或矛盾观测均不强行填入。新 CLI 和独立重放使用同一提取器，来源载体以显式 `wall_opening_policy` 固定算法版本和假设高度；旧载体缺省不补门，保持历史字节与重放含义。

[openings.py](../../src/agent/geometry/openings.py) 确定两侧完整宿主并按已有墙片切分；一面墙有多个计算片，仍对应一个源开口和一条空间连接。未知房间、错误邻居、跨墙不完整覆盖、重复及与其他门窗重叠均拒绝。源映射另核对派生开口是否缺失、移动、换种类/邻居/状态。

`connections` 明确开口连接的房间或室外及状态。门的默认开闭状态为 unknown；没有门扇的 open 固定为 open。连接记录表达潜在通路及当前已知状态，不表示所有门必然可通行，更不能由未记录开口推出两房完全封闭。

父面继续表达逻辑体积边界；物理墙面由父面减开口得到。查看器实际扣洞、保留同一源身份，并显示门/空开口和状态；地面门洞形成缺口，悬空洞形成内环，整面空口可移除整张可见墙。现有窗仍沿用覆盖显示。边界检查可显式使用未扣洞父面投影，但实际 specs/IDF 出口遇到新门洞会拒绝，避免未实现下游适配时静默封墙；这不算新增门洞的 EnergyPlus 验证。

暂不支持新开口的旧消费者须明确拒绝：`assemble_multifloor_geometry` 尚不能随层高/楼层组装变换门洞，非空输入报错；手动 GLB/PNG 工具也会报错并指向支持扣洞的 HTML 查看器。没有新开口的旧路径保持可用，不得先丢开口再继续导出。

## 独立源 BIM 生成（09-09）

`geometry/source_bim.py` 直接消费校正对象及适用的可信窗宿主证明。复用源空间/完整边界构造和多边形工具，输出楼层、源空间、完整边界、真实接触区域、门窗开口及两侧宿主、连接、来源、假设与未建项；权威文件不包含物性、EP 边界条件、一一配对面或显示映射。

一面完整边界可关联多个邻室，以接触区域记录实际范围，不拆源墙。水平接触也由真实几何求交表达；当前仍限正交、单外环、逐层统一高度的源空间，挑空/假楼板真实性未评价，不能因边界闭合就宣称这类输入已支持。

`source_view_geometry()` 生成独立显示投影，窗和门洞均实际扣洞，重复接触部分在未展开时隐藏，展开后保留两侧。显示片始终映射原边界，不生成虚构物理隔断。源 ID 保留原 cell/window/opening 身份；任意拓扑编辑后的 ID 迁移仍未实现。

源检查覆盖合法多边形、声明楼层轮廓的覆盖、空间体重叠、门窗完整宿主、实际相邻与声明连通一致、开口重叠、未解决观测。复用 `cell_polygon` 的有效性/边界框核对，不使用旧 EP 内核的 0.1 m 最短边。原图完整性与分区保真在评价侧另检，报告可直接评价实际输出的源空间，GT 不参与生成。sm25 两组未建门继续阻塞，sm24 的 8 空间历史辅助模型仍有独立分区差异。

完整契约与查看入口见 [源生成记录](../logs/worklog/2026-09-09_source_bim_pipeline.md)。新增 EP 分叉直接读取 v2：派生热区对应源空间，切配面对应完整源边界，窗对应源开口；逐面覆盖和接触区域核对通过才写 IDF。映射、坐标/北向约定及派生假设独立保存，源文件字节不变。物性模板必须不含几何，独立绑定源空间 ID 与物性热区名。目前支持外窗、理想负荷系统，以及逐源门 ID 显式提供关闭策略和不透明构造的门；源状态未知时仍保留 unknown，关闭仅为后端假设。内门两侧、外门单侧及跨父墙切片均保留来源；已知敞开/空通道仍明确阻塞。见 [EP 分叉记录](../logs/worklog/2026-09-09_ep_branch.md)；持久编辑暂缓。

## 显式实际围护（09-09 v3 增量）

`geometry/source_enclosure.py` 将绑定 v2 源摘要的 `source_enclosure_input_v1` 声明应用为新 `source_bim_v3`。`bim` 和共同 `flow` 均接 `--enclosure-input`；没有声明时仍生成原 v2。声明属于共同几何输入，没有构造、空调、换气或 EP 切配信息；此次接口用于生成，不代表已交付停点编辑交互。

- `spaces` 可明确声明 `enclosed`、`semi_open`、`open`，未声明空间不自动填 enclosed。空间类别不推断热区用途，也不自动创造开放区域。
- `boundaries` 按源边界 ID 指定 open/unknown、whole/partial。partial 给出同一建筑坐标下的三维顶点；whole 保留完整父面、改为 virtual 或 unknown，partial 用 mixed 及 `enclosure_regions` 表达实际范围。未声明边界沿用原 v2 的物理边界解释，这不是新增的原图确认。
- 每项记录 `evidence_kind`（observed/manual_annotation/example）、`source_refs` 和 `assumptions`，来源或假设至少一项。显式声明保存原始副本与摘要；example 不冒称图纸观测，来源文字也不等于已独立核验原图。
- 完整空间多边形、高度、父边界顶点及门窗保留；已有 `connections` 仍表示门/开口连接，新敞开区域的几何连接写在 `source_enclosure.open_connections`，内侧双向、外侧明确标室外。共享开敞区域必须有对侧匹配声明；unknown 不建立连通。
- 拒绝失配摘要、越界、不共面、区域重叠、覆盖已有门窗、单侧宣称穿透实墙。当前支持竖墙上的正交区域；楼板/顶板孔洞、挑空、独立屋盖及一般非正交区域不在这次范围内。

源显示投影仍从实体面扣掉 open/unknown 区域。按用户最新要求，交互查看统一增加半透明灰色辅助面（颜色 #8b949e、透明度 0.32），unknown 不重复生成普通墙面；状态、来源和假设通过点选文字区分，辅助面开关同时控制面与轮廓。这些仅是查看辅助，不回写实体面、体积或连通。完整父面继续用于逻辑范围和可选虚线层。旧 v2 查看兼容。灰空间设计暂止于此，遇到真实案例再细化。

未知围护产生 warning，允许导出可查看的逻辑几何，并令 `enclosure_information_complete=false`；原有 severe/未建项继续阻塞，不被 warning 覆盖。几何就绪不等于围护信息完整、图纸保真通过或后端接受。新 v3 由旧 EP 分叉明确拒绝；v2 的已跑通 EP 分叉保留。

三个历史 sm21 几何上的受控例覆盖整侧开敞、1.1 m 矮墙以上开敞和整侧未知，均不是新原图观测。详见 [本轮交接](../logs/worklog/2026-09-09_source_enclosure.md)。

## 源对象与派生对象

### 09-10 用户确认：空间块复杂度由用户选择

通用源 BIM 以逻辑闭合的空间块为基本单元，分块依据实体隔墙形成的实际建筑空间。用户生成前选择对这些空间做多少简化/合并，概念上以假设建筑信息完全推理准确为参照，但实现无需先全部恢复。后端模拟选择不参与定义复杂度。办公楼分档示例只适用于相应实际格局：核心筒四周若是一圈开放办公，最细仍为一个四周空间，不能按朝向、功能或块数目标人为细分。

粗块可以包含多个未展开的实际房间，记录其功能、合并范围和输入依据；最细档尽量保留实际空间，不增加不存在的隔间。边界仍分别表达观测或推断的物理隔断、抽象边界及未知状态；抽象边界不用于强行拆分开放空间。一个合并块内未展开隔墙，不表示内部真的开敞；逻辑闭合也不产生假楼板。已知细节保留在证据与抽象对应记录中，低档输出无需展开全部细节。后端可从任一档源 BIM 再行合并、细分或调整，保存对应关系，不静默覆盖源模型；这是与源简化相互独立的计算处理。

四周块可环绕核心筒，作为一个有内环的逻辑单元；如果底层计算需分片，片间不生成物理墙，也不将一个源块改成多个源房间。这是需要支持的表达，现有直接导出仍限单外环等条件；空间抽象元数据、多粒度生成及内环适配尚未实现。此前图纸重建的错拆并房检查仍适用，不能用新增设计文字把既有失败改成通过。

### 09-09 已确认方向：按需遮阳与灰空间

用户确认先生成通用底座、参考成熟表达，后端需补充的内容不前移。主体以闭合空间体界定范围，再表达真实围护及整面/局部敞开；遮阳按需后接。总体方向已确认，整面/局部竖墙开敞及未知围护已通过显式几何声明接通生成与显示；自动原图识读和后端适配仍待接入，不把下面的后端举例转成源生成前置。独立屋盖等构件允许用补充面表达，无需强制形成一个空间体。

建议保留空间的逻辑闭合，另标实际围护是否存在；空间体不限矩形盒子。完整敞开侧为虚拟空间边界，局部空缺为明确的开放区域，物理墙/栏板只占实际范围。明确敞开、门窗覆盖和信息未知应分别表达；相邻、可通行、对外开放也不能合并为一个布尔值。灰空间语义与是否空调分开，不能把封闭但不空调的房间当成敞开走廊。

开敞走廊示例：保留走廊空间、真实楼板、上方实际楼板/屋盖、靠室内真实墙与门；面向室外的侧面及开放端头只界定空间范围。若有栏板，下段物理、上段敞开。EP 根据用途派生室外环境、遮阳或显式空气交换模型，不因源空间逻辑闭合就自动生成封闭热区。当前 v3 源生成与显示已支持下述显式竖墙区域；EP 仍拒绝 v3，不能把源查看成功当成灰空间热工适配完成。

遮阳可作为按需启用的几何扩展：本栋建筑的挑檐、遮阳板等用共同坐标与来源，供不同后端共享；EP 的专用遮阳对象、透射率/控制归后端。09-10 用户收束为单体，不考虑邻楼和周边环境建模。已在输入中明确且决定建筑空间形态的屋盖、阳台板等应保留源几何，后端利用它们的遮阳作用，避免重复补一个同形遮阳面。完整遮阳识别与细化可后置，不要求本轮全做。

这一表达方向与 IFC 对物理/虚拟空间边界的区分相容，仅作为设计参考，不要求当前轻量 BIM 完整实现 IFC。参考：[IfcRelSpaceBoundary](https://standards.buildingsmart.org/IFC/RELEASE/IFC4_3/HTML/lexical/IfcRelSpaceBoundary.htm)。

| 内容 | 最少需要保留什么 |
|---|---|
| 建筑与楼层 | 外形、层高、尺度、局部坐标与方向 |
| 房间/空间块 | 几何、语义、所属楼层、抽象粒度与范围；推断空间标明假设 |
| 隔断与边界 | 物理隔断身份、两侧关系、参考面；源抽象分界和后端计算边界分别标明 |
| 窗/门/空开口 | 形状、位置、宿主、关联空间与外部；不能只剩显示 mesh |
| 空间关系 | 相邻和实际连通分开 |
| 建筑附属几何 | 本栋建筑的屋盖、遮阳、阳台等，可不形成区域；不纳入周边环境 |
| 来源与更新 | 稳定对象引用、输入依据、变换、假设、冲突和人工修改 |

源房间与隔断不因热区优化被覆盖。热区、切配面、查看 mesh、物性装配及 IDF 从源模型派生，并保存对应关系。面模型可继续作为内核，全实体墙不是普遍前置。
一个非矩形房间可以对应多个显示三角形、切配面或仿真单元，源模型仍是同一个房间，不能沿计算切线生成物理墙。物理隔断、开放区域的语义分界和用途特定的计算边界分别表示；不同房间相邻与实际有门/开口连通分开。
稳定源 ID 不依赖会随几何排序变化的 Z 编号。首次实现只补真实 case 所需的房间、隔断、开口与派生映射；到挑空阶段再补跨层空间与楼板孔洞，不能用每层造一个房间和楼板代替通高空间。
可选墙厚、窗内缩与洞深按用途表示为显式几何或可派生参数；构造层厚度与几何参考面不是同一个概念。其他求解器的开口/连通表达按各自用途转换，不直接假定等同于 EnergyPlus 的父面/子面。

## 单位、方向与参考面

输入原单位、尺度可信度和坐标变换要明确；保留局部到共同坐标的变换。内皮、外皮、轴线和厚度不得只凭数值接近混用，假设北向不伪装成观测。
现有 E4 出口用建筑坐标顶点、EnergyPlus Relative 和归零的 Zone 原点/相对转角；它是当前下游合同，不要求每种输入原本采用同一坐标系。源代码入口见 [output_coordinates.py](../../src/agent/output_coordinates.py)。

## 墙厚：几何信息与热工构造（09-10 讨论）

用户补充：墙厚精细几何优先级较低，但墙厚参数影响后续仿真；随后明确材料分层等热工信息归后端模块。几何侧按可用信息保留总厚/墙面间距，缺少可靠厚度时可采用明确的表示假设，不阻塞丐版 BIM。以下具体接口仍是设计建议，不是新 schema 或实现验收。

- **几何总厚/墙面间距**：保留测量位置、所指层次（结构/含饰面/未知）、来源和不确定性。可信总厚与参考线定位共同用于派生内外面、净尺寸和洞深；单有厚度不能判断尺寸是按轴还是按边，也不能默认所有轴线都居中。
- **表示用的参考线/面**：表示空间关系和装配范围，记录其与真实墙面的偏移约定。保留厚度参数和观测引用即可支持后续派生，不要求初始模型画成完整实体墙。
- **热工材料层**：层厚、材料导热率、密度、比热等归后端构造参数，不作为源几何生成前置。图上总厚不足以确定整墙传热/蓄热表现。EnergyPlus 将表面坐标与引用的材料构造分开；见 [官方手册内容](https://bigladdersoftware.com/epx/docs/24-2/input-output-reference/group-surface-construction-elements.html#specifying-the-building-envelope)。

二者分开管理但不能无视真实构造相容性：若均描述同一实际墙体，应核对几何总厚与构造层合计，允许明确记录结构层/饰面或等效热工简化造成的口径差。用户明确修改实际总厚时，需按固定参考线/面重新派生受影响几何；仅改变热工假设或等效参数时，不静默回写源墙位置。当前物性接口不提供几何修改，此处不宣称该编辑能力已实现。

成熟表示同样分别记录材料层及其相对参考线的偏移，并要求相应实体几何与材料层一致；参考 [IfcMaterialLayerSetUsage](https://standards.buildingsmart.org/IFC/DEV/IFC4_3/HTML/lexical/IfcMaterialLayerSetUsage.html)。本项目只借鉴这种信息区分，不以完整 IFC 或实体墙为前置。

### 墙厚与标注基准的实施方案（09-10 收工讨论，尚未实现）

以下保留当时方案；09-12 已实现的局部范围见下方“局部墙面与尺寸换算已接入实验 Agent”，其余仍是后续设计。

用户在还原线状态总结后询问墙厚和墙厚引起的标注问题，随后要求收工。以下为助手准备的下一程方案，延续轻量面模型、按输入证据建模、物性归后端的边界；不冒称用户已确认某个新 schema、统一中线规则或全实体墙方案。

**当前实际缺口**：实验 Agent 的方案直接给房间多边形和开口坐标，GUIDE 要求以声明的代表墙面抽象墙厚、空间无缝覆盖楼层。`SourceBoundary` 当前没有结构化厚度、墙两侧偏移或标注端点基准；房间相邻依赖共面的边界接触，门窗也放在这些边界上。`map_dimension_chain` 只累计数字，不能判断这些段是否首尾连接或量到同一种面；`source_image_overlay` 只投影房间边界，不派生真实两侧墙面。旧墙编译器有双面/墙带与参考线处理，可按用途复用，但不等于这些信息已进入当前 Agent 源输出。

**先补可计算的墙面关系，保留轻量输出。** 同一物理墙关联两侧源空间边界，按实际墙段记录：参考线/面及其性质、墙面或墙带证据、几何总厚、两侧相对参考面的有符号偏移、结构/饰面/未知口径、原图位置和观测/假设状态。已知总厚不自动推出两侧各一半；参考线可来自轴线、一侧墙面或明确的建模约定，图纸定位轴线不默认就是墙中线。厚度可按墙段不同，缺证据时允许未知或明确的近似，不默认整楼都是 240mm。

参考面加上两侧偏移即可按需派生墙面或二维墙带，暂不要求完整实体墙。物理墙、两侧房间边界和派生墙面保持对象对应；墙厚不变不表示定位基准已经正确。先让代表面继续服务现有覆盖/接触/开口内核，增加其与真实墙面的映射；不直接把每个房间独立缩成净空多边形，否则当前覆盖与共面相邻检查会失配。净面积、净容积和实际内外表面从明确的墙面关系派生并注明口径，代表面分配的面积不能称为已测净面积。一般角接、T 接点、局部变厚的净空派生后续按实际需求扩展，不能靠全局 polygon buffer 代替。

**标注要记录量到哪里，换算由代码执行。** 尺寸证据除原数字/单位、图面和方向，还需保留两端的原图定位、对象以及面/轴身份。两端分别记录，不把整张图统一叫“轴线尺寸”或“净尺寸”；轴到墙面等混合标注也应能表达。尚未识别的端点先保留未知，原数字不改写。只有端点身份及各墙面偏移确定后，代码才把约束转换到选定的模型参考面，并给出转换项和剩余差值。

例如两道 240mm 厚的墙、定位轴线都在中点：轴间 5.00m 对应内侧净距 4.76m；若标的是内侧净距 5.00m，则轴间为 5.24m。这个例子依赖已确认的两端墙面和中点条件，不是当前案例的新识读结果；偏心墙或端点落在不同层次的墙面时，使用各自偏移，不能统一加减半墙厚。

尺寸链核对先检查端点连接：净跨、墙宽、洞宽、轴跨或分链可能混在一起，漏掉一段墙带不能靠数字列表直接闭合。保留原样分段和、依据墙面关系转换后的总长，以及仍无法解释的残差。像素比例用同一对实际标注端点及其实际尺寸标定；不能把净跨两端像素配上轴间长度，也不能通过改变整图比例去消除局部墙厚偏移。每张图独立建立变换。

**回叠同时区分代表面和墙面。** 在已有原图回叠上，按已保存厚度/偏移派生两侧墙面或半透明墙带，用不同图层显示代表线与墙面，注明观测、推断或未知。原图画墙面时应与对应墙面核对，原图画轴线时应与对应轴线核对；代表线落进墙带只能提供局部位置线索，不能单独证明几何正确。尺寸基准转换不是自由拟合标定，不能扩大墙厚来吞掉偏差。变更后仍核对房间、实际隔断和门窗连接，保留版本与原标定。

门窗继续关联同一物理墙和源开口：墙厚主要进入法向定位、内缩与洞深；洞口沿墙方向的两端另看标注落在洞边、框边还是门扇。不能把厚度变化直接加减到所有门窗宽度。厚度或参考面改变时明确固定哪条线/面，再由代码派生受影响几何，不能移动其它楼层同坐标对象，也不能留下失去宿主的开口。

**下一程最小范围**：复用旧墙面证据与现有算术/投影能力，先把一小段有图证的墙厚、端点和参考面关系贯通到源记录与回叠。用受控的同墙异基准、偏心厚度和缺段尺寸链检查转换，再用 sm21 原图验证模型能否自行辨别基准并据反馈行动；只补真实路径需要的信息，不先要求全楼完整结构化读图或治理。GT 继续留事后评价，未知可以带说明交付，不宣称未知基准已经准确。

**对最近结果的解释补充**：run12/run13 的 14.76m 分段和不等于 15m，模型把两者直接写成相等仍不成立；但差出的 0.24m 可能涉及缺段或墙面基准，尚不能仅凭差值断言原因。类似 0.12m、0.18m 的位置残差也须核对基准，不能全算成读图错位，更不能全当墙厚自动豁免。历史 GT/叠图诊断按原口径保留；下一轮先区分参考面换算和真正的墙位问题，不倒改旧结果或按候选修改 GT。

### 09-12 局部墙面与尺寸换算已接入实验 Agent

`source_proposal` 现接可选 `wall_references` 与 `wall_dimensions`；结构化证据随源 BIM 摘要保存，不修改 `SourceBoundary` 原顶点或空间接触内核。`wall_reference.py` 绑定真实边界及完整重合的另一侧，保存世界正 x/y 方向的两侧偏移、几何总厚、参考面解释、厚度口径、观测/推断/未知状态与来源。只有厚度不会自动推出中线；两偏移差必须与所声明总厚一致。

每条尺寸分别保存两端的墙 ID、代表面/负侧面/正侧面/未知身份、原图与像素。代码按 `原尺寸 + 方向 × (起点偏移 − 终点偏移)` 换成代表面间距，并另报当前模型跨度及残差；不改原数值、不拟合墙位或比例。尺寸列表按给定顺序检查相接的墙及侧面，跨同一墙的不同侧面不能称为连接的链；原分段和继续单独报告。结果只说明调用方端点声明的计算后果，不认证识图正确。

Agent 可用 `check_wall_dimensions` 读取实际墙宿主清单/试算，再以 `set_wall_references` 保存两份完整证据列表。自动回叠在紫色代表线之外画蓝色派生墙面，元数据标明依据与未知。厚度证据更新固定原代表面，不改变开口宽度/连接；现有局部共墙移动会从新代表面派生相同偏移，原图尺寸仍保留。整图镜像遇到这类证据明确要求完整修订，避免偏移方向与旧墙引用静默失真。

首版只支持完整直墙及完整重合的两侧；局部接触/分段变厚、显式敞开围护、一般角接/T 接点净空、洞深与一般轴网尚未接。三维查看仍使用轻量代表面，净面积/净容积不在本批派生。旧源/旧 proposal 无此字段仍按原路径运行，EP 适配未扩展。受控验证见 [证据](../logs/experiments/2026-09-12_wall_reference_setup/README.md)，真实还原表现单独报告，不能把换算通过当作自主纠错成功。

### 09-12 后续：将端点矛盾与原图坐标反馈说清楚

上一轮真实工具返回了 -0.48m 残差，模型未处理。现对**同一墙**的尺寸单独给出已声明端点的世界坐标、方向和正负侧；当两端走向与尺寸方向相反/为同一面，明确标记端点次序冲突；同墙面距与标注不符另标记厚度不一致。原数值、转换项与残差保留，不自动翻转标签或移动房间。不同墙间的残差仍留给图意/基准/几何判断，不据任意容差当成错误；未知偏移不变成零。

`check_wall_dimensions` 将这些事实放在报告前部；有局部证据时默认不重复全楼边界清单，仍可按需请求。源导出持久保存新报告，`inspect_candidate` 和交付直接显示。交付页还保留当前源回叠的标定警告，与模型自填未解决项分别列出；旧源图继续单独记录，不改候选字节。

模型查看原图/裁图时，返回图默认带标原图像素的点状网格。它不会改变原图或当前裁剪/缩放映射，可用 `coordinate_grid=false` 关闭；小于100px的细节不加标尺。其用途是避免把缩略图上的显示坐标直接当成原图坐标，网格线不属于建筑证据。原始回叠文件仍由实际源与声明标定生成，未加新的人为几何或自动拟合。

run16 暴露全量证据列表重写容易抄入派生字段，模型还用删除尺寸来清掉 finding。后续增加 `update_wall_dimension` / `update_wall_reference` 单条修改：固定记录 ID，起/终点做字段级合并，未改的原数值/像素/另一端/其他记录保留，before/after 与新理由来源进入独立审计。允许有图证时修改原数值或引用，不自动选择正确标签，不增加“必须归零”硬门。局部试算和源导出继续使用同一验证器。

定向验证与真实效果见 [反馈恢复实验](../logs/experiments/2026-09-12_feedback_recovery_setup/README.md)。这些改动提高反馈可解释性和持久性，不替代原图识读，也未把所有墙厚/标定检查升级为源几何硬门。

### 09-12 后续：将原图尺寸证据与具体墙段并列回叠

同一法向坐标上的不同墙段可能使尺寸算术相同，不能据此确认宿主。现有 `overlay_candidate` 在精确原图/楼层范围内，标出已引用墙段 W 与尺寸原始起终点 D:S/E；完整 ID、原像素、模型墙段端点和按调用方标定映射的世界位置同时保留。保存修订后自动回叠也使用新源中的引用关系，当前/旧源交付保留各自的位置对照。

代码只计算沿墙坐标是否超出该有限墙段，以及相对代表面的法向位移。尺寸引出线可能合理地位于实体墙段外，标定也未经独立确认，因此这不是自动错误判断、宿主选择或保真放行；距离为零同样不证明归属正确。图面识读和具体证据取舍仍由模型负责，不自动扩大全墙厚度范围或改变物理源。

不给原图名的独立底层调用仍保持旧回叠；生产工具显式传入精确输入图名，避免把另一张图的尺寸端点画进当前图。字体无需新增外部依赖，实际缩略图保留可读标识。验证与恢复实验见[墙段证据对应](../logs/experiments/2026-09-12_wall_host_setup/README.md)。

## 简化与容差

区分用户选择的源空间复杂度、观测不确定度、参考面转换、数值精度、几何有效性和后端仿真简化，不共用一个未经解释的“精度值”。规整/简化记录实质改变对象、幅度、理由和来源；原始输入与观测保留，可随新证据重新生成。可编辑的源建筑模型允许是容差内规整后的几何，不必带着原始 CAD 噪声工作。
优先保住源房间、隔断、门窗及空间关系，量化精度服务于用途；生成模型内部的共享边界由代码统一生成。详见 [定性评价与容差](evaluation.md)。
当前项目存在 0.1 m 短边检查，不等于 EnergyPlus 的普遍物理下限。层间差异先核对原图、尺度、参考面和识读残差，再决定修实现还是生成用途特定的简化模型。
不能统一粗网格化、静默删窄面/房间/窗或按预测结果倒改 GT 来获得通过。展示模型与仿真模型可有不同接受状态，检查方法见 [验证与评价](evaluation.md)。
