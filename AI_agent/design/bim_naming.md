# BIM 全构件公开命名

当前方案为 `bim_names_v3`（10-07）：公开名统一用于平面图、查看页和交付报告。沿用 [06-23 已确认方案](../logs/reviews/request/2026-06-23_deterministic_naming_proposal.md)的排序与逆时针规则，以及 09-27 的门、洞口、显示片和边后缀；用途段内改短横，同层同用途同方位重复时加编号。回叠图不加名称标签。

| 对象 | 示例 | 编号依据 |
|---|---|---|
| 楼层 | `F1`、`F2` | 按底标高升序；同标高按源楼层 ID。这是序号，原图楼层名保留在源对象，地下层也按此排序，不推断实际楼层标识 |
| 房间／空间 | `Z01_F1_Office_SW1`、`Z02_F1_Office_SW2`、`Z03_F1_Conference-Meeting-Multipurpose_NE` | 四段以 `_` 分隔：全楼唯一序号＋层＋表内用途 token＋方位；序号至少两位。用途内多词用 `-`，如 `Office-Enclosed`、`Copy-Print` |
| 墙面 | `Z01_W1`、`Z01_W2` | 俯视逆时针；起点为最南顶点，同 Y 时取最西者；凹形沿完整轮廓继续到 W5、W6… |
| 地面、顶面 | `Z01_Floor`、`Z01_Ceiling` | 按真实几何类型命名；有明确 roof 对象才用 `Roof`，不把顶层 ceiling 自动判成外屋顶 |
| 窗 | `Z01_W1_Win1` | 每面墙独立，沿该墙逆时针方向从起端开始排；同位置按底高，再按几何排序 |
| 门 | `Z01_W1_Door1` | 同窗，门单独计数 |
| 无门洞口 | `Z01_W1_Opening1` | 同窗，洞口单独计数 |
| 显示局部面 | `Z01_W1_Part1` | 一个源面因接触、洞口或围护状态而形成多个显示片时加后缀；不产生新墙 |
| 开敞／未知区域 | `Z01_W1_Open1`、`Z01_W1_Unknown1` | 按源面＋区域条件分组，几何排序；仍是查看辅助面 |
| 可选边 | `Z01_W1_Edge1`、`Z01_W1_Win1_Edge1` | 父面／门窗＋边序；端点坐标规范排序，不依赖顶点列表起点或绕向 |

房间排序为底层到顶层，每层按质心由北向南、再由西向东；使用 06-23 的六位小数命名比较精度和几何指纹做并列排序，源 ID 只作最后兜底。房间方位相对**全楼所有楼层 footprint 包围盒**中心判定，中心容差沿用原实现（各半宽／半高的 5%，最高 0.5m，另加数值容差）。输入楼层或房间列表打乱不改变名称。

同一源楼层、同一表内用途、同一方位有多间房时，按上述已有房间顺序依次加 `1`、`2`…，如 `SW1`、`SW2`；仅一间不加。不同用途、楼层或方位各自计数，不按字母编号排序，也不改变用途分类。`office` 与 `office/enclosed` 分别仍为 `Office` 与 `Office-Enclosed`；上游代码、中文名、颜色和别名不变。

方位沿既有**模型 XY 坐标系**，+X=E、+Y=N；这是名称中的方向，不宣称已经确认地理真北。墙的“西南起点”具体是 `(y, x)` 最小顶点，凹多边形不假设包围盒西南角一定在轮廓上。

内部门或洞口只有一个源对象 ID，可以有两个房间侧名称，例如 `Z01_W2_Door1` / `Z02_W4_Door1`。`public_names.openings` 以较小房间序号一侧作主名，`opening_sides` 保存两侧别名；点哪侧显示哪侧名，连通栏列出两端房间全名，不复制门。

源对象和公开名分开：新导出的 `source_model.json.public_names` 保存 floors/spaces/boundaries/openings/opening_sides 映射，不改任何源 ID、门窗宿主、连接或坐标。名字由代码生成；房间类型选自 [固定功能表](room_types.md)，不得手写新类型。原始 proposal 保存原貌，标准化只作用于构建副本。

09-27 新增的 `set_space_role` 功能修订会在新候选中刷新房间公开名中的功能token及固定颜色；墙／开口公开序号、内部ID和物理几何保持。HTML房间栏同时展示实际保存的功能依据与推断说明，不能将颜色或规范名称视为用途已获确认。

公开序号描述当前 BIM，新增房间、移动排序位置或改变功能后名称可变；修订、证据、宿主和连接继续使用内部 ID。几何本身重建环次序的历史 ID 迁移限制仍适用。不追溯改写归档产物，也不把历史 EnergyPlus 派生面切片当成源墙。旧源 BIM 重绘时按当前规则在显示层重算名称，原文件、摘要和检查绑定不变。

实现入口为 `source_naming.build_public_names`、`public_names_for_display` 和 `viewer_names`。平面图文件名为 `plan_F1.png` 等，标题用公开楼层名，房间标签使用完整公开名，长名在分隔符处换行；图像元数据仍保留内部楼层和房间 ID。查看页所有可点选对象、所属房间／楼层／父面及连通两端用公开名，内部编号和原始记录放在默认收起的追溯栏。楼层信息使用源楼层身份，不靠门窗高度就近猜层；按层／空间选择优先于命中的门或开敞辅助面。

交付 HTML 由 `bim_agent_delivery_display.render_delivery_html` 显示已保存的检查记录：显式楼层／开口／边界字段查映射，说明文字中的完整对象引用换为公开名，路径和 URL 保留原样。交付 JSON 的内部引用、检查结论与绑定摘要不变；查看页原始依据可展开追溯。EnergyPlus 适配器接收独立 `zone_names` 映射，现有字符检查允许短横和数字后缀；它不会解析公开名推断用途。
