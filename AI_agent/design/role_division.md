# 工种与角色分工（10-05 初稿，边做边调）

## 当前 Lite BIM 规整路径（10-10，domain v57）

本包沿用调度员、平面读图员和立面读图员三个角色，runtime v2 不改。分工模式首次平面试建和立面提交默认采用 0.1 m；单模型参照路径保持。完整实现与离线证据见 [集成验证](../logs/experiments/2026-10-10_sm25_lite_regularization/integration_validation.md)，真实 sm25 人工调度效果见 [本轮实验](../logs/experiments/2026-10-10_sm25_lite_regularization/README.md)。下文早期状态按对应日期理解。

- 模型批量读取图上的尺寸和完整空间结构，提交近似原图像素；尺寸链按累计共享节点落位，局部链可从标定取得锚点，总长未给时可用分段和。代码负责闭合、统一网格和门窗随宿主联动，模型不逐段手工分配取整余量。
- 规整前后保留原始读数、采用值、移动量、对象关联与哈希。XYZ 采用值必须一致落网格，房间、开口、宿主及连接保持；不允许通过删房、并房、删门窗或退回未规整几何完成交付。
- 平面草稿自身标高与跨层装配目标标高分开，最终审计对应实际装配结果；立面绝对标高、宽度、窗台和窗顶采用同一政策。工具校验有效的规整变化不再逐项要求模型确认，实质拓扑或跨图矛盾仍需处理。
- 局部返工限定明确对象或字段，服务端保留完整上一版 artifact；发给模型的上下文保留几何、读数、证据与备注，省去大体积派生审计，只给摘要和哈希引用。未指向的几何与原始读数不能被返工顺带覆盖。
- 整图自动选择步长、用户精度控件和专用 OCR 尚未实现；本轮产品路径固定 0.1 m，底层函数可接受其他步长不等于产品配置已贯通。原图符合性、空间划分质量与数值网格分别验收。

人工调度可派工、查看产物、装配、复核及同次局部返工；现有 runtime 没有活动读图员消息注入入口。一次 `delegate` 返回后才能经现有入口继续协调，不修改活动日志或 checkpoint 来冒充指导。

**本版首次 sm25 实测终态：失败，尚未达到人工调度规整输出目标。** 四立面完成，118项原始/采用读数有4项被规整；F1五份完整声明均在numeric产物完成前失败，F2无声明。F1最后请求超时缺usage使runtime费用状态永久停止，同次恢复未派发。已定位的domain缺口是近轴接头与尺寸链移动顺序，以及raw declaration在编译前失败后不能原生局部恢复；本版未修复这两个新发现的问题。更高缓存及更短指引没有证明整案减负，完整事实见本轮实验，不再以旧稿离线规整通过代表新生成成功。

## 为什么要分工

单模型 Agent 已吸收完历史经验清单，但这只说明“已知缺陷逐项修了、离线验证过”，不说明单模型形态已经调到最好。10-05 分界回归（[记录](../logs/experiments/2026-10-05_node_regression_c3/README.md)）里，同一版 Agent 在 sm24 上 GLM 更好、27B 变差，GLM sm25 门窗位置从 48/61 跌到 22/61；两项新能力（依据事务、只报告的检查提示）基本没被用上或没用对。单模型形态有三处结构性限制，再调指引也去不掉：

1. **一条长对话 50–70 轮。** 反馈埋在长上下文里没人理（27B 对走廊隔墙的提示连续 16 次请求未回应）；压缩会丢早先的观察；首稿越来越晚（GLM sm25 第 80 分钟）。
2. **一个模型要什么都会。** 看图、量测、按格式写、判断与返工，任何一项弱都拖累整案。
3. **全部串行。** 各层平面、各个立面本可同时读。

分工也是提速的主要方向：时间与消耗靠架构控制，不靠收紧限额逼模型（用户 10-05）。

## 原则：角色不是越多越好

用户 10-05：“角色也不一定是越多越好……信息传递反而会伤害系统稳健性，让模型拿到适合的上下文，处理适合模型能力的输入输出才是最好的。” 据此：

- **只在三种情况下拆：** ① 活本身相互独立、共享信息少（各层平面、各个立面），拆开能并行；② 换一个干净、聚焦的上下文明显有帮助（核对）；③ 需要的能力差别很大（读裁图与做全楼决定）。其余留在一处。
- **交接传“产物”，不传转述。** 读数、依据、问题清单写成结构化文件进全楼状态；任何角色都能回看原图，不只看别人的总结，避免传话失真。
- **接口按小模型能填对的标准设计。** 扁平、少嵌套、必填项少；本地部署时可用约束解码保证格式。强模型阶段也统计格式出错率，免得换小模型时问题集中冒出来。
- **每加一个角色都要有证据。** 与单模型同条件对照，质量不降、时间与 token 明显下降才采用；否则撤回。

## 工种（从 24 次运行、1,751 次工具调用归纳）

| 工种 | 内容 | 需要的能力 | 现在谁做 |
|---|---|---|---|
| 1 输入盘点与标定 | 认出哪张是哪层平面、哪个立面；尺寸链定比例；平面与立面方向对齐 | 读图、判断 | 模型＋代码换算 |
| 2 平面读图 | 每层外轮廓、隔墙、房间、门窗位置与宽度 | 读图感知、读数字 | 模型（看图约三分之一、剖面约三分之一的调用） |
| 3 立面读图 | 每个立面的门窗高度、数量、层高、屋顶 | 读图感知、读数字 | 模型 |
| 4 立面—平面对位 | 立面上每扇窗对应平面上哪扇 | 对照推理 | 模型 |
| 5 写稿与总装 | 读数写成模型数据、编译、多层叠装 | 按格式输出 | 模型写、代码编译 |
| 6 核对与返工 | 稿与原图比对，定位差异，决定并实施修改 | 对照、判断 | 模型＋代码差异检查 |
| 7 依据与交付 | 每个数的来源、说明、交付 | 按格式输出 | 模型 |
| 8 调度 | 先做什么、派给谁、何时算完 | 规划、长程不跑偏 | 模型 |

## 最小起步方案（v1）

先只拆最有把握的两类，其余留在调度员手里：

| 角色 | 工种 | 输入 | 交出 | 并行 |
|---|---|---|---|---|
| 调度员 | 1 的判断、4、5、6 的决定与修改、7、8 | 任务、全楼状态、各角色产物 | 派工、全楼稿、返工、交付 | 一个 |
| 平面读图员 | 2（含本层依据） | 一层平面原图、比例 | 该层墙、房间、门窗读数与图上依据 | 每层一个 |
| 立面读图员 | 3（含本面依据） | 一个立面原图 | 门窗高度、数量、层高读数与依据 | 每面一个 |

第二步视 v1 证据再决定是否加 **核对员**（新开上下文，只看一层或一面的差异，交问题清单给调度员）。对位与总装以代码为主，模型只处理对不上的部分；“自动立面匹配”的基础版在这里做。

底座已有“调度模型派出局部看图任务、最多 4 个并行”的机制（阶段 3、R1），一直没在整案里真正用过；v1 在它上面做，需要补按角色配模型、按角色给指引与工具、产物写回全楼状态。

## 推进顺序

1. **强模型做稳分工：** 各角色先都用强于目标档的模型，在 sm21、sm24、sm25 上与单模型同条件对照。看质量、时间、token、格式出错率；底座效率对 Claude Code 全面超过为目标。10-06 用户按五档说明“强模型”（1 档：开发用的顶尖模型；2 档：国产头部；3 档：Sonnet、Terra 与国产 Flash 类；4 档：27B 等本地部署级与 Haiku、GPT mini；5 档：OCR 等专用小模型）：本项目以 4 档及以下为主力、接受 3 档，所以这里的强模型取 3 档。三个角色都用 GLM 订阅的 `glm-5.3-flash`，与 10-05 单模型基线同一型号与线路，不另花钱。
2. **底座优化（10-06 用户定，提到换模型之前）：** 分工做稳、三例对照之后，先做底座性能，以缓存命中为首，对 Claude Code 全面超过；之后再逐角色换模型。
3. **逐角色换模型：** 按角色从历史运行截出带标准答案的小题，候选（Flash 级与常见开源前沿模型，能经 API 调用即可，本地硬件不作限制）逐题测出画像；逐个角色换下来，整案验证，按速度、消耗、质量衡量。
4. 复杂度升级（自动立面匹配 → 全局坐标 → 多层复杂 → 泛化图纸）与推理建模，待本层做好做稳后再排（用户 10-05：“先在这里做好做稳再说”）。

## 提速的两类做法（10-07 用户定）

用户：现阶段与单模型持平或略快即可，提速随 Agent 迭代顺带取得；以时间为主要指标的纯提速之后专门做，长期目标是相对单模型大幅提速。

**时间花在哪（10-07 run7、sm21 run1 的事件记录）：** 4 个立面读图员同时读，第 3–8 分钟全部提交，不在关键路径上。关键路径是最慢的平面读图员（sm24 14 分钟，占一半；sm21 二层的一层 21 分钟，占四分之三）加读完后的调度员收尾（sm24 12 分钟，sm21 5 分钟）。平面读图员每轮中位 40–50 秒，几乎全是模型输出（GLM 约 60 token／秒）：约三分之二在看图量测（8–12 轮），三分之一在写稿；每次试建整份重写平面（7–8 千字符），提交时再手写全部依据（6–9 千字符）。sm24 收尾的 12 分钟里，约 7 分钟是东立面横向比例漂移（0.4–0.5 米）导致两扇窗对不上后的自查与返工，约 3 分钟是补房间用途时修改工具连续报错。

| 归入 Agent 迭代（为做对、做稳、接口好填，省时是顺带） | 归入纯提速（之后专门做，以时间与用量为指标、守住质量） |
|---|---|
| 立面与平面按门窗顺序和尺寸标注对位，比例漂移也能对上（“自动立面匹配”的基础版） | 程序预先找墙线与尺寸标注，减少读图员量测轮数（改变读图做法，风险最大；若对照显示平面误差主要是量错位置，可提前作质量对策） |
| 房间用途由平面读图员读图时填 | 一层平面拆给多个读图员同时读（加角色要有证据） |
| 调度员小修入口简化，减少格式报错 | 按角色调思考档；选模时把每秒输出量作为指标 |
| 换 4 档前三项：立面朝向由运行时推出、依据框由程序生成、墙面基准默认值 | 底座缓存（10-06 已定在换模型之前做）；开头盘点与派读图任务自动化；读完一层先建一层等流水线化 |
| 最后一次通过的试建直接作提交，返工只写改动部分 | |
| 平面读图员质量对策（核对员或试建里的对账提示），按三例对照样本定 | |

## 第一版已定（10-06）

- 平面读图员直接交 `build_plan_bim` 现有的平面格式，每项附原图依据，交付前先试建（同一套编译与检查，不存入全楼稿）；调度员按产物引用建层，不重抄。
- 立面读图员交标高、逐个门窗（顺序、楼层、横向像素范围、宽度、窗台、窗顶、依据）与横向标定；与平面的门窗对应由代码先做，对不上的交调度员。
- 依据由读图员在产物里逐项给出。
