# 用户自接与服务器多模型配置

09-28 用户明确的产品要求：最终用户能自行接入模型，服务器部署也能配置多个模型进行调度，不能仅在一套型号组合上做好。Flash 工作档以 Sonnet 为能力参照，更看重速度和低消耗、优先成本，同时衡量 token；智力上限不做严格限制，允许同档能力随时间提高。原全角色 Sonnet 硬上限在本档不再适用。降低智力依赖、提速和降本可以逐渐实现；Flash 不是型号字符串筛选条件。主力仍朝 Qwen 27B 这种可本地部署级模型发展，允许按实际任务使用适合的专用模型。

09-28 用户最新要求先恢复单 Sonnet 质量，再尝试功能分工，避免混入新的运行变量。按角色组织、型号可配置仍是后续方向；当前已有可选局部委派和配置雏形，没有验证过稳定的分工方案。此前六次较好结果均为单 Sonnet 配合确定性工具。正式入口接入暂缓，未完成草稿已[单独留档](../logs/experiments/2026-09-28_deferred_role_integration/README.md)。下述实施步骤是后续设计，不是当前排期。最新候选和来源见[能力池调研](../logs/experiments/2026-09-28_model_capability_research/README.md)。

## 三类配置分开

| 层次 | 保存的信息 | 要解决的问题 |
|---|---|---|
| 服务连接 | 服务 ID、协议/适配器、base URL、密钥引用、超时、并发及服务限制 | 用户自己的 API、平台聚合服务、服务器自部署均能接入；凭据不进任务提示或运行报告 |
| 模型能力 | 明确模型 ID/版本、输入模态、输出类型、工具/工具图片支持、上下文/图片限制、思考参数、价格/计费来源、延迟与用量记录、已验证范围 | 同名模型在不同部署不必有同样能力；不能从 Flash/VL/大小直接推断等级或能力 |
| 任务调度 | 主控/视觉/OCR/检索/重排等所需能力，候选池、允许的转交/失败处理、预算和并发策略 | 按任务选模型，配置可替换；同一型号可多用，也可跨家族协作，不写死两个等级/固定角色数 |

模型能力要区分官方声明、服务端暴露和项目实测。没有核实的能力/限制保留未知，不能用默认 true 填充。工作型号的采用由负责人根据明确版本、任务质量和实际经济性判断；Flash 档没有静态智力封顶。在质量要求满足时成本优先，同时比较全部 token 与有效交付耗时，不能只看单价、TPS 或一次成功。研究候选表不是运行白名单，模型/复核/回退仍须遵守实际配置、费用及调用权限。

## 对外适配与共同工具

- 通用聊天/工具循环复用既有 BIM MCP 工具及保存状态。第一适配是当前 Paratera 的兼容聊天协议，但提供者层不把“OpenAI 兼容”当所有能力唯一接口。
- 图像、工具调用及工具结果中的图片必须实际送达模型；思考字段是否须原样接续由适配器按协议处理，不把隐藏推理当质量评价依据。
- OCR/文档解析、embedding、rerank、ASR 作为专用能力接入。Paratera 文档中的 embedding 为 `/v1/embeddings`、rerank 为 `/v1/p002/rerank`，不能统一塞进 chat/completions。OCR 的单元素 VLM 与完整布局解析管线也需分别声明。
- 专用结果尽量保存原图/页/区域、原始文字或候选、坐标系/变换、来源版本及不确定性；返回哪些字段由实际接口决定，不凭空补 OCR 置信度。模型负责对象对应，确定性工具负责坐标、算术和几何合法性。
- 模型更换不改变同一任务的 BIM 数据契约和质量口径。OCR、检索、检测结果是观测来源，不直接变成已确认建筑事实；GT 和评测派生结论仍与生成隔离。
- 失败处理只在已配置、符合费用与调用权限的模型池内进行，并记实际型号、原因、父子用量、耗时及结果；未配置替代时明确停点/缺口。模型服务不可用与建模判断错误分开归因。

## 渐进实施和质量验证

1. 接通兼容 API 的同一 BIM 工具循环，离线验证多轮工具 ID、图片传输、错误/预算处理与保存回执；主任务和专门服务接口分别处理。
2. 先按需求接一项能解释实际失败的专用能力，例如尺寸文字识别；工具可以被主 Agent 按需选择，不能要求所有图纸强制经过 OCR/多模型流程。
3. 节点验证至少准备两种不同组合以核可替换性：如多模态主力+按需 OCR，以及文本工作模型+独立视觉/OCR。此为实施建议，型号、案例和次数届时准备，当前未启动。并非每个小改都全组合回归。
4. 先守住空间/门窗/连接等质量，再逐项换较低能力或更快更便宜的模型。按真实行为与保存结果定位降档失效位置，允许把任务拆给小模型/确定性工具后再比较。
5. 对比记录模型与服务配置、输入/工具/任务边界、完成质量、首响应和有效结果耗时、全部模型用量、失败及返工。单次最好结果或工具次数不能证明稳定，也不要求所有合法型号取得完全相同的坐标。

## 已实现的配置与离线工具循环

`src/agent/model_routes.py` 新增显式 `services / models / roles` 布局，由既有 `load_llm_section` / `create_llm` 消费。以 `schema_version: 1` 区分，未知角色不继承默认；仅未指定角色的调用使用显式 `default_role`。检查服务/型号引用与角色要求的能力；未知、缺失、false 均不能满足能力要求。能力来自部署配置声明，不因此变成项目实测证书。原 flat/section 消费布局保持既有行为。

示例 [model_roles_paratera.yaml](../../src/configs/model_roles_paratera.yaml) 可通过 `EP_AGENT_LLM_CONFIG=src/configs/model_roles_paratera.yaml` 显式选择。`modeling` 与 `visual_review` 只是功能角色示例；改变 `roles.<role>.model` 即可换型号，多个角色可指向同一 profile。服务支持不同地址/提供者/密钥环境变量引用，只读取当前所选服务的密钥；无鉴权本地兼容服务如客户端需要占位 key，可由该环境变量提供，不自动借用其他账户凭据。本轮未设置全局默认或据此启动远程模型。

`src/agent/execution/chat_mcp.py::run_chat_mcp` 接收已初始化 MCP 会话、明确工具集合、客户端/配置、模型调用/工具调用/总时间预算。SDK必须关闭自动重试；保存实际型号、原始 usage、HTTP状态和失败阶段，未报用量不按零成本处理。截断输出不执行工具，整批工具 ID/名称/JSON及剩余额度先检查，MCP工具错误交回模型，传输异常/超时即停止；不自动委派或换模型。总时间/次数及单次输出token有界，尚无可靠总金额硬限额。

工具结果保留文字、结构化内容和错误状态；图片原字节放在全部关联 tool 回复之后的多模态消息，带 tool_call_id 和 hash。无法接收图片或不支持的结果类型明确失败。服务要求的思考接续字段由调用方列入 `assistant_echo_fields`，仅转发、不用于公开行为评价；各部署/思考模式的真实兼容性仍待验证。

35项离线检查通过，涵盖角色替换/共用、不同服务地址、缺项拒绝、真实SDK离线序列化、图片字节/多工具ID、失败/预算停止；真实 BIM MCP 服务使用合成回复完成看图→两房间/一连接建模→保存查看文件。模型回复是测试桩，不是真实模型建模成功。本轮新增 API 推理0。

## 当前实现缺口

`scripts/tool_scripts/run_bim_agent.py` 仍走 Claude/GLM 订阅 CLI，尚未把新循环接入正式 BIM 运行入口、局部模型角色及其保存回执；没有完整动态调度、专用 OCR/embedding/rerank 适配或多组合建筑质量/经济性结果。此次对照运行的40个生产文件与原六图保持冻结，新增配置/适配不进入其生成过程。

`src/configs/llm_paratera.yaml` 原六 profile 及早先四模型小探针保留；新角色样例没有宣布最终型号组合。正式入口与角色选择贯通延后；先恢复单 Sonnet 的建模质量，再选择具体分工试验，分别验证质量保持与成本/速度收益。便宜、快速或名字带 Flash 均不能自动取得任务合格结论。
