# 输出检查与独立评价

评价源 BIM 是否符合输入与目标，以及完成它所需的时间、成本和干预。结构检查、模型自查、独立质量评价与用户验收分别记录，不能互相替代。

## 评价顺序

1. 是否完成要求的范围，哪些对象或信息仍缺失。
2. 空间划分、边界、开口宿主、相邻/连通是否正确；漏墙、多墙、错拆错并、假楼板与关系改变优先处理。
3. 尺寸、位置、标高及规整是否有依据，并区分原始读数和采用值。
4. 推断、假设与简化是否明确、合理且符合目标；工具通过不证明输入理解正确。
5. 有效交付时间、请求/失败/返工、总消耗与 dev model 介入。

图纸可按独立参照评价保真；信息较少的输入须同时评价已知约束与推断合理性。照片细度和生成 mesh 的具体指标仍待讨论，不以渲染观感或 EUI 接近替代整体质量。

## 实测与证据条件

| 运行条件 | 可以说明的范围 |
|---|---|
| 离线单测/集成检查 | 所测代码性质和接口，不是模型建模能力 |
| 确定性重放旧产物 | 工具或后段表现，不是新冷启动识图 |
| 使用 GT 诊断 kernel | 受控几何表现，不是无答案生成 |
| 人工调度/反馈/修改 | 明确辅助条件下的结果 |
| 原输入独立完成 | 该输入、模型、方法、版本和预算下的实际结果；推广需要更多证据 |

GT 仅在评价侧使用，不进入 work model 的输入、参考文件或提示。参考自身的缺口和表示约定要披露；不改容差或参照来掩盖退步。未启用项不计通过，NA 不计通过；未提供 expected 的数量检查不能证明对象完整。

## 报告格式

每次测试正文给可读表格，列范围/命令、runtime/domain 版本、结果、耗时、调用与用量、失败和复验、未覆盖范围及证据位置。

真实建模另列案例、输入、模式、各角色模型与思考参数、完成/质量结论、人工干预、关键路径和角色行为，并提供源 BIM、平面、回叠和查看页入口。尺寸差按 ≤5 cm、5–10 cm、10–30 cm、>30 cm 分档；未测的项明确标出，不用单一综合分覆盖拓扑问题。

供应商实报、估算与账单分开；缺 usage 和费用保留未知。旧成功和失败不追改为当前版本结果。模型可随版本变化，选型比较须固定输入、目标和评价条件，区分模型变化与 harness 变化。

## 实现与范围

独立评价主要在 `src/agent/judge` 与显式诊断工具；确定性检查由 kernel、工具反馈及 `src/validator` 提供。旧阶段判卷保留为历史专用流程，不是当前 Agent 的必经门槛。

EnergyPlus 运行成功只证明对应仿真执行条件，不证明建筑正确或实际能耗准确。开发检查按 [development](../workflow/development.md) 选择影响范围，普通文档改动不触发整案或重复全量。

详细历史评分方法、原始基线和实验说明已保存于 [归档索引](../reports/archive-index.md)；本轮未重新评价旧案例。
