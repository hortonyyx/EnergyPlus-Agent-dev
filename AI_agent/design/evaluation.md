# 输出验证与评价

评价目的在于判断轻量 BIM 是否有用、完整、可解释，并衡量投入。探索产出、正式比较和仿真结果分别说明，不要求每次探索先完成评分体系。

## 评价对象

图纸路线评价几何重建与输入证据的一致性；体量路线评价外部约束一致性及内部推断合理性，不要求从外皮唯一恢复未知真实格局。
共同观察尺度/外形、楼层和房间、隔断/开口、相邻与连通、假设和冲突；同时记录成功率、人工补充/编辑次数与时间、总成本和耗时。模型与人工条件相同才适合直接比较。

| 运行方式 | 结果可说明什么 |
|---|---|
| 单测或行为测试 | 所测输入和范围的行为，不是整案能力 |
| 重放已有 reading | 后段工程表现，不是本次冷启动识图 |
| GT 喂内核诊断 | 内核/下游受控表现，不是无答案生成 |
| 人工补充后成功 | 辅助模式结果，保留干预条件 |
| 原始输入到目标出口 | 该输入、代码和模型配置下的实际结果，推广需要更多证据 |

`PASS` 不代表未启用项已覆盖，`NA` 不计作通过。数量检查 expected 未提供时通过不证明房间完整。仿真成功不证明建筑正确；IdealLoads 供冷/供热需求不写成实际用电量。

## 几何检查与问题定位

| 层次 | 检查重点 |
|---|---|
| 输入基准 | 单位、尺度、原点、方向、楼层、内皮/外皮/轴线 |
| 单对象 | 坐标有限、面积/环、平面、自交、退化，开口宿主 |
| 已声明的配对 | 对象存在、互相引用、对应几何和法向 |
| 应有的覆盖 | 应相交范围与实际覆盖的差集，不能仅逐对检查 |
| 建筑完整性 | 源房间、隔断、门窗、空间关系及其来源是否保留 |
| 下游用途 | 对应求解器的几何、构造、边界和使用条件 |

墙面、分段线和物理墙对象先区分，再结合方向、距离、投影、厚度、相邻空间与原始引用找候选；重叠或相互最近不能单独证明同一性。合并分段后比较整体，同时保留原残差。
真实结构差异、参考面转换、识读误差和数值残差分别处理。用途允许的简化应保留源模型并记录改变，再核对覆盖、房间/开口和下游影响；不得为通过而静默删面或改 GT。
项目当前 0.1 m 短边检查不等于已证明的求解器通用底线。统一 50 mm 网格也不是普遍解法。两侧共用同名 Construction 不自动保证非对称材料层序互为反向，应按实际装配核验。

## GT 与当前评分链

GT 留在评测侧，不输入被评测生成器。原始设计几何、人工参考、机器规整与修订各自保留来源；修订要说明改变设计事实还是只规整表示，保留旧版本及相应确认依据。
已有 [gt_revisions.py](../../src/agent/judge/gt_revisions.py)、AnswerCompiler、暂存 facts 和 [judge](../../src/agent/judge/) 可复用。但 [gt_promotion.py](../../src/agent/judge/gt_promotion.py) 未把 facts 随正式 GT 晋升，暂存/签字/正式目录不能视为等价。
当前 as-drawn 平面评分按 request 源哈希查 signed DXF 后编译分母，立面从 GT 派生 targets（[flow_wiring.py](../../src/agent/judge/as_drawn/flow_wiring.py)）；整链尚未统一消费 frozen facts。评分只在实际启用和可用的条件下报告。

## 保存证据

记录代码版本、原始输入、命令与关键配置、模型/人工参与、输出位置、实际结果和未验证范围；稳定结论更新对应正文，具体过程留 run 或日志。不重复建设报告审批链。
输入或参考有矛盾时先展示证据和影响，不把日志末条推论直接升级为根因。用同一物性比较几何是受控诊断，不代表已复现实测能耗；协作者交付只有实际验收后才写成已验证。
