# 输出验证与评价

评价目的在于自动判断轻量 BIM 是否有用、完整、可解释，并衡量投入。2026-09-09 用户重申核心原则：**定性大于定量**。judge + GT 应减少人工核对，把输出是否正确、可用放在逐点误差之前；探索产出、正式比较和仿真结果分别说明。

## 定性判断与自动化

以下是本批执行与验收目标；当前自动化接线和缺口见 [现有实现](implementation.md)，不因本文更新而视为已经完成。

优先回答：楼层和外形是否对、房间是否保留且没有错误合并/凭空细分、门窗是否存在且属于正确宿主、相邻与实际连通是否正确，以及几何是否可供目标用途使用。关键尺度明显错误也属于实质问题；细小位置偏差不与漏房间、错楼层等同处理。

**分区保真是首要验收项。** 已知漏墙、多墙、错误拆房/并房、假楼板或连通改变，按严重问题处理；房间总数相同也可能同时漏一间、多一间，不能只看数量。比较源空间、物理边界和连通关系，允许同一源对象在显示或仿真侧有多个显式派生片。计算片若被导出为实际隔墙、或没有保留源房间身份，就不是轻微表示差异。

sm24 历史 11/8 区数例子不再作为 minor 放行的正例：用户明确该例 reading 正确，C2 之前 correction 把非矩形房间切成矩形。直接产物也显示 `1_correction` 已有 11 个 cell，后段形成三个内部 Wall 配对。应作为“读对但校正改错分区”的回归案例；旧 judge 的 minor 判定只能描述历史，不能作为当前 BIM 验收依据。

复用现有 `StageVerdict` 的 pass/minor/severe/fatal 及证据字段：轻微问题允许带提示继续；影响建筑结构、用途或可靠性的错误打回相应阶段。定性不是让 judge 凭印象打分，判断仍需对象、图像/GT 和确定性检查证据。证据不足或 GT 自身问题标为评测不完整，不能伪造通过或直接归罪生成模型。

日常运行自动做对象匹配、关系检查和报告生成，人工只抽查代表结果、裁决语义冲突或当前机器无法判断的异常。不将每个 case 的人工逐房重录、全量逐点对账或 GT 精修设为运行前置。没有 GT 的生产输入仍能用输入一致性、几何检查与 judge 评价，明确哪些参照不可用。

## 容差、规整和硬约束分别承担什么

| 问题 | 处理原则 |
|---|---|
| CAD 手抖、线段端点微小错开、识读/数值尾差 | 在对象身份与局部关系一致时，按用途容差吸附、闭合、去冗余或重新生成，记录实质变化；原始输入保留 |
| 生成模型与 GT 的位置、面积、窗墙比差异 | 对齐单位、方向和参考面，采用容差比较；指标用于判断量级和定位异常，不要求两个文件具有相同网格、分段或顶点数 |
| 房间丢失/错误合并、错楼层、窗错宿主、连通改变、明显尺度错误 | 属于实质错误，不用扩大容差消掉 |
| 为矩形算法拆房后产生额外隔墙、或在挑空处补上楼板 | 属于严重分区/空间错误；修源模型或派生边界类型，不靠总面积正确、EP 成功或合并热区放行 |
| 模型内部闭合、相交与配对、引用一致 | 由确定性内核生成自洽关系并检查；输入近似不要求输出也留下破缝和悬空引用 |
| 特定求解器的限制 | 在对应出口检查或做有记录的派生转换；区分建筑模型可查看/可用和该求解器能否接受 |

规整后的建筑模型可以作为可编辑的源模型，不要求工作模型原封不动保留 CAD 噪声。保留原始观测与改动来源即可；源房间/隔断身份仍需保留。判定不同物理对象或改变拓扑时不能仅凭坐标接近自动合并。

GT 也允许从原始 CAD 派生有记录的规整参考，不要求先手工修成数学上完美的 CAD。生成侧与评测侧可复用同一几何规整函数，各自独立消费自己的输入；GT 不进入生成侧。评测不能依据当前预测修改答案，也不能用相同规整掩盖共同的漏房间/误合并；保留规整前差异与关系检查。

具体容差按来源、对象尺度和用途选取，用 sm21/sm24/sm25 的“小扰动不应变坏、真实错误必须被检出”对照校准。不全局调粗一个网格，也不把历史 GT 1 mm/产物 10 mm 声明直接当作验收精度。本轮只明确原则；当前代码中的具体门槛仍按下述实现生效，修改须核对消费者并验证。

## 评价对象

图纸路线评价几何重建与输入证据的一致性；体量路线评价外部约束一致性及内部推断合理性，不要求从外皮唯一恢复未知真实格局。
共同观察尺度/外形、楼层和房间、隔断/开口、相邻与连通、假设和冲突；同时记录成功率、人工补充/编辑次数与时间、总成本和耗时。模型与人工条件相同才适合直接比较。

| 运行方式 | 结果可说明什么 |
|---|---|
| 单测或行为测试 | 所测输入和范围的行为，不是整案能力 |
| 重放已有 reading | 后段工程表现，不是本次冷启动识图 |
| GT 喂内核诊断 | 内核/下游受控表现，不是无答案生成 |
| 人工补充后成功 | 辅助模式结果，保留干预条件 |
| 原始输入到目标出口 | 该输入、代码和模型配置下的实际结果，推广需要更多证据 |

`PASS` 不代表未启用项已覆盖，`NA` 不计作通过。数量检查 expected 未提供时通过不证明房间完整。仿真成功不证明建筑正确；IdealLoads 供冷/供热需求不写成实际用电量。

## 几何检查与问题定位

| 层次 | 检查重点 |
|---|---|
| 输入基准 | 单位、尺度、原点、方向、楼层、内皮/外皮/轴线 |
| 单对象 | 坐标有限、面积/环、平面、自交、退化，开口宿主 |
| 已声明的配对 | 对象存在、互相引用、对应几何和法向 |
| 应有的覆盖 | 应相交范围与实际覆盖的差集，不能仅逐对检查 |
| 建筑完整性 | 源房间、隔断、门窗、空间关系及其来源是否保留 |
| 下游用途 | 对应求解器的几何、构造、边界和使用条件 |

墙面、分段线和物理墙对象先区分，再结合方向、距离、投影、厚度、相邻空间与原始引用找候选；重叠或相互最近不能单独证明同一性。合并分段后比较整体，同时保留原残差。
真实结构差异、参考面转换、识读误差和数值残差分别处理。用途允许的规整/简化保留原始依据并记录改变，再核对覆盖、房间/开口和下游影响；不得为通过而静默删面或按预测结果改 GT。
项目当前 0.1 m 短边检查不等于已证明的求解器通用底线。统一 50 mm 网格也不是普遍解法。两侧共用同名 Construction 不自动保证非对称材料层序互为反向，应按实际装配核验。

## GT 与当前评分链

GT 留在评测侧，不输入被评测生成器。原始设计几何、人工参考、机器规整与修订各自保留来源；修订要说明改变设计事实还是只规整表示，保留旧版本及相应确认依据。
已有 [gt_revisions.py](../../src/agent/judge/gt_revisions.py)、AnswerCompiler、暂存 facts 和 [judge](../../src/agent/judge/) 可复用。但 [gt_promotion.py](../../src/agent/judge/gt_promotion.py) 未把 facts 随正式 GT 晋升，暂存/签字/正式目录不能视为等价。
当前 as-drawn 平面评分按 request 源哈希查 signed DXF 后编译分母，立面从 GT 派生 targets（[flow_wiring.py](../../src/agent/judge/as_drawn/flow_wiring.py)）；整链尚未统一消费 frozen facts。评分只在实际启用和可用的条件下报告。

## 保存证据

记录代码版本、原始输入、命令与关键配置、模型/人工参与、输出位置、实际结果和未验证范围；稳定结论更新对应正文，具体过程留 run 或日志。不重复建设报告审批链。
输入或参考有矛盾时先展示证据和影响，不把日志末条推论直接升级为根因。用同一物性比较几何是受控诊断，不代表已复现实测能耗；协作者交付只有实际验收后才写成已验证。
