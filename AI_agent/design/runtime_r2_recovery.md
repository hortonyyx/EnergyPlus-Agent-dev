# 运行底座 R2：截断补救、输出上限与可核对记账

实现与证据入口：[R2 交付](../logs/experiments/2026-10-03_runtime_r2/README.md)。
本包只修改运行底座、契约及验证；建模工具、指引、几何、原执行模块保持原字节。

## 输出截断

`finish_reason=length` 表示整条回复未完成。适配器保存原始回复、可见文字和公开思考证据，
但不会把这条回复的任何工具调用暴露为可执行调用；即使某个调用已经是完整 JSON，
与半截调用同批返回时也一并丢弃。工具执行前仍有原来的角色授权检查。

底座先按接口实报全额结算，再写 `response_truncation` 事件，记录原请求/回复引用、
思考与可见文字的字符数、实报思考 token、有无工具调用、连续/累计次数及继续/停止原因。
下一次请求只增加一条短提示：上次超过输出上限，思考未保留、工具未执行，请直接给下一步完整调用或简短回答。
被截断的回复既不进入普通历史，也不参与后续上下文压缩。

默认每个任务允许连续补救 2 次；整个根运行（包括子角色和摘要请求）累计允许 3 次。
配置分别为 `RunLimits.max_consecutive_truncations` 和 `max_total_truncations`，CLI 对应
`--max-consecutive-truncations`、`--max-total-truncations`。设 0 即不补救，超过次数仍停为
`incomplete_response`。外层协调服务将根配置传给子角色；子请求同时消耗子账和根账，
新请求照常预留调用次数、token 和剩余时间。传输重试与截断补救分别计数，二者都不免费。

记录可在恢复时重放：已结算的回复不重复收费；截断事件和短提示按回复身份去重；
崩溃发生在回复之后、短提示之前时仍能补回提示；从保存点恢复不重置连续或累计次数。
缺失用量、时间耗尽和预算耗尽仍阻止新请求。

## 输出上限

`model_profiles.json` 中 `recommended_min_output_tokens` 与 `output_limit_source` 共同保存建议与依据：

| 模型 | 建议最小上限 | 现有证据 |
| --- | ---: | --- |
| GLM-5.3-Flash | 32,000 | 迁移首试 16,384 被思考用尽；Claude Code 同案例上限 32,000，曾有约 19,600 思考 token |
| Qwen3.8-27B | 16,384 | 历史局部运行最大输出 12,212、思考 11,473 |
| Qwen3.8-Flash | 16,384 | 历史最大输出 8,031 已接近 8,192；此处采用保守余量 |

这是基于已观察运行的建议，不是服务端硬上限，也不保证不会截断。小型协议探针、限定局部
回答可以用 `--low-output-limit-reason` 显式放行；理由只写入运行配置和回执，不送给服务端当作参数。
原有 R1 配置不改；`runtime_r1_preparation check/command/launch` 都验证上限，历史小上限会被拒绝。
可用该命令的同名参数记录临时例外，不必覆盖历史 JSON；例外随生成的启动命令传递。
若预算策略降低输出，在没有显式例外时也不会降到建议值以下。

## 版本和图片记账

`agent_versions.json` 登记完整工具实现闭包、指引、任务说明文件及四种工具目录哈希。
历史 `5bb10538` 保留；运行时校验当前登记，版本进入请求、启动记录与回执，外层协调
`runtime_state` 也报告版本。登记新版本的命令：

```bash
PYTHONPATH="$PWD" python -m src.agent_runtime.agent_registry register --root . --version agent-t1
PYTHONPATH="$PWD" python -m src.agent_runtime.agent_registry verify --root .
```

新增实现文件用 `--add-file tool:相对路径`；新增工具名称还需显式配置角色的工具授权。
登记动作不是扩大权限的替代品。Claude Code 运行器未在本包内修改。

图片用量通过实际发送字节的尺寸和型号公式估算，预留时已经包含在输入上界中，结算时
与 `actual.tokens` 中的服务实报分开。如果回包能用 `prompt_tokens=text_tokens+image_tokens`
证实已包含图片，就不再叠加；缺少该证据时，将图片估算加入预算，原始 usage 完整保留。
人民币估算由已有账单单价计算，回执分别给实报、图片估算、可核算部分和完整性标记；
没有足够单价证据时不伪造完整费用。GLM 图片是否另计、缓存单价仍为未知。
详见 [图片账单校准](../logs/experiments/2026-10-03_runtime_r2/image_accounting_calibration.md)。

## 验证边界

真实小测只验证 GLM 截断补救：128 输出上限，第一次截断，第二次回答 `OK`，2 次请求、
369 实报 token、约 4.01 秒，按文本单价估计 0.0006152 元（不是账单）。
迁移首试的真实 63,420-token 回复另用于离线反例；不得将此重放算作新增服务调用。
阶段 0–3/R1 回归继续验证恢复、预算、图片引用与真实工具行为，不代表新的整栋建模质量验收。
