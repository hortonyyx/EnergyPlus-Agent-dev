# 带贴图体量路线：调研与首例建议

2026-09-10。用户已确认当前先收束到“已有三维几何 + 图片贴图”的输入，纯照片另列分类；各类输入都应利用已有信息与明确推断产出有用模型。缺信息时可在生成过程中交互补足，这与 BIM 停点编辑不同。相关目标见 [产品目标](../project/goal.md)，实际素材见 [案例库](../../case_tests/textured_mass/README.md)。

## 调研结论

**能先拿到案例，并开展有边界的体量到 BIM 实验。** 当前已下载三个真实城市片区，加载几何与纹理、生成纯输入副本及预览；不能据此声称内部推断或 BIM 生成已跑通。当前可复用源 BIM、确定性几何工具和查看机制，新工作主要在体量读取、视图与空间位置对应、外壳语义及内部假设。

已有外部几何会减少外形、比例和视角对齐的推断，但它可能有噪声、缺面、植被与建筑粘连。窗常在图片贴图上比在三角面形状上更清楚；网格可渲染并不意味着是闭合建筑，更不意味着已有楼层、门窗或空间关系。

## 首例怎样接现有产品

以下是实施建议，尚未固定为所有输入必须遵循的流水线：

1. **确定建筑范围与可用几何。** 先选择一个主体较完整的单栋及少量周边；记录选择范围、坐标变换、单位依据和缺面。计算截面、拟合主要墙/屋面等由代码工具完成，保留未规整原件供比较。不要求先修成完美闭合网格。
2. **让模型看贴图并取得空间位置。** 工具可提供整体、局部与立面方向视图，同时保留相机参数、深度/面 ID，支持图像点回到三维表面。纹理图集本身常被切碎，不宜只把图集当平面建筑图阅读。模型识别楼层、窗、门、阳台，代码执行投影、尺寸计算和宿主关系检查。
3. **在外壳约束下补内部。** 结合用途、入口、进深、窗排列和已知楼层提出房间/走廊方案。需要时询问用途、层数或已知尺寸；回答细化当前假设，能先推进的部分继续。未知内部允许形成细致候选，但窗数不直接等于房间数，不能把推断隔墙标成观测事实。
4. **形成共同 BIM 并回看。** 共用源空间、边界、开口与连接，保留每项来源。由代码检查相交、越界、宿主、实际连通及主要外形一致性；总 Agent 可根据图像/几何反馈选择局部修订。当前源方案导出主要覆盖正交多边形，非正交墙、复杂屋顶等需要按首例实际范围接入，不能先声明任意实景网格可用。

首例建议从 `Tile_+1985_+2693` 中选一个与邻楼分开的主体，先得到含楼层和开口、内部假设清楚的可查看 BIM；用途/楼层并未由本次预览确认。之后再用连续街区和树木遮挡样例试验边界、内院与缺失处理。选目标本身若由开发助手完成须记为输入准备；不能把评测标签帮助裁楼或内部答案输入后的结果报告为完全自动冷启动。

## 评价能承诺什么

- 本轮下载/加载/贴图/去标签检查证明素材可接入工具，不证明生成能力。
- 外壳可对照原网格与多视图图片，评价主要轮廓、开口、楼层线索和遮挡处理；数据自身误差与几何规整分别说明。
- 内部没有图纸时评价约束一致性、空间可用性与假设合理性，不评价“恢复了真实房间布局”。后续加入图纸可用于生产细化；独立 GT 仍留在评测侧。
- 生成中交互补信息、人工选目标、旧结果恢复和独立冷启动分别记录。第一轮不要求完整停点编辑、物性或 EP。
