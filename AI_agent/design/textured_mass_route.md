# 带贴图体量路线：调研与首例建议

2026-09-10。用户已确认当前先收束到“已有三维几何 + 图片贴图”的输入，纯照片另列分类；各类输入都应利用已有信息与明确推断产出有用模型。缺信息时可在生成过程中交互补足，这与 BIM 停点编辑不同。相关目标见 [产品目标](../project/goal.md)，实际素材见 [案例库](../../case_tests/textured_mass/README.md)。

## 研究对象与产品目的（用户后续确认）

目的是改善前期仿真输入，研究对象是办公、住宿、普通商业等类型化**单体建筑，不考虑周边环境建模**。城市尺度仅是问题背景。复杂公共建筑不是近期主要对象，后续特化或明确简化。类型化也允许混合用途和局部变化，不能将全楼强套同一标准层。

**用户在生成前决定通用轻量 BIM 的复杂度，生成不以选择模拟目的或后端插件为前提。** 先交付由逻辑闭合空间块组成的共同模型，再由用户选择不同模拟插件；后端可以继续调整模型、合并热区等。用户举出的三档滑块及办公楼划分是复杂度含义的示例，尚未固定界面和档位。复杂度不等于实测准确性。当前只讨论方案，不开展新体量生成实验。

## 用户获取输入与现有模拟实践

用户可以通过开放城市数据、项目既有测绘成果或自行扫描重建的导出文件提供这种输入。例如 [OpenDroneMap 官方输出](https://docs.opendronemap.org/outputs/) 包含带纹理 OBJ 及对应图片。优先入口建议为单栋 GLB 或 OBJ+MTL+贴图包，附可用的单位、方向、位置及建筑用途；资料缺少时进入交互/假设分支。城市瓦片先通过选楼/裁剪形成单体输入，非目标楼体、地面与树木的分离属于输入准备，不生成环境 BIM；完整原件只保留作来源。不同地区的开放覆盖和采集质量有差异，不能承诺任意地址可直接下载。

另有一种更轻的来源是**带图片纹理的规则化建筑外壳**，不必都是密集摄影测量网格。[Helsinki 官方说明](https://www.hel.fi/en/decision-making/information-on-helsinki/maps-and-geospatial-data/helsinki-3d) 同时提供实景 OBJ 和带纹理的 LoD2 城市建筑模型；后者包含建筑对象身份，适合从单体层次组织输入。既有 BIM/CAD 导出的外壳也可进入同一输入类，但可见表面证据与原文件中已有语义应分别利用。

当前城市建模的常见基线可概括为建筑轮廓/高度/层数，加建筑用途、年代等信息，再赋典型参数与简化分区。界面上的体块不表示求解器内部完全没有窗、楼层或热区：

- [CEA 官方当前数据管理说明](https://github.com/architecture-building-systems/CityEnergyAnalyst/blob/master/docs/tutorials/cea4-app-training/08-data-management.md) 以用途、年代、建造标准及气候区映射典型围护、窗墙比、层高、内部负荷和系统信息。
- [URBANopt 基线](https://docs.urbanopt.net/resources/scenarios/baseline.html) 从 GeoJSON 拉伸建筑并派生核心/周边热区，可考虑邻楼遮阳，结合典型建筑构造、作息和系统。其 [映射接口](https://docs.urbanopt.net/resources/customization/modifying_mapper.html) 允许部分建筑使用详细 OpenStudio 模型，其他建筑继续默认生成。
- [UMI 能源模块](https://umidocs.readthedocs.io/en/latest/docs/energy-module-advanced.html) 使用代表性 shoebox 模型作为计算抽象。不能将所有城市模型统称为完全无细节体块，也不能假设增加源细节会自动穿透这些后端的简化。

这些资料支持的产品机会是：利用实际外壳、贴图与补充信息，减少单栋几何/开口对统一默认值的依赖，按用户选择的空间复杂度生成通用 BIM，再向后端交付。上面的模拟做法仅是背景，不定义本项目源空间划分，也不引入环境建模。现有详细模型接口说明存在对接路径，**本项目尚未实现 CEA、UMI 或 URBANopt 的适配**。

## 复杂度与空间块（用户确认）

复杂度控制源 BIM 对建筑空间展开到多细，各档都交付通用的空间块、边界、门窗/开口与关系。以下复述用户的高层办公楼示例，不规定所有建筑的块数、形状或相同标准层：

| 示例档位 | 源 BIM 的空间划分 | 表达含义 |
|---|---|---|
| 简单 | 每层一个核心筒块 + 一个四周块 | 表达主要空间组成，四周块内部的办公室等不逐间展开 |
| 中等 | 核心筒块 + 走廊块 + 四个朝向的办公室块 | 表达主要功能分区与相邻、连接关系 |
| 复杂 | 推断每间办公室及相关交通/服务空间，处理跨层不一致 | 将内部展开到房间级，保留标准层与局部例外 |

这里的核心筒/四周块是用户选择的**源空间抽象**，不能仅因它外形类似热区划分就移交后端。一个块可以代表多个未展开的房间，不宣称其内部真的没有隔墙。块边界需区分观测或推断的物理隔断、抽象分界和未知状态；闭合用于界定空间范围与体积，不等于每张边界面都是实墙或实楼板。

低复杂度可直接生成粗空间方案，无需先完整推断逐间布局再合并。已有细致资料可保留在输入证据及抽象对应记录中，不要求低档输出全部细节；用户选择的简化必须可解释，不能静默漏掉已知对象再冒称逐间重建成功。环绕核心筒的四周块允许是非矩形、有内环的逻辑单元；若几何实现需分片，应保持一个源块身份，计算片间不增设物理墙。具体表示尚待实现，不据此声称现有单外环导出已支持。

建筑用途、层数、入口、窗排列和已知尺寸为推断提供依据；模拟用途不决定生成档位。细档允许更多明确标注的内部推断，并可在生成过程中交互补信息。复杂度是用户要求的空间粒度，准确性取决于证据和验证，两者分别报告。

## 生成组织与后端边界（方案建议）

建议依赖关系为：**单体输入 + 用户选择复杂度 → 外壳与楼层/开口观察 → 相应粒度的空间块方案 → 通用 BIM 生成与检查 → 查看/编辑 → 选择模拟插件 → 后端派生与调整**。用户未选择模拟也能完成 BIM 生成和交付。总 Agent 按当前信息选择查看、量测、类型假设、提问、生成与检查动作，可回看与局部修订；这不是固定串行 Agent 清单。生成中补信息与生成后的停点编辑分别处理。

类型规律可以作为先验和确定性几何工具，例如标准层重复、核心筒与走廊布置、窗与房间的相对约束。模型按用户复杂度判断展开层次、适用模式及例外，代码求尺寸、排布与检查；不把办公/住宿写成唯一平面模板。外部观测和内部假设共同形成源 BIM，原始网格留作证据。

后端从该源 BIM 派生自身模型，可以进一步合并、细分、调整或补充。**源空间粒度和后端计算粒度是两项独立选择**；同一个简单档或复杂档 BIM 都可接不同插件，后端调整记录与源对象的对应关系，不静默覆盖共同底座。材料构造和运行参数沿用协作者模块。

后续评价可在同栋建筑、不同源复杂度上分别检查空间表达质量，再通过具体后端检验仿真改善。后端是否消费新增细节会影响结果，但不能反过来成为生成档位的定义或必填配置。当前不开展仿真，也不把细节数量当成精度提升证据。

## 调研结论

**能先拿到案例，并开展有边界的体量到 BIM 实验。** 当前已下载三个真实城市片区，加载几何与纹理、生成纯输入副本及预览；不能据此声称内部推断或 BIM 生成已跑通。当前可复用源 BIM、确定性几何工具和查看机制，新工作主要在体量读取、视图与空间位置对应、外壳语义及内部假设。

已有外部几何会减少外形、比例和视角对齐的推断，但它可能有噪声、缺面、植被与建筑粘连。窗常在图片贴图上比在三角面形状上更清楚；网格可渲染并不意味着是闭合建筑，更不意味着已有楼层、门窗或空间关系。

## 首例怎样接现有产品

以下是实施建议，尚未固定为所有输入必须遵循的流水线：

1. **确定建筑范围与可用几何。** 先选择一个主体较完整、用途符合范围的单栋；记录选择范围、坐标变换、单位依据和缺面。移除非目标对象属于输入准备，不重建周边环境。计算截面、拟合主要墙/屋面等由代码工具完成，保留未规整原件供比较。不要求先修成完美闭合网格。
2. **让模型看贴图并取得空间位置。** 工具可提供整体、局部与立面方向视图，同时保留相机参数、深度/面 ID，支持图像点回到三维表面。纹理图集本身常被切碎，不宜只把图集当平面建筑图阅读。模型识别楼层、窗、门、阳台，代码执行投影、尺寸计算和宿主关系检查。
3. **按用户复杂度补内部。** 在外壳与楼层约束下，结合建筑用途、入口、进深和窗排列提出相应粒度的空间块方案。需要时询问用途、层数或已知尺寸；回答细化当前假设，能先推进的部分继续。粗块不必先推断每间房，细档也不能把窗数直接等同于房间数；推断隔墙与抽象分界分别说明。
4. **形成共同 BIM 并回看。** 共用源空间、边界、开口与连接，保留每项来源。由代码检查相交、越界、宿主、实际连通及主要外形一致性；总 Agent 可根据图像/几何反馈选择局部修订。当前源方案导出主要覆盖正交多边形，非正交墙、复杂屋顶等需要按首例实际范围接入，不能先声明任意实景网格可用。

**案例建议已随用户范围调整：** 三片 SUM 数据保留为素材池，先核实普通办公、住宿或商业用途及单栋边界，再选择首例。此前仅依据独立外形推荐 `Tile_+1985_+2693` 中主体的标准不足，不再默认指定；用途未核实的独立主体或复杂公共建筑不优先。之后再按需要选择带内院或有遮挡的单栋样例。开发助手选目标须记为输入准备，不能把评测标签帮助裁楼或内部答案输入后的结果报告为完全自动冷启动。

## 评价能承诺什么

- 本轮下载/加载/贴图/去标签检查证明素材可接入工具，不证明生成能力。
- 外壳可对照原网格与多视图图片，评价主要轮廓、开口、楼层线索和遮挡处理；数据自身误差与几何规整分别说明。
- 内部没有图纸时评价约束一致性、空间可用性与假设合理性，不评价“恢复了真实房间布局”。后续加入图纸可用于生产细化；独立 GT 仍留在评测侧。
- 生成中交互补信息、人工选目标、旧结果恢复和独立冷启动分别记录。第一轮不要求完整停点编辑、物性或 EP。
