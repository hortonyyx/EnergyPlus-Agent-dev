# 带贴图体量路线：调研与首例建议

2026-09-10。用户已确认当前先收束到“已有三维几何 + 图片贴图”的输入，纯照片另列分类；各类输入都应利用已有信息与明确推断产出有用模型。缺信息时可在生成过程中交互补足，这与 BIM 停点编辑不同。相关目标见 [产品目标](../project/goal.md)，实际素材见 [案例库](../../case_tests/textured_mass/README.md)。

## 研究对象与产品目的（用户后续确认）

目的是改善前期仿真输入，研究对象是办公、住宿、普通商业等类型化**单体建筑**；城市尺度是应用背景，周边城市几何可以作为遮阳/遮挡等场景。复杂公共建筑不是近期主要对象，后续特化或明确简化。类型化也允许混合用途和局部变化，不能将全楼强套同一标准层。

需要补充到什么程度由用户项目配置。配置目标细化程度并不保证相应实测准确性；具体配置字段与组织方式仍是下文助手建议。当前用户要求只讨论方案，本轮不开展新体量生成实验。

## 用户获取输入与现有模拟实践

用户可以通过开放城市数据、项目既有测绘成果或自行扫描重建的导出文件提供这种输入。例如 [OpenDroneMap 官方输出](https://docs.opendronemap.org/outputs/) 包含带纹理 OBJ 及对应图片。优先入口建议为单栋 GLB 或 OBJ+MTL+贴图包，附可用的单位、方向、位置及用途；资料缺少时进入交互/假设分支。城市瓦片可先通过选楼/裁剪工具形成单体输入，并保留周边对象，不把整座城市重建作为单栋建模前置。不同地区的开放覆盖和采集质量有差异，不能承诺任意地址可直接下载。

另有一种更轻的来源是**带图片纹理的规则化建筑外壳**，不必都是密集摄影测量网格。[Helsinki 官方说明](https://www.hel.fi/en/decision-making/information-on-helsinki/maps-and-geospatial-data/helsinki-3d) 同时提供实景 OBJ 和带纹理的 LoD2 城市建筑模型；后者包含建筑对象身份，适合从单体层次组织输入。既有 BIM/CAD 导出的外壳也可进入同一输入类，但可见表面证据与原文件中已有语义应分别利用。

当前城市建模的常见基线可概括为建筑轮廓/高度/层数，加建筑用途、年代等信息，再赋典型参数与简化分区。界面上的体块不表示求解器内部完全没有窗、楼层或热区：

- [CEA 官方当前数据管理说明](https://github.com/architecture-building-systems/CityEnergyAnalyst/blob/master/docs/tutorials/cea4-app-training/08-data-management.md) 以用途、年代、建造标准及气候区映射典型围护、窗墙比、层高、内部负荷和系统信息。
- [URBANopt 基线](https://docs.urbanopt.net/resources/scenarios/baseline.html) 从 GeoJSON 拉伸建筑并派生核心/周边热区，可考虑邻楼遮阳，结合典型建筑构造、作息和系统。其 [映射接口](https://docs.urbanopt.net/resources/customization/modifying_mapper.html) 允许部分建筑使用详细 OpenStudio 模型，其他建筑继续默认生成。
- [UMI 能源模块](https://umidocs.readthedocs.io/en/latest/docs/energy-module-advanced.html) 使用代表性 shoebox 模型作为计算抽象。不能将所有城市模型统称为完全无细节体块，也不能假设增加源细节会自动穿透这些后端的简化。

这些资料支持的产品机会是：利用实际外壳、贴图与补充信息，减少单栋几何/开口对统一默认值的依赖，按项目目的组织内部空间，再向可消费这些细节的后端交付。现有详细模型接口说明存在对接路径，**本项目尚未实现 CEA、UMI 或 URBANopt 的适配**。

## 配置与生成组织（方案建议）

建议用“项目用途预设 + 分项覆盖”，并把目标细化程度与观测/推断依据分开保存：

| 配置维度 | 可选方向及含义 |
|---|---|
| 分析目的 | 年能耗/冷热负荷、日照/遮阳、室内采光、自然通风等，决定优先获取哪些信息；并非都已接后端 |
| 外壳与开口 | 主要轮廓和分面窗墙比、规则窗列、逐窗位置/形状及重要遮阳；保存已知细节，后端按需简化 |
| 内部空间 | 未解析内部、楼层空间、典型功能分区、房间/走廊级；推断的物理隔断明确标注，未知内部不当成真实开敞大厅 |
| 先验条件 | 用途/混合用途、年代、层数、标准层、户型/走廊形式等；有来源的用户信息优先于一般类型假设 |
| 信息补足策略 | 可询问的关键问题、允许采用的假设及可选候选方案；精细请求但证据不足时说明实际产出与缺口 |
| 时间与预算 | 控制识别、复核、候选和局部细化投入，不定义准确率承诺 |

同栋建筑的不同属性可细化到不同层次。例如已识别逐窗位置而内部只知用途，可保留逐窗外壳并暂以楼层空间表达内部未解析状态；不因总体选择较粗而删除已有可靠对象。标准层可用于推断重复模式，首层商业、屋顶退台等例外仍单独处理。

建议依赖关系为：**目标/配置与输入 → 单体及周边 → 外壳/开口证据 → 按需内部方案 → 共同 BIM → 后端派生**。总 Agent 在这组依赖上选择查看、量测、类型假设、提问、生成与检查动作，可回看与局部修订；不是六个固定串行 Agent。需要的重要信息可在任何生成环节询问，不等 BIM 交付停点才补。

类型规律可以做成可配置先验和确定性几何工具，例如标准层重复、走廊布置、窗与房间的相对约束。模型判断适用模式及例外，代码求尺寸、排布与检查；不让语言模型逐个猜全部顶点，也不把办公/住宿写成唯一平面模板。语义观测与规则外壳共同进入 BIM，原始密集网格作为证据/场景保留。

**用于计算的核心/周边分区等仍由后端派生，不能回写为真实房间隔墙。** 材料构造和运行参数沿用协作者模块，图像外观不能直接证明墙体构造或热工参数。用户选择细化程度不会改变源/派生边界。

仿真接口需有细节消费说明：如果后端只取总面积和统一窗墙比，逐窗位置的改进未必影响它的结果。研究建议按同一建筑比较“体块+典型参数”“外壳/开口增强”“再加内部推断”，受控保持物性等条件一致，并与有更充分资料的参考模型对照，检验新增几何是否改善所关心指标。该设计用于验证目标，当前不开展仿真或把细节数量当成精度提升证据。

## 调研结论

**能先拿到案例，并开展有边界的体量到 BIM 实验。** 当前已下载三个真实城市片区，加载几何与纹理、生成纯输入副本及预览；不能据此声称内部推断或 BIM 生成已跑通。当前可复用源 BIM、确定性几何工具和查看机制，新工作主要在体量读取、视图与空间位置对应、外壳语义及内部假设。

已有外部几何会减少外形、比例和视角对齐的推断，但它可能有噪声、缺面、植被与建筑粘连。窗常在图片贴图上比在三角面形状上更清楚；网格可渲染并不意味着是闭合建筑，更不意味着已有楼层、门窗或空间关系。

Google Earth 继续作为输入形态参照。Google 官方 [Map Tiles 政策](https://developers.google.com/maps/documentation/tile/policies?hl=en) 限制内容存储等用途，[官方 FAQ](https://mapsplatform.google.com/resources/blog/commonly-asked-questions-about-our-recently-launched-photorealistic-3d-tiles/) 也明确讨论机器解读/提取的限制。因此当前获取可离线保留、用于建模分析的实验素材时，优先上述开放城市数据。本轮没有从 Google 提取网格或调用其付费 API。

## 首例怎样接现有产品

以下是实施建议，尚未固定为所有输入必须遵循的流水线：

1. **确定建筑范围与可用几何。** 先选择一个主体较完整的单栋及少量周边；记录选择范围、坐标变换、单位依据和缺面。计算截面、拟合主要墙/屋面等由代码工具完成，保留未规整原件供比较。不要求先修成完美闭合网格。
2. **让模型看贴图并取得空间位置。** 工具可提供整体、局部与立面方向视图，同时保留相机参数、深度/面 ID，支持图像点回到三维表面。纹理图集本身常被切碎，不宜只把图集当平面建筑图阅读。模型识别楼层、窗、门、阳台，代码执行投影、尺寸计算和宿主关系检查。
3. **在外壳约束下补内部。** 结合用途、入口、进深、窗排列和已知楼层提出房间/走廊方案。需要时询问用途、层数或已知尺寸；回答细化当前假设，能先推进的部分继续。未知内部允许形成细致候选，但窗数不直接等于房间数，不能把推断隔墙标成观测事实。
4. **形成共同 BIM 并回看。** 共用源空间、边界、开口与连接，保留每项来源。由代码检查相交、越界、宿主、实际连通及主要外形一致性；总 Agent 可根据图像/几何反馈选择局部修订。当前源方案导出主要覆盖正交多边形，非正交墙、复杂屋顶等需要按首例实际范围接入，不能先声明任意实景网格可用。

**案例建议已随用户范围调整：** 三片 SUM 数据保留为素材池，先核实普通办公、住宿或商业用途及单栋边界，再选择首例。此前仅依据独立外形推荐 `Tile_+1985_+2693` 中主体的标准不足，不再默认指定；用途未核实的独立主体或复杂公共建筑不优先。之后再按需要加入街区/内院与遮挡样例。开发助手选目标须记为输入准备，不能把评测标签帮助裁楼或内部答案输入后的结果报告为完全自动冷启动。

## 评价能承诺什么

- 本轮下载/加载/贴图/去标签检查证明素材可接入工具，不证明生成能力。
- 外壳可对照原网格与多视图图片，评价主要轮廓、开口、楼层线索和遮挡处理；数据自身误差与几何规整分别说明。
- 内部没有图纸时评价约束一致性、空间可用性与假设合理性，不评价“恢复了真实房间布局”。后续加入图纸可用于生产细化；独立 GT 仍留在评测侧。
- 生成中交互补信息、人工选目标、旧结果恢复和独立冷启动分别记录。第一轮不要求完整停点编辑、物性或 EP。
