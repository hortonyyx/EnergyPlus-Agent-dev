# 两路输入与同一个轻量 BIM

状态：设计建议，尚未统一实现。产品目标见 [交付范围](../project/goal.md)，已有接口见 [现有实现](implementation.md)。

## 输入适配与共同出口

```text
图纸 / 文字 / case → 图纸观测与重建 ─┐
带表皮体量       → 外形读取与内部推断 ┼→ 证据整合与缺失补全 → 轻量建筑模型
CAD / 其他资料   → 相应输入适配 ─────┘                         │
                                          查看、编辑与质量说明 ←┤
                                                BIM 停点版本 ←┘
                                                     ├→ EP：热区/切配 + 独立物性 → IDF → 仿真
                                                     └→ 其他后端（后续）
```

图纸适配利用尺寸、房间和视图证据重建；体量适配先保存外形、楼层和表皮，再推断缺失内部。CAD 生产输入和 CAD→GT 工具分别处理，不把评测答案输入生成器。
不同模态可有不同观测 schema，共用 [建筑模型](model.md)、坐标与来源约定、几何内核和输出。体量无需伪装成平立面 reading；不复制两套整条管线。

共同底座采用空间体、边界面、门窗/其他开口及关系；逻辑上可计算体积，物理开口仍可连通。建筑源模型不承担所有求解器的最终网格和边界条件，EP 热区与其他用途几何分别派生。计算切分不能把一个源空间变成多个物理房间，也不能把挑空填成楼板。最小源对象、显式门洞/连通及结构化平面开口记录自动接入已实现，全图识读、编辑和一般开口仍须补齐，范围见 [共同模型](model.md)。

图纸和后续 CAD 适配均允许在来源/拓扑约束下做容差规整，交付正确、自洽的建筑模型。judge + GT 自动评价结构、语义和用途相关精度；GT 的 CAD 解析/规整工具可复用于生产适配，但答案和输入分别管理。以 [定性优先的评价原则](evaluation.md) 为准，不将原始 CAD 每个顶点当成工作模型必须精确复刻的目标。

## 图纸 reading / correction 的设计依据

09-10 已完成三位 Claude 梳理及主助手原件复核。用户随后明确：改双线是为了减少 reading 提前选线的推理负担，但不应再由固定表示/量测工序限制泛化。模型负责识别图意、选择证据与工具、处理冲突及推断；代码负责测量、计算、装配与自洽检查。单线、双面和墙带按输入选用，不预先固定唯一自动出口。历史依据、当前接线及下一项见 [reading / correction 设计](reading_correction.md)。

## 源 BIM 生成与 EP 后端的边界

原图自动主干现有显式入口：`flow --reading-model` 先调用 `execution/automatic_reading.py`，复用既有隔离构建、订阅读图与可信合并；通过后再走普通校正和源生成。一次失败保存并停止，复用已接受 reading 不重抽。校正由 `claude_subscription` 配置调用无工具的文本 CLI；`--llm-config` 从主干起点生效，读图模型单独显式选择。当前是第一批真实实验入口，不宣称所有图纸可无人值守通过。

09-09 本次开工用户调整主线：先完成原图 → 观测 → 校正/源几何重建 → 丐版 BIM 与查看/质量报告。当前生成出口不挂载热工物性，不依赖 EP 切配；持久编辑暂缓，后续统一设计直接操作、自然语言及结合方式，并考虑插件中的物性挂载修改。

源层负责房间/楼层/边界/门窗开口、真实隔断、相邻和连通、来源及假设。为识别共享边界所需的几何求交、覆盖判断，以及显示三角化仍可使用；EP 所需的热区派生、表面切分与一一配对、物性装配、专用检查和导出属于后端插件。源层检查保留完整性、几何自洽和真实空间关系，不能把解除 EP 检查依赖等同于免检。

**当前实现（`d6fd8732`）**：`flow --target source-bim --bim-out NEW_DIRECTORY` 在正常 reading/correction 后调用独立源生成器，不进入旧 Stage 2–5，也不创建人工确认。`bim CASE RUN --out NEW_DIRECTORY` 可单独复用已接受校正；显式 `--candidate-attempt N` 可查看核验过的候选，不授予接受状态。源输出为 `source_bim_v2`，完整边界、接触区域、门窗宿主及两侧关系不依赖 EP 表面。显示投影负责扣洞和重叠区域隐藏，源模型本身不切成显示片。保留多边形合法性、房间覆盖/重叠、开口宿主/连通与完整性检查；源多边形不套用旧内核 0.1 m 短边下限。

09-09 通用底座增量接通显式围护声明：主干可选 `--enclosure-input`，在源生成阶段保留完整逻辑空间并输出 v3 的真实/开敞/未知区域；查看投影独立扣面，EP 仍按版本明确拒绝尚未适配的语义。无需先补遮阳、物性或空气交换；旧 v2 的正常分叉继续可用。契约和范围见 [共同模型](model.md#显式实际围护09-09-v3-增量)。

09-09 用户进一步明确：这是共同主干后的多条分叉，当前需要跑通 EP 分叉。现已增加 `execution/ep_branch.py`：仅从停点 `source_bim_v2` 派生热区、切配和窗，逐面核对源边界覆盖及真实接触区域，再装配独立的无几何物性模板；不回读 correction。`flow` 默认停在源 BIM，`--target ep` 接上这一分叉，历史 Stage 2–5 路线须显式 `--target legacy-ep`。`backend-ep` 可从已保存的 BIM 直接起跑。sm21 共同主干加 EP 分叉已实际全年运行成功、0 severe，源文件未改；这是历史上游重放与既有物性模板，尚非原图冷启动。详见 [EP 分叉实现与证据](../logs/worklog/2026-09-09_ep_branch.md)。

首版 EP 分叉按一个源房间一个热区派生，支持正交空间、外窗及独立理想负荷物性模板；源北向优先，未知时把模板北向记录为假设。后续已接显式关闭门，必须逐源门 ID 配置关闭状态、构造和理由，源中未知状态不被回写；内门双侧、外门单侧，派生切片保留来源。已知敞开门/空通道、一般 HVAC 与物性编辑仍待适配，遇到时明确拒绝，不简化源 BIM。见 [本轮门适配记录](../logs/worklog/2026-09-09_ep_doors.md)。新分叉记录版本摘要和实验身份，不伪造旧 flow 的人工确认；旧查看/确认机制暂留历史路线，完整编辑及确认交互另行统一设计。

## 输入不完整与冲突

充分输入支持较细的房间、隔断和开口；缺少内部证据时输出带明确假设的推断空间，粗热区仍是派生物。缺少尺度时说明相对坐标或概念尺寸，缺少窗信息时可用可替换的默认方案。
09-10 用户确认采信顺序为 **标注 + 像素双证据 ＞ 像素证据 ＞ 纯推理**。按对象/属性利用现有信息，标注缺失、像素量测失败或图像表现形式不同不应自动终止源生成；模型可补全明确假设，代码执行。证据越充分，输出可承诺的精度越高，而非只有最高证据档才能出 BIM；材料分层等热工信息在后端补充。
“给多少输入都产出输出”是目标能力：降级产出当前信息能支持的有用模型和缺失说明，不用空 JSON 充数，也不把概念模型称作真实重建。
新增图纸或 CAD 只细化有依据的对象，保留来源、变换和冲突；不写死后来覆盖先来或 CAD 永远正确。质量先用来源与可解释等级，不制造未校准的精度百分比。

## 查看、编辑与确认

用户确认图纸路线的主要人工交互停点放在 **Stage 2 形成可查看源 BIM 之后、进入下游用途派生之前**。人工重点看源房间、隔断、门窗、层间关系和需要判断的假设；自动 gate/judge 先提供检查结果，人工无需逐尺寸核对。上游关键歧义仍可提前询问，但不默认让用户逐阶段审批。

近期最低交付是复用 [现有查看器](../../scripts/tool_scripts/render_geometry_viewer.py) 的离线 HTML：可旋转、缩放、半透明、剖切、分层/分区展开、点选和测量；同时提供自动质量报告、假设及未完成项。09-09 已增加显式门/空开口扣洞显示、来源和两侧连接；未覆盖全部源 BIM 类型。只要有可安全显示的几何，失败/局部结果也应有明确状态的查看入口；未通过下游专用检查不应使已有源 BIM 无法查看。

首步先贯通“生成 → HTML 查看 → 记录人工确认 → 恢复执行”，确认可沿用 CLI/记录入口，HTML 内按钮和完整编辑界面后续设计。自动实验可按既有策略继续并记录未人工确认，不将自动通过冒充人工确认。确认应绑定用户实际查看的源模型版本；源模型修改后重新生成和检查，再确认受影响结果。持久编辑是 M1 后续交付，不阻塞首份 HTML。

**当前实现**：正式确认已移到 `2_modelling` 后、`3_split_pairing` 前。`source_checkpoint.py` 绑定已接受的校正/建模版本、源对象、显示几何、冻结策略及当前检查；从可信校正确定性重建后核对显示内容，不再依赖 Stage 3 的仿真序列化。查看交付保存 HTML、源模型、派生几何和检查记录的不可变快照，`manual_review/geometry_viewer.html` 指向当前版本。CLI 确认必须传入所看版本的完整 `--digest`，确认记录另绑定快照文件摘要；源输入、检查或显示快照变化后旧确认失效，恢复从 Stage 3 继续，直接进入 Stage 3–5 也受确认策略约束。旧 2+3 摘要仅保留作历史审计，不自动升级为新源确认。

已有可用几何的未接受候选仍可查看，并标明未建/未支持项及不能确认的状态；硬建模失败、尚无几何时不能生成新查看结果。源映射通过不代表原图完整性或仿真通过，已有未建/未支持观测会拒绝确认。自动实验仍可显式记录 `auto`，不冒充人工确认。持久编辑回写及修改界面尚未实现；当前已验证产物变化使旧确认失效。操作见 [运行 case](../workflow/run_case.md#stage-2-源模型查看确认与恢复)。

直接操作与自然语言动作尽量复用同一种几何操作：更新源对象 → 重建受影响的几何/配对 → 检查并刷新查看产物。共享墙变更涉及两侧房间和宿主开口；失败需可见、可撤销。只改变浏览器 mesh 不构成交付。
先用一个窗口移动或已知几何补正打通落盘闭环，再扩展墙推拉。静态查看器的持久化通道可按需求选局部服务或导出修改补丁；尚未定稿。建筑隔断编辑与仿真热区合并分开。

## 如何落地与并行

1. 先用一个图纸样本和一个用户提供的体量样本找共同接口的实际缺口，复用 `CorrectedGeometry` / `BuildingGeometry` 或薄转换层。
2. main 先落共同模型和出口的最小例子；图纸/体量适配在有明确文件边界的短期分支施工。
3. 公共 schema、配置和内核改动及时回主干；两路通过同一个出口验证，完成即收树。
4. 再增加一个局部 CAD/图纸等补充输入，证明它能细化同一个模型。

验收先看可查看的几何、已知信息完整性和质量说明，再推进选定下游。具体近期顺序看 [当前任务](../project/roadmap.md)，不把本页所有设想同时设为开工前置。

图纸路线的渐进能力按 [详细执行计划](../project/drawing_reconstruction_plan.md) 推进：源分区与自动评价基础、三案例基线、立面匹配、退台、内院/挑空、非正交及组合案例。保持同一源模型，按实际依赖调整顺序；旧 C2/C2.1 仅作历史资产索引，不另建长期架构或批次准入治理。
