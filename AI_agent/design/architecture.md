状态：09-10 用户明确模型驱动的总 Agent 产品方向；以下具体组织方式为助手的实施建议，尚未统一实现。产品目标见 [交付范围](../project/goal.md)，已有接口见 [现有实现](implementation.md)。

**09-14 收工确认的研发定位：模型 + harness = Agent。** 本项目的工作kit与harness均指围绕工作模型完成任务的整套支撑，包括工具、指引、上下文/状态、中间产物、任务组织、检查和返工。开发主体就是这套支撑及其与模型配合的效果，不将两者拆成独立产品或把harness仅当调用模型的包装。完整复现成功做法与开发助手工具化探路，是形成有效harness的两条互补方法，由助手按实际证据综合安排；不改变模型驱动、Sonnet产品上限和源BIM保真目标。最新完整交接见[收工记录](../logs/worklog/2026-09-14_reconstruction_kit_strategy_close.md)。

## 总 Agent 如何组织工作（09-10）

用户希望为模型配备足够的代码、模型等工具，由模型驱动各环节，最终交付一个总 Agent，并委托开发助手总体把控。建议先采用**一个总 Agent、按需调用专门能力、共用一个建筑工作状态**。工具与子 Agent 的数量按真实效果增加，不把 reading/correction 等名称固定为必须串行经过的独立模型角色。

09-13 用户补充：Sonnet调度、低档执行的组合属于可接受范围，开发不需一步到位，最终也可更少依赖模型智力。该组合用于当前实验取舍，不作为每轮固定流程或最终角色配置；可以先验证一个能力，再迁移给更低档模型或确定性代码。保持实际质量、时间和消耗可核对，不把模型降档本身等同产品进步。

09-14 讨论调整研发顺序：先完整复现已取得好结果的方法组合，再拆解、精简、重组吸收到总Agent，避免结构先行、逐个补要素忽略协同作用。好reading源于Sonnet自主开发/使用CV工具，随后才固化供Haiku使用；明确工序可作为总Agent按需调用的专门能力，模型驱动不要求单会话同时承担所有任务。具体复现边界见[读图方法](reading_correction.md#成功方法的复现与吸收09-14-讨论确认)，本次未实现新结构或启动实验。

同次讨论补充开发助手探路路径：先用可复用工具、明确中间数据和确定性计算走通任务，整理成工作模型可执行的kit，再根据其具体失败补harness。开发助手的强视觉/空间直觉不充作已实现工具能力，开发成功与目标模型独立成功分别评价。该路径与历史方法复现互补，由实际效果决定如何组织工具与专门能力，详见[迁移方法](reading_correction.md#开发助手先探路再交工作模型09-14-讨论补充)；本次仅记录。

总 Agent 持续读取用户目标、原始输入、当前 BIM/观测、未解决问题及工具结果，决定下一项动作；动作可以是观察、量测、请求专门模型、补充假设、生成/局部修改、检查或交付。工具执行后把真实结果交回，模型重新判断，允许回看或改方法。产物和任务状态落盘，长任务可恢复；不能只靠聊天上下文保存建筑事实。

| 层次 | 负责什么 |
|---|---|
| 总 Agent | 判断还缺什么、下一步做什么、是否值得继续细化，以及何时形成可交付结果；处理整体语义和冲突 |
| 可组合工具/专门模型 | 查看/裁图、量测、图意识别、几何生成与修改、检查与渲染；后续 CAD 和后端能力通过同类接口接入 |
| 确定性内核与运行支撑 | 可靠计算与装配、统一源模型、工具执行及错误返回、产物保存/恢复、调用预算和最终状态核对 |

### 旧 0–5 职责如何放进总 Agent

用户追问是否将 0–5 各做成 Agent、是否需要 Agent 嵌套。助手曾建议总 Agent 直接调用代码/模型工具、必要时一层子 Agent；用户随后要求不要预先定死，边试边推进。下表仅为旧职责的参考映射，当前不施工 EP 的 3–5。若实验需要子 Agent，其返回结果、候选及依据，共同建筑改动统一应用，避免多个角色各自维护一栋楼。

| 旧职责 | 首版建议形态 | 对总 Agent 的作用 |
|---|---|---|
| 0 reading | 可交互的读图工具；需要自主多次看图/量测时用读图子 Agent | 返回观测、对象候选和不确定项；可针对局部重新调用，无需整图重读 |
| 1 correction | 总 Agent 的整体判断 + 量测/约束求解与几何操作工具 | 处理跨图一致性、冲突及假设；复杂局部可再交专门能力，不强制设置独立 correction Agent |
| 2 modelling | 确定性源几何生成、检查、渲染工具 | 将已选方案变成可查看的共同 BIM，模型可据反馈局部修订 |
| 3 split/pairing | 后端确定性派生工具 | 按具体模拟用途切配，共同源 BIM 不被改成计算片 |
| 4 MEP/物性 | 后端模块，按需要用模型工具或其专门 Agent | 材料分层、热工信息等沿用协作者分工，不前移为几何生成前置 |
| 5 intake/output | 后端校验、装配与导出工具 | 执行对应出口合同；源 BIM 查看与交付无需等待旧 EP 导出阶段 |

调用一次模型做识别/判断可以是普通模型工具；只有子任务需要持有局部上下文、自主选择多个工具并根据结果继续时，才值得做成子 Agent。总 Agent 的规划不是每次生成整条流程图，而是在当前目标和状态下决定下一项有效动作。确定性的数据依赖依然存在；需要仿真时可调用一个内部含稳定步骤的后端工具。

稳定的几何依赖和计算顺序留在工具内部，例如按给定房间边界生成墙面、挂窗并核对宿主。模型不必重新算每个顶点，也不必每次指挥同一组底层步骤；它需要能选择这项能力、理解适用范围和失败原因。工具应围绕有意义的任务提供清楚的输入、结果及受影响对象，避免照搬几百个底层函数。少量临时代码可用于输入分析和方法探索，几何写入仍经过共同内核与检查。

专门视觉模型或子 Agent 可作为工具被调用，返回所见、候选、假设和产物引用；总 Agent 判断是否采信及下一步。既有“标注 + 像素 ＞ 像素 ＞ 纯推理”原则继续适用。子任务可分摊给目标档模型，整体判断维持 Sonnet 级运行上限；任务权限、实际通道与费用沿用 [模型约定](../workflow/models.md)，产品设计不扩大调用授权。

例如纹理遮住墙线：总 Agent 可先看局部、尝试量测，量测不足时调用视觉判读或结合房间关系提出假设，再生成粗 BIM 并查看检查结果；之后只修影响空间关系的部分。工具未检出线不直接结束整案。该例说明可选择的行为，不是给每张图强制安排的新流程。

## 反馈、停止与交付

Agent 化增加可选择的方法，但不能自动消除死循环和误判。设计重点是让模型看到具体问题并能采取有效动作：

- 工具返回结果、局部失败及有关对象/图像位置。几何操作失败时保留上一份可用状态，总 Agent 可重看、补假设或调用其他方法；真正的内核缺陷不能通过反复生成掩盖。
- 生产侧原图、量测、几何检查和渲染反馈可以用于有针对性的修订。**评测侧 GT 及其派生裁判信息不回流给生成 Agent**；旧盲重抽策略保留其历史实验含义，不扩展为禁止产品利用自身执行反馈。
- 09-10 用户明确原图回叠应进入生产侧校正循环。模型选择图面、楼层、像素/米锚点及墙面基准，确定性工具负责把实际源 BIM 画回该图；登记后，新候选复用同一标定返回新图，模型据此决定是否修改或补查。只有显式重新标定才改变基准，不能随新墙位自动拟合以掩盖差异。各图独立，保留每版源和标定的绑定；投影失败保留候选并明确反馈。工具生成、返回图像与模型正确读懂图像分开记录，原图语义、标定正确性和停止决定仍需模型判断，不新增 GT 或固定外部 judge 作为生成依赖。
- 正常完成以真实保存的 BIM、当前检查和可查看产物为依据，不能只相信模型说“完成”。几何可用、信息完整程度和后端可接受性分别说明；输入不足允许带假设交付，已知严重问题不得包装为通过。
- 有界调用预算、连续无进展判断和恢复状态由运行代码支撑。预算耗尽保存已有成果及缺口，不能空转，也不能把预算停止当成成功。普通不确定性由模型处理；涉及用户目标冲突或所需信息无法合理假设时再询问。

这些运行约束规定动作与成果是否有效，不预先穷举整案的任务路线。源 BIM 仍是共同交付与查看停点，材料分层等热工信息和专用派生留给后端。

## 现有能力与首个增量

### 09-13 收工：架构骨架明确，执行方法仍在收敛

当前实验入口已经可执行“原图/保存方案 → 模型选择观察、量测与局部模型 → 方案及确定性源生成 → 实际源查看/原图回叠/开口检查 → 修订或带缺口交付”。这是能力与数据依赖的概括，不要求每次依次经过固定阶段。下层几何生成、保存/恢复、检查、查看已有实际证据；上层选取有效局部任务、解释墙段与尺寸、判断反馈、保护既有正确对象及预算内收尾仍不稳定。当前应称为**能运行并取得局部修复的Agent原型**，还不是三案例可重复通过的产品管线，也不是仅有概念设计。

开发助手近期仍在选择局部问题和安排恢复运行；不能把这部分人工组织算作产品Agent自身能力。Sonnet局部尺寸观察辅助sm24撤假墙是有效结果，但随分区修订又无新量测地缩窄一扇门，说明闭环还缺可靠的修改取舍。Haiku历史好reading及当前局部正确观察支持继续试低成本能力，不证明其能独立承担整案发现、裁定和自我纠错。成功子任务应按实测能力下放，模型分工不固定为必须双Agent接力。

下一步收敛可观察的工作状态：已确认信息、待核冲突、候选改动、当前源检查/未核范围，以及是否还有值得继续的修复；动作仍由模型选择。先在原图新运行中验证错误能被自行发现和修复、可靠对象能保留，再整合正式flow，避免把同图定点补救无限延长或先重写框架。三案例状态、主观可行性估计及开发轮次假设见[本次收工](../logs/worklog/2026-09-13_reconstruction_session_close.md)。

09-10 新增独立实验入口 [run_bim_agent.py](../../scripts/tool_scripts/run_bim_agent.py)：Sonnet 订阅模型直接选择查看/裁图、像素投影量测、坐标换算、Haiku 局部复核、生成与检查、候选平面查看。工具仅暴露本次显式原图与自产候选，未提供仓库/任意文件/命令访问；不向模型暴露 GT。几何方案通过 [直接方案导出](../../src/agent/execution/source_proposal.py) 接共同源内核，无需旧 correction run 或接受记录。每次候选单独保存，假设、未解决项及输入来源跟随源模型和查看器；几何通过仍不代表原图保真。

09-10 续推增加保存方案恢复及局部修订：`--resume-candidate` 只导入上一候选的 proposal，重新执行生产几何检查，不导入旧评价；`inspect_candidate` 读取方案，`revise_bim` 由确定性代码执行整体反射、门窗更新/开口改判及假设备注替换。新旧候选分开保存，修订理由、来源、前后值及父方案摘要留档，几何对象 ID 保留。更新后的来源同步到门窗对象，旧来源及删门前对象留在审计；完整修订历史也进入独立源 BIM 的 generation 字段，不能仅靠外部对话保留。这是方案恢复实验，不是完整编辑产品，也不承诺派生边界 ID 跨修订稳定。

新增开口回查工具 `check_openings`：生成后先给出按楼层/空间分组的实际开口清单，模型可提交原图各独立标记与对象的对应关系，代码报告未对应、重复及连接不一致。观察与结果独立保存并绑定源/图像摘要，候选修订后不自动沿用旧回查。它不读取 GT、不自动识别像素，也不把自然语言备注解释成门数；模型需把判断落成可核对的标记清单。局部或推断观察仍可保存，不以完整回查作为已有 BIM 可查看的前置。

后续增量增加 `overlay_candidate` 与 `finish_bim`。前者复用既有像素标定器，按模型给出的原图像素/米锚点，将已建源房间和门窗投影回原图，便于发现分开查看时漏掉的错位；分轴比例、警告、来源摘要和原分辨率叠图独立保存，不自动识别图像真值。后者让模型选择保存候选，由代码汇总实际几何检查和当前源回查，交付 `delivery.json/html`；未回查、局部观察、仍需跟进和旧源回查分别显示，不把模型最后文字当验收依据。模型未显式选定时运行结束仍保留最新保存候选，并标明回退选择。带问题候选可以交付查看，没有强制全层回查或新的审批链。

这是原型入口，尚未替换正式 `flow`，不代表跨案例能力已验证或已支持完整恢复/持久编辑。当前实验设置最多 6 个候选、2 次局部复核，订阅调用有时限；记录真实工具轨迹、模型和用量。这些是本次试验范围，不固定产品角色数量或所有输入必须经过的工序。实际结果见 [当前任务](../project/roadmap.md)。

仓库已有 [局部工具调用循环](../../src/agent/react.py)，旧 [下游图](../../src/agent/graph.py) 把这些循环装入固定阶段；[flow](../../scripts/tool_scripts/run_stage.py) 仍按阶段顺序运行，[旧失败路由](../../src/agent/execution/routing.py) 主要按阶段类型选择重抽、人工重读或停止。开发期的 [orchestrate.py](../../src/agent/execution/orchestrate.py) 明确依赖会话主助手驱动，不等于已交付产品总 Agent。新源分叉绕开 EP 阶段，但尚未成为跨观察、修订、生成和检查的总 Agent 循环。

首个独立入口原型已按上述范围接通，sm21 实跑说明模型能消费检查反馈，却仍会为消除几何错误改变立面语义。下一增量以保存的候选和原图处理坐标变换、门洞身份与候选生成节奏；不先更换框架、重写内核或包装全库。旧 flow 留作重放/对照，后续按验证结果整合到同一产品入口。

当前先用一个真实输入试到可查看 BIM，工具和任务拆分随发现调整；不以框架选型、嵌套层级、完整恢复系统或所有复杂输入覆盖为首份输出的前置。EP 相关工具不纳入这轮原型。

验收给产品 Agent 原始输入和 BIM 目标，不由开发助手逐步下达工具顺序：先取得可查看成果，再用相关缺标注或量测失败场景检验它能否根据实际反馈改方法、保留已知结构并说明假设。检查中断恢复与停止时成果保存；同时记录质量、人工干预、用量和时间。不规定必须走哪条工具轨迹，不宣称一个成功案例证明广泛泛化。

方法参考：Anthropic 区分预定义工作流与模型动态选择动作的 Agent，并讨论反馈循环和停止条件，见 [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)；其工具设计经验建议选择少量有明确任务价值的工具，按实际效果迭代，见 [Writing effective tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents)。这些是设计参考，不是本项目成功证据，也不构成采用其托管服务或 SDK 的决定。

## 统一入口与职责组织（09-14 讨论建议）

用户已确认：最终为“单栋建筑的全部资料 → Agent → 丐版BIM”，本轮优先真实带贴图三维体量，sm24缺图对照后置；当前先讨论与还原建模的兼容。用户随后明确“都同意”，接受以下总体组织方向；具体角色配置和接口按实验推进，不代表已实现。

采用**一个总Agent管理同一栋建筑，按模态调用观察能力，按建筑问题组织跨模态判断，共用几何生成与反馈**。研究可分轮次开发，产品不以还原/部分推理/完全推理作为互斥分流开关，也不要求图纸、网格各自先生成完整BIM再合并。

- **资料观察按模态专门化。** 图纸工具处理裁图、标定、尺寸和墙/开口观察；三维网格工具处理旋转、剖切、表面量测、带空间映射的完整贴图投影；文字/建筑声明提取用途、层数、尺寸等明确约束。保留各模态原始观测及坐标，不强迫网格伪装成图纸reading。
- **建筑判断按问题组织。** 总Agent围绕外形、楼层、某段外墙/窗、某层空间布局等问题组合证据，决定采信、冲突回查、补问或推断。内部推理可同时使用网格进深、图纸局部和用途说明，不专属某个输入入口。
- **同一份建筑工作状态。** 原始资料与变换、对象/属性相关的观测和约束、带理由的假设/冲突、当前可编辑方案与实际BIM检查分别保存并关联。原始观测不被采信结论覆盖，证据存在也不等于几何已应用。跨模态匹配不确定时保留候选对应，不能静默强配。
- **共同的确定性生成与检查。** 模型选方案/修改意图，代码做换算、装配、宿主/覆盖/连通检查及显示。各输入共用源BIM及可编辑方案；增补资料可以修订相关假设和几何，也允许有依据的较大重建，保留修订来源及影响。

角色与模型型号解耦。近期建议一个Sonnet级总Agent配合代码工具；局部观察可调用较低档模型，任务需要多步观察和自主返工时再封装专门子Agent。不固定每种模态一台模型或每个职责一个常驻Agent，也不要求强模型每次重看全部资料。有效的还原reading方法保留工具、指引、中间产物与检查返工的完整组合，作为可按需调用的能力逐步接入；不因统一入口立即重写已验证方法。

例如同一栋建筑已有三维外壳和一张首层平面：从外壳量测外形、退台和窗列；首层有图证处用平面约束实际隔断；上层内部缺证据时按用途、外形和开口推断。后来补标准层平面，核对与原方案差异并更新受影响部分。若平面与网格不一致，先查尺度、朝向、楼层、图纸版本及采集时期，而非规定某模态永远覆盖另一模态。还原和推理可同时发生在不同对象/属性上。

统一的是工作状态、对象引用、空间对应与几何操作边界；模态观察记录可不同。第一步应选真实单体，把三维观察的空间映射及所需源方案入口接进共同循环，再用原有还原案例确认接口兼容；不以预建全模态平台、固定多Agent拓扑或完成全部对照为前置。本段尚无新代码/实验成果。

## 输入适配与共同出口

任务统一按信息充分程度分为还原建模、部分推理建模、完全推理建模，定义见 [产品目标](../project/goal.md#按信息充分程度划分建模任务)。格式适配负责读取图纸、网格、照片、文字或 CAD；总 Agent 根据实际已有约束及缺口组织还原和推断。同一任务可混合输入、补充后改变信息充分程度，共用同一 BIM，不为三个名称建立三套管线。输出简化程度由用户独立选择，具体控件和对应规则后续设计。

09-10 用户明确：只生成目标单体，不考虑环境；用户在生成前选择通用 BIM 对实际建筑空间的简化/合并程度，不必先选模拟。分块依据实体隔墙，最细保留实际格局；大开敞办公区不因复杂度提高而多分块，示例见 [体量路线](textured_mass_route.md)。生成可直接推断简化后的表达，无需先完整恢复再合并。各档共享同一模型概念和后端入口，后端自行派生、合并或继续调整；源简化与后端计算粒度独立。这是产品要求，配置与多粒度生成尚未实现。

下图说明资料和成果的依赖关系，具体调用顺序由总 Agent 根据当前任务及用户选定的复杂度决定。

```text
图纸 / 贴图体量 / 图片 / 文字 / CAD 等混合资料
                        ↓ 技术输入适配
              已知建筑约束、参考与缺失信息
                        ↕
          同一总 Agent 按建筑问题组织观察、推断与修订
                        ↓ 遵循用户选择的简化意图
                  共同轻量 BIM
                        ↓ 查看、编辑与质量说明
                  BIM 停点版本
                        ├→ EP：热区/切配 + 独立物性 → IDF → 仿真
                        └→ 其他后端（后续）
```

图纸适配利用尺寸、房间和视图证据重建；体量适配先保存外形、楼层和表皮，再推断缺失内部。CAD 生产输入和 CAD→GT 工具分别处理，不把评测答案输入生成器。
不同模态可有不同观测 schema，共用 [建筑模型](model.md)、坐标与来源约定、几何内核和输出。体量无需伪装成平立面 reading；同一输入格式也不绑定某一信息充分程度。

共同底座采用空间体、边界面、门窗/其他开口及关系；逻辑上可计算体积，物理开口仍可连通。源空间可以是房间，也可以是用户选择的粗粒度空间块；抽象分界与观测/推断物理隔断分别表示，低档不要求先恢复全部房间再合并。建筑源模型不承担所有求解器的最终网格和边界条件，EP 热区与其他用途几何分别派生。计算切分不能把一个源空间变成多个物理房间，也不能把挑空填成楼板。最小源对象、显式门洞/连通及结构化平面开口记录自动接入已实现，全图识读、编辑和一般开口仍须补齐，范围见 [共同模型](model.md)。

图纸和后续 CAD 适配均允许在来源/拓扑约束下做容差规整，交付正确、自洽的建筑模型。judge + GT 自动评价结构、语义和用途相关精度；GT 的 CAD 解析/规整工具可复用于生产适配，但答案和输入分别管理。以 [定性优先的评价原则](evaluation.md) 为准，不将原始 CAD 每个顶点当成工作模型必须精确复刻的目标。

## 输入不完整与冲突

09-10 用户明确区分两种交互：生成过程中获取缺失信息，以及已有 BIM 停点上的编辑/确认。总 Agent 可以根据当前歧义询问建筑用途、楼层、已知尺寸或所需补充视图，再继续同一任务；能以明确假设推进的对象不必一并等待。后续应将问题、回答、受影响假设和对象一起保存。此为确认的产品方向，当前还未形成完整交互实现。

充分输入支持较细的房间、隔断和开口；缺少内部证据时输出带明确假设的推断空间，粗热区仍是派生物。缺少尺度时说明相对坐标或概念尺寸，缺少窗信息时可用可替换的默认方案。
09-10 用户确认采信顺序为 **标注 + 像素双证据 ＞ 像素证据 ＞ 纯推理**。按对象/属性利用现有信息，标注缺失、像素量测失败或图像表现形式不同不应自动终止源生成；模型可补全明确假设，代码执行。证据越充分，输出可承诺的精度越高，而非只有最高证据档才能出 BIM；材料分层等热工信息在后端补充。
“给多少输入都产出输出”是目标能力：降级产出当前信息能支持的有用模型和缺失说明，不用空 JSON 充数，也不把概念模型称作真实重建。
新增图纸或 CAD 只细化有依据的对象，保留来源、变换和冲突；不写死后来覆盖先来或 CAD 永远正确。质量先用来源与可解释等级，不制造未校准的精度百分比。

**当前实现**：正式确认已移到 `2_modelling` 后、`3_split_pairing` 前。`source_checkpoint.py` 绑定已接受的校正/建模版本、源对象、显示几何、冻结策略及当前检查；从可信校正确定性重建后核对显示内容，不再依赖 Stage 3 的仿真序列化。查看交付保存 HTML、源模型、派生几何和检查记录的不可变快照，`manual_review/geometry_viewer.html` 指向当前版本。CLI 确认必须传入所看版本的完整 `--digest`，确认记录另绑定快照文件摘要；源输入、检查或显示快照变化后旧确认失效，恢复从 Stage 3 继续，直接进入 Stage 3–5 也受确认策略约束。旧 2+3 摘要仅保留作历史审计，不自动升级为新源确认。

已有可用几何的未接受候选仍可查看，并标明未建/未支持项及不能确认的状态；硬建模失败、尚无几何时不能生成新查看结果。源映射通过不代表原图完整性或仿真通过，已有未建/未支持观测会拒绝确认。自动实验仍可显式记录 `auto`，不冒充人工确认。持久编辑回写及修改界面尚未实现；当前已验证产物变化使旧确认失效。操作见 [运行 case](../workflow/run_case.md#stage-2-源模型查看确认与恢复)。

直接操作与自然语言动作尽量复用同一种几何操作：更新源对象 → 重建受影响的几何/配对 → 检查并刷新查看产物。共享墙变更涉及两侧房间和宿主开口；失败需可见、可撤销。只改变浏览器 mesh 不构成交付。
先用一个窗口移动或已知几何补正打通落盘闭环，再扩展墙推拉。静态查看器的持久化通道可按需求选局部服务或导出修改补丁；尚未定稿。建筑隔断编辑与仿真热区合并分开。
