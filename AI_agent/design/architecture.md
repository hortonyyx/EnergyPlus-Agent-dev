# 两路输入与同一个轻量 BIM

状态：设计建议，尚未统一实现。产品目标见 [交付范围](../project/goal.md)，已有接口见 [现有实现](implementation.md)。

## 输入适配与共同出口

```text
图纸 / 文字 / case → 图纸观测与重建 ─┐
带表皮体量       → 外形读取与内部推断 ┼→ 证据整合与缺失补全 → 轻量建筑模型
CAD / 其他资料   → 相应输入适配 ─────┘                         │
                                          查看、编辑与质量说明 ←┤
                                  物性 / 热区 / IDF / EnergyPlus ←┘
```

图纸适配利用尺寸、房间和视图证据重建；体量适配先保存外形、楼层和表皮，再推断缺失内部。CAD 生产输入和 CAD→GT 工具分别处理，不把评测答案输入生成器。
不同模态可有不同观测 schema，共用 [建筑模型](model.md)、坐标与来源约定、几何内核和输出。体量无需伪装成平立面 reading；不复制两套整条管线。

共同底座采用空间体、边界面、门窗/其他开口及关系；逻辑上可计算体积，物理开口仍可连通。建筑源模型不承担所有求解器的最终网格和边界条件，EP 热区与其他用途几何分别派生。计算切分不能把一个源空间变成多个物理房间，也不能把挑空填成楼板。最小源对象、显式门洞/连通及结构化平面开口记录自动接入已实现，全图识读、编辑和一般开口仍须补齐，范围见 [共同模型](model.md)。

图纸和后续 CAD 适配均允许在来源/拓扑约束下做容差规整，交付正确、自洽的建筑模型。judge + GT 自动评价结构、语义和用途相关精度；GT 的 CAD 解析/规整工具可复用于生产适配，但答案和输入分别管理。以 [定性优先的评价原则](evaluation.md) 为准，不将原始 CAD 每个顶点当成工作模型必须精确复刻的目标。

## 输入不完整与冲突

充分输入支持较细的房间、隔断和开口；缺少内部证据时输出带明确假设的推断空间，粗热区仍是派生物。缺少尺度时说明相对坐标或概念尺寸，缺少窗信息时可用可替换的默认方案。
“给多少输入都产出输出”是目标能力：降级产出当前信息能支持的有用模型和缺失说明，不用空 JSON 充数，也不把概念模型称作真实重建。
新增图纸或 CAD 只细化有依据的对象，保留来源、变换和冲突；不写死后来覆盖先来或 CAD 永远正确。质量先用来源与可解释等级，不制造未校准的精度百分比。

## 查看、编辑与确认

用户确认图纸路线的主要人工交互停点放在 **Stage 2 形成可查看源 BIM 之后、进入下游用途派生之前**。人工重点看源房间、隔断、门窗、层间关系和需要判断的假设；自动 gate/judge 先提供检查结果，人工无需逐尺寸核对。上游关键歧义仍可提前询问，但不默认让用户逐阶段审批。

近期最低交付是复用 [现有查看器](../../scripts/tool_scripts/render_geometry_viewer.py) 的离线 HTML：可旋转、缩放、半透明、剖切、分层/分区展开、点选和测量；同时提供自动质量报告、假设及未完成项。09-09 已增加显式门/空开口扣洞显示、来源和两侧连接；未覆盖全部源 BIM 类型。只要有可安全显示的几何，失败/局部结果也应有明确状态的查看入口；未通过下游专用检查不应使已有源 BIM 无法查看。

首步先贯通“生成 → HTML 查看 → 记录人工确认 → 恢复执行”，确认可沿用 CLI/记录入口，HTML 内按钮和完整编辑界面后续设计。自动实验可按既有策略继续并记录未人工确认，不将自动通过冒充人工确认。确认应绑定用户实际查看的源模型版本；源模型修改后重新生成和检查，再确认受影响结果。持久编辑是 M1 后续交付，不阻塞首份 HTML。

**当前实现差异**：`step_orchestrator.py` 的 `GEOMETRY_CHECKPOINT_STAGE` 仍是 `3_split_pairing`，确认摘要绑定 2+3 及 kernel report，`4_mep` 按确认策略受控。09-09 已让 `run_stage.py::_draw_modelling` 在形成 Stage 2 候选后立即生成 `manual_review/geometry_viewer.html`，下游几何 gate 失败及有可保存候选的源映射失败也可查看；显示源 ID、计数与映射检查范围。附带源投影须匹配实际显示几何的摘要。硬建模失败、尚无可用几何时仍不能生成新查看结果；诊断工具另保留历史产物查看。正式确认停点、源版本确认/恢复和编辑失效尚待 M1 迁移，生成 HTML 不等于已获人工确认。

直接操作与自然语言动作尽量复用同一种几何操作：更新源对象 → 重建受影响的几何/配对 → 检查并刷新查看产物。共享墙变更涉及两侧房间和宿主开口；失败需可见、可撤销。只改变浏览器 mesh 不构成交付。
先用一个窗口移动或已知几何补正打通落盘闭环，再扩展墙推拉。静态查看器的持久化通道可按需求选局部服务或导出修改补丁；尚未定稿。建筑隔断编辑与仿真热区合并分开。

## 如何落地与并行

1. 先用一个图纸样本和一个用户提供的体量样本找共同接口的实际缺口，复用 `CorrectedGeometry` / `BuildingGeometry` 或薄转换层。
2. main 先落共同模型和出口的最小例子；图纸/体量适配在有明确文件边界的短期分支施工。
3. 公共 schema、配置和内核改动及时回主干；两路通过同一个出口验证，完成即收树。
4. 再增加一个局部 CAD/图纸等补充输入，证明它能细化同一个模型。

验收先看可查看的几何、已知信息完整性和质量说明，再推进选定下游。具体近期顺序看 [当前任务](../project/roadmap.md)，不把本页所有设想同时设为开工前置。

图纸路线的渐进能力按 [详细执行计划](../project/drawing_reconstruction_plan.md) 推进：源分区与自动评价基础、三案例基线、立面匹配、退台、内院/挑空、非正交及组合案例。保持同一源模型，按实际依赖调整顺序；旧 C2/C2.1 仅作历史资产索引，不另建长期架构或批次准入治理。
