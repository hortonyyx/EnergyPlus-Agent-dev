# 统一 Agent：长任务、上下文与恢复

阶段 2 实现说明。验收口径由 Opus 维护的[验收文件](../project/unified_agent_acceptance.md)决定；本文不代替验收结论，也不证明工作模型能完成整案。

## 保存什么，发送什么

`src/agent_runtime/context.py` 将三类内容分开：

- 完整历史：原始消息、公开模型回包、工具原始回包、图片及来源。原件只增不减，使用内容哈希附件；检查点只保存索引，不反复内嵌图片。
- 当前状态：带来源和版本号的用户要求、约束引用、依据、当前源 BIM、未决项、待办、尺寸、对象编号和几何引用。
- 活动请求：保留初始指引和用户任务，选取近期完整工具交互组，加入当前状态清单。一个 assistant 的工具调用与全部对应回包不可被窗口切开。

重复大回包被替换为指向原件的明确引用；旧版本摘要不再发出；同一图片字节每个请求只发一次。移出的历史仍可通过检查点索引和哈希附件逐项还原。实际发送的完整 HTTP 请求另存，不能用“准备发送的回包”冒充实际呈现。

每次压缩、图片保留、移出或取回都有事件，包含原因、受影响事件或图片身份、前后引用和决策详情。`runtime_behaviour.py` 同时区分原始回包、准备内容与实际请求中呈现的内容。

## 当前状态与摘要

通用运行底座不读取建筑对象。建筑入口的 `src/agent/runtime_context.py` 从保存的文件建立索引：

- `view_id` 和图像来源；claim 与推断文件的完整哈希引用；它们的解释状态仍是推断。
- 当前工作源 BIM 与已选交付版本分别登记；查看旧候选不会自动回退当前工作版本。
- 几何和尺寸指向完整源文件，对象编号来自实际保存的对象；检查报告中的未决项另带报告来源。
- 用户约束保留原文来源，不依靠程序猜测或扩写；用途、忠实度等具体语义仍由上层任务解释。
- 附加用户建筑声明连同既有字段语义在首次请求中保留，不把热区数当作物理房间数；最新保存的工作复核及下一步动作另列为待办，仍标为模型判断。

模型摘要默认关闭。启用时，先做确定性投影，再通过正常适配器发送一个受约束的摘要请求。摘要只能选择已有状态项，不能改变值、来源或“观察／计算／推断／假设／未决”等状态，正文必须与所选条目的标准序列化一致。相关状态更新后，旧摘要退出请求。尺寸、对象编号和几何不允许只以摘要为依据。

这是一种保守的状态索引摘要，没有实现任意长文本的自由改写摘要。后者的真实性校验与质量收益未核实。

## 图片策略

按活动窗口、固定标签、指定 view_id、图片数量和原始字节总量决定发送内容。固定证据与容量冲突时明确拒绝，不静默丢掉固定证据。显式取回使用 `(view_id, sha256)`，包括同一视图的旧版本；重新校验字节哈希，不重新渲染或缩小原图。

CLI 的 `--keep-view-id` 固定某视图，`--retrieve-image VIEW_ID SHA256` 精确取回。通用 API 可用图片标签表达当前楼层、当前立面和未决证据；底座不从文件名猜测楼层语义。所有策略值属于本地配置，不宣称是 Paratera 的服务限制。

## 一份预算总账

`budget.py` 在每次请求前预留 token、金额、时间、次数，完成后按可获得的实际用量结算。主任务、子任务预留、摘要和重试使用同一账本；本阶段未实现真正的子任务执行或多角色委派。

- token 预留为请求 UTF-8 字节数、图片像素数和输出上限之和。这是保守的本地估计，不能当作服务 tokenizer 或实际账单。服务返回的 token 用量单独保存。
- 金额根据显式提供且注明来源的价格表估计；无价格表时不允许在金额上限下发请求。未取得实际账单就保留估计或未知，不能写零费用。
- 缺失用量的维度继续占用原预留；实际用量超过预留时保留原回包并停止，不能截小实际数值来让账本通过。
- 默认快超限即停止；`reduce_output` 只显式减少输出上限并重新计算最终请求，记录原值、实际值和理由。固定输入与证据不通过预算模块偷偷截断。
- 时间上限覆盖整个运行，包括工具、摘要、重试和重启期间的墙上时间；不是单次 HTTP 超时。恢复时未知请求的时间占用也不会伪造为零。

## 持久化与恢复

写工具之前先落盘操作意图，模型调用之前先落盘预算与最终请求。事件和内容附件刷盘，检查点也作为事件引用内容哈希；`checkpoint.json` 只是快速定位指针。恢复先读取最后一个完整检查点，再重放其后的完整回包和上下文事件，核对真实保存状态及六层版本。

| 中断位置 | 恢复行为 |
| --- | --- |
| 完整检查点，尚未发起下一操作 | 核对配置、版本和保存状态后续接 |
| 已收到模型响应但未更新检查点 | 从原响应补回消息；不重复调用模型 |
| 工具已回包并留下完整执行事件 | 补回工具消息与状态；不再次执行 |
| 已写入工具意图，缺完整回包 | 先记录实际状态检查；不能判定写入结果则停止，不重试写入 |
| 预算已预留，尚无请求事件 | 保留预留并返回 `resume_uncheckpointed_budget_reservation`；尚无自动释放协议 |
| 请求结果未知 | 保守保留用量；仅在配置和剩余额度允许时作显式有界模型重试；未知摘要请求停止 |
| JSONL 末尾破损 | 默认拒绝；显式 `--resume --repair-tail` 先归档原尾字节、原文件和前缀哈希，再修复最后一条 |

同一 run 的代码、依赖锁、指引、工具定义、参数、路由以及上下文与预算配置变化，均拒绝直接续接。不能把“文件变了”或“文件没变”当作未知写已成功或尚未执行的证明。已完成运行重复 resume 不增加写操作或用量。

## 入口与范围

新增选项见 `python -m src.agent.runtime_entry --help`。继续使用阶段 1 的冻结工具服务、工具名单和指引；建筑回调只索引已保存产物。`review_detail` 内部会调用其他模型，仍由既有阶段限制阻止，不绕过总账启动。

可复验材料位于[阶段 2 交付目录](../logs/experiments/2026-10-02_harness_stage2/README.md)。长任务来自 run99 的实际工具调用和原图片，使用离线脚本回放，并将历史成功写映射到隔离的保存副本。它验证运行机制、来源保存和故障边界，不能代表新的建筑方案生成或模型质量。
