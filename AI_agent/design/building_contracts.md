# 统一 Agent 的建筑共用接口（阶段 0）

本页说明 `src/agent/contracts/` 的正式建筑接口。它服务还原、部分推理和完全推理三类任务，不按路线拆成三套格式。阶段 0 只定义数据、确定性校验和离线样例，不实现运行循环、几何算法、规整算法或角色调度。

底座核心的事件、预算、角色、模型绑定和工具白名单由 `src/harness_contracts` 负责。建筑层不再定义第二套角色配置。建筑层只说明一个建筑证据任务要带什么、局部结果怎样返回，以及建筑声明、检查和覆盖怎样彼此衔接。

## 总入口

`BuildingContractBundle` 是一个案例的连接总表。它同时包含用户要求、依据、计算链、建筑声明、保存模型版本、局部证据任务、检查、规整和覆盖。单张表能够通过校验并不够；总表还会检查所有跨表引用。

总表主要拒绝这些“看起来完成”的假结果：

- 声明引用不存在的依据、要求或推断；
- 保存版本引用不存在的声明；
- 检查说“通过”，却没有保存文件哈希、模型版本和被检查对象；
- 覆盖只有理由，没有实际保存对象；
- 覆盖检查的是另一个模型版本，或没有检查到所声称的对象；
- 粗档合并没有用户明确的简化要求；
- 草案声明同时混入已应用声明；
- 局部观察基于旧模型版本，却准备应用到新版本。

`evidence_impact_index()` 给出“依据 → 受影响声明 → 保存模型版本”的反查。它会先展开对象组和模板继承，所以从模板继承的依据也进入反查，不要求模型在每个对象上重复填写。

## 对象和证据引用

`BuildingObjectRef` 沿用当前提案和源模型中的对象 ID，种类限于 `space`、`boundary`、`opening`、`window` 和 `floor`。接口不自动按同名对象重新绑定。

`ExistingEvidenceRef` 沿用三个已有编号：

| scheme | 现有来源 | 格式 |
|---|---|---|
| `view_id` | 查看图片后保存的视图 | `view_0001` |
| `claim` | `record_claim` 保存的 claim | `claim_0001` |
| `record_inference` | `record_inference` 保存的推断 | `inference_001` |

接口没有另造一套平行的视图号、claim 号或推断号。跨运行使用 `RunQualifiedEvidenceRef`，在原编号外补运行 ID、原图 SHA-256 和坐标关系。坐标关系能表达原像素不变、原图裁剪、仿射换算，以及“先裁剪、再缩放”的实际视图。缺少原图哈希或坐标关系时拒绝，避免另一运行中的同名 `view_0001` 被误用。

## 依据、用户要求和计算链

`UserRequirement` 单独保存用户要求与偏好，类型包括功能、简化、保真、偏好和约束。它不是建筑事实，也不因为进入模型就变成观测。

`EvidenceItem` 有四种可以并存的依据：

- `observation`：直接观察，必须有定位后的来源；
- `inference`：建筑解释，必须复用 `record_inference` 编号；
- `simplification`：用户允许或选择的表达简化；
- `assumption`：信息不足时明确保存的临时假设。

`EvidenceTemplate` 保存重复使用的依据集合，`EvidenceGroup` 把模板和额外依据赋给一组对象，`ObjectEvidenceBinding` 把对象接到组。`expanded_object_evidence()` 按 ID 排序后确定性展开。同一空间可以同时得到观测、推断、简化和假设，不使用互斥的“唯一依据类型”。

`EvidenceConflict` 保留冲突双方。已决冲突必须写处理结果；未决冲突不能提前填写一个伪处理结果。无论是否已决，双方依据都留在账本里。

`CalculationChain` 固定为四步：`raw → converted → normalized → saved`。每步都保存输入、输出和原因，下一步输入必须逐值等于上一步输出。毫米、厘米和米按固定比例换算；像素值必须显式给出米/像素比例。换算值的算术不对就拒绝。规整后的值必须原样成为保存值，不能在保存时再次静默变化。

还原样例可记录“图纸 6000 mm → 6.0 m → 对齐既有 5.94 m 线 → 保存 5.94 m”。只有照片的样例也能记录“假设层高 3000 mm → 3.0 m”，但其依据仍是 `assumption`，不会被包装成观测。

## 建筑声明

`BuildingDeclaration` 是现有工具输入外的一层薄封装。`ExistingToolCall` 只接受：

- `build_plan_bim(image, plan_json)`；
- `build_parametric_bim(plan_json)`；
- `revise_bim(candidate, operations_json)`。

各工具的参数名与现有入口完全一致，不发明一门包办所有建模的新语言。阶段 1 可以直接把已校验的 payload 交给对应工具；更深的工具输入内容仍由现有工具自身校验。

`DeclarationScope` 可指一层、一翼、一个对象组或一个跨层空间。跨层范围显式列出空间与楼层 ID。`FieldPartition` 分开列出模型实际声明的路径和代码展开/计算的路径，两边不得重叠。这样可以追溯建筑取舍来自模型，还是空间装配来自代码。

`RepetitionRule` 表达按层、翼或对象组重复；每个实例可以给 JSON 路径形式的例外。代码负责展开，模型不用为每层重写同一声明。例外是声明的一部分，不能在展开后静默覆盖。

`InferenceHypothesis` 只用于尚待验证的推理侧功能要求、空间关系和方案选择，字段 `hypothesis` 固定为 `true`。用户直接给出的功能要求放在 `UserRequirement`，不放到这里。方案选择必须回答至少一项用户要求；空间关系必须列出至少两个对象。这个接口能表达完全推理，但其任务划分与稳定性仍是待实际案例验证的假设。

`BuildingModelVersion` 把模型版本 ID、源模型内容哈希、保存文件哈希和形成它的声明连在一起。保存文件哈希供检查与覆盖核实实际产物，不能用“代码运行过”代替。

## 建筑证据包和局部返回

`EvidencePackage` 是通用角色收到的建筑材料：问题、已知依据、带运行/原图/坐标关系的 `view_id`、源模型版本、返回 schema 和本任务预算。当前 `EvidenceTaskBudget` 只是建筑包的最小可校验形状；接入运行器时由底座预算对象转换或替代，预算总账仍只有底座一份权威。

`LocalizedEvidenceResult` 把结果分成三栏：

- `directly_seen`：直接看见的内容，必须给原图像素位置；
- `interpretations`：对所见内容的解释，必须引用直接观察；
- `uncertain`：仍不确定的内容，可引用相关观察。

这能避免“看到一条线”和“它是墙中线”混成同一句事实。协调侧在应用建议前调用 `assert_result_applicable()`；包、任务或源模型版本不一致都会拒绝，尤其拒绝把旧版本观察直接用于已修改的新模型。返回中的每个像素定位还必须逐项匹配证据包实际下发的图片引用、原图哈希和坐标关系，不能从同一运行或版本里夹带另一张未下发图片。

角色的只读工具白名单由底座核心执行，建筑层不复制该规则。首批只读局部观察者使用上述证据包与结果。`FloorDraftContract` 只给后续单层起草角色预留草案形状，`maturity` 固定为 `draft_only`；草案必须是一层范围，并且总表禁止它同时出现在已应用声明中。

## 检查、规整和覆盖

`CheckResult` 的类别是几何、拓扑或覆盖。每条结果必须列对象、依据、建议动作、规整前后值。容差用 `ToleranceDecision` 记录数值、单位、来源 ID 和原因；来源分工具默认、档位上限和模型裁决，模型裁决也不能省略理由。

状态为 `passed` 的检查必须带 `SavedVerification`：保存模型版本、保存文件 SHA-256、实际检查对象。总表进一步核对文件哈希确实属于该模型版本。失败或未决检查可以没有保存验证，并能原样进入“未完成覆盖”，用于保存两次 Sol 测试中偏好未落实的反例。

`NormalizationProposal` 只接受 `set_dimension`。每个编辑必须：

1. 指向一个已分类特征；
2. 在规整前快照中找到待改尺寸；
3. 在规整后快照中找到实际保存的新尺寸；
4. 在规整前快照中找到作为目标的另一条既有线；
5. 新值逐值等于既有线坐标；
6. 变化幅度不超过本提案声明的容差；
7. 除已声明尺寸外没有其他尺寸变化。

目标可以是另一对象或另一楼层的既有线，符合 sm25 一层 4.00 m 线对齐二层既有 3.94 m 线的情况。接口没有“取两线中点”的目标种类，因此不能用新造的 3.97 m 线规整。阶段 0 的规整容差统一用米；其他单位必须先换算，不能把 12 cm 当成 12 m 比较。

前后快照还明确列出楼层 ID、墙 ID、房间 ID、每个开口的平面端点、竖向范围和宿主、连通关系。任何墙增删、房间拆并、开口平移/改高/换宿主或连通变化都会使语义快照不同并被拒绝，不能靠调用者把操作命名为 `set_dimension` 绕过。特征分类中的真实窄空间、真实台阶和真实退台只能 `preserve`；只有制图噪声可以进入尺寸规整。

`CoverageEntry` 串起：

`用户要求 → design_choice 推断 → 保存模型版本中的实际对象 → 检查 → 未完成项`

`complete` 要求所有引用检查通过、绑定同一保存版本和文件、并实际检查到全部对象。`incomplete` 必须列未完成项，可以保留失败或未决检查。实际对象还必须出现在该保存版本所用声明的 `declared_object_refs` 中。这样只有推断理由、没有保存对象和保存后核查的记录不能算覆盖完成。

粗档允许合法合并，但 `coarse_merge=true` 时对应要求必须是用户明确的 `simplification`，不能把遗漏房间事后改名成简化。细档并不授权凭空拆开真实开敞空间；对象是否合理仍由建筑复核与后续真实案例评价决定。

## 与现有代码的关系

| 新接口 | 现有代码关系 |
|---|---|
| `ExistingEvidenceRef(view_id)` | 沿用 `run_bim_agent.py` 保存的 `view_####` |
| `ExistingEvidenceRef(claim)` | 沿用 `src/agent/execution/bim_claims.py` 的 `claim_####` |
| `ExistingEvidenceRef(record_inference)` | 沿用 `bim_agent_inference.py` 的 `inference_###` |
| `ExistingToolCall` | 原样封装 `build_plan_bim`、`build_parametric_bim`、`revise_bim` 参数 |
| `BuildingObjectRef` | 引用现有提案/源模型 ID，不替换源模型 schema |
| `EvidencePackage` / `LocalizedEvidenceResult` | 新增；供底座通用角色传递建筑材料和返回局部结果 |
| `BuildingContractBundle` | 新增；阶段 0 的离线连接校验，不是新的运行器或几何内核 |

新包只依赖标准库和 Pydantic，不引用 `scripts/tool_scripts`、几何内核、修正模块或底座建筑实现。冻结基准中的旧模块没有改动。

## 样例构造和验证

`tests/test_building_contracts.py` 提供可复用的公开构造器：

- `make_contract_bundle(case_id, mode=..., coarse_merge=..., room_id=..., view_id=...)`；
- `make_reconstruction_bundle()`；
- `make_partial_inference_bundle()`；
- `make_photo_inference_bundle()`。

构造器中的默认 ID 和哈希只是结构代用品。阶段 0 的六个真实来源夹具可以先构造连接模型，再替换为实际 run、源图哈希、对象 ID 和来源说明。三个构造器都实际使用依据、计算链、声明、证据包、检查、规整和覆盖；部分推理另演示跨层范围及重复例外，照片样例演示缺图纸时的明确假设。

当前有 34 项正反例，覆盖编号复用、跨运行坐标关系、继承展开、冲突、单位换算、保存连续性、旧版本返回、未下发图片引用、草案边界、保存文件验证、语义规整保护、容差上限、完整/未完成覆盖与粗粒合并要求。

## 当前限制和待确认项

- 推理侧的功能要求、空间关系和方案选择仍标为 hypothesis；真实工作模型案例可能要求调整字段，而不是提前扩成大而全的语言。
- `EvidenceTaskBudget` 与底座正式预算对象的转换待核心接口稳定后接通。本文件不把它定为第二份预算总账。
- 当前只校验现有工具调用的外层参数名，`plan_json` 和 `operations_json` 内部继续由现有工具校验。阶段 0 不复制旧工具 schema。
- 前后语义快照由阶段 1 以保存源模型确定性生成；阶段 0 只定义其必须比较的字段，不实现抽取算法。当前接口也不会推导“移动带开口边界必然带动开口坐标”这类几何联动：如果快照生成器错误地只改边界尺寸、却原样抄回门窗坐标，结构校验本身无法发现该隐含矛盾。阶段 1 的快照生成和规整算法必须从实际保存源模型重算开口端点、宿主与连通，不能由调用者分别填写两份互不相干的快照。
- 接口证明记录彼此一致，不证明照片解释、推断方案或源 BIM 本身正确。真实质量仍需原始证据和建筑评价。
