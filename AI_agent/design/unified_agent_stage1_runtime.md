# 阶段 1：冻结工具的单角色运行底座

本阶段的输入是案例材料、角色、模型路由和四项预算；输出是源 BIM 产物、可验证的事件记录和停止原因。只实现一个角色的逐轮调用。冻结基准为 `5bb10538`；本阶段没有改工具、两套指引、参考资料或几何内核。

## 入口和边界

`python -m src.agent.runtime_entry --help` 是建筑侧入口。`--provider scripted --script ...` 读取明确标记的离线响应；`--provider paratera` 才会请求 Paratera。必须给 `--out` 和图片目录或网格，运行目录只允许落在本工作树中。图片目前接收 PNG；可附 `--building-input`、任务文字、角色及预算。不存在自动换服务、重试或自动补上外部评审。

- `src/harness_contracts/`：严格类型和事件/预算规则，只依赖通用概念。
- `src/agent_runtime/`：追加记录、Chat Completions 转换、通用 MCP 进程、单角色循环和版本清单。它不引用建筑层。
- `src/agent/runtime_entry.py`、`runtime_tools.py`：准备建筑输入，连接原 `run_bim_agent.py serve`，提供协调/局部观察的真实工具白名单。
- `src/agent/runtime_snapshot.py`、`runtime_behaviour.py`：从保存源 BIM 生成语义快照，解释建筑行为指标。建筑概念留在这一层。

局部观察 ID 统一为 `local_observer`。纯图输入的协调目录为 42 工具、观察目录为 13 工具；原工具服务遇到网格输入会扩为 49/18 工具，四种目录分别固定哈希，按实际输入选择。基础 42 工具为 23 个只读、19 个不可安全重复的写；网格目录为 29 个只读、20 个写，均没有获得服务端去重保证的可重复写。分类与逐工具解释见阶段 1 `tools_report.md`。工具 `review_detail` 的原始定义仍保留，但因它会启动额外模型，本阶段执行前明确返回 blocked，不冒充已执行或未知写入。

## 一轮如何留证据

1. 在发送前序列化最终 JSON 请求；记录每条消息及工具列表的来源、实际图片字节与原图哈希，核对引用位置后存入按 SHA-256 命名的附件。
2. 先预留预算，再写请求事件，直接发送同一份 UTF-8 字节；HTTP 层没有 SDK 的隐藏参数合并、重试和重定向。
3. 保存服务原始 JSON、可见文字、工具调用、原始 usage。公开思考正文、摘要、token 数、签名分别记录；拿不到就写原因。请求了某参数不等于服务确认生效；远端模型别名一直标未核实。
4. 工具调用前先持久化意图。完整参数、MCP 原始返回和转换后的呈现分别记录。Chat 工具消息不承载图片，因此图片按原字节放到本轮所有工具回复之后的用户消息，并记录转换关系。
5. 工具返回先标 `prepared`。只有包含它的下一次请求得到服务响应，才追加 `tool_presentation`，证明该请求被接口接受。它不证明模型在认知上使用了图片。预算耗尽而未发送的工具结果不会算作模型已经看到。

事件文件是 `events.jsonl`，每行符合当前 `EventEnvelope`。`blobs/<sha256>` 保存大对象，读取时核哈希；`journal.json` 固定运行身份与预算。写日志和检查点均先落盘，单写者文件锁避免两个恢复进程同时操作。历史兼容读取可以带缺口；新运行不能用历史缺口事件冒充捕获成功。

## 停止、预算与恢复

模型次数、工具次数、秒数、token 任一耗尽即停止，并把已有模型、viewer、报告和附件列入停止事件及 `receipt.json`。token 预留采用请求 UTF-8 字节数、图片像素数和最大输出之和的保守估算，累计预留不回收；这不是服务分词器或账单。实际 usage 单独结算。缺失 usage 或实际超过预留时停止，保留原回执。服务未返回价格，本阶段不猜美元价格；新增 `CostUnavailable`，也不允许未知价格结清有金额上限的预留。

写工具回包丢失时，保存调用前状态和当前实际文件状态，追加检查事件。仅凭文件变化不能排除后台迟到写入，所以结果为不确定，停止且不重试。被阶段策略提前拒绝的工具则记录已知失败。错误日志只记异常类型和阶段，避免把凭据或请求头带入日志。

安全轮末保存检查点，含对话、图片来源、计数、保存状态和六层版本。`--resume` 必须核对保存状态、版本和日志尾部；未确认请求、未确认工具意图、额外状态变化都不能跳过。孤立写意图先转为未知结果并检查状态。已完成运行再次恢复只返回旧收据。失败的恢复不会覆盖原 `versions.json` 或冻结材料。

当前保守地要求代码及参数完全一致。跨提交迁移、长任务压缩、图片移出/取回、完整故障矩阵及外层 MCP 派工在后续阶段，不在本轮实现。

## 版本与验证限度

六层版本分别是 Git 提交及工作文件哈希、`uv.lock`、提示、工具定义、参数和路由。未提交开发代码的文件哈希也会入档；后续提交不改写已经产生的记录。锁文件证明所引用的依赖版本表，不单独证明当前环境与锁完全一致；本轮实际环境另见交付目录的 `validation_environment.json`。

工具定义保留完整名称、说明、输入 schema 及元数据；策略另存，不混进发给模型的描述。冻结证明和历史重放分别保存；相同源 BIM、成功打开 viewer、单元检查通过均不等于图纸识读或整案质量通过。最小真实接口测试仅使用人工颜色卡，不能外推建筑能力。
