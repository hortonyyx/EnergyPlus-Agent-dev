# 统一 Agent 阶段 0：接口入口与边界

本轮在专用工作树新增两层正式 Pydantic 契约、六类离线样例和反例检查。
还原与推理使用同一个 `BuildingContractBundle`，公共运行信息使用同一个 `EventLog`。
它们为阶段 1 提供格式与校验入口，不执行模型、BIM 工具、规整、压缩或委派。

详细字段、约束及新旧关系分别见 [底座核心接口](harness_core_contracts.md) 和
[建筑共用接口](building_contracts.md)。样例与 A–J 证据见
[覆盖与验收说明](../logs/experiments/2026-10-02_harness_stage0/coverage.md)。

## 文件与职责

| 文件（省略 `src/`） | 一句话说明 |
|---|---|
| `harness_contracts/base.py` | 通用封闭字段模型、时间和父任务身份，允许历史缺失有理由地出现。 |
| `harness_contracts/refs.py` | 用原始文件与实际发送内容的哈希、位置和来源标识材料。 |
| `harness_contracts/events.py` | 保存最终请求、响应、五类思考信息、工具原始/所见结果、版本、生命周期、上下文和外层 MCP。 |
| `harness_contracts/budget.py` | 主任务、子任务、摘要和重试统一预留、结算，缺失用量与费用上界分开。 |
| `harness_contracts/roles.py` | 分离角色与模型绑定，用白名单落实只读，不把推荐模型当自动回退。 |
| `harness_contracts/validation.py` | 按事件顺序检查恢复、重试、上下文、预算和重复写。 |
| `agent/contracts/_base.py` | 建筑层 JSON 值与严格字段类型的公共约束。 |
| `agent/contracts/refs.py` | 沿用建筑对象及 view/claim/inference 编号，补运行、原图和坐标关系。 |
| `agent/contracts/evidence.py` | 分开需求与四类依据，展开继承，保留冲突及四步计算链。 |
| `agent/contracts/declarations.py` | 薄封装三个现有 BIM 入口，表达范围、声明/计算边界、重复例外和待验证方案。 |

## 阶段 1 的读取方式

建筑层启用严格 Python 类型，读取保存的 JSON 应使用
`BuildingContractBundle.model_validate_json(text)`；Python 直接构造应传 tuple 等正确类型。
核心层未全面开启 strict 类型转换，但拒绝额外字段与非有限数；用
`EventLog.model_validate_json(text)` 可统一处理两层。两者的 `model_json_schema()`
直接给出可机器读取的 schema，无须另维护一份手写定义。

旧工具参数和内部 JSON 继续由旧工具负责。`ExistingToolCall` 校验入口和参数名，
不复制整套工具语法；样例中的工具调用仅是待执行声明。本轮未接通 `record.py`，
也未把契约塞进旧流程，因此旧工具行为保持冻结。

## 样例的真实性与适用范围

历史来源、原始/所见返回的映射见 [source_mapping.md](../logs/experiments/2026-10-02_harness_stage0/source_mapping.md)
和 [历史事件说明](../../tests/fixtures/harness_stage0/history/README.md)。
`sources/` 是历史节选，`history/` 是缺口公开的新事件映射；根目录六个样例是本轮离线组合，
不能当作曾经执行过的模型轨迹。每份有 `fixture_kind` 和 `provenance`。

sm25 的原始保存 BIM 与另存的规整建议快照分开：原生隔墙
`space/F1%3AO2/wall/0` 对应 y=16.00，目标 `space/F2%3AO1/wall/2` 对应 y=16.06；
距北外边 20 米的 4.00/3.94 是派生尺寸。建议只演示对齐既有线的声明和前后快照，
没有实际移动原 BIM。门窗、房间、墙清单和连通的变化反例会被拒。

Voimatalo 的已验收 `CORE_E`、标准层门对、单门例外及两次 Sol 不足来自真实文件。
本轮从这些对象归纳重复规则，规则不是历史模型曾声明过的模板。
混合输入把两张 Voimatalo 渲染和文字要求用于同一对象的复核；跨实验对象对应是
明确标注的待核实推断，不作为已有几何配准或直接观测事实。

完全推理仅给贴图扫描渲染与虚构功能需求。8×6 米、3 米层高和两层片段都是显式假设；
破损渲染不支持精确层数或开口计数。仓库未找到适用独立实拍，因此仍需用户选真实照片案例。
粗档也只是两个真实房间合并成一个声明片段的合法表达，未声明门窗齐全或整楼完成。

所有 `passed` 都限于各条检查写出的范围：读取保存片段核对正面积/高度、已声明宿主引用、
所列对象及哈希。接口一致、保存片段通过、整楼质量合格是不同结论。

## 需要与 Opus 定的技术项

1. 阶段 1 从保存源模型确定性生成语义快照。结构校验不能替代真实几何联动检查；
   移动带窗边界时若调用方抄回旧窗坐标，必须由保存结果抽取和几何检查发现。
2. 建筑证据包的输入/输出 token 小预算映射到底座总预算；总账权威只有底座，
   不引入另一套额度系统。当前总预留保守不回收，动态释放留阶段 2。
3. `InferenceHypothesis` 也用于还原中的解释/方案选择；其名字与 `hypothesis=true`
   表示尚待验证的建筑判断，不把已知尺寸或用户要求改成假设。是否改成更中性的名称可在首次接入前定。
4. 大请求可落 blob，逐段注入位置和图片字节须在适配器落盘时核对；核心只校验内联内容，
   不读取外部 URI。事件持久化的原子性、摘要替换关系和保存状态验证在下一阶段实现。
5. 历史 CLI 的最终网络请求和截断前 MCP 返回有缺口，无法靠映射补齐；
   原始附件完整保存、确定性重放、跨版本建筑差异须分别验收。
6. 只读权限目前由合同和调用前检查表达，阶段 3 必须接到真正的工具分发表；不能仅靠提示词。

## 交用户决定的产品事项

- 后续完全推理用哪栋建筑的真实照片、允许哪些补充文字，单独拟案例；本轮不发起实跑。
- 粗细档名称、默认简化程度和全局容差数值仍未定；本轮的数值仅是具体样例的记录/假设。
- 正式新增整案回归的模型、次数和预算按既有节点回归约定另行提案。本轮不预授权。

## 阶段 1–3 估算

| 阶段 | 开发会话轮数 | 可审查的结束点 |
|---|---:|---|
| 1 冻结工具单角色闭环 | 2–3 | 先接请求/工具持久记录和历史兼容读取，再做三层历史重放；确需接口小测交 Opus 安排。 |
| 2 长任务恢复 | 1–2 | 60–120 步离线故障注入覆盖压缩、图片取回、预算停止和未知写恢复。 |
| 3 带图委派与首版 | 1–2，另计获批整案执行 | 外层 MCP 协调、只读局部角色确实收到图、版本核查和回看成立，然后提交还原/部分推理实测方案。 |

合计 4–7 轮开发会话，不把审批等待或真实案例返工折算成确定日历时间。
最大风险是日志缺口导致历史不能完全重放，以及适配器、保存状态和真实模型行为的联调。
接口正反例通过只能缩小这些风险，不能证明工作模型质量恢复。
