## 二、⛔ L4 的结构性上限（这是立项的核心）

`guard.py` 用**词法模式匹配**去判**任意 shell + 任意源码 + 任意散文**。输入空间无界
⇒ **假阳性没有上限**，每一种新的合法用法都是一条新缺陷。六条同族缺陷**无一例外**都是
「合法的东西长得像禁忌的东西」（省略号被判上级目录 · 波浪号被判家目录 ·
`grade line`〔室外地坪线，立面核心词汇〕被判越权 · 一个笔记文件毒死整个执行面 ·
heredoc 正文被当命令参数）。

**本仓 2026-08-16 就已记下这条上限**（「词法扫描只能判断以文本出现的路径，这是结构性上限，
不是补词表能解决的」），**然后又补了两天词表**。⇒ 立此专项即为了不再重复。

### 未决方向（三选一或组合）

1. **进程/文件系统级隔离**（08-16 已登记：BLOCKER-1 换行绕过 + BLOCKER-2 `cwd`/`__file__`/`parents`
   锚点族 + F-59 root 降权，「三者是同一题目的三个面，建议合并」）⇒ 边界改为**构造上够不着**，
   `guard.py` 永久退化为只记录。
2. **维持 `observe` 不再演进**：既然 L1 已保证答案不在里面，L4 只作审计装置。
   ⇒ 那么 `guard.py` 里大量词表/判据是**死代码**，该清理。
3. **保留拦截但换测量点**：只判进程能力与文件系统可达面，不判文本。

⚠️ **决策依赖一个尚未回答的问题**：`observe` 档下 `guard.py` 现存约 1500 行里，
**有多少是只在 strict 档才有意义的死代码**？未清点。

## 三、⚠️ 非对称：codex / 非 Claude 读图器不过 L2/L3/L4

`guard.py` 是 Claude Code 的 PreToolUse hook，**codex 不走**。07-08 那次 9/9 就是这样跑的，
2026-08-19 的 P1 臂也是。⇒ **GPT 臂的隔离 = L1 + cwd**，比 Claude 臂弱，但 gt 照样物理不在。

**决策项**：两项验收里 GPT 臂与 Sonnet 臂的隔离强度**不同**，成绩口径要不要因此分开标注？

## 四、⚠️ root 运行 ⇒ 权限位无效（F-55 后半）

全程 root，**root 绕过自己拥有文件的 DAC**；`chattr +i` 在 overlayfs 不可用；
`setpriv` 降权可行但接入 spawn 超出当时范围（候选 F-59）。
⇒ **真正起作用的是「不在它知道的那棵树里」，不是权限位。**

## 六、⛔ 本专项与 reading 专项的分界

- **本专项**答：「读图器**能看到什么、能跑什么**，以及我们**怎么知道它做了什么**。」
- **[reading 专项](../capability/reading/improvement_methodology.md)** 答：「读图器**该怎么量**，以及怎么让它做不到眼估。」
- 交叉点只有一个：`run_cv_probe.py` 的 wrapper 形态（A2）——它既是隔离面，也是量测入口。
  **锚点只收 `candidate_id`** 那条修法（reading 专项 §9.1）要改的正是这个文件。⇒ **改动需两边对账。**
