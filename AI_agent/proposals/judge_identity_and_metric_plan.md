## 0. 一句话

判卷器放弃「把坐标映到绝对格子」，改为**在信任边界对实际出现的坐标做单链接聚类 + 直径守卫 + 歧义显式拒绝**；同时把墙的分母由「邻接界面条数」换成**长度（米）**，用**联合切点原子化**取代一对一指派。

---

## 1. 两版独立收敛的四条（高置信，主控采纳）

**C-1 · 身份机制（Q1）**：任何**全定义**的离散化（定格量化 / Decimal 取整 / 定点整数）都有边界，边界两侧任意接近的两点被判异 ⇒ **注定失败**（r2 已实证一次）。出路是**部分函数**：对一次 score request 内实际出现的坐标按轴建图，距离足够近才连边，取连通分量作为身份原子；**分不清时显式拒绝**，绝不静默给答案。边界依然存在，但两侧从「两个静默答案」变成「接受 vs 响亮拒绝」。

**C-1′ · 身份池作用域 = 文档内，不跨文档（主控裁定，两源稿此处分歧，GLM P10-① 点出综合稿原稿未落锤）。**
GPT 侧主张 GT 与产品坐标**联合**建池；Claude 侧主张按 `(文档侧, floor, 轴)` **文档内**建池。**裁定取文档内**，理由是两个层次必须分开：

| 层 | 问题 | 判据 | 尺度 |
|---|---|---|---|
| **身份层** | 「同一份文档里这两个数是不是同一个坐标」 | **精确**（聚类 + 直径守卫 + 歧义拒绝） | 皮米级（表示噪声） |
| **判卷层** | 「产品画的这道墙算不算命中答案的墙」 | **容差**（既有 `plan_*_tol_m`，用户可配） | 分米级（判卷尺） |

联合池把两层混在一起：产品坐标一旦落在答案端点的直径阈内就会并入同簇、挪动簇代表 ⇒ **答案的墙长（分母）成为产品输入的函数**。幅度虽在亚皮米级，但这是**测量独立性**的架构原则——**尺子不能被被测物变形**，且与 gt 铁律精神一致（答案独立于产品）。

**随之而来的口径（必须一并落实）**：跨文档比较**只发生在判卷容差层**，绝不通过共享身份池。产品切点向答案切点**单向**配准（产品→答案，永不反向），配准判据 = 既有判卷容差、显式声明、单向性写进合同。
**⇒ 新增硬锁**：**答案侧的原子与分母必须是「答案字节」的纯函数**——喂入不同产品、答案的原子集合与 `denominator_m` 必须**逐字节相同**。这条锁同时把「产品能改自己分母」的口子机械焊死。

**C-1″ · 输入合法性合同必须显式落地（GLM P10-②）**：C-1 的「无条件」是**在输入合同下的无条件**，该合同四条须写进代码与文档、并在运行时执行，不得只当假设：① 同一意图坐标的全部出现值直径 < 合并阈；② 不同意图坐标之间最小距离 > 分裂阈；③ 不出现落在护带内的距离；④ 归并不得造成零长边 / 相邻重复顶点 / 环自交 / owner 重数冲突。**违反任一条 = 整轮响亮拒绝**（分码见 R-5）。施工方若只实现聚类而不实现并执行该合同，「无条件」即落空 ⇒ 验收不通过。

**C-2 · 分母（Q3）= 长度（米）**。否决「邻接界面条数」（同长墙因邻接房间多而权重升高；真实签字 sm24 实测**每米权重最大/最小差 3.96×**）；否决「物理墙条数」作主分母（「一道墙」的定义会持续引入新歧义）。长度对切分**可加**，分区不变性可证。

**C-3 · 匹配（Q4）= 联合切点原子化**，否决一对多覆盖指派。⇒ `score_match_ambiguous` 在该通路**结构性不可达**（覆盖是集合运算，无并列最优）。

**C-4 · 已签字 sm24 答案（Q5）= 字节不动、签名继续有效、不重签、不迁移**。本方案不修改源图 / request / 清单 / GT 任一字节。**⚠️ 施工前后必须对整个 `sm24_anchor` 受保护清单做逐字节 hash 对照；任何变化 = 施工直接失败**，不许拿「规范化」当改写答案的理由。需要失效的只是**派生件**（旧 `score_vs_gt` sidecar、旧 grade 图、旧 identity 合同下的阶段缓存、挂起中 sm24 run 在校正接受点之后的评分派生件）。

> **对用户的白话结论**：**你不需要再签一次字。**

## 2. 主控裁定的分歧点

**R-1 · 阈值结构 = 取「护带」而非「单点边界」（采 Claude 侧结构）。**
GPT 侧用单一上界 `1e-12` + 「距离恰等于上界才拒」；Claude 侧用护带（合并阈 / 分裂阈之间一律拒）。**裁定取护带**，理由：单点边界是**零测度**事件，现实中永不触发 ⇒ 漂移只要略大于上界就**静默分裂**，正是本批要消灭的假红换个位置复发。护带把这段区间变成**响亮拒绝**，才兑现 C-1 的承诺。

**R-2 · 三个阈值不由本文钉死，须由施工批「实测推导 + 双向证明」。**
Claude 侧给的一组（合并 `1e-11` / 分裂 `1e-10` / 直径 `5e-11`）对 **1e-9 必红锁只剩 10× 余量**，偏薄；GPT 侧 `1e-12` 对 1e-9 有 1000× 余量但无护带。**裁定**：护带位置由**实测**定——下界须显著高于真实 case 的合法表示漂移上限（20 m 量级下 1 ulp ≈ 3.55e-15，若干次算术后约 1e-14），上界须显著低于必须判红的最小真实缺口（1e-9）。施工批须给出：① 实测漂移分布；② 两侧余量各多少倍；③ 两条锁分别证明「合法漂移必合并」与「1e-9 缺口必红」。**禁止**先定数字再补论证。

**R-3 · criterion 三分（采 GPT 侧）**：`walls_complete`（漏画，分母只来自答案）/ `no_extra_walls`（多画，额外长度须为 0）/ `no_duplicate_wall_strokes`（重笔；若产品语义允许重笔则显式 NA，不许悄悄忽略）。⇒ 漏画、多画、重复画**分开算账**，同一个缺口不在多个 criterion 里重复扣分。**产品多画一条墙不得把分母变大**。

**R-4 · 上下游口径（Q2·采 Claude 侧框架）**：正交性判据抽进**生产与判卷共用**的模块（零 gt import，守不变量 #4）；并**拆开两个问题**——「几何**合不合法**」权威在生产端，「判卷器**能不能量**」权威在判卷端，且后者只许说 **unsupported（能力 NA）**、**不许说 broken**。这正是三轮假红的结构性根源：判卷器拿自己的能力上限去宣判上游几何非法。上游 `_EPS=1e-9` 的收紧**分两阶段**：本批只加 advisory，**两次真实 run 零命中后**再翻 blocking。

**R-5 · 错误分类学（采 GPT 侧）**：身份层失败一律 fail-closed 且**分码**（非有限值 / 护带内歧义 / 链式桥接超直径 / 归并致边坍缩 / 合同版本不匹配 …），错误上下文**必须记录十六进制 binary64 与精确直径**，不得只打印舍成十进制的值——否则事后无法复现判定。

## 3. 点名风险（Claude 侧独有发现，必须写进派工单）

**⚠️ 最脆环节 = `score_service.py` 里 `product_to_gt` 的构造**：它同时喂**墙的计分**与**窗的宿主解析**。摘掉一对一指派后必须由覆盖式的多对多结果重填，而两者语义**不等价**。施工若图省事「取第一个」，**多段覆盖时窗会静默绑错墙，且没有任何测试变红**（既有窗锁全是单段夹具）= 典型「门是真的、锁是缺的」。

**出口（硬性）**：该项**不许混在常规回归里**，必须 ① 写成逐键相等的显式契约锁；② 新增**多段覆盖**的窗夹具；③ 派工单单列一条。

## 5. 验收总纲（细目由派工单展开）

1. **三个既有活体反例全部转绿**：真实 sm24 `8.059999999999999`↔`8.06`；typed correction `0.1+0.2`↔`0.3`；r2 的 1-ulp 量子边界对。
2. **1e-9 缺口双侧仍红**（答案侧 + 产品侧各一条锁），且错误码逐字不变。
3. **护带内歧义 = 响亮拒绝**（分码正确），非静默合并也非静默分裂。
4. **Q3 三情形得分**：整墙画漏 `0/4`；画对但分段不同 `4/4 = 100%`（现状是抛歧义不出分）；画对一半 `2/4`。并证明同一道墙整条画漏时 `failing` 恒等于墙长、与对面房间数无关。
5. **sm24 受保护清单逐字节不变**（施工前后 hash 对照，变即失败）。
6. **sm21 legacy 通路零变化**（既有分数字节 + 渲染像素 hash + 分派路径）。
7. **窗宿主解析多段覆盖锁**（§3）。
8. **答案原子/分母 = 答案字节的纯函数**（C-1′）：同一份答案配不同产品，原子集合与 `denominator_m` 逐字节相同。
9. **输入合法性合同四条在运行时被执行**（C-1″），违反即响亮拒绝并分码；只实现聚类不执行合同 = 不通过。
10. **开工门（GLM P10-③）**：动 `segment_scorer` 的 Literal / 加 `coordinate_identity` 字段会改变新 run 的评分身份摘要 ⇒ **开工第一步先核** `tests/test_c2_b4b_contract.py` 是否钉死该摘要常量，撞上则先出处置方案再动手。
11. **每条锁自带指定 neuter，共用守卫的锁必须归并披露**——不许再把共用同一守卫的多条锁记成多条独立承重锁（r2 直接教训）。
