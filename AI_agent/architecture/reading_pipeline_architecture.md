## 〇、一句话

> **量归代码、认归模型、对账归代码门。**
> 代码在 reading 里只当**卡尺**，⛔ 不当**工序**；工序最终归 `reading-agent`。

> ⭐ **reading 判的是「描得像不像」，correction 判的是「画得对不对」**（2026-08-25 用户定）——
> correction 之后**信息才简化收束**，才有唯一正确答案可判。
> ⛔ 别再把完备性负担全压给 reading（「读得够好就不需要 correction」= **分工塌了**，不是 reading 强）。
> 判分口径全档 → [../guides/reading_correction_split_guide.md §四](../guides/reading_correction_split_guide.md)。

## 一、当前形态（2026-08-24 实测跑通，⛔ 全在探索档）

**输入** = 一张平面图 PNG ＋ 一份配置（画框 · 世界原点 · 尺寸链声明 · 声明墙厚 · perception 指针，共 15 键）。

| 步 | 谁干 | 干什么 | 实测 |
|---|---|---|---|
| ① **认笔** | 代码 | 按**色度**聚类发现墨族，报每族占比 + 形状统计（连通域数 / 中位面积 / 最长跨度 / 细长比）。⛔ **不给任何族起名** | sm25 4 族 · sm21 3 · sm24 3 · **sm20 1 族（纯灰）** |
| ② **量尺子** | 代码 | 从尺寸链刻度 + 声明段值拟合 mm/px 与世界原点 | 链闭合 **0.0 mm** · rmse 0.226 px · 最大残差 **8.2 mm** |
| ③ **抽面线** | 代码 | 结构族墨按列/行分组，每组一条面线：支撑列 · 两条边 · 沿线**哪段有墨**(runs) · **哪段是空的**(gaps) · 每空档附各族墨迹剖面 | 49 / 46 / 98 条 |
| ④ ⭐ **认** | **模型** | 族角色 · **哪两条线是一堵墙**（代码先穷举全部候选、⛔ 不设阈值）· 每个空档是**门/窗/不是洞口/我认不出来** · 非墙面线显式列出 | 候选 374 / 1185 个；产物 = `perception/<case>.json` |
| ⑤ **合成** | 代码 | 三层产物：**观测层**（我看到的墨，不可争议）· **声明层**（图上写的字，OCR，只比字面）· **假设层**（我认为它们是什么，可以错、可被推翻） | as-drawn v2 |
| ⑥ **自检** | 代码 · **11 道门** · ⛔ 不读 gt | 见下表 | 每道门都真红过也真绿过（机器统计） |
| ⑦ **判分** | 代码 · **对 gt** | 分母（从 gt 机械派生目标）+ 判分器（画对 / 漏画 / 多画 / 门窗身份）+ grade 图 | 见 [judge_grade_model.md](judge_grade_model.md) |

## 二、目标形态

```
reading-agent  ←── ① SOP（强模型多次摸索出来的好做法；解决「别每次重新试」；不太变化）
                   ② 判例库（窗有哪些画法 · 墙一般怎么画 · 各自的坑；⭐ 模型按需查；一直长）
                   ③ 工具箱（代码工具 + 子模型工具）
   │
   ├─ 看图 → 判断这是什么画法 → 查判例、按 SOP 选一条流程方案
   ├─ 调工具开始读，边调边认
   ├─ 出一版成果
   ├─ 回叠原图检查 ─────┐
   └─ 不满意就再来 ←────┘      ⭐ 循环在 agent 内部
          ↓
      最终成果（三层产物）
          ↓
      确定性门（代码，⛔ agent 改不动）
          ↓
      judge（现阶段 = 高智力模型看总体；上线版本撤）
```

### ⭐ 三层归属（本文的锚，⛔ 不得含糊）

| 层 | 是什么 | 归谁 | 当前 |
|---|---|---|---|
| **量具** | 认笔 · 抽面线 · 拟合尺子 · 剖面 · 连通域 | **代码**，但只当**卡尺** | ✅ 形态对 |
| **工序** | 这张图走哪条路 · 先干什么 · 量哪儿 · 这是什么 | ⭐ **模型** | ⛔ **焊死** |
| **出口** | 确定性门 + 判分 | **代码，产出方碰不到** | ✅ 形态对 |

**⭐ 措辞校准（用户 2026-08-24 确认）**：代码此前把**量具**和**工序**焊在一起。要拆的是**工序**；
**量具必须留着**，且这**不叫「把工人变成确定代码」，叫「给工人卡尺」**——
工人仍自己决定量哪儿、用哪把尺、这是墙还是家具、这个洞是门还是窗，**只是读数从卡尺上读、不靠眼睛估**。
⇒ **「agent 驱动工序」与「agent 一个坐标都不自己填」两条同时成立，不冲突。**

**依据（实测，非偏好）**：2026-08-21 全仓 27 份独立 reading 解剖 ——
**5 份好的 100% 用代码测量、零例外**；2026-08-19 三臂判别病灶 = **眼估入口敞开**。

### ⭐⭐ SOP 与判例是**两份东西**，⛔ 别压成一份

> 2026-08-24 用户纠正 orchestrator（orchestrator 曾提「手册应写成判例集而不是作业规程」，
> 用户：**两个都要，各管各的**）。

| | **SOP（标准流程）** | **判例（知识库）** |
|---|---|---|
| 是什么 | **强模型多次摸索出来的比较好的做法** | 窗户的画法有哪些 · 墙一般什么画法 · 各自的坑 |
| 解决什么 | **规避绕弯路——不用每次自己去试** | **适配多种图 ⇒ 泛化性** |
| 稳定性 | **不太变化**（某环节的具体步骤可有出入） | **一直长** |
| 怎么用 | 按流程走 | ⭐ **模型选择性调用**（当前实现 = 上下文全灌，**是过渡态**） |

⛔ 判例的目的是**不把一种风格/画法烤死在工序或代码里**，⛔ **不是**给流程加分支。

⚠️ **写 SOP 的已知反效果（2026-08-20 实测）**：GPT 撞上「跨轴分歧」告警后，
**把两轴拆成两次单独调用把告警消掉**——而这是 orchestrator 的返工要求「两轴必须一次给全」**教出来的**。
⇒ 立规则必须给合法出口。
⚠️ 且 2026-08-21 解剖已证**具体做法层面没有单一杠杆**（07-08 零像素锚 / 零引用 / 零台账 /
六图只标定两张，**照样 9/9**）⇒ SOP 写「好做法」，⛔ 别写成「必须这么做」。

### ⛔ 两条不让给 agent 的边界

1. **坐标不由 agent 填**（见上「卡尺」）。
2. ⭐ **验收出口必须是代码，且 agent 改不动。**
   手册提高的是「做对的概率」，⛔ 它**不保证「做错时被发现」**——两件事。
   依据：五轮跨家族审造了九种作弊全靠出口的门拦下；最狠的 `band_collapse`
   **产物里没有一个假数字**（每个数都从原图老实重算）却比诚实产物得分高、当时八门全绿。
   ⇒ 同「谁写谁不批」：**判产物的人不能是产出它的人。**

## 五、已知盲区与后果（⛔ 一直写着，别当新发现）

1. **单色图现在不成立**：实测 sm20 只有 **1 族墨**（`achromatic_only=True`，100% 一族），
   墙/家具/标注/门窗全在里面 ⇒ 按族排除、按族判门窗的判据直接塌。
   ⭐ 塌的是**判据**不是**形态**：三层 + 对账门仍成立，需换证据维度
   （线宽 / 线型 / 封闭性 / 连通域形状——`ink_palette` 其实已在测，只是无人消费）。
   ⚠️ 且 sm20 墨量是 sm25 的 **30 倍**、细长比仅 **0.023**（sm25 0.13）⇒ **是另一种画法**，非「同图去色」。
2. **「洞口 = 面线上的空档」是烤死的方言**：窗若画成墙内 3–4 条平行线（墙面线不断），
   该窗**进不了候选集**。⇒ 归路线图第 1–3 步。
3. **尺寸链只定尺子、不逐条钉墙**：22 条 x 向面线中仅 **4 条（18%）**能被刻度钉到 2 cm 内；
   `dimension_witnesses` 记了 20+34 个刻度而**无任何判据消费**。
   ⚠️ 2026-08-22 orchestrator 亲手那次做过的「刻度定洞口边界」，**v2 重写时丢了**。
4. **agent 驱动 ⇒ 同图两跑产物可能不同。** 与门不冲突（门只判产物、不判过程），
   但**任何成绩必须至少两抽，n=1 不算数**（历史坑：19 个「满分」实为同一份产物复用 19 次）。
5. **`reading-agent` 的状态变更**：它自 2026-08-02 起一直是「打包延后归 reading 专项、
   ⛔ 不是本批准入门」。**2026-08-24 用户把它定为架构方向**，⛔ 非 orchestrator 顺手改。
6. ⭐ **「几何对、语义错」的分工是实测过的**（2026-08-25，六个只改语义不动几何的变异，逐个重建产物再判分）：

   | 只改语义 | reading grade | 门 |
   |---|---|---|
   | 断口说成「不是洞口」 | **C5 100 → 0** | 全绿 |
   | 门窗全说成门 | **C5 → 51.6** | 全绿 |
   | 门窗全对调 | **C5 → 0** | 全绿 |
   | 标注文字改口说成墙 | **C4 多画 0.722 → 2.280** | 全绿 |
   | 一堵真墙说成家具 | **C1 → 92.7 · C2 → 92.0** | 全绿 |
   | 全部弃权（我都认不出） | **全 0** | 1 道红 |
   | ⛔ **族角色对调（窗族↔家具族）** | ⛔ **一个数都不动** | ⭐ **2 道红** |

   ⇒ **grade 判「语义错误的后果」，门判「语义声明本身」**；⛔ 两个都看才闭合，单看任一有盲区。
   ⇒ 且 **弃权买不了分**——全部弃权 = 全 0，只把损失从多画挪到漏画。

7. ⭐ **「墙统一记成有厚度的墙带」= 已评估、⛔ 不采纳**（2026-08-25 用户提议，实测否决）：
   - **它就是五审那个作弊的形状**：`band_collapse` 把两线墙各塌成一条带，**产物里没有一个假数字**
     却优于诚实产物且八门全绿。拦住它的两道门（支撑条必须是一条墨 · 区间须与墨条重算相符）
     **在带成为合法表示时就得拆掉**。
   - **厚度会变成事实性名字**（F-78：0.49 像素噪声变成图上不存在的墙厚 0.131/0.146）。
   - **一堵墙两侧本来就不同步**（T 形接头一侧断一侧不断；洞口两侧因门垛不齐）。
   - ⭐ **而且现在并非「只认双线」**：sm24 走 `solid_band_walls`，面线取带的两条边；
     判分器四审已改成认「带的两条边」，sm24 **44.3% → 95.7%**。原则是**画了什么记什么**。
   - **配对负担实测比看起来小，但⛔ 不能自动化**：

     | | 候选 | 模型选了 | 互为最近邻 | 真需判断 |
     |---|---|---|---|---|
     | sm25 1F | 374 | 22 对 | 20 | **2** |
     | sm25 2F | 303 | 21 对 | 20 | **1** |
     | sm24 1F | 1185 | 8 对 + 4 带 | 8 | **0** |

     ⛔ 但「互为最近邻」会**把两条「240」标注文字笔画配成一堵墙**
     （L035↔L033 间距 **0.1190 m**、L049↔L048 **0.1082 m**，都是完美合法的 120 墙间距）
