# 坐标、源几何与派生模型

实现基线：`461dfc98`；本文同时标明现状与演进要求。不会通过改文档取消仍在代码里执行的检查。

## 已有可复用核心

- [correction/schema.py](../../src/agent/correction/schema.py) 的 `Cell` 以米表达房间平面，`Floor` 提供楼层与高度；legacy 类注释使用 world-frame/centerline 表述；当前 V3 的输出坐标合同采用建筑坐标，增加外形、立面段、来源等结构，不等于已实现完整外皮输出。
- [geometry/modelling.py](../../src/agent/geometry/modelling.py) 提供 `ZoneVolume`、`Surface`、`BuildingGeometry` 等几何原语；[build.py](../../src/agent/geometry/build.py) 组织建模，切分和配对在 [split_pairing.py](../../src/agent/geometry/split_pairing.py) 执行。
- 当前配对按楼层分组处理墙和相邻层水平面；不能据 `ZoneVolume` 注释推断通高、中庭、斜屋面或任意三维体量均已支持。
- 现有 window 结构与宿主解析可复用；通用门洞、物理隔断对象与连通图仍需演进，不能把已有热区面模型直接宣称完整通用 BIM。

V3 外皮事务与 B5 的部分宿主/可见性链还要求各层 footprint/family 范围匹配，assumed existence 在现有声明绑定中会被拒绝。少输入时推断窗、不同外壳或退台不能直接视为此链已支持；应在输入适配和共同模型演进时处理这些具体限制。

## 现有 EnergyPlus 坐标出口

[output_coordinates.py](../../src/agent/output_coordinates.py) 已建立坐标合同和 sidecar：几何顶点保留建筑坐标，EnergyPlus 使用 Relative，Zone 原点/相对转角归零，朝向来自校正证据或显式假设。它已接入装配及导出验证，不是未来才实现的 E4 方案；并非所有 legacy 入口都等价消费此合同。

## 两路输入共用的约定

| 内容 | 要求 |
|---|---|
| 单位与尺度 | 输入原单位、转换及可信尺度明确；概念尺寸属于假设 |
| 原点与方向 | 保存局部到共同坐标的变换；假定北向不伪装为观测 |
| 墙与参考面 | 区分内皮、外皮、参考轴和厚度，不能只因数值接近就混用 |
| 源对象 | 保留有证据的房间、隔断、窗门及稳定来源引用 |
| 派生对象 | 热区、计算面、IDF 和查看 mesh 从源模型派生，保留对应关系 |
| 简化与更新 | 改了什么、为何、依据何种输入要能追溯；新信息能替换相应假设 |

这些是共享模型的设计约束，具体新字段尚未定稿。可从现有类演进或加薄转换层；先用图纸/体量小样本找实际缺口。

## 容差与薄片

区分观测不确定度、参考面转换、浮点/序列化精度、几何有效性和面向仿真的简化。它们不应共用一个未经解释的“精度阈值”。
当前建模用到的最小边长从 correction 配置读取；项目检查存在 0.1 m 阈值，不因此宣称所有 EnergyPlus 版本低于此值必然崩溃。
层间墙位相差可能形成窄条交叠；先核对原图、单位和参考面，区分真实结构、识读误差和数值残差。两个墙带重叠只能产生待核候选，不能证明它们是同一道墙。

不能用统一粗网格、删除窄面或改 GT 来自动消除问题。若用途允许简化，应形成有记录的派生模型，并检查房间信息、覆盖、闭合、开口和配对是否仍合理；源几何保留。
查看产物和仿真可接受产物可有不同状态，不要把一个检查失败解释成整份输入没有可用信息。
