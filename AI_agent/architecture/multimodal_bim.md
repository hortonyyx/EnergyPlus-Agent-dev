# 两路输入与统一轻量 BIM：下一阶段建议

状态：设计建议，尚未实现；本轮只清理与存档。用户已明确两路与最终混合入口目标，具体接口在开工时以小样本定稿。

## 推荐结构

```text
图纸 / 文本 / case ─→ 图纸适配 ─┐
带表皮体量 ───────→ 体量适配 ─┼→ 证据整合与缺失补全 → 共同轻量 BIM
CAD / 其他来源 ───→ 后续适配 ─┘                        │
                               几何与质量说明 / 查看器 ←┤
                              IntakeOutput / IDF / EP ←┘
```

两路差别主要在“如何提取与推断”，没有必要把几何、场景表达、交接与导出全部分叉。
先围绕一个图纸样本和一个体量样本定义最小公共接口，复用现有模型；不先造全模态平台。

## 共同模型最少承载什么

| 内容 | 足够输入时 | 信息不足时 |
|---|---|---|
| 尺度、位置、方向 | 保留输入量测与变换 | 明示默认尺度/相对坐标，说明适用范围 |
| 外形、楼层、外表皮 | 保留可验证形状与分层 | 先产体量级结果，楼层/高度推断单独标记 |
| 内部分区 | 使用已知房间和边界 | 用粗分区服务仿真，标注为推断热区 |
| 门窗、构造和用途 | 保留来源及可支持的细节 | 可用窗墙比/默认构造等可替换假设 |
| 质量 | 标出各字段的证据和验证 | 列出缺失、冲突、假设与可继续补充的输入 |

具体字段可以从 `CorrectedGeometry` / `BuildingGeometry` 演进，也可以加薄的转换层；由实际缺口决定。
不把体量模型强行转换成假的平立面 reading，不把热区划分冒充真实房间。
质量先用可解释的来源与等级，不制造没有校准依据的精度百分比。

## 混合输入如何提升结果

补充输入只更新它有证据支撑的部分。例如外部体量给外皮与朝向，平面图给房间，CAD 给准确尺寸。
冲突时比较来源、尺度和测量依据，保留冲突记录；不写死“CAD 永远对”或“后来的永远覆盖”。
原始输入保留，几何变换和简化可重做。共享原点与标识需要两路一致，但不要求所有模态使用同一观测 schema。

“给多少输入都产出输出”是能力目标：信息不足时降级输出当前可支持的模型和缺失说明。
完全无有效几何/尺度时可以提供明确标注假设的概念模型；不能宣称真实建筑精度，也不能只造空 JSON 充数。

## 工作树与合并

1. `main` 先落共同模型的最小样例与生产者/消费者接口。
2. 如需同时施工，用 `feat/drawing-input`、`feat/massing-input` 等短期分支/worktree。
3. 输入模块各自修改；公共 schema、内核、配置和主入口的变化先小步回主干。
4. 经常集成，每路用同一出口验证。完成即收树，不等两套系统写完才合并。

Git 的文本冲突通常能解决，真正的合并风险是不同单位、不同“墙/房间”定义和不同缺失值语义。
提前统一这些小接口，比长期维持两套大架构更容易控制成本。当前不创建这两棵开发树，先完成本轮对齐。

## 最小验收

图纸样本和体量样本都能生成可查看的几何与质量说明；混合输入能补强同一个结果。
再用选定 case 验证 IntakeOutput 和需要的仿真出口。真实输出先于提高分数和完善治理。
