# 运行证据与评价

本页统一原 GT 流程图、评分方案和成绩口径中仍适用的边界。它不要求每次探索都正式评分。

## 先说明跑的是什么

| 情况 | 能支持的结论 |
|---|---|
| 单元/行为测试通过 | 所测范围和输入满足相应行为，不能替代真实 case |
| 复用旧 reading 继续运行 | 后段工程链在该输入上的表现，不是本次冷启动识图 |
| GT 喂内核诊断 | 几何内核或下游的受控检查，不是无答案生成能力 |
| 人工补充或修改后成功 | 辅助模式结果，记录干预信息、次数与时间 |
| 从原始输入生成到目标出口 | 该输入、模型、代码、配置下的实际结果；推广能力需更多样本 |

报告区分生成、校验、评分和仿真。`PASS` 不代表未启用的检查已覆盖，`NA` 要说明缺少了什么。数量检查没有 expected 值时通过，也不证明房间完整。

## 评价目标

几何看尺度/形状、楼层和房间完整性、外皮与开口、相邻和连通；同时记录假设、失败、人工负担、总成本和耗时。
图纸路线看重建与证据的一致性；体量路线还需评价推断合理性，不能要求恢复一个无法从外皮唯一确定的真实内部分区。
正式比较应固定可比较的输入、人工条件、模型配置与评价口径。没有完成评分不必阻止展示探索模型；不制造未校准的精度百分比。

## GT 与来源

GT 是评测参考，不进入被评测生成器。原始设计几何、人工参考和自动处理结果各保留来源；修订 GT 时写明改变的是设计事实还是机器规整，保留旧版本及相应确认依据。
现有 [gt_revisions.py](../../src/agent/judge/gt_revisions.py)、[judge](../../src/agent/judge/) 等工具按任务复用。暂存的 facts、签字 DXF、正式 GT 与已晋升版本并非同一状态，不根据目录名称推断等价。
现有 AnswerCompiler 和暂存 facts 已实现，但 [gt_promotion.py](../../src/agent/judge/gt_promotion.py) 晋升时未复制 facts。当前 as-drawn 平面评分按 request 源哈希查 signed DXF 后编译分母，立面从 GT 派生 targets（[flow_wiring.py](../../src/agent/judge/as_drawn/flow_wiring.py)）；整条链尚未统一消费 frozen facts。

当输入或参考自身存在矛盾，先展示证据和影响，再决定修哪里。旧日志中未经证实的根因不自动变成修正依据。

## 下游结果

用相同物性比较不同几何可以做受控诊断，但不能排除物性/使用行为造成的现实差异。EnergyPlus 运行成功不证明建筑重建准确；IdealLoads 供冷/供热需求不写成实际用电量。
本项目目前以几何和可用输出为主，物性接口复用协作者交付；交付状态按实际验证记录，不能把用户称已完成写成助手已验收。
