## 当前工作包：图纸路线优先

计划已梳理，下一步从 [图纸重建计划的首个工作包](drawing_reconstruction_plan.md#紧接本计划的首个工作包) 开始：

1. 用 sm25 旧产物建立可查看基线和房间/开口对应清单，解释 27/29 的差别；单独标明历史重放。
2. 核对隔离读图与 as-drawn 接线，用一张平面和一张立面做目标档与 Sonnet 级实验，再推进六视图冷启动模型。
3. 按真实输出改善精度/完整性，补最小源对象关系；短边专项验证不阻塞早期查看和读图实验。
4. 用 sm24 检查迁移，打通一次开口修改回写，随后接协作者物性与首个 EP 出口。

当前输入为 sm25/sm24 原始图纸、声明及隔离使用的历史诊断产物；完成依据是冷启动可查看模型、逐对象完整性/误差说明、编辑持久化及实际下游运行，分别按阶段报告。新实验尚无结果，不能将本计划写成已实现能力。

建议保持一条 main，确需并行时用短期树，公共接口及时合入；不创建两套长期架构。详见 [融合建议](../design/architecture.md)。

## 后续与暂缓

| 事项 | 进入开发的依据 |
|---|---|
| 输入融合和编辑回写 | 按图纸/体量样例的实际缺口推进，不同时建设全模态平台 |
| 物性与下游对接 | 复用协作者接口，真实 case 暴露缺口时再补 |
| idfpy / BEM 重构 | 现有下游及协作者接口确实不能满足输出时评估 |
| token / 缓存全面优化 | 目标档模型形成实测质量/成本/耗时基线并出现具体瓶颈 |
| 自动角色治理、全实体与其他求解器 | 有具体产品工作量或下游用途需要，且现有简单实现不足 |

历史批次、审阅债和分数目标不会自动成为待办。当前先让真实输入产出有用的建筑模型，再按输出问题选择改动。
