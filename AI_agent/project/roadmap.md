## 下一次建议的第一批工作（尚未开工）

1. 用已有 case 几何做可视检查和房间对应核对，明确可保留的源建筑信息；同时定位从当前产物到目标出口的最短阻塞。
2. 对具体短边模型核查检查用途与下游实际要求，确定是否修转换、调整检查或建立有记录的仿真简化；不先改 GT 或静默删面。
3. 明确从原始素材生成 reading 的实际入口，让一个代表 case 能按可复现路径产出可查看模型和问题说明。
4. 以一个图纸样本和一个带表皮体量样本，提炼共有模型/出口的最小接口，输入适配分模块，再用局部 CAD/图纸等补充输入验证融合。

建议保持一条 main，确需并行时用短期树，公共接口及时合入；不创建两套长期架构。详见 [融合建议](../design/architecture.md)。

## 后续与暂缓

| 事项 | 进入开发的依据 |
|---|---|
| 输入融合和编辑回写 | 按图纸/体量样例的实际缺口推进，不同时建设全模态平台 |
| 物性与下游对接 | 复用协作者接口，真实 case 暴露缺口时再补 |
| idfpy / BEM 重构 | 现有下游及协作者接口确实不能满足输出时评估 |
| token / 缓存全面优化 | 目标档模型形成实测质量/成本/耗时基线并出现具体瓶颈 |
| 自动角色治理、全实体与其他求解器 | 有具体产品工作量或下游用途需要，且现有简单实现不足 |

历史批次、审阅债和分数目标不会自动成为待办。当前先让真实输入产出有用的建筑模型，再按输出问题选择改动。
