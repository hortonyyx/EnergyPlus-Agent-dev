# 统一 Agent 底座与建筑共用层开发计划

10-02 由 Opus 与 Astra 讨论定稿，交用户。依据：[调研报告](../logs/experiments/2026-10-02_harness_research/astra_report.md)、两轮讨论（[第一轮](../logs/experiments/2026-10-02_harness_research/discussion_01_astra.md)、[第二轮](../logs/experiments/2026-10-02_harness_research/discussion_02_astra.md)）、[讨论记录](../logs/worklog/2026-10-02_reconstruction_discussion.md)。

用户已确定的前提：
- 工作模型现在就换，不再等 Sonnet 恢复；
- 自建一个轻量、本项目专用的底座，以后可开源；
- 支持多个子代理，按角色分、不按模型分，角色可以接不同模型；
- 首版按阶段开做，实测走 Paratera；
- 最终是一个统一的 Agent，三条线协同设计，不能只服务还原建模。

## 一、目标与边界

- **一个统一 Agent。** 还原、部分推理、完全推理只描述输入信息有多充分，并用于组织评价，不建三套长期管线。同一任务可以混用图纸、三维网格、照片和文字需求，同一栋楼的不同部位也可以分别靠观测或推断。
- **首版验收：** 形成可追踪、可恢复的建模闭环，并完成带图委派。初期由开发模型在命令行外层协调，工作角色在自有底座里运行；外层拿不到的请求内容如实标注。工作档模型自主协调放到后续阶段。
- **底座本身不承诺提升建模质量。** 换底座能去掉看不见的变量、方便排错。工作模型的建模质量在底座之后单独推进。
- **推理侧还在探索。** 部分推理只做过开发模型的测试，还没有工作模型完成的案例，架构没有定型；完全推理尚未开始。推理专属的设计都标为待验证的假设，包括方案推断角色、由需求生成方案参数、推断语义，并单列探索线（见第四节）。共同件只做已确认需要的部分，探索结果出来后再回头修订。

## 二、共用结构

- **底座核心（不含建筑概念）：** 模型接口、工具执行、角色调度、上下文管理、事件记录、预算与恢复。首版只接 OpenAI 兼容的 Chat Completions，其他接口按获准服务再加。
- **建筑共用层（三条线共用）：**
  - 同一套源模型、对象身份和修改规则。
  - **依据与需求记录：** 观测、推断、简化、假设可以同时作用于同一对象，不互斥。用户要求和计算过程单独记，例如标注值经换算、规整落入模型时，保留原值和变化原因。依据可以从模板或对象组继承，由代码补齐派生关系，不要求模型逐字段手填。复用现有的 view_id、claim、record_inference。依据变动后，能找到受影响的声明和模型版本。
  - **建筑声明：** 在现有建模、参数化和修改接口上逐步统一，不另起一门包办一切的大语言。一次声明的单位可以是一层、一翼、一组房间或跨层空间，重复允许例外。完全推理还需要表达功能需求、空间关系和方案选择。代码负责展开和计算，建筑上的取舍由模型做。目标是不需要模型临场写脚本。
  - **检查与规整：** 包括几何（细条、细缝、上下层对齐）、拓扑（门窗挂墙、连通）和覆盖三类。按 10-02 定的原则，规整只改尺寸、不改实质；也不能抹掉真实的错层、退台和窄空间，不能把精细档机械理解成每个空间都细分。
  - **覆盖清单：** 串起“用户要求 → 方案选择 → 实际对象 → 检查结果 → 未完成项”。只写了推断理由不算覆盖通过，要核对实际保存的结果。还原侧允许用户明确授权的简化。
  - **角色目录与证据包：** 角色按功能划分，按需调用，不是流水线。交给子任务的证据包包括问题、已知事实、图片或 view_id、裁剪范围和坐标换算；子任务交回带定位的观察或建议，由协调侧核对当前模型版本后再应用。每个角色配默认模型和推荐模型，注明已验证的范围；型号可以替换，推荐列表也不自动变成失败后的换模列表。
- **方法模块：** 按当前问题组合图纸、网格、照片、文字方法，不按路线固定选择。现有两套说明（图纸用 09-30 版，三维用 10-01 版）逐步统一为“共用核心＋方法模块＋角色提示”。

## 三、阶段（每阶段离线验收，不承诺周数）

**阶段 0：接口与验收样例。** 定下角色输入输出、图片与坐标引用、依据与需求的关系、声明边界、事件格式和恢复规则。接口同时用三类离线样例检验：
- 有明确尺寸的还原；
- 资料缺失、含跨层空间的部分推理；
- 只有文字需求的完全推理。

另外还要检验混合输入、证据冲突，以及同一输入下不同的简化偏好。技术细节由双方定稿，新增的产品取舍交用户决定。

**阶段 1：冻结工具的单角色闭环。**
- 工具和两套原始说明以主线 `5bb10538` 为基准，只换运行底座，保留比较基础。
- 统一的事件日志保存这些内容：实际请求与响应，工具参数与原始返回，模型实际看到的返回，图片及其引用，服务返回的思考内容，用量，采样参数，各层版本。没有返回的信息标为缺失，不补造。
- record.py 改为读统一日志，同时保留对历史格式的读取。
- 历史重放用 run99、run100、Opus 三例和两次 Sol 测试的记录。验收分三条：
  - 原始记录和附件完整保存；
  - 同一版本、过程确定的工具重放结果一致，不确定的字段明确列出；
  - 跨版本的历史结果比较对象、几何、挂墙和连通，并解释差异。
- 重放通过不代表模型能力通过。
- 按需做 Paratera 接口小测（工具调用、图片、思考字段），事后报用量。

**阶段 2：长任务与恢复。**
- 支持上下文压缩，图片可以移出当前请求，需要时按原引用取回。压缩后保留用户约束、依据引用、当前模型版本、未决项和待办；原始记录始终保留。
- 设 token、金额、时间和调用次数预算，子角色、摘要和重试都计入总账。
- 用 60–120 步的长记录做故障注入检查：中断前后、图片取回、压缩后恢复、预算停止、写操作结果不明。恢复时先核查已保存的状态，避免重复修改源模型。

**阶段 3：带图委派与首版验收。**
- 开发模型在外层协调，通过 MCP 使用建模工具和委派工具；底座内先只运行只读的“局部观察”角色。
- 记录父子任务关系和各模型实际做了什么，验证子角色确实收到了图片，协调侧能回看核对。
- 角色小测试覆盖：图纸、网格、照片，以及无图需求和信息不足的情况。输入种类和推理程度在验收表里分别列出。
- 随后提交首批整案方案：至少还原、部分推理各一例，写明模型、次数、预算和评价口径，由用户批准后执行。
- 首版要演示“建模 → 检查 → 针对问题修改 → 保存可查看的结果”，以及中断恢复和带图委派。

**阶段 4：建筑共用层增强。** 阶段 0 定稿后即可并行离线开发，按包分别启用，每包各自确定回归范围，不与底座迁移混在一起，也不合成一次大变化：
1. 依据继承、从需求到对象的追踪、建筑声明补充（包括按标注值落位、读图记录检查）；
2. 全楼几何、拓扑和覆盖检查，以及确定性规整（含上下层对齐、细条检查）；
3. 命名修正（同一排房间分排编号、楼层 F# 与体量命名）和统一说明层。

每包先离线验收，需要整案回归时另报方案。检查既要能发现缺漏，也要保护真实的开敞空间、跨层体量和用户明确授权的简化。

**阶段 5：工作档自主协调。** 把协调角色移进底座，沿用相同的对象、声明、工具和评价规则，逐步加入起草、方案推断和复核角色。强模型辅助的结果和工作档自主的结果分别报告。完全推理的首个真实探索案例在本阶段前另拟方案，交用户确认。单个代表案例成功只算探索结果，不据此宣称稳定。

## 四、部分推理探索线（与阶段 3–5 并行，Astra 牵头）

目标是做出部分推理第一个由工作模型完成的案例，并据此弄清推理侧真正需要哪些角色、声明和检查。
- 先由开发模型调度 27B 做一例（辅助模式），以用户已验收的 Voimatalo 精细档为评价参照，看哪些环节 27B 能做、哪些需要工具或协调补位。
- 再逐步减少开发模型的介入。
- 结果用来修订共同设计：角色目录、声明语义、覆盖清单。

前期推理侧的验收只用站得住的内容：两次 Sol 测试记录的重放，以及网格局部观察小测。不用推理侧的整案质量当底座的验收标准。

## 五、分工与交付方式

- **Astra：** 底座核心、记录与恢复、三维与部分推理方法；共同声明中的体量、跨层与推断语义；用户偏好落实的验收；牵头部分推理探索线。
- **Opus：** 依据层、声明展开、全楼检查与覆盖的主要实现；图纸方法；还原验收和相关角色题目。
- **共同负责：** 角色目录、证据包、记录格式、建筑声明、统一说明，以及完全推理的最小接口。共用接口必须同时经过还原和推理样例检查，不能一侧定型后另一侧再补。
- **协作方式：** 共享文件指定主要实现者；短分支开发，共享接口互审；Astra 负责主线集成和统一交接。

## 六、实测与批准

- **接口小测：** 开发中按需调用 Paratera，事后报实际用量。
- **整案实测与节点回归：** 先报方案（案例、模型、次数、预算、评价口径），用户批准后执行。
- **新旧底座的严格对照：** 需要同一服务、同样参数配对，另行批准。09-30 的 GLM 结果只作历史参照。GLM 订阅按智谱条款不能接自有底座，未获许可不用。DeepSeek 专项许可不变。

## 七、主要风险

- 接口兼容的细节：工具调用编号、图片格式、思考字段，各家部署不同。
- 图片缩放、压缩丢掉证据；摘要改变事实。
- 子任务把错误和费用放大。
- 远端模型无法完全冻结：锁住客户端版本和模型名字，不等于锁住远端模型。
- 推理侧架构尚未定型，探索结果可能要求回头修改共同设计。阶段 0 只定已确认需要的接口，为此留出空间。
