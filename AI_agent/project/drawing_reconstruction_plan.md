# 图纸路线执行计划：源分区保真、自动评价与复杂度递进

2026-09-09 详细版。用于本路线开发的主计划，取代同日两版初稿。已开始 M0-1/2/4 的首个增量：源投影、分区比较及三案例离线诊断已交付，其他工作包不因此视为完成。进度见 [当前任务](roadmap.md)；目标以 [产品范围](goal.md) 为准，实际能力见 [实现](../design/implementation.md)。

## 1. 路线目标与不可混淆的对象

交付供多种模拟共用的轻量 BIM：以面围成房间/空间体，记录门、窗、其他开口、物理隔断和空间关系。空间体有明确体积及边界，开口仍表达连通；“封闭块”不等于处处密封，更不能在挑空处补假楼板。全实体墙不是前置，EnergyPlus 是首个适配器。

优先级固定为：**源空间/物理分区与连通正确 → 外形、楼层、开口和整体尺度正确 → 几何自洽可用 → 用途相关的尺寸细化**。小尺寸误差若造成门洞消失或相邻关系改变，就按拓扑错误处理。不存在用面积/总分高抵消漏墙、多墙的做法。

| 对象层 | 必须保留什么 | 可以怎样派生 |
|---|---|---|
| 原始输入/观测 | 图纸、CAD、尺寸/像素/推断来源和冲突 | 可以容差规整；原始数据留档，不把噪声原封不动带入工作模型 |
| 源建筑模型 | 房间/空间稳定 ID、几何边界、真实隔断、开口宿主、两侧与连通关系 | 合理校正可改变几何；分区改变需要输入证据与明确记录，不能为满足矩形算法强拆房间 |
| 计算/显示派生物 | 回到源空间、源边界、源开口的映射 | 同一房间可有多个三角形/切配面/计算单元；计算边界不能成为源模型的物理墙 |
| 下游用途模型 | 当前用途所需的边界和物性 | 热区可拆并；其他适配器按自身需要转换开口、导航或流动域，不反向覆盖源分区 |

sm24 是核心反例：用户确认 reading 正确，C2 之前 correction 将非矩形空间拆成 11 个矩形 cell。直接产物已有走廊两片、办公室三片，后续生成三个内部 Wall 配对。旧 judge 判 minor 和 EP 成功都不能证明源 BIM 正确。源码与坐标证据见 [本轮记录](../logs/worklog/2026-09-09_drawing_route_execution_plan.md)。

## 2. 怎样管理建筑复杂度

**保留逐步增加复杂度的实验方式，按能力依赖推进。** C2/C2.1 等旧名称只用于定位资产与历史，不再要求一批所有旧测试锁/审签债清零才能进入下一批。C2 多边形内核已存在，当前应贯通和验证，而非从头再造。

主执行顺序：**M0 源模型与评价基础 → M1 三案例完整基线 → M2 视图匹配与缺图 → M3 退台 → M4 内院/挑空 → M5 非正交 → M6 组合案例**。

这不是一条不可调整的技术锁链：M2 属于输入匹配，M3/M4 属于竖向几何，M5 属于平面方向。非正交原语的小实验可在 M1 后提前做；有实际项目需求时可将 M5 前移。退台默认先于挑空，因为它主要扩展每层外形，挑空还要表达孔洞、跨层空间和竖向连通。整栋旋转不等同于内部非正交，单独验证朝向与变换即可。

| 能力轴 | 当前起点 | 主要实施依赖 | 代表例 |
|---|---|---|---|
| 正交非矩形房间 | C2 polygon、造面、挂窗和相关局部测试已有 | 源空间保留、冷启动读图/校正不退化 | sm24 走廊/办公室，sm25 凹形外轮廓 |
| 未命名立面/缺图/朝向 | manifest、投影/可见性/宿主已有 | 视图身份候选、匹配/歧义、缺失信息补全；复用 M1 模型 | U 形不转建筑的全图、乱序图、少图；再整体旋转 |
| 退台/悬挑 | 每层 footprint 与切配交差集原语已有 | 移除实际同 footprint 限制并改消费者，区分屋面/外露底板 | 两层缩进，随后单侧悬挑 |
| 内院/挑空/通高 | 现面模型与高度原语可复用 | 内环/楼板孔洞、空间独立高度、跨层边界/连通 | 露天内院；两层通高中庭；局部挑空 |
| 平面非正交 | 底层 polygon/线段可复用 | 读图、校正、宿主、校验和评分的 x/y 轴限制 | 一面斜墙、斜向走廊、斜外墙带窗 |
| 组合与迁移 | 前述能力各有有效结果 | 至少两项已验证能力组合，实际整图冷启动 | 退台+中庭，或非正交+未命名立面 |

每类先用最小可控样本定位内核/接口，再用完整图纸验收。合成几何通过不等于读图能力通过。已有三案例用于基线与回归，不包装成未见过的新图式；未来样本路径在实际选择后写入 run。

## 3. 保留 0–5 pipeline，明确各段责任

| 阶段 | 本路线职责及最小输出 | gate/judge 应保护什么 |
|---|---|---|
| 0_reading | 从原图形成视图、尺寸/尺度、墙/隔断、房间或空间候选、门窗与不确定信息；观测不伪装成最终 BIM | 输入坐标/契约可用；J0 抓漏真构件、把家具读成墙、错层/错方向。门洞中断的墙线不因没闭合就直接判错 |
| 1_correction | 结合多视图与来源进行容差校正、分区重建，形成权威源建筑模型及改动记录 | J1 优先抓读对改错、错误拆并房、漏/多墙、错开口和连通；校正可以修读图错误，但必须有依据 |
| 2_modelling | 确定性生成空间体、边界和查看几何，保留源 ID；交付 HTML 与质量说明，作为主要人工查看/确认停点 | 有效空间、共享边界自洽、开口有正确宿主，源对象无静默增删；查看与确认状态分别记录 |
| 3_split_pairing | 按下游用途切配/序列化，并保留源映射 | 物理隔断与计算边界分开；不能由计算分块给源模型添墙。配对、法向、应有覆盖与开口守恒 |
| 4_mep | 对接协作者物性和用途语义 | 不重分源房间，不静默改几何；物性缺项明确报告 |
| 5_intakeoutput | 装配选定出口，校验坐标、引用及源映射 | 导出一致、可回查；EP 的特殊约束仅决定 EP 出口状态 |

当前 build 已内部执行切配，3_split_pairing 又重建并核对序列化。这是复用起点；先理清源/派生结果的责任，不为阶段名称好看立即拆大模块。公共源模型可以是现有类型加必要字段/薄转换层，最终落点由 M0 的实际消费者决定。

用户已确认 Stage 2 是主要人工交互停点，近期先参考现有 HTML 形式确保模型可查看、可供确认，完整交互后续设计。当前代码的阻塞确认实际在 Stage 3 后，迁移时需一起调整确认依据与恢复逻辑；不只改阶段常量。最低查看交付、自动实验与人工确认的区分见 [查看、编辑与确认](../design/architecture.md#查看编辑与确认)。

## 4. M0：源分区保真与自动评价基础

目标：先让“错分区会被发现、正确非矩形空间不会被强拆、尺寸小扰动不误杀”在实际链路成立。只做支撑本批真实案例的最小对象和判定，不先搭完整 BIM 平台。

| 工作包 | 具体工作与复用位置 | 完成依据 |
|---|---|---|
| M0-1 复用与反例固定 | sm21 成功产物、sm24 正确 reading/错误 correction、sm25 当前产物分别固定为独立诊断 run；复用 checks、judge、查看器/报告 | 自动列出成功、分区错误、下游阻塞及未评价范围；历史产物不混作本次冷启动 |
| M0-2 最小源对象 | 在 `correction/schema.py`、几何输出及薄适配层保留稳定空间/边界/开口 ID、来源、物理/虚拟类别和源到派生映射；利用现有 Cell.polygon、ZoneVolume.cell_id | 一个 L 形源房间始终是一个房间；显示切片和仿真单元数改变不改变源房间数；计算切线不导出为物理隔墙 |
| M0-3 门与连通 | 复用窗/宿主工具和开口台账，补门、无填充开口、宿主边界、两侧空间/室外及连通状态；不做门扇实体细节 | 门的位置、归属和空间连接能保存、显示与检查；未支持部分明确记录，不能按窗处理或静默丢掉 |
| M0-4 定性评价 | 复用 J0/J1、对象匹配、几何检查和报告，增加/接通源分区与真实隔断核对。计数只作信号；用房间匹配、边界类型及连通判断 | sm24 错切结果不能再作为 BIM minor 放行；漏墙/多墙、同数量错房、门错宿主能被检出；正常面细分仍可通过 |
| M0-5 有界规整 | 在现有 correction/确定性几何工具上处理小缝、共线冗余与有依据的同墙偏移；GT 在评测侧独立规整。优先解决实际阻塞，不全面清查阈值 | 小扰动保持源拓扑；源房间、门窗及连通不被吸附吞掉；实际消费者与报告看到的结论一致 |

M0-2 最小字段范围：空间 ID/几何/楼层与高度；边界 ID/几何/物理或虚拟类型/两侧空间；开口 ID/门窗或空洞类型/几何/宿主/连接对象；来源、假设、实质修正；派生对象到源对象的映射。开放区域的语义分界可显式定义虚拟边界，不能据此生造物理墙。墙厚、构造层和门开启工况按用途后挂。

验证只围绕实质行为：sm24 非矩形房间保留；少/多一道隔墙；数量不变但分区错位；门洞关闭/错接；纯网格细分；1/5/10 mm 等局部扰动（是实验取值，不是全局容差）；sm25 当前短边。已有相关测试可复用，缺少的真实故障补局部回归。sm25 的 CAD 微观成因不必全部考证完才尝试用途允许的规整。

**M0 出口**：源对象和定性报告可被实际链路消费；分区错误不再被表示差异掩盖；相同建筑的小扰动不翻成严重错误。某项失败时可交付可查看的局部结果，但不得宣称完整 BIM 正确。自动读图实验可与 M0 中不依赖它的工作交错推进，不等待整套评价系统完备。

09-09 首个增量已验证源空间/源边界/窗的映射、sm24 三墙反例与 8 空间人工分组诊断、比较器的拆并/同数错分区/微扰对照，以及 sm21/sm25 当前重放。源映射严重错误已阻断实际链路；独立分区比较暂由诊断入口消费，还未自动取 reading/GT 参照接 J0/J1。第二个增量已实现显式给定的 door/open、两侧连接与扣洞显示，并修复贴边窗误拦；sm24 的 8 空间、11 窗和 1 处门洞可在同一人工辅助模型查看。第三个增量自动接入已有结构化平面门洞观测，sm25 得到 29 处门/通道；明确未建项阻塞完整性，同时定位尺寸吸附丢失原隔断连接的问题。全图开口识读、一般规整、虚拟边界、下游开口适配和源模型编辑仍待续。证据见 [首个 M0 记录](../logs/worklog/2026-09-09_m0_source_partition.md)、[门洞及贴边窗记录](../logs/worklog/2026-09-09_m0_wall_openings.md) 和 [结构化门洞接入记录](../logs/worklog/2026-09-09_m0_reading_openings.md)。

## 5. M1：三案例从原图到可用 BIM

1. 复用 `spawn_isolated_reader.py`、reading toolbox/CV、as-drawn 和 run_stage，补最小读图驱动与输出合入；让调用者能从原图开始运行，而非手工准备 `_view.json` 和 case 感知答案。
2. 先用一张平面、一张立面验证目标档的感知/工具使用和输出接缝；Sonnet 级作有界对照。若固定 as-drawn 工序不适配，保留有用工具并让模型选工具，不把手写 case 规则包装成通用识图。
3. 先在最容易复用成功链的 sm21 打通，紧接 sm24 保分区回归与 sm25 多层整案；失败从已保存中间产物定位，不反复重跑全部模型调用。
4. 先贯通 Stage 2 的 HTML 交付和确认/恢复：每次形成可查看空间体、门窗/开口、源分区/连通报告、假设及未完成项。复用现有离线查看器和确认入口，检查确认绑定的是所看源模型版本、修改后不能沿用旧确认；已有可显示的局部/失败结果也应可查看并标明状态。J0/J1、gate 与 GT 自动出证据，人工重点处理歧义和抽查代表结果。首份 HTML 不等待完整交互界面或下一项持久编辑实现。
5. 复用查看器打通一次窗口/门洞的位置修改：选稳定源 ID → 修改源参数 → 重新生成受影响派生物 → 检查 → 保存/撤销 → 重开仍有效。先参数动作，再接自然语言到同一动作接口；不在浏览器 mesh 上做无法回写的假编辑。
6. 复用协作者接口和历史成功 EP 链，对至少一个本批模型完成一次真实导出/运行，用于验证首个适配器。源 BIM 的完成状态与 EP 状态分别报告。

**M1 出口**：三案例均有当前代码、固定配置的原图冷启动结果，源分区/物理边界/开口和关系经自动评价，已知严重错误为零；轻微尺寸差可带提示。每案例再做一次同配置独立冷启动检查可重复性（首轮失败先修复，不盲目补满次数），只称“三案例重复基线”，不据此宣称广泛成功率。有一个持久编辑闭环和一个本批实际 EP 出口。预算/通道依模型约定核实，不能为凑次数调用未授权付费模型。

## 6. M2：立面匹配、缺图与整体朝向

范围：未命名/乱序立面先匹配到建筑局部侧面或段，再处理缺少某视图，最后验证整体旋转。复用 view manifest、投影框架、可见性、B5 宿主解析和历史 C2.1 设计资产，不恢复整套旧审签依赖。

- 首先比较同一建筑的命名立面与打乱/去名立面：模型识别图意与提示，代码比较投影宽、层结构、窗列等候选证据；正反方向/镜像一起核对。对称或证据不足时保留歧义，不能由文件名或强行选最高分冒充确定匹配。
- 再移除一张立面：可从平面确定存在的门窗保留，缺少的高度等允许明确假设；未提供视图不等于没有开口，也不凭空恢复不可知的全部开口。
- 最后给整栋建筑施加方向变化：局部房间/隔断拓扑应不变，只更新坐标变换与朝向。内部斜墙仍归 M5。
- 修改范围重点为 `view_manifest`、`facade*`、`window_sources/host`、run_stage 入口和 judge 的匹配证据；现有名确定的下游消费者应继续复用。

**M2 出口**：命名与正确匹配后的源模型在语义/容差内等价；错配/镜像错误能被自动发现；缺图输出覆盖范围、假设和未解项明确；缺图不导致已知空间与开口丢失。全图→乱序→缺图→旋转按子例分别记录，不一次叠满变量。

## 7. M3：退台与外露表面

先两层正交缩进，再单侧悬挑；初例保持命名完整立面，避免同时首测匹配和竖向几何。

- 使用每层真实 footprint，不把上层强吸到首层；核查 `multifloor.py`、schema、来源/宿主、coverage 的同 footprint 限制，按实际消费者替换。
- 复用层间交集/差集生成楼板、屋面和外露底板；判断没有上层覆盖的部分、不能人为封成同底面的柱体。
- 检查退台处房间边界、窗宿主与遮挡；覆盖检查从“所有层相同外包”转为明确应有的空间/楼板范围，不能用关闭覆盖检查过关。
- 若出口需要额外拆面，保留空间和源表面的映射，建筑源对象不因切配增删。

**M3 出口**：缩进和悬挑图纸均得到正确楼层外形与室内/室外边界；自动报告抓住错补墙/屋面/底板，房间和开口完整。代码里已有差集原语不算此阶段完成，必须有整案可视输出与相关出口验证。

## 8. M4：内院、挑空与通高空间

分两个工作包：M4-A 露天内院/平面内环；M4-B 局部挑空与有顶通高中庭。前者验证孔洞和内侧立面，后者验证竖向空间连通，两者不能混为“中间缺一块”。

- 为真实孔洞、楼板开口和跨层空间增加最小表达，区分室外内院与室内通高空间；当前单外环/整层统一高度不足时扩展 schema/薄模型，不用分层假房间代替。
- 替换 projection bridge 的单多边形无内环限制及覆盖分母；明确哪里本来就没有楼板，保留周边房间与竖向连通。
- 切配从单纯同层墙/相邻楼层，扩到实际几何范围与高度重叠；上下层墙部分相接的部分和开口应正确处理。
- 内院立面识别、跨层窗和必要剖面/文字证据按实际输入接入；缺关键高度/连通证据按歧义策略交付，不靠造楼板把模型“封闭”。

**M4 出口**：一个实际通高空间仍是一个源空间；挑空位置没有虚构楼板，露天内院没有被当作室内区域，周边连通与开口正确。自动评价须能发现“屋里多一层地板”的错误；EP 可有用途分层，但虚拟面不得传播为物理楼板。

## 9. M5：平面非正交直线建筑

先一个斜向隔墙，再斜外墙及带窗立面；不把曲面、自由形体和斜屋面同时并入这一阶段。

- 复用 polygon/线段/平面法向与宿主参数化；逐消费者改读图、校正、几何检查、立面可见性和评分中的 H/V、x/y 限制。
- 不通过把斜边吸正或阶梯化来满足旧 profile；容差规整沿实际几何方向，真实角度保留。
- 视图定位和开口宿主采用相应局部方向/平面；整栋旋转与内部夹角分别验证。
- 新 profile 只描述实际实现范围；不能仅增加枚举就宣称能力完成。三角形、多边形和斜墙相交所需表达按当前样例补齐。

**M5 出口**：斜墙确实存在且房间划分不被改写；斜外墙上的门窗宿主与方向正确；不把非正交输入误归为微小正交噪声。完整图纸及自动评价贯通，已支持的正交 case 不退化。

M5 与 M3/M4 没有必须串行的数学依赖。默认在其后做是控制整链变更面；实际需求或短实验表明值得前移时调整主顺序并记原因，无需为旧编号等待。

## 10. M6：组合案例、CAD 接缝与范围扩展

选择一个完整案例叠加两项已经单独验过的复杂度，检验共用模型、坐标、ID、视图映射和报告；不要从第一张图就同时要求所有复杂能力。

M1 源模型稳定后即可按需要用一个局部 CAD 补充作为独立接缝实验：复用 GT/CAD 工具，生成侧只读明确提供的生产 CAD，新增信息细化相关对象，不复制第二套 BIM，也不把评测 GT 喂回去。完整 CAD 产品化不是 M2–M5 的普遍前置。

曲线/曲面墙、斜屋面、任意复杂实体及各模拟专用网格暂列后续，由实际输入/用途触发。当前不承诺所有求解器已支持；共同模型保存足够的源几何与关系，让各出口有据可转。

## 11. 自动评价与实验执行规则

| 检查 | 正常应怎样判断 | 典型错误对照 |
|---|---|---|
| 源空间/隔断 | 按对象及关系匹配，物理隔断不因计算细分改变 | 删一墙、多一墙、拆走廊、合办公室、同数量错分区 |
| 门窗/连通 | 开口有正确宿主和连接对象，存在与尺度分别评价 | 错房间的门、封门洞、窗移到另一侧、真实开口丢失 |
| 竖向结构 | 按已知楼板/空间范围检查，真实空洞不算漏铺 | 挑空加板、退台填满、内院变房间、上层错接 |
| 容差规整 | 拓扑不变的小扰动结论稳定，保存改动来源 | 吸附吞小房/门洞、凭坐标近就合墙、把斜墙拉正 |
| 派生/导出 | 回到源 ID；虚拟计算边界与真实边界分别处理 | 显示网格或 EP 拆分变成物理墙、导出丢对象 |
| 完整性与状态 | 正确/有轻微问题/严重错误/未评价分别说明 | GT 坏了当模型坏了、NA 当通过、旧 replay 当冷启动 |

先复用现有 checks、J0/J1、GT 评分与报告，只补真实漏检或误报。GT 可容差规整但不能随当前预测改答案；共享规整函数各自独立消费输入。对象证据不足时明确未评价，不能只用计数或面积做无依据的完整性声明。

目标档从首批模型实验参加，Sonnet 级为运行上限，开发助手不代替产品补答案。固定每个角色的实际模型、通道、回退和全阶段配置传播，预算包含失败和重试；DeepSeek 任何调用仍需任务/批次专项同意，订阅授权不扩展到付费 API。先小图探针再整案，失败复用已产出数据定位；同阶段重复失败且无新假设时停止整案重抽。按 [模型约定](../workflow/models.md) 和 [开发方式](../workflow/development.md) 执行。

每一里程碑保存独立 run、输入/代码/模型配置、自动报告、可视入口、人工参与和未完成项。局部改动跑相关行为检查；阶段接缝跑一次真实产物贯通；整案和广泛回归按影响安排，不强制每步全量或跨模型审签。例子/单测通过只证明对应范围。

## 12. 紧接本计划的施工顺序

1. **先 M0-1/M0-2/M0-4**：用 sm24 错切结果检验并修正源分区表示与判定，复用 C2 原生多边形；同时把 sm21 成功、sm25 当前失败接到同一份自动报告。
2. **续 M0-3 与 M0-5**：显式门洞/连通和贴边窗已交付，下一步补输入证据自动接线，围绕具体样本做规整；sm25 短边不能压过分区保真成为主线。
3. **交错开展 M1 读图小实验**：在已有源/报告接口可用后尽快出第一个当前冷启动模型，再覆盖三案例、保存编辑并接一个 EP 出口。
4. **M1 之后按 M2→M3→M4→M5→M6 主顺序**，每阶段先独立新能力再组合；有用户项目需求或明确实验依据才调整顺序，同步本计划和 roadmap。

计划按里程碑和可验产物管理，不在调用通道、样本和实际缺陷尚未验证前虚报日历工期。每个工作包完成即小提交并汇报结果/剩余问题；可独立交付的部分不被下一复杂度的未知问题拖住。

## 13. 当前待补信息与默认安排

已向用户询问：① 影响隔断/开口/挑空的歧义如何处理；② 后续复杂建筑是否有指定实际样例/优先需求。收到回答后同步这里。
