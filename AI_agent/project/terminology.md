**状态：10-02 草案；10-07 按现状更新（分工模式、五档、项目经理、新底座），待用户确认。** 确认后，新写的文档、代码、报告和对话都按本表取名；旧文档不集中改写，改到哪里顺手统一。BIM 里各构件怎么起名（F1、房间名、逆时针编号）是另一回事，见 [BIM 命名](../design/bim_naming.md)。

## 一、五条总规则

1. **单说“模型”只指 AI 模型。** 建筑模型一律说 BIM（源 BIM、轻量 BIM），不说“源模型”。
2. **“档”必须带前缀：** 模型档（1–5 档）、细度档（精细档／粗档）、思考档（low 到 max）。
3. **“声明”拆成三个词，单说“声明”不再用：** 建筑概况（用户填的结构化信息）、定位观测（claim，模型记的带位置的观测）、建模声明（模型写给代码展开的结构化描述）。
4. **“主线”只指 Git 的 `main` 分支。** 还原、部分推理、完全推理三个研发方向叫“研发线”；旧流水线的 Stage 0–5 编号停用，“阶段”只指[开发计划](unified_agent_harness_plan.md)的阶段 0–5。
5. **包代号和运行编号只在工程记录里用。** C4、D1i、run7 这类写在工作记录与验收里；对用户汇报按内容说做了什么。

## 二、产品与系统结构

`建模 Agent = 模型 + 工作套件`，工作套件 = 运行底座 + 建筑共用层 + 几何内核 + 工具 + 方法模块 + 指引 + 角色。

| 中文 | English | 指什么 | 不再用 |
|---|---|---|---|
| 建模 Agent | BIM Agent | 本项目的产品：把一栋楼的各种资料变成轻量 BIM 的那一个 Agent。还原、部分推理、完全推理都由它完成 | 总 Agent、管线；“统一 Agent”只作强调 |
| 工作套件 | harness | Agent 里除模型以外让它完成任务的全部支撑（09-14 所说的“工作 kit／harness”） | 工作 kit、kit |
| 运行底座（简称底座） | runtime | 工作套件中与建筑无关的部分：模型接口、工具执行、角色调度、上下文管理、事件日志、预算与恢复。已自建（`src/agent_runtime`），与 Claude Code 对照时叫“新底座” | 基座、底座核心 |
| 建筑共用层 | building layer | 三条研发线共用的建筑部分：源 BIM 的结构和修改规则、依据与需求记录、建模声明、检查与规整、覆盖清单、角色目录 | 建筑层、BIM 层 |
| 几何内核 | geometry kernel | 确定性的几何计算：编译、装配、挂门窗、规整、切配。主要在 `src/agent/geometry` | 内核（单说） |
| 工具／工具集 | tool / toolset | 模型能调用的单个功能（看图、量测、试建、建模、修改、检查、交付）；全部工具合称工具集。每个角色有自己的工具目录 | 工具箱 |
| 方法模块 | method module | 针对一种输入的做法：图纸、三维网格、照片、文字。各含一段指引和专用工具，按问题组合，不按研发线固定 | 读图方法（泛称时） |
| 指引 | guidance | 写给模型看的全部文字，分五种：系统提示、任务说明、参考资料（`get_bim_reference`）、工具说明、工具反馈 | 指令层、说明层、操作指南、工具说明书 |
| 角色 | role | 按功能定义的一类工作：职责、可用工具、输入、交出的产物、预算。现有调度员、平面读图员、立面读图员；在议：核对员 | 子模型 |
| 调度员 | coordinator | 分工模式下统筹整案：盘点输入、派读图任务、一步建楼、处理对不上的项、派返工、交付 | 协调角色、主控 |
| 平面读图员 | plan reader | 每层一个：读外轮廓、隔墙、房间、门窗，试建通过后提交平面产物 | |
| 立面读图员 | elevation reader | 每个立面一个：读标高、逐个门窗的横向位置、宽度、窗台与窗顶，提交立面产物 | |
| 局部观察角色 | local observer | 只读：就一处局部回答带定位的观察，不改源 BIM（`review_detail`）；单模型可选，分工模式不用 | |
| 子代理 | sub-agent | 运行中派出的一个角色实例，有独立上下文；读图员的每个实例叫一个读图任务 | |
| 角色配置 | role configuration | 运行配置里把每个角色绑定到线路、型号和参数（思考档、温度、输出上限） | 模型路由、选模表 |
| 运行配置 | runtime configuration | 一次实测的 JSON：案例、模式、角色配置、保护线、输出目录；用 `python -m src.agent.runtime_configuration check｜launch <配置> --case <编号>` 检查与启动 | |
| 运行器 | runner | Claude Code 底座的运行入口 `run_bim_agent.py`：准备输入、提供工具、启动客户端、收结果 | |
| 桥接器 | bridge | `bim_agent_bridge.py`：让开发助手直接调用同一套工具 | |
| 查看页 | viewer | 源 BIM 的 HTML 交互查看页 | |

## 五、BIM 与产物

| 中文 | English | 指什么 | 不再用 |
|---|---|---|---|
| 轻量 BIM | lightweight BIM | 我们产出的建筑模型这一类东西：空间、边界、开口、关系和依据；口语“丐版 BIM”是同一个东西 | 通用 BIM |
| 源 BIM | source BIM | 一次任务的那份权威建筑模型，各后端都从它派生。代码里叫 `source_model` | 源模型 |

| 房间 | room | 实际建筑里由实体隔墙围成的房间；空间是它在 BIM 里的表达 | |

| 开口 | opening | 边界上的门（door）、窗（window）、通道（passage，无门的洞口） | 门窗（泛称时） |

| 热区 | thermal zone | EnergyPlus 等后端从源 BIM 派生的计算分区，不属于源 BIM | |

| 起始稿 | seed | 运行开始时给定的已有版本（恢复运行用） | |
| 平面稿 | plan draft | 单层平面编译后、装配前的中间稿：单模型里的 `draft_id`，分工模式里由平面产物建出 | 草稿（单说）、平面草稿 |

| 回叠 | overlay | 把当前源 BIM 画回原图上对照 | 叠图 |

## 七、运行与开发流程

| 中文 | English | 指什么 | 不再用 |
|---|---|---|---|
| 运行 | run | Agent 执行一次任务，如“sm24 run7” | |
| 单模型模式（简称单模型） | single-model mode | 一个工作模型在一条对话里包办全部工作（`mode: single_model`）；现冻结作参照 | 单驱动 |
| 分工模式 | role-division mode | 调度员加各读图员分工完成（`mode: role_division`） | |
| 读图任务 | reader task | 调度员派给一个读图员的一份工作：目标（楼层或立面）、原点、可选说明（至多 400 字符）、返工时的问题（`delegate_readers`） | 派工（产品场景） |
| 试建 | trial build | 读图员提交前，用同一套编译与检查试建本层，不存入全楼稿（`trial_plan_bim`） | |
| 提交 | submit | 读图员把产物交给调度员（`submit_plan_reading`、`submit_elevation_reading`） | 交付（读图员场景） |
| 一步建楼 | one-step assembly | 调度员一次调用完成选产物、定标高、逐层建、多层总装、立面对位、写高度（`assemble_from_readers`），只把对不上的交出来 | |
| 返工 | rework | 有问题的工作按具体问题重做：产品里调度员重派读图任务；开发里退回执行方 | |
| 交付 | delivery | 整案选定交付稿并结束（`finish_bim`） | |
| 保护线 | protection limits | 防失控的时长、请求、工具调用、token 上限；开发测试不按它考核 | |
| 关键路径 | critical path | 决定一次运行总用时的那串步骤；分工模式下现为最慢的平面读图员加调度员收尾 | |
| 实验 | experiment | `logs/experiments/` 下的一个目录，含准备、一次或多次运行与评价 | |
| 冷启动 | cold start | 只给原始输入，没有已有版本和答案的运行 | |
| 恢复运行 | recovery run | 从已有版本开始的运行 | |
| 续查 | continuation | 同一运行里模型停下后再追加调用 | 续跑 |
| 行为记录 | behaviour record | 一次运行的完整行为：每步工具调用参数与返回、可见文字、思考、用量 | |
| 事件日志 | event log | 运行底座逐条写下的原始记录；行为报告由它生成 | |
| 重放 | replay | 分三种说清：行为回看（只读记录）、确定性重放（重做工具操作）、重新调用（再请模型，不保证同结果） | |

| 整案实测（简称整案） | whole-case test | 用案例跑完整建模；节点回归和对照先报方案、用户批准 | 跑 case |
| 对照 | comparison | 同条件比较两种做法的一组整案，如三例对照（单模型与分工各跑 sm21、sm24、sm25） | |
| 节点回归 | milestone regression | 能力包闭合后确认旧能力没退步的整案实测；先报方案，用户批准 | 回归（单说） |

| 工作包 | work package | 派工单位：谁、做什么、在哪个分支、改哪些文件 | |
| 能力包 | capability package | 一起开发、一起评价的一组改动，如清理包、吸收包、工具改进包 | |
| 检查分档 | test tiers | 全量检查（全部检查，约 35 分钟，节点前跑）；合并检查（改到共用代码时的大集合）；角色检查（分工模块的检查与三例离线贯通） | |
| Agent 版本 | agent version | 登记的版本号，如 `t1-20261007-d1i.1`，对应一组文件哈希，运行时核对 | |
