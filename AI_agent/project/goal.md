## 交付与研究问题

- 核心产物是通用轻量建筑信息/几何模型（丐版 BIM）。EnergyPlus 是首个下游仿真插件，后续可接采光、声学、气流等适配器；不宣称这些出口已经验证。
- 09-10 课题汇报时用户明确上位研究问题：**在设计前期，如何实现相对高精度的各类建筑仿真，用以辅助方案设计。** 多模态输入到轻量 BIM 的 Agent 是实现这一目标的建模方法；“相对高精度”是研究目标，当前尚无统一对照结果证明达到该目标。后续主要方向为提升空间理解能力、复杂建筑稳定性、降低模型依赖度，以及轻量 BIM 的交互式编辑能力。
- 09-10 用户重申研究目的：利用 AI 改善前期各类仿真所用建筑模型的信息质量与精度。体量路线针对城市尺度计算中常见的粗体块输入，工作对象仍是单体建筑；主要研究办公、住宿、普通商业等类型化建筑，复杂公共建筑后续特化或明确简化，不作为近期主要对象。
- 09-13 用户重申工作模型以Sonnet级为上限，并主要承担调度思考，需控制消耗与时间。低档模型的局部执行和确定性工具应承接具体工作；以实际质量/总耗时/用量验收，不能以更强模型包办所有读图来替代工作方式改进。具体约定见[模型与费用](../workflow/models.md)。
- 09-13 最后收工时用户澄清：上述分工组合是可接受范围，**不要求开发过程一步到位，也不固定为最终目标**。可分步验证能力、工具和组织方式；若能通过更好的量测、约束与执行方法进一步降低对模型智力的依赖，应继续探索。Sonnet级工作模型上限和时间/消耗意识保留，不将每轮必须完成低档委派或达到最终分工设为前置条件。
- 09-10 用户进一步明确：**只生成目标单体建筑，不考虑环境。用户在生成前决定通用轻量 BIM 的简化/合并程度，与后端模拟需求独立；先生成 BIM，再选模拟插件。** 各档均以逻辑闭合的空间块为基本单元，分块以实体隔墙形成的实际空间为依据。复杂度可理解为假设建筑已完全推理准确后保留多少空间细节，但实现无需先完整推理再合并。若核心筒四周是一圈开放办公，最细也保留一个四周空间，不按朝向或功能凭空拆分。三档滑块仅为举例，具体界面未定。
- 共同几何底座的基本形式是带明确边界、门窗/开口及空间关系的空间体：以面表达空间范围和体积，面内开口表达连接。逻辑闭合不等于物理处处密封，挑空不能通过加假楼板封闭。各模拟按用途派生边界/网格，不能让 EP 的表示要求定义源 BIM。
- 09-09 灰空间讨论后用户确认：优先生成通用底座，参考成熟的物理/虚拟空间边界表达。主体可理解为多个逻辑闭合的空间体，形状不限矩形，整面或局部实际敞开需明确表达；独立构件可另用面表达。按需遮阳补充、热区切配、物性和空气交换等后端工作不得前移成源生成前置，也不要求完整实现 IFC。
- 09-09 后续用户明确：开敞/未知围护在交互查看中统一用半透明灰色辅助表示，具体状态仍由文字/源信息区分；灰空间设计先停在最小表达，遇到真实案例再细化，当前继续原图到通用 BIM 主线。
- 09-10 用户明确最终产品是**模型驱动的总 Agent**：配备代码工具、模型工具等能力，自主组织各环节任务，依据输入和执行反馈调整方法，交付轻量 BIM；固定流程不能成为产品唯一执行方式。用户委托开发助手总体判断架构与复杂度。各角色模型可配置，专门模型/子 Agent 按需调用，不以固定角色数量定义产品。
- 09-14 收工确认：**当前开发主体就是整套工作kit/harness，模型 + harness = Agent。** 在本项目讨论中两者指同一套让工作模型完成任务的支撑，涵盖工具、工作指引、任务组织、状态/中间产物及检查返工，不能把kit限缩为几个CV函数或把harness另列成后补包装。历史完整复现与开发助手工具化探路，都是提高开发效率、取得可迁移方法的路径，由助手综合把控；结果仍以目标模型实际建模质量为准。
- 09-10 收工前进一步收敛：**边试边推进，不预先固定 Agent 数量、嵌套层级或完整工具结构。当前只集中于产出可查看的丐版 BIM，暂不管跑通 EP，也不需要凑齐旧 0–5 六个环节。** 结构取舍依据最小真实实验调整，避免过早复杂化。
- 研究给定输入信息、模型能力和运行预算能达到怎样的保真度，建立实测质量/成本基线。用途是前期快速、较细致的模拟参考模型，不要求替代正式工程验收或复现实测能耗。
- **定性大于定量**：首要结果是房间、外形、楼层、门窗和空间关系正确的丐版 BIM，允许合理容差内的重生成与规整。pipeline 产物、CAD 接入产物和评测 GT 都不以逐顶点严丝合缝为目标；细小制图/数值偏差不应主导研发排期。
- 源建筑的分区错误比尺寸微差严重：漏墙、多墙、错误拆房/并房、错加楼板和改变门洞连通不能因热工模拟可合并热区而降级。用户选定的粗粒度源空间抽象属于合法交付，一个块可代表多个未展开的房间，需说明抽象范围并区分物理隔断、抽象分界和未知状态；不能将它误判为漏房，也不能借它掩盖逐间重建错误。计算切片只作为有源对象映射的派生表示，不能伪装成物理隔断。
- judge 与 GT 的用途是自动发现实质错误、说明输出可用程度，减少人工逐项核对，并复用 CAD 解析资产为后续模态接入铺路。量化指标提供诊断证据，不替代定性判断。
- 09-10 用户进一步要求把产出回叠原图纳入生成中的反馈，使 Agent 能根据原始输入自行校正、迭代，减少对开发助手、外部 judge 和 GT 的依赖。生产侧闭环使用原图、标定、实际源 BIM 与工具反馈；GT 仍仅供独立事后评价。回叠已生成不等于模型已正确判读，也不等于自动验收通过；实际接通范围与效果分别记录。

**09-24 用户核看sm24/run39：** 认为本次形态基本正确、质量较高，同意继续按计划验证稳定性。内部门高度在原资料中没有信息，允许明确假设，不作为验收阻塞项；不能因此降低门的存在、宿主、连接和几何自洽要求。毫米小数位表示数值存储/测量显示精细度，不等于原图识读具有毫米准确度；当前继续以形态与空间关系优先。

**09-23 厚度需求澄清：** 墙厚、板厚作为构件信息对后续仿真重要，应保存可用数值及其依据；厚度对几何的细小影响不是当前需求重点。既定逻辑闭合空间体形态和基于该形态的停点构件编辑保持不变，不将厚度驱动的实体生成、净空重算或尺寸精修排为当前前置任务。

**09-16 用户验收纠偏：** Voimatalo candidate_04未通过用户验收：主体内部基本整层开放，未形成充分的合理分隔；缺失扫描处主要标未知，未完成应有的体量/围护/开口推断补全。部分推理必须真正补足重要缺失内容，标未知不能代替生成；“保留已知开放空间”也不意味着内部未知时默认整层开放。先由开发模型与用户一起调好符合目标的模型，经用户验收成功，再将该成功方法交工作模型做建模迁移；既有自洽测试与窗数不代替此验收。09-16收工确认：视觉模型暂缓，待迁移完成后按实际问题针对性补工具，不先行选型或评估。建筑自身复杂程度与输出简化程度分开理解；具体档位仍未固定，见[收工记录](../logs/worklog/2026-09-16_partial_inference_session_close.md)。

**当前关键目标是在有限模型智力下，稳定生成相对精准的丐版 BIM。** 先解决房间、外形、楼层、门窗和空间关系的可靠还原，保持轻量表达与合理容差；不将毫米级复刻或增加模型智力作为取得质量的主要办法。既有 Sonnet 级工作模型上限和目标档参与方向保留。

**时间问题不是当前关键约束，耗时优化可以后续解决。** 用户以之前尝试的 prescan 为可能办法举例，不是要求立即重启或固定采用该方法。下一轮按质量与稳定性选择工作方式、实验范围和运行预算，给观察、判断及修订留出充分时间；不再以缩短首稿时间、300/600秒内抢交付或先优化速度作为当前主要目标。耗时和用量继续如实记录，既有调用权限仍适用。

历史限时实验的超时、失败和输入范围原样保留；它们不能单独证明现有模型智力无法达标。稳定性需由实际重复生成和适当换例的保真结果支持，不能用一次正确局部观察、辅助修复或工具通过代替。

## 成功方法先复现，再吸收（09-14 讨论确认）

**09-21 用户澄清两条路线的选择：** 历史成功方法复现、开发模型先做好再指导工作模型，两条路线由开发助手根据实际测试综合判断，不固定押注一路。用户重视历史reading曾达到100分，要求查清后来复现失败的原因；这不是要求当前主线切回。当前方法验证继续，另派代理并行核历史成功与复现的具体差异；不能用“只是旧reading”淡化已获成功，也不能在未控制差异前声称旧方法无法复现。

用户建议并由助手采纳：已有成功做法可能依赖多个要素协同，应先尽量完整复现，建立当前可重复的成功基线，再拆解、试验、精简和重组，吸收到当前总Agent。避免先定结构、再零散补要素，以致在缺少关键组合时反复试错；具体技术安排仍由助手总体把控。复现时保留原有工具、任务组织、中间产物、检查与返工的组合，必要兼容改动及人工参与如实记录，不把预先简化后的局部探针当完整复现。

用户补充历史来源：好reading最初来自Sonnet自主执行读图时自行开发并使用CV工具，获得当时100%的reading结果；随后才从其行为提炼固化工具箱，Haiku配合主控事后检查/返工也取得好结果，后者不算完全自主。该来源说明方法可以从Agent的有效行为中提炼，不与模型驱动架构冲突；历史reading成绩与当前完整源BIM、稳定无人介入能力仍分别评价。设计及证据见[读图方法](../design/reading_correction.md#成功方法的复现与吸收09-14-讨论确认)。本次仅讨论和同步记录，未启动复现实验。

### 开发助手探路与工作kit（09-14 讨论补充）

用户提出另一条互补路径：开发助手可先自己完整做一遍，摸出可行方法，整理为工作模型可执行的工具、操作说明、中间产物和检查返工方式（工作kit），再让工作模型实际执行；在哪个环节失效，就针对该环节补harness支撑。Astra自身视觉/空间建模能力较强，探路时应主动采用可记录、可复用的工具和确定性计算，尽量降低对纯视觉及隐含三维推理能力的依赖；仅由强模型直接生成正确答案不能证明kit可迁移。

## 按信息充分程度划分建模任务

09-10 用户统一命名：**还原建模、部分推理建模、完全推理建模**。分类依据输入提供了多少可确定的建筑信息，不按图纸、照片、文字或三维文件格式划分，也不是三套独立产品或固定管线。

| 类别 | 信息条件与主要工作 | 当前定位 / 示例 |
|---|---|---|
| 还原建模 | 建筑信息基本齐全，主要识读、对齐、规整并还原；允许少量补缺 | 当前主线 sm21、sm24、sm25；完整平立面、充分的 CAD 或其他详细资料 |
| 部分推理建模 | 已有部分可用建筑约束，需要推断重要缺失内容 | 保留研究方向，按轮次单独推进：带贴图三维体量，可加局部图纸/说明；不完整图纸本身也可属于此类 |
| 完全推理建模 | 只有有限参考或意图，建筑形体、空间等整体方案主要靠推断形成 | 参考图片、概念性自然语言等；详细研究后续展开 |

“完全推理”仍需遵守输入约束，不意味着没有任何已知信息；“还原”也不要求绝对零推断。这三类覆盖从信息基本充分到主要靠推断的任务范围，具体边界不定百分比。相同格式可以属于不同类别：完整图纸的照片可以支持还原，详细文字可提供较强约束，局部 CAD 仍可能需要大量推断。同栋建筑的外壳和内部可具有不同信息充分程度，补充资料后任务可逐步向还原靠近，不需切换源模型。

**信息充分程度与输出简化/合并程度独立。** 用户可对信息充分的建筑要求粗模型，也可对信息不充分的建筑要求较细的推断模型。复杂度的档数、控件及各档对应关系尚未设计，之前的办公楼例子仅用于说明方向；详细设计在研究中另行展开。模拟后端的计算粒度继续独立。

- 还原建模主线继续使用 sm21、sm24、sm25 原图和既有资产，按 [执行计划](drawing_reconstruction_plan.md) 与当前交接推进；不等待旧批次全锁清零，也不将已知失败改称低信息任务以回避保真问题。
- 部分推理建模按 [研究计划](partial_inference_research_plan.md) 保留为共用底座的另一研究方向，**每轮只推进一个方面**；先准备真实三维单体及已有案例的受控缺信息对照，取得源 BIM，再比较局部图纸、文字或交互补信息的效果。09-10 前一程已完成受控四立面生成及一次辅助恢复；用户随后要求按轮次聚焦；09-14新会话明确切回部分推理建模，还原建模保留已有成果与下一入口。实际状态见当前任务。
- 各类任务都应根据已有信息和明确假设产出有用模型。图纸、体量、照片、文字和 CAD 仍作为技术输入适配类别，混合输入按实际可用信息处理；新增证据细化假设并呈现冲突。Google Earth 仅是贴图体量形态举例。

用户明确最终产品为：**一个建筑的所有信息进入 Agent，输出丐版 BIM。** 用户不需要选择还原、部分推理或某种模态的独立产品入口；上述分类保留为信息充分程度和研究/评价范围的描述。生成前的源简化意图仍是独立输入。

09-14 本轮收工进一步明确：用户可直接提供原始带贴图三维模型，如何利用几何、是否需要图片、选角度与局部观察属于Agent及harness内部职责，不要求用户先准备多角度截图。原资产应保留为可再次查询的输入，图片是按需派生的观察结果。前一程Voimatalo只迁移了开发准备视图后的工作；续推已接通原GLB查询、按需渲染和表面量测并实际生成候选，观察取舍与建模保真仍待改善，见[设计](../design/architecture.md#原始三维资产与内部观察09-14收工)。

**09-18 用户确认素材责任划分：当前主要是在开发阶段摸出一条可行的路，产品投入使用后，素材由用户自己去找所需的建筑贴图模型。** 因此开发侧不承担「全球任意建筑都能取到」，只需少数几个能稳定拿到、类型有梯度的样本；产品侧则需要能兼容用户带来的各种来源与格式，并给出可操作的获取指引。可选来源、获取路线与选样梯度见[带贴图体量素材调研](../design/textured_mass/sources.md)。

本轮优先真实带贴图三维体量。sm24人为移除平面的缺图对照缺少当前明确的实际对应场景，优先级降低，留到后续统一产品的缺信息能力验证，不作为本轮首要路线。用户要求先讨论如何组织Agent、处理不同模态并兼容还原建模，讨论后用户已同意总体架构并授权继续Voimatalo迁移实验；实现与实际效果见当前任务。

## 建筑基础声明作为输入（09-14 用户确认）

`testdata_prompt.json`所代表的结构化建筑基础声明是正式输入模态之一，实际使用也需要用户填写这类信息，与图纸等资料共同参与建模。用途、位置、面积、层数和图面关联等不能仅因能辅助判断而被当成评测答案排除；GT仍独立留在评测侧。具体字段必填性与界面尚未设计，旧字段如`thermal_zones`需按其实际语义使用，不把后端热区数自动等同于源物理房间数。

用户同时允许开发助手为研究/调教工作模型能力，自行按实验目的限定输入，例如仅给原图、只看一张平面或暂不提供某些声明。须记录实际提供/排除的内容，区别能力探针与完整产品输入；不要求每轮实验必须携带完整JSON，也不把实验临时排除声明写成产品设计。独立BIM实验入口已接显式声明参数，省略时仍为仅原图，接入范围见[运行说明](../workflow/run_case.md)。

## 证据与渐进精度（09-10 用户确认）

**先根据现有输入生成有用、可查看的丐版 BIM，再随信息增加提升精度。证据采信的基本顺序是：标注 + 像素双证据 ＞ 像素证据 ＞ 纯推理。** 这是利用信息的原则，不是要求输入依次通过的三道门槛；不能因为某种图像匹配不上既定识读方法就没有模型输出。

- 标注与像素相互印证时支持更准确的定位和尺寸；只有像素时利用可见形状、比例与空间关系；看不清或没有给出的部分允许模型合理推断，并说明假设。不同对象、同一对象的不同属性可以采用不同来源，不按最弱一项把整栋信息一并降级。
- 模型负责识别图意、选择可用证据/工具、处理冲突和补全未知；纹理、模糊、单色及复杂表现图不应被一种颜色规则、固定量测工序或强制双线识别约束。代码负责计算、变换、几何装配与自洽检查。
- 推断是正常的生成能力。保留已有可靠信息，明确哪些内容是观测、估计或假设，后续新输入可细化；不能把推断称作读准，也不能借信息不足丢掉已读到的房间、门窗和连通关系。
- 09-10 Voimatalo 展示复核时用户强调：图像/网格缺失不能直接推成透空，也不能统一补为整面无窗墙。先结合残余几何、窗列、屋顶、邻接关系与建筑常识判断缺失处的墙面、开口或交通体量，再补全并记录推断依据。

## 轻量几何范围

| 组成 | 需要保留的信息 |
|---|---|
| 房间/空间块 | 几何、楼层、高度、语义与抽象粒度；已有房间信息保留为依据，后端分区不覆盖源空间 |
| 边界/隔断 | 类型、方向、两侧关系；同一物理隔断在不同房间派生面之间可关联 |
| 窗、门、未填充开口 | 宿主、形状、位置及连到的空间/室外 |
| 空间关系 | 相邻和实际连通分开，物理隔断、源空间抽象分界与后端计算边界分开 |
| 建筑附属几何 | 本栋建筑的屋盖、遮阳、阳台等，可不形成区域；邻楼和周边环境不在本次单体范围 |
| 可选细节 | 墙厚、参考面偏移、窗洞深度；注明内皮/外皮/中间参考面基准 |
| 可更新性 | 稳定对象引用、来源、假设与用户修改记录，支撑查看与更新 |

09-10 用户补充：墙厚精细几何不是当前优先目标，需重视其作为墙体参数对后续仿真的影响；“读准墙厚是否顺带提高几何精度”的权衡仍在讨论，不据此新增精度硬门或放弃已有厚度信息。

09-10 收工前用户再次询问如何解决墙厚及其带来的标注问题。助手提出保留轻量代表面、增加墙厚/两侧偏移与标注端点基准、用代码换算并在回叠中区分墙面和代表线；具体见 [实施方案](../design/model.md#墙厚与标注基准的实施方案09-10-收工讨论尚未实现)。这是当时的下一程方案，不视为用户要求统一中线、完整实体墙或新的精度门槛。09-12 已接通局部墙面/尺寸换算，实际范围与未完成项见同页后续实现段，可靠自主纠错仍待验证。

保留面模型内核，全实体墙不是全项目的普遍前置。构造层厚度可后挂；净尺寸、窗内缩和遮阳等几何效应需显式几何或可派生参数。
热桥等局部实体域、CFD/疏散的流动或导航几何是专项扩展，不把所有下游细节同时塞入最初的共享模型。
导出时按用途处理开口和连通：不能假定 EnergyPlus 的父面加子面表示无需转换就能交给其他求解器。

## 人工参与与查看编辑

- 09-24 用户提出后续在HTML人工校验停点按置信度呈现，让人看出明确推断、高置信度和低置信度内容。当前只记录方向，具体分类、依据、交互和显示方式留待展开讨论，不立即实施，也不要求先补此界面再继续还原验证。见[查看设计](../design/architecture.md#查看编辑与确认)。
- 09-10 用户明确：缺少信息时，Agent 可在生成过程中通过交互补足，例如询问用途、楼层、已知尺寸或补充视图。这是生成中的信息获取，与已有 BIM 停点上的查看、编辑、确认分开；停点编辑暂缓不代表生成阶段不能提问。可用假设继续的部分先推进，补充信息及其影响应留在来源记录。
- 共用生成主干在源 BIM 停点分叉，各后端必须消费同一份 BIM；EP 模型不能再从 correction 另起一条几何重建路线。09-09 要求的 EP 分叉已通过历史产物贯通，09-10 当前工作暂不推进 EP。源 BIM 仍不含热工物性和 EP 切配；直接操作、自然语言及两者结合、物性挂载修改的完整交互继续暂缓。
- 仿真前应能查看、补充、修改模型，然后确认继续。自然语言修改和直接几何操作都是目标功能。
- 图纸路线以 Stage 2 源 BIM 可视结果作为主要人工查看/确认停点。近期先复用现有 HTML 形式交付可查看模型和质量说明，完整交互设计与编辑逐步补齐；具体交付及当前代码差异见 [系统设计](../design/architecture.md#查看编辑与确认)。
- 已有 [查看器生成器](../../scripts/tool_scripts/render_geometry_viewer.py) 与 flow 的几何确认/恢复入口；具体交互能力按代码核对。
- 墙推拉、窗移动、回写及自然语言编辑仍需实现/核查，不能把 [编辑设计](../design/architecture.md) 当作已交付功能。
- 编辑更新权威源几何，再重建受影响派生物、检查并刷新查看器；直接操作和自然语言动作尽量复用相同几何操作。
- 建筑隔断编辑与仿真热区分组分开。自动和人工辅助结果分别评价，记录补充信息、干预次数与时间。

## 运行模型与评价

- 09-24 用户确认 GT 可作为辅助，现有 DXF 也属于后续要支持的输入模态。优先复用已有 GT/容差评价，疑点再回查原图，不必每例重新手工描完整参照。DXF 作为明确输入的建模与原图独立生成分开报告；辅助评价或开发示范不冒充工作模型输出。本程先完成保存墙网的局部修订及一次 GLM 恢复，再收工。
- 产品运行目标为可本地部署级和 Flash 级模型，初期统一经 API 调用；部署硬件不是前置。
- Sonnet 级是用户接受的运行模型上限，规划、判断、修复和评分不能暗中依赖更高档模型。
- 目标档模型从首批实验开始参与，不采用“先只靠最高档跑通、弱模型以后才接”的路线；也不要求每次都从最低档开始。
- 开发助手的模型分配独立于产品上限，见 [模型使用约定](../workflow/models.md)。具体 API ID 和能力使用时核对，不照搬历史型号。
- 评价尺寸、外皮/开口、空间拓扑与完整性，同时看成功率、人工投入、总成本与时间。已知设计几何和人工参考模型可以作几何参照，不要求先收集实测能耗。
- 还原建模先看重建结构、语义和整体尺度的保真；部分推理建模分别评价已知约束与缺失部分的推断；完全推理建模重点评价参考/意图符合程度和建筑空间合理性。用同物性比较几何时，供冷/供热需求不能写成实际用电量。
- 更高精度有价值，但毫米收敛、历史字节相同、全套防御测试或旧债清零不应成为默认阻塞。
