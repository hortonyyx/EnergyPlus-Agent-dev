# 关键决策

以下是当前已确认的方向和约束；进度看 [当前任务](roadmap.md)，具体工作规则看 [会话入口](../Agent.md)。

| 日期 | 已确认的决定 | 原因与影响 |
|---|---|---|
| 2026-09-10（按实际分隔简化/合并） | 源分块以实体隔墙为依据；复杂度表示对假定完全准确的建筑空间做多少简化/合并，最细也不凭空拆分开敞空间 | 核心筒四周若是一圈开放办公，最细仍是一个四周空间；朝向与功能本身不构成隔墙依据。低档可直接推断合并后表达，无需先完整恢复；物理/抽象边界仍需区分，源简化与 EP 热区合并独立 |
| 2026-09-10（单体、源空间复杂度与后端独立） | 只做目标单体，不考虑环境；用户生成前选择通用 BIM 的空间复杂度，再选不同模拟插件 | 办公楼三档划分仅为举例，须结合实际隔墙与上述简化原则理解，不固定块数或强制按朝向切块。后端热区合并等继续独立派生。撤回助手此前按模拟用途配置生成、纳入周边场景的建议 |
| 2026-09-10（体量路线对象与细化配置） | 服务前期各类仿真，以办公、住宿、普通商业等类型化单体建筑为主；模型细化程度由用户配置 | 城市尺度是使用背景；复杂公共建筑后续特化/简化。当前只讨论获取方式与 pipeline，不启动实验；此前按独立外壳推荐的案例须按建筑用途重新筛选 |
| 2026-09-10（体量输入与交互补充） | 各类输入都应尽量产出有用模型，精度与准确性随信息变化；当前先调研并取得带贴图三维体量案例，纯照片另列输入分类 | 缺信息可在生成过程中交互补足，与生成后的 BIM 停点编辑分开；本次先取得输入资产和路线依据，不把照片到几何重建一并作为首例前置 |
| 2026-09-10（收工前收敛范围） | 边试边推进，不预先固定 Agent 结构；当前只集中于产出丐版 BIM，暂不管 EP，不需要六个运行环节 | 一层子 Agent、0–5 映射等是先前讨论建议，不是必须落地的结构。下轮从最小真实实验继续，按实际需要接工具，避免再陷入结构设计和过早复杂化 |
| 2026-09-10（总 Agent 产品形态） | 用户明确主要思路为模型驱动的总 Agent，配备代码、模型等工具完成各环节，并委托助手总体把控架构 | 整案执行由目标、输入与反馈驱动；固定步骤可以是工具内部实现，不能成为所有输入的唯一流程。助手建议先一个总 Agent 加按需专门能力，复用几何内核，以真实 BIM 与失败恢复检验效果，不先堆角色或重写全库 |
| 2026-09-10（证据与泛化） | 标注 + 像素双证据 ＞ 像素证据 ＞ 纯推理；先出有用丐版 BIM，输入越充分再提高精度。材料分层等热工信息归后端模块 | 证据顺序不是生成准入门槛；模型承担图意、采信、工具选择和合理推断，不能为固定图像样式、量测工序或单/双线契约牺牲泛化。推断显式说明，已知空间/开口仍须保留；代码负责几何计算与自洽 |
| 2026-09-10（补充历史动机） | 从单线改双线，是为了减少 reading 提前选线的推理负担，并延后墙厚、轴线/墙边标注引出的出模对齐取舍 | 不能只凭历史单线好结果预先恢复这一职责安排；墙厚几何优先级较低，可靠厚度与几何精度的利用方式仍在讨论，未确认新阈值或唯一表示路线 |
| 2026-09-09（灰空间讨论后确认） | 优先通用底座，主体以逻辑闭合空间体和实际围护/开口表达，参考成熟的物理/虚拟边界思想 | 空间不限矩形，逻辑闭合不要求实体围护封闭；源中保留真实敞开及未知信息。遮阳按需补充、热区切配、物性、空气交换等留给后端，不作为源生成前置；具体 schema 和灰空间贯通仍待实现 |
| 2026-09-09（源出口交付后澄清） | 共同生成主干在停点 BIM 分叉，各后端均从这份 BIM 派生；当前先跑通 EP 分叉 | EP 不得从 correction 另行重建几何。源 BIM 不含热工物性/EP 切配；EP 分叉负责用途派生及独立物性挂载。编辑交互仍留待统一设计 |
| 2026-09-09（本次开工调整） | 先推不含物性、不依赖 EP 切配的丐版 BIM 生成 pipeline；切配归 EP 后端插件；停点编辑暂缓 | 编辑后续统一设计直接操作、自然语言/结合及热工物性挂载修改。当前优先原图到源 BIM、可查看输出与自动评价，持久编辑和 EP 运行移出本批验收；真实边界、相邻和连通仍属源模型 |
| 2026-09-07～08 | 通用轻量 BIM 为核心，EnergyPlus 是首个下游；我方做几何，物性对接协作者 | 保留源房间与隔断，热区和仿真模型作为派生；不按旧 MEP 草案重造已分工的工程 |
| 2026-09-08 | 图纸/case 与带表皮体量两路先行，最终混合 CAD 等输入 | 输入多少影响精度；推断与已知事实分开，先产出有用模型 |
| 2026-09-07～08 | 查看、补充、直接或自然语言编辑是产品能力 | 编辑回写源几何并更新派生物，人工辅助结果单独评价 |
| 2026-09-07～08 | 目标档运行模型从首批实验参与，运行上限 Sonnet 级 | 开发模型与产品运行模型分开，不走先只依赖最高档、以后再换的路线 |
| 2026-09-08 | 直接推进真实 case，已有框架按需复用/替换，撤销重复全量与固定角色审签 | 相关检查保护实际风险，旧批次和测试锁不自动成为任务 |
| 2026-09-08 | Git 日常操作全权授权；收工更新文档、commit 和 push | 持续保留可回退版本，不逐次申请正常 Git 操作 |
| 2026-09-08 | 所有助手项目记忆同步仓库，本地只留索引 | 切模型从相同文档接续，项目知识不独存在 memory |
| 2026-09-08 | DeepSeek 先获明确同意；Claude、GLM 现有订阅可自行调用/派工 | 用户指出 DeepSeek 直接付费；具体范围见 [模型与费用](../workflow/models.md) |
| 2026-09-08 | 按内容重新组织管理体系，删除旧兼容入口 | 现行文档直接说明目标与做法，原文由归档和 Git 保存；不为旧目录维持跳转页 |
| 2026-09-09 | 正式推进先做相对精准的图纸重建，先梳理计划；项目库作为资产灵活复用，疑点用实验推进 | 本批先做可视基线、原图冷启动与几何完整性，体量适配暂缓；具体阶段为 [推进计划](drawing_reconstruction_plan.md) 中的执行建议 |
| 2026-09-09 | 重申定性大于定量，以 sm21/sm24/sm25 既有案例推进；judge + GT 负责自动校验以减少人工核对 | pipeline、CAD 接入产物和 GT 都允许合理容差规整，主目标是正确可用的丐版 BIM；不再以 GT 精修、逐点吻合或微小 CAD 误差考证主导排期。具体门槛按消费者验证后修改 |
| 2026-09-09 | 源分区保真高于尺寸微差；sm24 是 reading 正确、C2 前 correction 切房 | 源 BIM 的漏墙/多墙、错拆并房、假楼板与连通改变按严重错误处理，不能借热区可合并或历史 judge minor 降级；计算片与物理隔断分开 |
| 2026-09-09 | BIM 是多模拟共用的空间体、边界面和门窗/开口底座，用户委托助手总体把控复杂度并形成后续执行计划 | 以源模型和自动验收为基础，按能力依赖渐进扩展；M0–M6 默认顺序及具体工作包见 [详细计划](drawing_reconstruction_plan.md)，未答复的产品选项明确标为暂定 |
| 2026-09-09 | Stage 2 是源 BIM 的主要人工交互停点；近期先参考已有 HTML 输出供人工查看确认，完整交互后续设计 | 先交付查看与质量说明，再补编辑；现有代码停点仍在 Stage 3 后，迁移和确认版本绑定纳入 M0/M1，详见 [系统设计](../design/architecture.md#查看编辑与确认) |
