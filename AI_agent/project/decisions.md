# 关键决策

以下是当前已确认的方向和约束；进度看 [当前任务](roadmap.md)，具体工作规则看 [会话入口](../Agent.md)。

| 日期 | 已确认的决定 | 原因与影响 |
|---|---|---|
| 2026-09-07～08 | 通用轻量 BIM 为核心，EnergyPlus 是首个下游；我方做几何，物性对接协作者 | 保留源房间与隔断，热区和仿真模型作为派生；不按旧 MEP 草案重造已分工的工程 |
| 2026-09-08 | 图纸/case 与带表皮体量两路先行，最终混合 CAD 等输入 | 输入多少影响精度；推断与已知事实分开，先产出有用模型 |
| 2026-09-07～08 | 查看、补充、直接或自然语言编辑是产品能力 | 编辑回写源几何并更新派生物，人工辅助结果单独评价 |
| 2026-09-07～08 | 目标档运行模型从首批实验参与，运行上限 Sonnet 级 | 开发模型与产品运行模型分开，不走先只依赖最高档、以后再换的路线 |
| 2026-09-08 | 直接推进真实 case，已有框架按需复用/替换，撤销重复全量与固定角色审签 | 相关检查保护实际风险，旧批次和测试锁不自动成为任务 |
| 2026-09-08 | Git 日常操作全权授权；收工更新文档、commit 和 push | 持续保留可回退版本，不逐次申请正常 Git 操作 |
| 2026-09-08 | 所有助手项目记忆同步仓库，本地只留索引 | 切模型从相同文档接续，项目知识不独存在 memory |
| 2026-09-08 | DeepSeek 先获明确同意；Claude、GLM 现有订阅可自行调用/派工 | 用户指出 DeepSeek 直接付费；具体范围见 [模型与费用](../workflow/models.md) |
| 2026-09-08 | 按内容重新组织管理体系，删除旧兼容入口 | 现行文档直接说明目标与做法，原文由归档和 Git 保存；不为旧目录维持跳转页 |
| 2026-09-09 | 正式推进先做相对精准的图纸重建，先梳理计划；项目库作为资产灵活复用，疑点用实验推进 | 本批先做可视基线、原图冷启动与几何完整性，体量适配暂缓；具体阶段为 [推进计划](drawing_reconstruction_plan.md) 中的执行建议 |
| 2026-09-09 | 重申定性大于定量，以 sm21/sm24/sm25 既有案例推进；judge + GT 负责自动校验以减少人工核对 | pipeline、CAD 接入产物和 GT 都允许合理容差规整，主目标是正确可用的丐版 BIM；不再以 GT 精修、逐点吻合或微小 CAD 误差考证主导排期。具体门槛按消费者验证后修改 |
| 2026-09-09 | 源分区保真高于尺寸微差；sm24 是 reading 正确、C2 前 correction 切房 | 源 BIM 的漏墙/多墙、错拆并房、假楼板与连通改变按严重错误处理，不能借热区可合并或历史 judge minor 降级；计算片与物理隔断分开 |
| 2026-09-09 | BIM 是多模拟共用的空间体、边界面和门窗/开口底座，用户委托助手总体把控复杂度并形成后续执行计划 | 以源模型和自动验收为基础，按能力依赖渐进扩展；M0–M6 默认顺序及具体工作包见 [详细计划](drawing_reconstruction_plan.md)，未答复的产品选项明确标为暂定 |
| 2026-09-09 | Stage 2 是源 BIM 的主要人工交互停点；近期先参考已有 HTML 输出供人工查看确认，完整交互后续设计 | 先交付查看与质量说明，再补编辑；现有代码停点仍在 Stage 3 后，迁移和确认版本绑定纳入 M0/M1，详见 [系统设计](../design/architecture.md#查看编辑与确认) |

**仍属设计建议**：两路共享建筑模型、几何内核与出口，输入适配分模块；需要并行时用短期树，公共接口先合主干。详见 [系统设计](../design/architecture.md)，不宣称统一入口已经实现。
